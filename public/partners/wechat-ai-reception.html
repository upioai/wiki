Problems We Solve

01

02
One Brain · Four Ends

一个大脑，四种微信端

话术、记忆、知识库、接管逻辑只维护一份，落到企微与个微不同的端上。

大脑与端侧执行器
架构示意 · 端侧只做读屏与点击

// 四个端都只做读屏与点击，大脑与数据全在服务端

WECOM 1:1企微好友单聊代回

以真人销售的身份接待，多身份互不串；发成功才记账。

WEIXIN ×3个微代回

装在销售自己的设备上；Windows 与安卓默认回全部一对一，Mac 可设白名单；群聊硬拦。

RECALL ×7七天召回

按画像选 7 个话题；客户一回话或删人即停；店长可逐条改。

03
Message Pipeline

一条客户消息的处理链路

先过确定性规则，再决定要不要交给模型；写完还要过滤才能发。

端侧
读屏截屏识别新消息，不接微信 API
规则
先判已转人工？质疑真人？命中固定问答？三条都是确定性判据
人工
接管命中即交给销售本人，之后不再自动回，冷静期到点恢复
记忆
知识50 轮压缩上下文 ＋ 客户画像 ＋ 效果图库 / 材料库 / 户型图识别
模型
起草按该销售的人设与甲方口径写一句话
输出
过滤出站三道确定性过滤，不合格不出门（见 05）
拟人
发出等待补足到 3–8 秒再逐字输入；发成功才落库，联合版本号可倒查

// 判定在模型之前：要不要人接手，不交给模型决定

04
Handoff Gate · Deterministic

人工接管闸：两档判据

客户一问「是不是机器人」，调用模型之前就转人工。这是规则，不是模型判断。

接管判定的两级出口
判据为确定性正则 · 非模型推断

// 琥珀 = 人在环出口 · 青 = 机器继续自动 · 冷静期默认 24 小时

05
Output Safety · Five Filters

模型写完，不等于能发

入站两道嗅探、出站三道过滤，全是确定性规则，不依赖模型自己守规矩。

一条回复前后的五道确定性检查
03 · 04 入站读屏嗅探 · 01 · 02 · 05 出站过滤
01工具调用泄漏剥离剥掉模型吐出的协议字节
02舞台指示剥离去掉「微笑」这类动作描写
03说话人错标嗅探读屏认错说话人，跳过并告警
04会话列表误读嗅探截图裁进左栏列表，跳过并告警
05单条合并企微与个微硬性合并成一条，不刷屏
