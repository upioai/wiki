01
End-to-End Pipeline

全程一条线，每一棒都落库

九段串行，段间靠任务单状态交接。任何一段崩了都能从库里的状态捡起来重跑，不重复扣费。

工作台
提单 店长粘一条源片链接、选出镜形象。提单那一刻把「用谁的脸、谁的声、哪些料」固化成一张资产快照写进任务单——后续一律以快照为准，不查任何写死名单
解构端
判型 拆镜头、转写、量节奏，顺手判出这条源片属于哪条路线。复刻端只消费判型，不许凭感觉选——没判型就打回去补
文稿
重写 压缩改写成自家口播稿。付费前必过稿件闸：时长、平均句长、最长句、单项长度、清单项数量五项一起查
预算
预检 按路线档位估算音色克隆 + 配音 + 口型 + 画面生成的总价。超档不许抬上限，只能回去改分镜
配音
+ 对齐 音色克隆一次、后续复用。合成后做强制对齐拿逐字时间轴——字幕不按字数估算时间
画面
按路线分叉 整条产线只有这一步分叉。真人底片裁窗 / 素材库检索 / 文生图→图生视频 / 参考生视频，四选一或逐镜混搭
合成
+ 自检 切段、贴字幕、响度归一、出封面。合成前后跑闸门，退出码非 0 一律不许往下走
独立
审核 四个阶段各交一个不可变阶段包，由与生产端隔离的审核端逐个复验指纹后签发
人工
终审 店长必须完整播放一遍并逐项勾选，才解锁下载。没看完不给下载键

// 关键设计：付费步骤的编号由服务端固定下发——网络断了用同一个编号重连，恢复原请求，绝不会产生第二笔费用。

03
Separation of Powers

生产的不审核，审核的不发布

生产端只生产并提交不可变阶段包，审核端只审当前包。两者都没有发布权，人工终审与发布只在工作台完成。

ISOLATION产物怎么传

  • 阶段包落私有对象存储，生产端只有该前缀的写权限
  • 服务端另持一把只读凭据，前缀相同
  • 审核端与浏览器都拿不到底层地址，只能走服务端鉴权代理
  • 每次读取重查任务、阶段、认领态与强校验标签，任一不符即拒

PAYMENT钱怎么管

  • 生产 worker 禁止持有支付服务凭据
  • 配音与口型一律经服务端工作流用后端密钥唯一提交
  • 每个付费动作由服务端下发固定编号
  • 断线重连沿用同一编号恢复原请求，不产生第二笔

CONTRACT包里放什么

  • 四个阶段各自自包含，互不夹带
  • 清单必须声明核心载荷指纹与逐文件指纹
  • 不许只写生产机上的绝对路径
  • 发布前完整复验四个包 + 根素材 + 成片
04
Two Ledgers

生成费之外，还有一本大脑费

一条视频的钱分两本。生成费有硬闸管着；大脑费——产线自己那个 AI 会话烧的推理成本——曾经完全没有上限。

// 两本账刻意不合并：把推理成本并进生成费会瞬间打爆预算档，连锁拒付掉本来正常的付费步骤

为什么会失控：AI 会话每做一步，都要把之前所有内容重新发一遍。步骤越多、上下文越长，重发越贵——而墙钟超时只卡时间，卡不住钱。
05
Deterministic Gates

24 道闸门，全是拿返工换来的

每一道都对应一次真实翻车。确定性校验优先——能用代码判的不让模型判，退出码非 0 一律不许往下走。

管什么闸门拦住的翻车
开工前判型校验 · 施工单校验 · 需求语义路线选拧、施工单带未填项就开始烧钱
文稿稿件闸 · 语速 · 停顿离群稿子超长靠加速硬塞；某句被塞进超长停顿
配音音画一致 · 说话人身份配音内容和稿子对不上；串了别人的音色
画面看图对题 · 场景保真 · 重复镜 · 源片复用红线 · 人脸红线画面答非所问；直接拿源片截图当素材＝翻拍；B-roll 里闪出原博主
口型口型质量 · 口型偏移 · 人脸覆盖整段崩坏（帧数对、脸也检得出，旧闸一道都查不出）；嘴和声音差几帧
剪辑切段体检 · B-roll 切点 · 帧对齐按秒切片的累积漂移，开头闪一下别的镜头
成片技术校验 · 完整性 · 闸门清单核对该跑的闸没跑完就报「已完成」

06
Failure Handling

卡住、失败、还是等人补料

三件事必须分开：卡住等人补料、失败值不值得重试、死了要不要换机器重排。混在一起就会出现「一条坏单无限转世，每一世都真的在花钱」。

// 判死看的是心跳不是进度：画面生成要跑好几分钟，期间进度条一动不动但心跳照报——按进度判会把正常长步骤误杀

BLOCKED卡住 · 等人

  • 缺素材、缺授权、余额不足
  • 不是失败——任务停在原地，页面告诉店长缺什么
  • 补好后点继续，回到可认领状态

FAILED失败 · 分 13 类

  • 模型拒调 / 超时 / 出错
  • 余额不足 / 生成出错 / 传不上云
  • 素材缺失 / 参数错 / 超预算 / 音色失效
  • 只有「会话自己崩了」值得重试——余额和参数重试一百次也一样

DEAD判死 · 换机器

  • 判死同时把认领就地过期
  • 原机器下一次报活被拒，据此杀掉本地会话让出机器
  • 只翻数据库不杀会话，机器还占着，队列照样堵
07
Current Status

已上线 / 待合入 / 在建

纯工程口径。没上线的一律不写成已上线——产线自己的诚实性要求也是这一条。

SHIPPED已上线

  • Style A 真人复刻全链路（音色克隆 / 口型 / 表情保真 / 烧录字幕消除）
  • Style B / C 两条生成式路线与三档预算
  • 四阶段不可变阶段包 + 独立审核契约
  • 私有对象存储 + 服务端鉴权代理，无匿名 URL
  • 付费调用服务端托管、固定编号防重复扣费
  • 心跳 / 判死 / 自动重排 / 13 类失败分类
  • 客户单资产快照化（不查写死名单）
  • 大脑费按 token 用量记账 + 对账脚本

PENDING已提交 · 待合入

  • 会话级美元硬闸：单次会话烧到上限即停
  • 上下文压缩窗口钉死，堵住「每一步全量重发」
  • 烧穿预算单列一类失败原因，不进自动重排——否则一条坏单三倍账单

WIP在建 / 待决

  • 逐镜点菜：三条路线降级为点菜表的预设；首张零件组合卡试验中，代码未合入
  • 产线说明书瘦身：说明书本身约 4 万 token，每一步都在重发
  • 高预算档要不要保留：单条上限收紧后，两条生成式路线在数学上进不去
  • 价格表对账：内置估算表与账单口径尚未逐条核平
一句话总括：一条生产与审核分权的视频产线——判型决定画面从哪来，24 道确定性闸门挡住返工，付费调用由服务端托管保证不重复扣费，最后由人完整看一遍才放行。难点不在生成质量，在让每一分钱和每一次放行都有据可查。
