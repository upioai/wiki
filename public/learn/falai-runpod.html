fal.ai × RunPod

在 AI 内容生成四件套 里我们讲过「用什么模型生成」；这篇讲的是「生成这件事发生在哪台机器上、钱按什么算」。fal.ai 和 RunPod 是我们做图片 / 视频生成绕不开的两类平台的代表：一个按「结果」收费，一个按「GPU 时间」收费。读完你会知道两家各自是什么、一张图到底该在哪生成、Replicate / Modal / Vast.ai 这些名字各站在哪，以及我们两家都在用、分别用来干什么、踩过哪些坑。

篇幅 6 章 · 约 12 分钟 受众 全员 · 不需要会写代码 主线 团队图片 / 视频生成链路的真实选型

先给一句话版本：fal.ai 是「餐厅」——菜单上一千多道现成模型，点一道上一道，按份收钱；RunPod 是「出租厨房」——按小时租给你一台带 GPU 的灶台，里面做什么、怎么做全由你。同一个需求「AI 生成一张图」，在这两家是完全不同的买法。

怎么用这篇 · 读完你应该能回答三个问题：① 同事说「这个模型跑在 RunPod 上」和「这个直接调 fal」时，两句话分别意味着什么；② 新的生成需求来了，该点菜还是该开火；③ 为什么我们的图像生成走 RunPod 自建、视频模型横评却用 fal。文中所有价格均为 2026 年 7 月官方牌价，以两家 pricing 页为准。
01

Section 01 · Two Ways to Buy

按结果付钱，还是按时间付钱

所有「AI 生成」的成本，最后都落在 GPU 上。区别只在于你站在离 GPU 多远的地方付钱：

fal.ai（模型 API 市场）

你调一个现成模型的 API，传入提示词，拿回图片/视频。按「每张图 / 每秒视频」计费。GPU、模型部署、扩缩容全部不可见——你买的是结果。

vs

RunPod（GPU 云）

你租一台带 GPU 的机器（或一个自动扩缩的容器），把自己的模型和工作流装进去跑。按「GPU 每秒 / 每小时」计费。生成什么、怎么生成全由你——你买的是算力。

这不是「谁更好」的关系，而是灵活性和省心程度的交换。往下每一层，你多担一层责任、也多拿一层控制权：

层次代表你负责平台负责
模型 APIfal.ai、Replicate写提示词、调 API模型、GPU、部署、扩缩容
Serverless GPURunPod Serverless、Modal打包自己的模型进 Docker 镜像GPU、按请求启停、排队
整租 GPURunPod Pods、Lambda、Vast.ai模型、环境、启停、利用率只管把带卡的机器交给你
似曾相识？· 这和 Fly.io 那篇讲的「全托管 PaaS vs 租 VPS」是同一个故事在 GPU 世界的重演：fal 之于 RunPod，约等于 Vercel 之于 Fly.io——只是这里租的机器上多了一块几万块钱的显卡，账单数字也跟着放大了一个量级。

Section 02 · What is fal.ai

一千多个生成模型的「统一点菜口」

fal.ai 自我定位是「面向开发者的生成式媒体平台」：把市面上的图像、视频、音频、3D 生成模型——官方口径超过 1,000 个——包装成同一套 API。FLUX、Kling、Veo、Seedance、Wan、Seedream 这些当红模型全在菜单上，一个账号一个 key，今天调字节的模型、明天换 Google 的，代码几乎不用改。

它不是小作坊：2021 年成立，2025 年 12 月完成 Sequoia 领投的 D 轮融资 1.4 亿美元，估值 45 亿美元——一年之内估值翻了三倍，是生成式媒体基建赛道目前的头部玩家。

按结果计费长什么样

图像按张（或按百万像素 MP），视频按秒。几个当前牌价感受一下量级：

工程侧的体验也是它的卖点：Python / JS 官方 SDK，所有模型天生支持异步队列 + Webhook 回调（提交任务立刻返回，生成完回调你的接口——长视频生成必须这么干），还有网页 Playground 让你不写代码先试效果。

三个容易误解的地方

「Serverless GPU」不是随开随用 · fal 的 pricing 页挂着 H100 $3.99/小时之类的 GPU 牌价，容易让人以为它也能像 RunPod 一样随开随用。实际上 fal Serverless 现在是企业客户申请制——个人注册后点进去是「Request Access」。对绝大多数用户，fal 就是一个模型 API 平台。
第三方模型含「中介费」· Kling、Veo 这些别家的模型经 fal 转售，价格通常高于去厂商官方直调。你多付的是「一个 key 调所有家」的聚合便利。量小、在横评阶段，这笔钱花得值；量大、模型已锁定时，直调厂商更省（下文第 5 章我们自己的迁移就是例子）。
预充值余额烧完，服务立刻停 · fal 是充值扣款模式。余额清零不是「降速」而是直接开始报错——生产链路挂它上面，必须把「余额监控」当成一个正经运维项。我们真实地被这个停过一次工。

Section 03 · What is RunPod

把带显卡的机器，按秒租给你

RunPod 自我定位是「AI Developer Cloud」：2022 年成立，2024 年拿了 Intel Capital 与 Dell 资本共同领投的 2000 万美元种子轮，2026 年 6 月又完成 Summit Partners 领投的 1 亿美元 A 轮，估值 10 亿美元，宣称开发者超百万、31 个地区有机房。它卖的东西很纯粹——带 GPU 的算力，主要三种形态：

形态它是什么适合
Pods整租一台 GPU 虚拟机，按需或抢占式（Spot），拿到就是你的训练、微调、交互式实验（开着 ComfyUI 慢慢调）
Serverless你交一个 Docker 镜像 + 处理函数，请求来了自动起 worker、按秒计费、没请求缩到零线上推理服务——我们的图像生成就是这个形态
Instant Clusters多机多卡集群，一键拉起分布式环境大规模训练，小团队基本用不到

另外还有两个新面孔：Runpod Hub（开源 AI 项目一键部署市场）和 Public Endpoints（RunPod 自己也开始卖现成模型 API 了——按调用付费，等于在自家厨房里开了个小餐厅，直接对标 fal 的生意）。

两个机房档位

RunPod 的卡分两池：Secure Cloud 是正经 T3/T4 数据中心的卡，给生产负载用；Community Cloud 是经审核的第三方算力主机（有点像「算力界的顺风车」），同卡便宜一到三成，但机器可能被中断——共识是实验用 Community，生产必须 Secure。

Serverless 单价比整租贵约六成，买的是弹性：按秒计费、空闲缩到零。像我们这种「一天几百张图、请求一阵一阵」的负载，Serverless 一个月几十美元；同样的活整租一台 4090 常开，一个月 $500 起步。存储另计：容器盘 $0.10/GB/月，Network Volume $0.07/GB/月。

冷启动的宣传与现实 · 官方宣传 FlashBoot「冷启动低于 200 毫秒」——那说的是容器本身。真实世界里你的镜像动辄十几 GB（模型权重占大头），第一次请求要等拉镜像 + 载模型，社区实测几秒到十几秒是常态，大镜像首次冷启动可达分钟级。设计链路时要按「首次请求很慢、热着以后很快」来预期，或花钱配常驻 worker。

Section 04 · The Landscape

什么时候点菜，什么时候开火

决策清单

  • 用现成模型、要结果、量还不大 → fal.ai 点菜。零部署成本，十分钟接通
  • 要横评多家模型选型 → fal.ai 一个 key 全试遍，别逐家开户折腾
  • 工作流是自己攒的（自定义 ComfyUI 节点、LoRA、私有 checkpoint）→ RunPod Serverless。菜单上根本没有这道菜，只能自己开火
  • 训练 / 微调 / 交互式炼丹 → RunPod Pods 整租，按小时开关
  • 模型已锁定、量大成本敏感 → 绕过聚合层：开源模型自部署摊薄成本，商业模型去厂商官方直调砍掉中介费

两家各自的邻居

平台和谁一个赛道一句话定位
Replicatefal 的直接对手社区模型生态最广（长尾模型多），但热度低的模型冷启动明显；fal 胜在快和「生成媒体」专注度
Together / Fireworks隔壁赛道同是模型 API，但主战场是开源 LLM 文本推理（按 token 计费），和 fal 的图像视频赛道错位
ModalRunPod Serverless 的对手纯代码优先的 serverless（Python 装饰器即部署），开发体验极佳，价格略高，不租整机
Lambda LabsRunPod Pods 的对手开箱即用的训练 VM，预装 PyTorch，研究向口碑好
Vast.aiCommunity Cloud 的对手纯 P2P 算力集市，全场最低价，机器质量看运气——RunPod Community 是它的「有审核版」
CoreWeave不同量级企业级 GPU 云（几十万张卡、InfiniBand），服务大厂大模型训练，不是小团队的选项
行情背景 · GPU 租赁是眼下竞争最惨烈的市场之一：H100 时租从 2024 年底的 $8–10 一路杀到 2026 年初专业云的 $1.5–2.5。这对用户是好事——也解释了为什么各家都在往上层「模型 API」卷（RunPod 开 Public Endpoints、fal 冲 45 亿估值）：卖裸算力越来越不赚钱，卖「结果」才有溢价。

Section 05 · How We Use Them

一个当厨房，一个当试吃摊

我们不是二选一，而是两家都在用，各干各的活：

场景用谁为什么非它不可
Softie 图像生成RunPod Serverless工作流是自己攒的 ComfyUI 镜像（SDXL / FLUX + 角色一致性节点，同一个虚拟角色反复出图），任何模型 API 菜单上都没有这道菜
视频模型横评fal.aiSeedance / Kling / Veo 多家旗舰同题对照选型，一个 key 全试遍，不用逐家开户充值
锁定后的量产厂商官方直调横评定下模型后，SFW 图像量产迁到了字节火山方舟官方 API——同款模型比走聚合层便宜

这三行连起来正好是一条「探索 → 锁定 → 降本」的路径：探索期用 fal 低成本试遍所有选项；需求非标就在 RunPod 自建；需求标准且量大了,就绕过中介直连厂商。聚合平台最大的价值在探索期，它挣的就是你「还没想清楚用哪个模型」时的钱——这没什么不对，但想清楚之后要记得重新算账。

工程形态上，我们的 RunPod 链路是：模型权重直接烘焙进 Docker 镜像（约 27GB）→ 推到镜像仓库 → RunPod Serverless 拉起 worker → 工作流引擎异步提交任务并轮询结果。0–2 个 worker 按需启停，闲时费用趋近于零。

Section 06 · Lessons Learned

这些坑我们都真实踩过，你不用再踩一遍
RunPod：Serverless 挂 Network Volume 不可靠 · 教科书方案是「模型放共享网络盘，镜像做小」。我们在三个地区反复实测：endpoint 一绑 Network Volume，worker 就随机性起不来；解绑立刻正常。团队铁律：Serverless 一律把模型烘焙进镜像，镜像大点（27GB）没关系，稳定压倒一切。
RunPod：更新镜像必须用 digest，别信 latest · 推了新镜像、endpoint 却还在跑旧代码——因为 latest 标签有缓存。必须用 镜像名@sha256:… 指定唯一版本，并且改完模板要重新保存 endpoint、等旧 worker 过期，新冷启动的 worker 才拉新镜像。「推上去了」不等于「跑的是新的」。
RunPod：改了配置，老 worker 不会自动刷新 · 修改 endpoint 配置后，已经热着的 worker 继续按旧配置跑。要强制生效：先把最大 worker 数调成 0 逼停所有旧 worker，再调回来。和上一条同源——控制台显示的配置和线上真实状态是两回事，以后者为准。
RunPod：两个域名各管一套 API · api.runpod.ai 管任务调用（提交 / 查状态），api.runpod.io 管资源管理（GraphQL）。用错域名返回 404，报错信息完全看不出是域名的问题。排查任务失败时，先用「列出最近任务 → 查单个任务详情」两步拿到真实报错，别瞎猜。
fal：把余额监控当成运维项 · 预充值余额烧完服务立刻报错，没有缓冲。接进生产链路的那天，就要把「余额低于阈值告警」配上——我们是被真实停工教育后才补的课。
fal：模型各有各的「隐形门槛」· 同在 fal 菜单上，各家模型的内容政策不同。例如字节 Seedance 内置真人人脸检测：拿真实照片当参考图会直接被拦（返回 face detected），AI 生成的人像则能通过。选型横评时把这类政策差异当成和「画质、价格」并列的正式评测项，别到量产才发现走不通。
通用：异步是必修课 · 视频生成动辄几十秒到几分钟，同步等结果的 HTTP 请求必超时。fal 的队列 + Webhook、RunPod 的提交 + 轮询，本质都是「先拿号、后取餐」。接任何生成类 API，第一天就按异步设计，别先写同步版再返工。
fal.ai 卖的是做好的菜，RunPod 租的是带灶的厨房——试菜阶段尽管点，独门配方就得自己开火，而吃定了一道菜时，记得去找灶台的主人谈个批发价。
