Caveats

风险与坑

以下每一条都对应表格里至少一处朱红提示，是调研过程中实际核到的，不是泛泛的免责声明。

许可传导比想象中深

金融 LLM 几乎全是 Llama 2/3 微调，基座许可跟着走；有个人作者把 Llama-3.1 微调标成 Apache-2.0，存在冲突。HF 上 8 个高下载模型根本没填 license 字段，ProsusAI/finbert 只能回 GitHub 仓查。

评测基准多为非商用

方法、口径与局限

抓取时间
2026-09-06，四路并行抓取，星数与下载量均为当时快照。
GitHub
先用 search/repositories 跑 48 组关键词（backtesting、quant、trading bot、LLM finance、金融大模型 等），再对 170 余个候选仓库逐个 repos/{owner}/{repo} 直查星数、许可、最近 push、archived 状态；README 用于核定位与论文链接。
Hugging Face
用 /api/models、/api/datasets、/api/spaces 按关键词与作者定向搜索，再逐个取 downloads（30 天）、likes、license、lastModified。中文关键词在 HF 站内搜索无效，中文资源按作者定向补齐。
活跃度
按最近一次 push 距今天数：<6 个月活跃、6–18 个月放缓、>18 个月或已归档记停更。这是仓库层面的信号，不代表 PyPI 包或服务端状态（tushare、backtrader 即为反例）。
证据档位
A = 有论文且模型卡 / 数据卡完整；B = 卡片完整但无论文；C = 只有权重或几乎空白的说明。GitHub 项目不单独分档，以 README 与许可字段为准。
局限
① 收录以星数与下载量为主要入口，小众但高质量的项目可能漏掉；② HF 下载量对 LoRA 与走 GitHub 分发的权重严重低估；③ 未做任何回测复现，所有关于「效果」的判断都来自项目自述与社区讨论；④ 许可判断基于 API 返回字段，NOASSERTION 的自定义条款需逐个读原文。
