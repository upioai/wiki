Claude Tag · 把 Claude 拉进 Slack 当队友

不再是"打开网页问它一句"，而是让 Claude 常驻在你们的 Slack 频道里——@ 一下就接活，干不完会自己接着干，没人跟进的事它还会主动提醒。

跑在 Opus 4.8 面向 Enterprise / Team beta 研究预览 旧 Slack 应用 8/3 切换

一、Claude Tag 是个啥？

过去我们用 Claude，是"我打开一个对话框，问它，它答我，结束"——它是个工具，每次都得我主动去找它。

Claude Tag 把这件事彻底翻了个面：你把 Claude 请进 Slack 频道当成员，给它授权能用哪些工具、看哪些数据（甚至代码库）。之后频道里任何人 @Claude 一下，就能把活派给它，自己该忙别的忙别的，它在 thread 里把结果交回来。Anthropic 把它定位成 "Claude Code 的一次演进"。

就像团队来了个新同事 🧑‍💻
你不会每次都"打开同事 App 问一句"。他就坐在群里：你 @ 他派个活，他自己拆步骤去做；做到一半你下班了，另一个同事能接着往下做；有件事拖着没人管，他还会主动冒泡提醒。
—— Claude Tag 想做的，就是从"一个你要去用的工具"变成"一个待在群里的同事"。

它会替换掉旧的 "Claude in Slack" 应用，2026 年 8 月 3 日正式切到 Claude Tag 体验，给 30 天迁移窗口。

二、它和以前的 Slack 机器人有啥不一样？

Slack 里早有各种 bot，为什么这个值得专门讲？因为它在四件事上跟传统 bot 根本不是一类东西：

1
多人共享「同一个」Claude 一个频道里只有一个 Claude，和所有人交互。谁都能看到它正在干什么，也能接着上一个人的进度往下做——官方叫它 "multiplayer / @Claude is multiplayer"。不是每人一个互不相通的私聊。
2
有记忆，而且按频道隔离 它会在频道里慢慢记住相关信息，授权后还能从别的频道/数据源学。但记忆严格锁在管理员划定的频道范围内——销售频道的 Claude 不会把记忆串到工程频道。
3
会「主动」冒泡（ambient 模式） 传统 bot 你不戳它就不动。开启后的 Claude Tag 会主动把它觉得你该知道的信息抛给你、追那些没人跟进、悬着没解决的 thread / 任务。
4
能异步自治，连干几小时甚至几天 派给它一个任务你就能走开，它把任务拆成阶段逐步推进；还能给自己排期，把一个项目自主推进数小时到数天，而不是一问一答完事。

三、日常怎么用它？

核心动作就一个：在频道里 @Claude，用大白话把活说清楚。它接到后的流程是：

① @Claude 提需求 → ② 它把任务拆成步骤 → ③ 用连接的工具/数据干活 → ④ 在 thread 里交结果

三种入口：

  • 频道里 @Claude —— 派活给"共享的那个 Claude"，全频道可见、可接力。
  • 私聊 DM —— 想要私密回答、用你个人的工具和连接器时，单独私信它。
  • AI 助手面板 —— Slack 顶部 AI 助手区里的 Claude 图标。
提示：非管理员在公司 Slack 里通常需要管理员批准才能装；可以在 Slack 应用市场里向管理员发安装申请。

四、关键特性一览

共享单一身份一个频道一个 Claude，全员协作、随时接力。
频道隔离的记忆越用越懂你们的活，但记忆不跨界泄漏。
Ambient 主动模式主动提醒、追悬而未决的事，不用你催。
异步自治能自排期、连干数小时到数天。
接工具·数据·代码库授权后能调你们实际在用的系统去干活。
Opus 4.8 驱动底座是目前的旗舰模型。

五、管理员怎么开通 + 安全边界

这部分对团队尤其重要——谁能开、花多少钱、数据会不会串，都在管理员手里。官方给的是四步：

配对 —— 把 Claude Tag 和你们的 Slack workspace 绑上。
授权工具 —— 指定它能用哪些工具、看哪些数据，按频道分别配（等于给不同用途建不同的 Claude 身份）。
设每月预算上限 —— 给组织设 token 花费上限（可按组织 / 按频道分别限）。
私有频道先测 —— 先在一个私有频道里试，跑顺了再铺开。
安全要点：权限按频道精细控制；有活动日志记录 @Claude 干过的每一件事、以及是谁派的活；敏感数据和工具能被锁得很死；私有频道的内容不会跨范围外泄。面向 Claude Enterprise / Team 客户，beta 阶段有启动额度。

六、对我们团队意味着什么？

用对了，它能把"群里那些拖着没人管的事"和"重复的查数/跑活"接过去。但用法上有个常见误区：

✗ 当成"群里的一次性问答机"

@一句问完就走，不给它授权工具、不开记忆和主动模式——那它和你自己开网页问 Claude 没区别，白瞎了"常驻队友"这层价值。

✓ 当成"能持续盯事的队友"

给它接上真用的工具/数据，让它在频道里长期积累上下文、主动追进度、把多步任务自己跑完。同一个模型，挂进这套协作循环里，产出天差地别。

一个数字 👉 在 Anthropic 内部，产品团队 65% 的代码由他们内部版的 Claude Tag 生成；这套用法还扩散到了工程之外——追产品指标和数据、处理支持工单、帮忙定位棘手 bug 的根因。这正是我们可以照着搬的几类场景。

目前只在 Slack 上；Anthropic 说目标是扩展到团队工作的更多地方。我们这种重 Slack 协作的小团队，是它的典型受益对象。
