B-roll 镜头获取系统 · 运转全景图

数据核实时间 2026-08-04 · 仓库 WorkflowUP/Workflow · 所有路径均为本机真实路径，可直接调取

一句话：让人说一句口播文案，机器立刻找出能配的画面。
打个比方：这就是一座图书馆。入库线是把一车车的书（下载来的装修视频）拆开、编目、贴标签、上架； 出库线是借书台——你说一句「我要讲瓷砖崩边」，管理员去架子上把对得上的那几本抽出来给你。 中间那本总目录就是 broll.db，两条线只通过它对话。
为什么要做：之前的痛点原话是——文案在讲瓷砖崩边，画面配的却是刷墙。

二、全景图：一段素材的一生

左边是入库线（把素材变成能被搜到的东西），右边是出库线（把一句口播变成一段画面）。 两条线互不通气，只通过中间的 broll.db 交接。

把标注文字编码成 512 维向量存进库。本地 bge-small-zh 模型，零 API 费用，全量约 7 秒。 增量：靠 embed_hash 比对，标注改了才重算

出库线 一句口播 → 一段画面
① 拿到配音时间轴
复刻生产跑完 TTS 与强制对齐后的产物，逐行对应稿件

② 生成需求骨架
每句一行，翻译字段留空写 TODO

③ 人填「翻译」 没有自动挡
把口播从「讲述」翻成「描述」：
「先用保护条盖住」→「墙角贴着白色塑料护角条，覆盖整条阳角」
刻意不自动写——自动生成的正是套壳写法那种错（正确率 27%），人写后是 100%
visual_level / shot_function / desc / search_query
④ 检索 生产入口
纯向量召回 + 及格线 + 自动记两本账。60 句约 20 秒，CPU 推理（把 MPS 让给标注进程）

⑤ 出片段 + 拷贝切片
产出 produce_replica.py 认识的 {"type":"broll", …}， 同时把选中切片复制进工作目录 broll/——素材库在外接盘，合成时盘可能已经拔了
broll-plan.py emit --found … --out broll-segments.json
⑥ 人工画面复核 不可省
两件事机器保证不了：分数高 ≠ 对题（最高分 0.760 那条，要浅色地砖给了深色）； has_face 标注不可信，必须在最终处理链上逐帧扫
audit_broll.py · gate_faces_yunet.py
⑦ 回填战绩 用完必做

broll-retrieve.py --record-choice --outcome used_good|used|rejected

三、出库线细节：broll-retrieve.py 里到底发生了什么

0. 先确认素材库挂着
素材实体在外接盘的稀疏映像里，本机只有 db 和一堆符号链接。映像会自己掉线（盘休眠、误卸载）， 而 db 还在——于是检索照常给候选，clip_path 却全打不开。 检索给了路径就等于承诺文件能打开，做不到就当场拒绝（exit 2）
check_library_mounted() 探针：$LIB/_clips 存不存在
1. 取候选池
SQL 取 approved=1 且 embedding 非空，并再次排除正脸 / 水印 / 黑名单 / 待删除—— 放行公式可能改，这里不假设它永远正确。当前池子 3,677 段
load_pool() · segments JOIN clips ON rep_clip_id
2. 需求编码
所有查询一次性编码（避免每句重载模型）。bge 系列要求查询加指令前缀、文档不加， 必须与 build-embeddings.py 一致，否则查询和文档落在向量空间的不同区域
BAAI/bge-small-zh-v1.5 · CPU · QUERY_PREFIX
3. 余弦相似度 + 战绩微调
矩阵点积一把出全部分数。回头客本的战绩每分只 ±0.01——刻意做小，不能盖过语义相似度本身 （used_good +2 / used +1 / rejected −2）
mat @ qvec + 0.01 × experience
4. 按镜头功能过滤（池子太小就放弃）
目标类少于 50 段时自动不过滤。第二轮踩过的坑：库里 problem 类只有 1 段， 硬过滤导致同一段垃圾候选被反复顶到 top-1
MIN_POOL_FOR_FILTER = 50
5. 打散
同一条源片最多出 2 段、同一 sibling_group 只出 1 段。 没有这个，top-3 经常是同一镜头的三个相邻窗口——看着有三个选择，其实只有一个
diversify()
6. 及格线裁决
向量检索天生的毛病是永远能排出个第一名，哪怕库里根本没有合适画面。 本模块不承诺挑出好的，只承诺拦掉铁定不行的
retrieval_gate.apply_gate()
7. 自动记两本账
缺货本：报 no_match 或弱命中就写一条，同一需求幂等只记一次，重跑不灌水。
回头客本：系统给过什么先留痕（served），人事后回填 used/rejected 时以此为对照基线。 主键由「片子+口播+段+outcome」决定，重跑覆盖同一行
gap-log.jsonl（素材库根）· match_experience 表

及格线三档是怎么定的（不是拍脑袋）

用 2026-08-03 两轮真人判卷的 105 个候选标定。定义在 retrieval_gate.py。

相似度 < 0.52 → 报缺货
该档「不能用」占比 100%（6/6，零误杀）。不返回候选，直接记缺货本
0.52 ~ 0.62 → 标 weak
该档「不能用」占比 78%。返回但打标，提示人工过目；emit 默认不采用，除非加 --accept-weak
≥ 0.62 → 标 normal
该档仍有 71% 不可用——这不是及格线能解决的，根因在素材覆盖与标注信息量
为什么三档都不够准？人判断时看的是画面，而这些方法都在读标注文本。 一段 3.5 秒画面压缩成五十字标注后，「能不能用」所依赖的信息已经丢了。 正确的下一步是让视觉模型看图精排（召回 top-N → 看图），而不是继续在文本层面找阈值—— verdict 已留 pending_visual 档位供接入。

五、脚本速查：跑什么、什么时候跑

日常生产（复刻一条片子时按顺序跑）

# 0. 开工先看素材库还挂着没（每次都要）
bash scripts/broll-library/mount-broll.sh status

# 1. 从配音时间轴生成需求骨架
python3 scripts/broll-library/broll-plan.py init \
    --align align.json --script script.txt --out needs.json

# 2. 人工逐句填 visual_level / shot_function / desc / search_query（没有自动挡）
#    章节总起句一律填 none；「不要A要B」拆成两个 shot

# 3. 检索（自动记两本账）
python3 scripts/broll-library/broll-retrieve.py \
    --needs needs.json --video 片名 --output found.json

# 4. 产出 storyboard 片段，切片同时复制进工作目录 broll/
python3 scripts/broll-library/broll-plan.py emit \
    --found found.json --needs needs.json --out broll-segments.json --workdir .

# 5. 人工画面复核（不可省）
python3 .claude/skills/douyin-replica/scripts/audit_broll.py …
python3 .claude/skills/douyin-replica/scripts/gate_faces_yunet.py …

# 6. 用完回填战绩
python3 scripts/broll-library/broll-retrieve.py --record-choice \
    --video 片名 --shot s01 --chosen <segment_id> --outcome used_good --reason "理由"

维护与评测

# 标注改过之后重算向量（增量，改了才算）
python3 scripts/broll-library/build-embeddings.py          # --all 全量 / --check 只体检

# 常设考卷：任何改动前后都跑，60 句永不更换，只换检索器

八、几个必须知道的坑

  • 素材库映像会自己掉线。db 还在、检索照跑、路径全是死的。所以每次开工先 mount-broll.sh status。
  • 翻译没填完不许往下走。emit 见到 TODO 直接 exit 2——套壳需求生成的候选，看着有结果其实全是错的。
  • 跨镜头去重是硬需求。检索逐句独立跑，两句语义相近会拿到同一段（实测「水泥腻子灌进底盒」和「水泥砂浆封线槽」md5 一致）。 成片里就是同一画面播两遍，而每句单看都「有候选」、指标全绿。
  • has_face 标注不可信。过滤后的候选里照样有人入画，且可能正是被复刻那位博主本人。B-roll 出现人物是红线，必须在最终处理链之后逐帧扫。
  • 被复刻的源片可能就躺在库里。越对题的候选越可能是原片自己——出库四规矩里的「复刻谁躲开谁」就是防这个。
  • 分数高 ≠ 对题。最高分 0.760 那条，需求是「要浅色地砖」而画面是深色地砖。画面复核这步没有替代品。
