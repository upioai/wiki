结论：一站式平台出片最快，但难自动化接进自有 pipeline、控制粒度低。适合先用来验证"AI 剧情片能不能打"，不适合做要的高产能矩阵化流水线。

3跨镜头人物一致性工程

这是"多镜头剧情片 vs 单镜口播"的技术分水岭。三条路线，从易到难：

  1. 可灵 @Element 体系（推荐）：多张角色参考图显式绑定身份，API 支持逐镜独立 prompt + 自定义时长，单次可产最多 6 个共享音轨的连续镜头。原生解决，工程量最小。6
  2. Seedance @-reference：单次调用喂 9 图+3 视频+3 音频，prompt 里用 Shot 1:/Shot 2: 分镜，靠 video extension 做首尾帧衔接。fan-in 最宽，但无 Kling 那样的 element 角色系统。2
  3. 参考图先行 + 图生视频（最通用）：先用即梦角色锁定 / Midjourney --cref 固定主角形象 → 逐镜 image-to-video → ffmpeg 拼接。

现成 n8n 模板（可直接导入，接现有 n8n + RunPod 仓）：

  • n8n #3121：OpenAI 写脚本 → Flux 生分镜图 → Kling 图生视频 → ElevenLabs 配音 → Creatomate 合成。骨架可复用，但模型选型偏旧、纯旁白无对白口型。8
  • n8n #7964：Gemini 分镜 → fal.ai 生图变体 → Wan 动画化 → 带转场合成。
  • 自托管备选：ComfyUI Base/Extend 子图链式复用 previous_frames，对应 RunPod GPU 仓，是闭源 API 之外的降本路线。

6合规红线（真正的一票否决项）

6a. 抖音自然流（矩阵号）—— 义务明确，可自动化

  • 自 2025-09-01 起，发 AI 内容必须主动声明：发布界面 高级设置 → 发文助手自主声明 → 内容由 AI 生成13
  • 不主动标 → 平台机检强制补标「疑似使用了 AI 生成技术，请谨慎甄别」（措辞更难看）+ 可能限流
  • 元数据可用 ffmpeg 直接写入（接现有合成环节）14：
ffmpeg -i in.mp4 -map_metadata -1 -c copy -movflags +use_metadata_tags \
  -metadata aigc='{"GeneratingTool":"...","Timestamp":"...","ContentID":"..."}' \
  -f mp4 -y out.mp4

显式水印样式固定：文本「AI 生成」，4*20@1x（375*812 基准按比例放大），不可自定义。

6b. 千川广告投放 —— 两条红线可能直接毙掉"全 AI 剧情片"

⛔

红线 1 —「不得使用难以核实/无法核实的人设做推荐证明」（千川规则速递条目15）：AI 虚构的"业主/设计师"讲装修效果见证，若被判定为虚构人设做背书，直接违规。这是"踩坑→反转→效果展示"套路的核心风险点。

红线 2 —「营销内容中不得涉及不当使用 AI 功能或误导性描述」（2026-01-16 新规）+「商品信息虚假误导专项治理」（2026-06-15）：AI 生成的装修"效果展示"镜头（非真实交付的渲染画面）若被判虚假误导，落入治理范围。

  • 巨量 2025-10 起上自研 AI 治理大模型，机检识别 AI 人脸/配音/换脸痕迹，且必须在素材描述明示；"条文法"识别，靠微调绕审空间被压缩。16
  • 处罚三档递进：暂停投放 → 封号 → 永久拉黑公示。
  • 2026-06-17 升级肖像授权机制——全 AI 生成的"真人"是否需肖像授权/是否豁免，是必须向千川客服核实的盲点，公开侧查不到答案。15
🔍
重要发现：截至 2026-07-10，千川规则中心首页整页 HTML grep "AIGC" 命中 0 处——即抖音的 AIGC 标识义务并未在千川广告规则里独立成章。所以广告审核口径要另找巨量广告审核侧/抖音安全中心核实，别把内容侧规则当广告侧规则用。
✓
合规打法：把 AI 人物明示为"剧情演绎/情景短剧"而非真实客户证言，规避"虚构人设做推荐证明"红线；效果展示用真实案例素材或明确标注为示意；投放前拿一条样片走千川送审试水。

7落地 PoC + 决策矩阵

推荐主路线：可灵 Kling 3.0 官方 API + n8n + 现有 ffmpeg 合成层

为什么是它：中文对白口型全球顶级 + 官方人民币透明定价（¥1.2/s）+ 国内直连不用翻墙 + @Element 原生角色一致性 + 逐镜 prompt 控制——四项全中场景。

STEP 1

注册

可灵开放平台开 API 账号，充值资源包（¥ 积分制，1 积分=¥1）。备一个 fal.ai 账号做 Seedance 对照。

STEP 2

脚本层

复用 Akke 现有 LLM 层（src/lib/llm.ts）写"铺垫→转折→揭秘"三段装修剧本 + 分镜 prompt，不用新接模型。

STEP 3

角色锚定

即梦角色锁定或 Midjourney --cref 出 2–3 张主角参考图。

STEP 4

逐镜生成

n8n 编排（复用 #3121 骨架，模型换成 Kling 3.0）→ @Element 绑角色 → 3×10s 图生视频有声镜头。

STEP 5

合成 + 打标

Fly worker ffmpeg concat + 写 aigc 元数据 + 烧「AI 生成」水印（复用现有 worker/services/video_gen.py 合成接缝）。

STEP 6

合规送审

先发 1 条到抖音矩阵号（自主声明打标）验自然流；再拿 1 条走千川送审验广告口径。

STEP 7

算账

记录抽卡次数算真实重 roll 系数，校准单条成本。

8跟历次调研的差异

本次专门针对上几轮"不满意"的三个点重做：

  • 不落地 → 给了具体 API 入口、人民币按秒价、ffmpeg 打标命令、可导入的 n8n 模板编号、7 步 PoC 清单。
