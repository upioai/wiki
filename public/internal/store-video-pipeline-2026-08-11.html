05
Claim Gates · Optimistic Lock

两台机器为什么抢不到同一单

一次认领要过六道闸；最后一道 CAS 乐观锁保证并发下只有一台命中一行。

闸一
排空 排空开关打开时回 503——部署前只挡新认领，不打断在产的单
闸二
稳定 ID claim_id 必须是产线自带的稳定 UUID，落在工作目录里——响应丢了也能凭同一 ID 幂等取回，不生成第二个付费 operation
闸三
撞牌 已有活 claim：同 ID 回 already:true 安全重试；异 ID 一律 409「已被另一台认领」
闸四
状态 只放行 queued / running / revision_requested 三态，其余 409
闸五
预算 fal 预算余额 ≤ 0 → 409 budget_exceeded，钱闸先于开工
闸六
CAS patchIfUpdated 按读到的 updated_at 条件更新——两台同时抢，只有一台命中 1 行，另一台拿 409 重新拉队列

// 认领刻意不写 heartbeat_at——心跳是产线声明「我说新协议」的唯一凭据，代写会让老单 5 分钟后被误杀。
// 心跳走独立通道 touchHeartbeat，只写一列、不推进乐观锁令牌——否则 60s 一次的心跳会把耗时几十秒的 deliver 撞成 409。

第一层CAS 乐观锁

updated_at 是全仓唯一写令牌，同一毫秒也严格 +1ms 前进。

第二层号牌绑单不绑机

同一把 key 可同时持多张号牌（云端多灶位）；同单换 ID 再领必 409。

第三层心跳即对账

claim 失配的心跳回 409——daemon 收到就杀掉本地会话，让出机器。

07
Failure Isolation · Self-Healing

单卡死了，页面说得出卡在哪

「假 15%」教训之后：进度是最后一笔写入的遗照，不是状态——判活只认心跳，判死才敢重排。

判死规则心跳静默 > 5 分钟

running 且发过心跳的单才判；无心跳一律不判——秒退会话曾挂满 12h 租约，这是实测换来的边界。

第二层原地续跑 --resume

会话崩了不换认领：claude --resume 接着跑，最多 2 段，共享 3h 死线——换认领是付费链倒下的第一张骨牌。

失败分类12 类 error_code

日志尾巴按序匹配：余额先于泛错、鉴权判 block 不判 fail；heartbeat_lost 只许看门狗写，产线自报 403。

让出机器claim 就地过期

判死时把租约当场作废——吊死会话的下一次心跳拿到 409，daemon 据此杀会话，队列不再被堵。

08
Review · Two Ways Back

审片：一个入口，两条回头路

「今日待审」是选定与返修在全仓唯一的界面入口；打回分两条路，产物、预算、状态流转都不同。

路一 · FEEDBACK定向返修（原单）

老板点「有问题」：勾缺陷 + 播放器真实时间打点 → 同一次乐观锁写 revision_requested。预算封原单成本 30%，最多 2 轮；产线领走后回填「这一版改了什么」。

路二 · REVISE整片重做（新单）

成片屏「要改」：新开一条单、parent_job_id 指回、版本 +1，重新固化资产快照不抄旧的。重新拿一份完整预算；看板按血缘折叠多版。

动作做什么前置
watched看完自动上报，页面不能自己置位video onEnded
human人工 5 项清单逐项勾选写 qc_checks已看完
select选定 → done + 发下载；SHA+ETag 复验对象没变只过机器闸

诚实性取向

「选定」刻意不拿人工清单当门槛，下载与预览同条件——用胁迫换来的反馈是假反馈，「能看不能存」的闸也挡不住录屏。

10
Discipline · Known Gaps · Stack

钉死的纪律、已知的暗缝

PINNED钉死的纪律

  • 落库再交接：崩了从状态捡起来重跑
  • fail-closed：缺 key 503、缺列 503、缺快照不开工
  • CAS 唯一令牌，心跳单独通道绕行
  • 取料只发快照内 key，越权进 denied 不静默
  • s3 地址永不出 Store，只发短时票据
  • 状态值域只放宽不收窄，测试读 SQL 钉死

GAPS已知暗缝

  • 取料端发 storage_keys、路由读 keys——每次落进全量重签分支
  • DDL 未跑时 attempt 闸空转 = 无限重排
  • LLM_API_KEY 未配，7 条过模型路径必失败
  • 旧线素材名查错列，上线以来零成功（已修）

REDLINE破例与红线

  • video_jobs 不进迁移链：多实例无共享磁盘，本地队列=各记各的账
  • SQL 只许追加幂等语句、只碰这一张表
  • 版权红线：客户单只用门店自有素材与可商用授权素材
