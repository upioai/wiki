需求文档：开场白昵称标准化与按意向类型匹配话术

打招呼（开场白）话术的两处改进：把昵称称呼标准化、按评论意向类型匹配不同话术模板。

优先级 P1 状态 待办 内部资料 · 不公开索引

1. 需求名

优化打招呼话术的昵称标准化与个性化匹配

2. 优先级 / 状态

P1 / 待办

3. 背景与目的

当前打招呼话术存在两个问题：

  • 昵称处理粗糙：昵称捕捉不准确，性别定位模糊，导致称呼不当（如对男性用户称呼"姐"）
  • 话术缺乏个性化：未根据用户评论的意向类型（知识型/产品型/分享型）匹配差异化话术，回复转化率低

目的：通过标准化昵称处理（性别清晰化）+ 意向分类匹配，提升打招呼的精准度和用户回复率。

4. 应用场景

  • 谁：AI 话术生成模型（generateOpener 函数）
  • 在哪：/api/cron/analyze 中调用话术生成时
  • 做什么：
    1. 解析用户昵称，判断性别，输出标准化称呼（"姐"/"哥"/跳过）
    2. 根据评论意向分类（knowledge/product/share），匹配对应话术模板
    3. 组合输出：称呼 + IP地域 + 视频细节 + 分类话术
  • 不做会怎样：称呼错误导致用户反感，话术千篇一律导致回复率无法提升

5. 输入与输出

项目说明
输入profiles.nickname（用户昵称）
profiles.gender（性别，如有）
profiles.ip_location（IP地域）
comments.content（评论内容）
comments.video_tags（视频标签）
comments.comment_type（A-1分类结果：knowledge/product/share）
输出message_queue.opener_text（最终打招呼话术）
message_queue.opener_components（jsonb：{称呼, 地域, 视频细节, 话术类型}）

6. 与现有系统关系

组件关系
profiles 表读取：nickname、gender、ip_location
comments 表读取：content、video_tags、comment_type
generateOpener 函数修改：增加昵称标准化 + 话术匹配逻辑
A-1 意向度三分类依赖：需要 comment_type 已分类

7. 业务规则与边界

7.1 昵称标准化规则

情况处理方式示例
昵称明确女性特征称呼"姐""小美" → "小美姐"
昵称明确男性特征称呼"哥""大伟" → "大伟哥"
昵称性别模糊跳过称呼，直接说"你好""天空" → "你好"
昵称为纯数字/符号跳过称呼"123456" → "你好"
gender 字段已存在优先使用 gender 字段gender=female → "姐"

性别特征词库：

  • 女性特征：姐、妹、妈、姨、婷、娜、丽、芳、燕、花、草、萌、甜、软、糯
  • 男性特征：哥、弟、叔、伯、伟、强、刚、军、杰、龙、虎、猛、硬、酷、帅

7.2 话术匹配规则（基于 comment_type）

comment_type话术模板核心要素
product「{称呼}，看到你在问{视频细节}，我们{IP地域}这边最近好多业主也在关注这个，{品牌/价格信息}，方便加微信发你详细方案吗？」直奔主题，给价格/品牌信息
knowledge「{称呼}，你问的{视频细节}确实关键，我们整理过一份{相关知识}，{IP地域}这边业主反馈很实用，要不要发你参考？」先给专业答案，再引导
share「{称呼}，你家{视频细节}做得真好看！{IP地域}这边刚完工一个类似案例，业主很满意，加微信发你看看？」赞美共鸣，轻引导
注：{品牌/价格信息} 只填本方已核实的当期信息，不写其他品牌名，也不写未经核实的促销口径。

7.3 视频细节提取

从 video_tags 或 comments.content 中提取：

  • 装修风格（现代简约/北欧/中式）
  • 空间类型（客厅/卧室/厨房/卫生间）
  • 材料/工艺（瓷砖/地板/全屋定制/封边）

8. 历史数据处理

  • 不回填：只对新生成的 opener 生效
  • 已发送的 message_queue 记录中 opener_components 保持 NULL
  • 不对已发送话术做 retroactive 校验

9. 验收标准

数据验证：

-- 昵称标准化覆盖率
SELECT
  count(*) FILTER (WHERE opener_components->>'称呼' IN ('姐','哥','你好')) AS standardized,
  count(*) AS total,
  round(standardized * 100.0 / total, 1) AS coverage_pct
FROM message_queue
WHERE created_at > '2026-05-07' AND opener_text IS NOT NULL;
-- 期望：coverage_pct = 100%

-- 性别判断准确率（人工抽检）
-- 抽检 100 条，性别判断准确率 ≥ 90%

-- 话术类型匹配率
SELECT comment_type,
  count(*) FILTER (WHERE opener_components->>'话术类型' = comment_type) AS matched,
  count(*) AS total
FROM message_queue
WHERE created_at > '2026-05-07'
GROUP BY 1;
-- 期望：matched / total ≥ 95%

北极星指标：打招呼回复率较基线提升 ≥ 15%，A/B 测试样本量 ≥ 500 条。

10. 不做什么

  • ❌ 不修改昵称存储逻辑（只读取，不写入）
  • ❌ 不强制要求所有昵称必须有性别（模糊时跳过）
  • ❌ 不回填历史 message_queue 数据
  • ❌ 不做前端 UI 展示（opener_components 仅用于后端分析）
  • ❌ 不做复杂的 NLP 性别识别（只用特征词匹配）
