消息完整流转流程
从用户发送到系统回复，每个节点的输入、决策逻辑和输出结果。
01
社交平台消息产生
用户在小红书（一期）发送评论或私信 → 平台通过 Webhook 推送消息事件到系统接收端点。
关键设计：系统收到Webhook后立即返回200，消息推入Redis队列异步处理，避免平台超时重推。
触发：消息入队
02
消息标准化 & 去重
Platform Adapter 解析原始消息体 → 标准化为内部 MessageDTO（含 tenant_id, platform, msg_type, content 等字段）→ 基于 msg_id 幂等去重（Redis SETNX），防止平台重复推送导致重复回复。
输出：标准化消息
03
黑名单过滤
检查用户ID是否在黑名单（Redis Set，O(1)查询）。
命中 → 静默忽略，记录日志，不进行后续处理。未命中 → 进入下一步。
黑名单来源：运营人员手动添加（营销号、骚扰用户等）。
命中：静默忽略
04
敏感意图识别
规则引擎扫描消息内容（多类敏感词库 + 正则模式）识别6类敏感意图：急症求助 / 疾病诊断 / 用药建议 / 投诉纠纷 / 隐私信息 / 强烈负面情绪。
命中急症类 → 直接发安抚模板B（含急诊电话）+ 转高优先级人工队列。
命中其他敏感类 → 发安抚模板A + 转人工队列（按类型分优先级）。
命中：转人工队列
05
工作时段判断
查询当前租户配置的工作时段（支持多时段、节假日配置）。
工作时段内：敏感消息实时推送WebSocket通知到在线运营人员。
非工作时段：已匹配到高置信度FAQ → 仍可自动回复；低置信度 → 发安抚模板 + 标记次日处理。
输出：时段标记
06
FAQ 语义匹配
① 调用 Embedding 服务将用户消息向量化（BGE-M3，约20ms）
② 在 ChromaDB 中按 tenant_id + Collection 检索 Top-3 候选FAQ（约10ms）
③ 返回每个候选的相似度分数（0-1）
④ 取最高分与阈值比较。全程约 30-50ms。
输出：Top-K + 分数
07
置信度路由判断
最高分 ≥ 0.82（自动回复阈值）且 FAQ敏感等级=0：→ 进入自动回复生成。
0.65 ≤ 最高分 < 0.82（候选提示区间）：→ 转人工，附Top-3候选FAQ供参考，发兜底安抚。
最高分 < 0.65（低置信度）：→ 转人工，仅发安抚模板，不附候选。
FAQ敏感等级=1：→ 无论分数，生成后需人工审核确认再发布。
FAQ敏感等级=2：→ 强制转人工，不自动回复。
高分: 自动回复其余: 转人工
08
回复内容生成
① 取最匹配FAQ的标准回复 / 平台定制回复
② 套用平台语气模板（前缀/后缀/Emoji规则）
③ 合规过滤：扫描敏感词库（诊断/疗效/处方/价格），命中则降级到安抚模板
④ 字数校验并截断（各平台上限不同）
⑤ 将生成内容写入「待发布」队列
输出：回复内容
09
平台回复发布
Platform Adapter 调用对应平台 API 发布回复。失败重试（最多3次，指数退避）。
发布成功 → 写入日志（含 operator_id=system, handle_type=auto_reply）。
发布失败（平台API异常）→ 告警 + 转人工队列 + 不计工作量。
输出：已发布回复
10
日志记录 & 工作量归因
写入完整日志（MessageLog表）：原文/匹配FAQ/置信度/处理方式/处理人/响应时长/发布内容/时间戳。
若为人工处理：is_counted=true，归因到 operator_id，更新 Redis 实时计数器。
若为自动处理：is_counted=false，operator_id=null。
输出：完整日志
11
运营标注 & FAQ优化反馈
运营人员在后台对已发布回复标注「正确/错误」。
错误标注 → 关联FAQ正确率下降 → 累计10条错误时系统提醒管理员复盘该FAQ。
标注数据 → 定期汇总为训练语料 → 二期/三期触发模型微调流水线。
输出：优化信号

SaaS 多租户扩展架构
从单院部署到多院SaaS的演进路径，数据隔离策略与租户配置设计。
一期 · 单租户独立部署
单家医院，自有服务器部署。Docker Compose一键启动。所有数据在本地，合规最简单。

适用：已有IT基础设施的三甲医院，对数据本地化有要求。
→
二期 · 共享集群多租户
多家医院共享一套基础设施，数据库层用 tenant_id 行级隔离，向量库按 Collection 隔离。

适用：中小医院，无IT运维能力，接受云端SaaS模式。
→
三期 · 企业级多租户平台
医院集团（多院区），专属K8s命名空间，Schema级数据库隔离，独立向量库实例。

适用：大型医疗集团，多院区统一管理，有定制化需求。

隔离维度共享集群方案（二期）企业级方案（三期）单机独立（一期）
