周一晨会框架

45 分钟，把过去一周和未来一周对齐到同一页。
少开会，多决策，可回看。

2026·05·17　 | 　主持人轮值制

为什么需要框架

现状

  • 团队 ≤6 人，多 track 并行（抓取 / DM / Prompt / 基建）
  • 本周（5/11–5/17）新增 17 条 feedback memory，事故和教训密度很高
  • 没有固定节奏 → 信息散在 commit / Lark / 私聊里
  • 已出现多次并行任务互相踩踏的事故，根因之一是周末/周初对齐不充分

目标

  • 每周一开 45 分钟 把齿轮咬合好
  • 所有人知道 KPI 红绿 / Top 3 是什么 / 谁卡谁
  • 会后产物归档到团队周会目录
  • 积累框架本身——两周做一次 retro，迭代这份模板

设计原则（融合三家做法）

来源做法Akke 怎么用
Amazon 6-pager 静默阅读 → 再讨论 周报 Day0 写好；会上前 5 min 全员安静读，禁口头汇报
Stripe / Linear 书面优先；async 能解决的不进会议 上周已 ship 的代码不复述；只讨论需要决策 / 有阻塞的事
Pixar Braintrust Lessons 必须当事人讲，对事不对人 事故 / 反例环节由 owner 自己 review，不许第三方代述
Spotify Squad Health 固定 3–5 个信号灯，不写长报告 数据透视环节固定 5 项 KPI，不增不减

原则：先做减法。每加一个环节都要砍掉一个旧的。

开始之前 · 反模式硬禁止

  • 不做"我上周做了 X / 今天做 Y"的轮报 — 那是 daily standup，不是 Monday kickoff
  • 不在会上看代码、看 dashboard 详情、调试 bug — 拉小会
  • 不让一个人讲超过 5 分钟 — 时间员负责打断
  • 不在会上做"要不要做 X"的开放头脑风暴 — 进需求文档库，走需求模板流程
  • 不把 Top 3 加到第 4 条 — scope 蔓延是 Akke 项目最大的隐性成本
铁律 会前 24h 没准备完 = 取消本次会，发书面 update 顶替。 这条比按时开会更重要。

Day 0 · 会前准备（周日 22:00 前）

主持人（rotating）写完 → PM 复核 → 提交到团队周会目录（YYYY-MM-DD.md）

需要凑齐的 5 份输入

  1. 生产 KPI 快照 — 全量测试 + 数据审计脚本
  2. 上周交付清单 — git log --since="7 days ago" --oneline 中 feat/fix
  3. 上周事故 / 教训 — 团队 memory 库本周新增的 feedback 条目
  4. 本周 Top 3 候选 — PM 拍板，每条配 owner + Friday 收口标准
  5. 未决问题 — 需要会上拍板的 ≤3 个 yes/no 问题
原则 80% async 就绪。 会上只补差距、做决策、对齐方向。如果 80% 都没准备完，会议就没必要开。

多了不看，少了不算数。任一红色项 → 自动进决策区，必须给本周收口计划。

业务核心指标 × 3
按当期业务线自定（如产出量 / 有效率 / 上游成功率）
7d 滚动，对比上周环比

≥3 黄 · ≥5 红
CI 通过率
main 7d CI pass rate
<95% 黄

客户漏斗（同环节展示）

comments → high-intent → approved → sent → reply
关注转化率而不是绝对值。某一段掉 ≥30% → 进决策区。

上周回顾 · 三栏硬性格式

每个 owner ≤2 分钟。避免变成流水账。

✅ Shipped

≤3 条最重要的
每条带 commit hash 或 PR 号

feat(queue): 原子 claim RPC + 24h 回库 cron

❌ Missed

上周 commit 但没收口
必须说为什么

反向评论扩样: Caption 抓取治杜撰已上，但候选有效率仍 <40% — 卡在 source pool 太薄

💡 Lessons

本周写入团队 memory 库
必须附 memory 条目名

feedback_xxx.md — 一句话写清教训（示例略）
关键 本周如果没写任何 memory，要么是没干活，要么是没反思。PM 当场点名追问。 Akke 最有价值的资产就是团队 memory 库（截至 2026-05-17 已 220+ 条），每周新增 3–5 条才能保持团队学习速度。

本周聚焦 · Top 3 硬约束

只看 Top 3。第 4 条往后默认 OOS（out of scope）。

每条 Top 3 必须满足

字段要求反例
Owner唯一人名"团队负责" / "@a 和 @b"
收口标准Friday 17:00 可验证"做一下 X"
回滚预案翻车怎么撤未填
依赖卡谁 / 卡什么"应该没依赖"
禁止 把 Top 4–6 也加进来 = 这周哪个都做不好。 全员举手不反对 → 过；有人反对 → PM 当场拍板，不开放讨论。

风险与决策 · 嵌入 Top 3 环节

只问两类问题

  • Yes/No 决策：可以当场拍的，PM 给一句话答案
  • Blocker：谁卡住、需要谁出手；写入 action items

不能现场解决 → 下午拉小会 + 写到 doc 里。不允许在大会上展开技术讨论。

红色 KPI 自动入场

  • 有 owner 接手
  • 有本周收口计划
  • 有 Lark 卡片同步全员

三项缺一不可，否则不让出会议室。
