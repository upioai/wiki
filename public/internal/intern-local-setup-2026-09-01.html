服务器来源位置 / 装法

装机顺序

四步 · 后一步依赖前一步

顺序有依赖：先有 CC 和 marketplace，才谈得上 plugin；先有 lark-cli 真二进制，配额阀门 shim 才挂得上去；私有仓要先拿到 org 权限。

1

Marketplace plugin —— 7 个已启用

来源 github.com/anthropics/claude-plugins-official，公开。你机器上另有 16 个装了但 enabled:false，别一起给实习生。

# 逐个装并显式 --scope user（默认写 project scope，跨项目不生效）
for p in superpowers playwright code-review frontend-design \
         supabase security-guidance hookify; do
  claude plugin install $p@claude-plugins-official
  claude plugin enable  $p --scope user
done
claude plugin list

装完覆盖：superpowers 全家（brainstorming / systematic-debugging / writing-plans …）+ frontend-design + playwright MCP。

2

两个 CLI ＋ 26 个 skill —— 是两件事

CLI 的 postinstall 只下载二进制，一个 skill 都不写。skill 由 skills 这个工具单独装：它把目录放进 $AGENTS_HOME/skills/、再软链进 $CC_HOME/skills/，来源记在 $AGENTS_HOME/.skill-lock.json（sourceType: github，不是 npm 包）。本机 40 个 skill 目录里 26 个是这么来的软链。

# a. 装 CLI 二进制
npm i -g @larksuite/cli @wecom/cli

# b. 装 skill —— 软链的真正来源
npx skills add larksuite/cli -y -g        # 19 个 lark-*
npx skills add WeComTeam/wecom-cli -y     # 7 个 wecomcli-*（不要加 -g）
ls -la $CC_HOME/skills | grep '\->' | wc -l   # 应为 26

# c. 授权 —— 用团队统一应用，别 --new 自建
lark-cli auth login --domain all

# d. 配额阀门 shim —— 正本在业务主仓，步骤 3 clone 完就有
cd $MAIN_REPO/tools/lark-quota-valve
./install.sh --supabase-url <URL> --supabase-key <ANON_KEY> --user <他的名字>

装完覆盖：lark-task / lark-im / lark-contact / lark-doc 等。lark-cli 本地配置目录里的 token 与 MCP 侧凭据互相独立，刷一个不影响另一个；refresh_token 7 天过期，失效重跑 auth login。

3

私有仓 —— skill 随仓走，clone 即生效

这批不用单独配置：.claude/skills/ 和 .claude/commands/ 是仓内文件，clone 下来 CC 自动识别。实习生已是组织成员（2026-09-02 核过），直接 clone——配额阀门的正本也在主仓里。

git clone git@github.com:$ORG/$MAIN_REPO.git         # 业务主仓：23 skill + 4 command + 仓内 hooks
git clone git@github.com:$ORG/$RECEPTION_REPO.git    # 接待服务仓：2 skill
ls $MAIN_REPO/.claude/skills $MAIN_REPO/.claude/commands

装完覆盖：push-conversation-summary / akke-version-sync / loop-goal-spec 等。主仓还带一套 SessionStart / WorktreeCreate hook，比全局那套更严。

4

仅本机的那批 —— 只能你手动拷

这一步没有命令可以让实习生自己跑。$CC_HOME/skills/ 下 14 个实体目录、CLAUDE.md、8 个 hook、10 个 script、1 个 agent，全部只存在于这台 Mac。cc-team-config 仓已决定暂缓（2026-09-02），目前仍靠手工打包；下面的建仓命令留档备用。

# 建议：把这些先变成一个私有仓，而不是 AirDrop 一个 zip
mkdir -p $TEAM_CONFIG_REPO && cd $TEAM_CONFIG_REPO && git init
cp -R $CC_HOME/skills/{wrap-up,feynman,challenge,mem,verify,scout,\
prd,dark-tech-page,finance-report,memory-stale-audit} skills/
cp -R $CC_HOME/hooks $CC_HOME/scripts $CC_HOME/agents .
cp $CC_HOME/CLAUDE.md .

# 拷之前必须处理：finance-report 里有 1 个文件硬编码了本机 home 绝对路径
grep -rn "$HOME" skills/finance-report/

覆盖：wrap-up / dark-tech-page / feynman / challenge / mem 等。$CC_HOME/CLAUDE.md（262 行契约）不拷的话，实习生的 Claude 不知道 CI 门禁、验证前置、worktree 纪律这些规矩。

盘点时撞到的四件事

配置前先看

skills-repo 不是备份，是个停更的空壳

$OLD_SKILLS_REPO（一个早期的私有 skills 仓）最后一次提交是 2026-03-29，里面 5 个 skill（clawra / code-annotator / knowledge-visualizer / lark-bot-setup / softie-test）与现在实际在用的 40 个零重合。同理 $OLD_MCP_REPO（早期的私有 MCP 仓）只有一个 airwallex server，本机 MCP 配置里没有它。

要是照着「团队 skill 都在那个旧 skills 仓」给实习生拉一份，他会拿到一套谁都不用的东西。

brain MCP 给不出去

$BRAIN_DIR 是 git 仓但 remote 为空，MCP 走 $BRAIN_DIR/.venv/bin/python -m brain.mcp_server。它的用途是「查企业大脑」，实习生装不了，也没有替代入口。要么给它推个远端，要么在他的配置里直接省掉。

wrap-up 有两份，会打架

全局 $CC_HOME/skills/wrap-up 和 $MAIN_REPO/.claude/skills/wrap-up 是同源双副本。实习生同时拿到两份时，在主仓目录下走的是仓内版。改任何一侧都要同步另一侧——这条你的 CLAUDE.md 里已经写了。

别把 23 个已停用的 skill 一起搬过去

你的 settings.json 里 skillOverrides 关掉了 23 个（canary / debono / grill-me / grilling + 全部 wecomcli-* + 一半 lark-*）。给实习生的 settings 建议照抄这份 off 名单，否则 skill 列表会挤占预算并触发 /doctor 的 truncation 警告。
