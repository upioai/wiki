门店工作台 · Agent 接入

在 Work Buddy 里连上门店工作台

连上之后，你可以在办公软件里直接问「今天门店怎么样」「哪些客户该跟了」「这句话能不能发给客户」， 它会去工作台取真实数据回答你。全程三步，大约五分钟。

本文为公开版，具体标识已替换为占位符；服务地址向负责人索取。

服务已上线，14 个工具可用 国内直连实测 0.6–0.9 秒 更新于 2026-08-19

  1. 拿一条 Agent 凭据

    负责人会单独发给你一条 Agent 凭据。它就是你的钥匙。

    两件事别做：别把它发在群里或写进代码库；也别转给别人用 —— 丢了或怀疑泄露，找负责人换一条。

  2. 把配置粘进客户端

    按你实际在用的那个软件挑一段，把 <你的凭据> 换成第 1 步拿到的字符串，<门店工作台地址> 换成负责人给你的服务地址。

    腾讯 Work Buddy

    编辑 ~/.workbuddy/mcp.json（也可以放项目目录下的 .workbuddy/mcp.json）：

    // ~/.workbuddy/mcp.json
{
  "mcpServers": {
    "workbench": {
      "type": "streamable_http",
      "url": "https://<门店工作台地址>/api/mcp",
      "headers": {
        "Authorization": "Bearer <你的凭据>"
      }
    }
  }
}

    阿里 QwenWork（千问办公）

    扩展 → 连接器 → 粘 JSON。只有一个字不一样：type 用连字符。

    {
  "mcpServers": {
    "workbench": {
      "type": "streamable-http",   // ← 连字符，不是下划线
      "url": "https://<门店工作台地址>/api/mcp",
      "headers": {
        "Authorization": "Bearer <你的凭据>"
      }
    }
  }
}

    这两个键名我们没能在真机上验过。它们来自两家的公开文档。 如果客户端提示连不上，第一件事就是把 streamable_http 和 streamable-http 互换再试一次 —— 这是最可能的原因，改一个字符的事。

  3. 验一下确实连上了

    重启客户端，然后问它一句：

    • 你现在能用门店工作台的哪些工具

    它应该列出 14 个以 store_ 开头的工具。数量对上就算通了。

  4. 开始用

    直接说人话就行，不用记工具名。这些是它最擅长回答的：

    • 今天门店怎么样，有什么要我处理的
    • 有哪些内容等我批
    • 哪些客户该跟了 / 张女士什么情况
    • 我们家现在能对外说的价格活动是什么
    • 机器人接待得怎么样，客户都在问什么
    • 这句话能不能发给这个客户
    • 我们家不能说什么，一天最多发几条

    最后两句值得单独记一下：它知道这家店的红线（不许承诺最低价、必问哪几件事、服务哪几个城市）， 也能在你发出去之前先帮你过一遍六道出站检查，省掉「排进去才发现批不了」的来回。

它能做什么，不能做什么

这条边界是产品设计，不是权限没配好。

可以你的凭据允许

  • 读门店的全部经营数据：客户、接待记录、资料、视频素材、效果数据
  • 零副作用地自检一句话过不过闸
  • 给某位客户起草一条跟进，排进审核台

不行设计上不给

  • 批准任何内容 —— 那是店长在工作台点的那一下
  • 直接给客户发消息
  • 改门店资料、线上话术、闸配置、量房券、视频产线

起草不等于发出去。你让它排一条跟进，它只会写进审核台变成一条待批记录， 在有人到工作台点批准之前，触达不到任何客户。而且它会先把内容念给你听、等你点头， 才真的写进去 —— 你说「不对，改一下」它就不会写。

一件需要你知道的事

它读到的是门店的真实经营数据。请照着「这台电脑上开着门店后台」的标准来对待它：别在公共场合投屏演示，别把回答整段转发到外部群。

接不上、或者想加别的能力，直接找负责人。
