模块 2 · 内容分析 触发评论 · LLM 评分 · 破冰 + 跟进文案

客户只问"在哪做" · 破冰却先报了价

内容侧是评分模型 + 破冰话术生成共同决定的：客户留了什么、系统看到了什么、AI 写了什么。本案的关键张力是 — 客户的诉求极其单一且明确（在哪做），但自动破冰是一段标准的产品 + 报价模板，没有正面接住他的问题。

2.1 触发评论 · 两个字，但指向清晰

在石材橱柜板材批发（号源池里类目「工厂号」的石英石台面 + 橱柜板材账号）的视频底下，他只写了 「哪里」。两个字看似信息量极低，但结合后续他回关后第一句 「你们在哪里做」，意图非常明确：①关心的是地理可达性 — 不是问价、不是问工艺，而是"你们能不能服务到我这儿"；②对石英石台面 / 橱柜有现成兴趣 — 才会停在工厂号视频上留言；③处在调研早期 — 先确认"能不能做"，再谈"怎么做"。这是典型的下沉市场本地化采购心态。

2.4 跟进文案 · 运营手动补位 · 正面答地区

跟进 DM 在 transcript（#3）。运营没有继续堆产品，而是直接回答客户的原问题：①正面答"在哪做"「全国都有店铺，贵州也有分店」；②给信任锚「量房、安装、售后都是本地团队上门」；③双向加微「给个 v / 或 +Homedz3791（武海艳设计师）备注抖音」；④降门槛「先免费帮您量房出方案」。这是一次很到位的人工补救。

"本地团队上门"是回答地区问题的正解
客户问"在哪做"，潜台词是"你们能不能服务到贵州我这儿"。运营答的不是一个城市名，而是"贵州有分店 + 本地团队量房安装售后上门" — 直接消解了"会不会只是远程接单、出了问题没人管"的顾虑。再叠加"免费量房"把第一步门槛压到零，加微的钩子顺势就有了落点。

给上面 6 个分析模块各打一个评价。good = 已达可复用标准；mid = 能用但有压缩空间；bad = 是这条链路的明显短板。

模块 1

时效性 · 5 分 25 秒破冰

GOOD
✓ 做到位
  • 评论→触达 5m25s：入库 2m14s + 破冰 3m11s，分钟级响应。
  • 关注流实时打法：趁评论记忆鲜热回关 + 破冰，无需"提醒是哪条视频"。
✗ 不足
  • 时效快没换来内容准：客户 11:56 开口，11:57 破冰却答非所问。
  • 本周建议：关注流场景下，破冰生成前先读客户已发来的 DM，别只按 comment 生成。
模块 2

内容 · 评分准但破冰答非所问

MID
✓ 做到位
  • 78 分评级准："哪里"信息密度低，中意向定档合理。
  • 破冰结构完整：呼应关注点 + 价格锚 + 稀缺 + 钩加微 + 反问。
  • 运营人工补位到位：跟进 #3 正面答地区，救回破冰的错位。
✗ 不足
  • 破冰答非所问：客户问"在哪做"，AI 答产品+报价，靠人工兜底。
  • 本周建议：关注流破冰模板加一句"我们贵州有分店"类省级落地，先答地理再谈产品。
模块 3

账号信任度 · 小文（野荞）

BAD
✓ 做到位
  • 主页这关大概率过了：客户愿意回关并主动开口是间接证据。
✗ 不足
  • 主页资产全部缺失：昵称/简介/粉丝/作品数均未抓取，无法量化信任门槛。
  • 关注流尤其吃主页厚度：要客户主动回关，空主页直接流失。
  • 本周建议：补「小文（野荞）」主页截图落到本页，再评估关注流真实转化门槛。
模块 4

地区 · 客户主诉求就是地区

GOOD
✓ 做到位
  • 正面答了主诉求："贵州也有分店、本地团队上门"精准消解地理顾虑。
  • 降门槛叠加："免费量房"给加微钩子一个落点。
✗ 不足
  • 破冰没第一时间提省：客户最在意地区，省级却到跟进才出现。
  • "本地感"无数据背书：号源服务市为空、客户市未公开，同城徽章打不出，全靠话术。
  • 建议：补录号源 source_accounts.city + 客户进一步确认贵州具体市。
模块 5

价格 · 锚硬但抛早、口径糊

MID
✓ 做到位
  • 锚定+稀缺结构成熟：868→568 让利感 + "只锁一套"紧迫感。
  • 材料背书具体：兔宝宝板材 / 悍高五金 / ENF 级环保，不是空报价。
✗ 不足
  • 时机错：客户问地区，破冰先报价，显得急于成交。
  • "568 全包"口径糊：含台面/橱柜/全屋未界定，加微后必被追问。
  • 本周建议：备"568 计价口径 + 典型厨房估算"，加微首轮就抛清。
模块 6

信息流转 · 关注流跑通但 writeback 漏

BAD
✓ 做到位
  • 关注流打法跑通：回关即私信 + 趁热破冰，链路顺。
  • ADB 通道稳定：野荞号 5-13 后切 ADB，破冰正常入库。
✗ 不足
  • writeback 只覆盖 opener：客户主动私信 + 跟进 DM 全丢，DB stage 失真为 ice_break。
  • 去重风险：该 user 未标 contacted-with-content，4h 后可能被重复 claim 触达。
  • 云电脑仍是规划态：5 步迁移已画，未跑通。
