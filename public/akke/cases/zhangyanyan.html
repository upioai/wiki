模块 2 · 内容分析 触发评论 · LLM 评分 · 破冰 + 跟进

「兔宝宝 + 胡桃色」两个具体词，把一句问句提成了中意向

内容侧由评分模型 + 破冰/跟进话术共同决定：客户留了什么、系统看到了什么、AI 写了什么。这条 lead 的价值全在"她指名了品牌和颜色"。

2.1 触发评论 · 她暴露了两件事

在大橘的家🏠（软装中）（号源池里一位偏业主装修日记的本地号）发的胡桃色木门测评视频底下，张燕燕留了一句：「有没有人做兔宝宝的门胡桃色」。看似随口一问，但她暴露了两件事：①指名品牌"兔宝宝"（说明她已经在做功课、有品牌意识），②锁定颜色"胡桃色"（有明确审美偏好）。这两个具体词让 LLM 把她判成 product 类问购、specificity=medium。

2.2 系统给她打了 78 分

78/100
中意向
comment_type · product specificity · medium freshness · active
评分理由：问购·一般·在调研。
她指名了品牌和颜色，但没给面积/户型/预算，也没说"急做"——所以停在 78 中意向而不是高意向。这是典型的"在调研"阶段：知道自己想要什么料什么色，但还没到落地量尺那一步。破冰要做的是先接住"能做"、再往需求纵深挖一层。

2.3 破冰文案 · 先接住诉求，再抛一个二选一

她指名兔宝宝胡桃色门，opener（见 #1）第一件事就是正面答"能做"，把她"有没有人做"的问题接住；再用"合作大牌供色系"补背书，"现货排期紧"埋一个轻紧迫钩子，最后用"新房还是翻新"的二选一把对话推进。

① 招呼
称呼带「姐」
「张燕燕姐」
② 正面答
先接住"能做"
「兔宝宝的胡桃色门能做」
③ 背书+钩子
大牌供色系 + 排期紧
「合作的几个大牌都能供…现货排期也紧」
④ 反问
新房/翻新二选一
「你家是新房还是翻新？」
破冰文案 · "指名品牌型"变体
当客户在评论里指名了品牌/颜色，opener 第一拍必须是正面确认"能做"——她问的是"有没有人做"，你要是不先答就先问户型，就是"问 A 答 B"，信任当场流失。这条 opener 接住得干净。唯一可议的是"现货排期也紧"：对一个 78 分还在调研的客户，紧迫词略微前置（见复盘模块 2 的不足）。

2.4 跟进文案 · 接住「新房」，只挖一个细节

她回了两个字「新房」（#2）——按第二轮决策卡口径，这是L1 试水档（1-2 字短答、被动给信息）。L1 的最佳打法是 B 档：问 1 个细节挖需求、不抢加微。跟进（#3）正是这么做的：

① 接住新房
把"新房"转成价值
「新房正好从头规划」
② 落她的诉求
胡桃色门配全屋统一
「胡桃色门配全屋柜体一套统一…显质感」
③ 省钱理由
从头做比后期补省
「也比后期补省」
④ 只问 1 个
装修进度 = 探紧迫度
「装到哪步了，量尺了没？」
跟进文案 · 为什么这轮"故意不要微信"
第二轮决策卡实测：客户 L1 试水档时抢跑加微（63% 的翻车案例都栽在这），大概率已读不回。所以这轮刻意只问装修进度、不要 v——用一个能探出"紧迫度"的问题把她从"调研"往"要落地"推。这一步之后她果然升档了（见 2.5）。

2.5 决策档推进 · 从「不要微信」到「该要微信了」

她接下来的回复一路升档：#4「在买门」＝正在采购、#6「没时间看 + 胡桃色多少钱一个」＝抛异议 + 直接问价、#8「7 个房门」＝给出关键数量。按决策卡这已从 L1 试水升到 L2 配合 / L3 接近决策——这时候引导加微才是对的。我方三步接得很稳：

① 拦"单买"
往门+全屋柜体抬一档
#5「别急着一樘樘单买…配全屋柜体一起更划算」
② 报价+转钩子
1512 一樘 + 把"没时间"变加微理由
#7「1512 一樘…你没空跑就更省事，让设计师加你」
③ 兑现+要微信
核总价 1.06 万 + 准价单钩子
#9「7 樘≈1.06 万…留个微信，设计师把准价单+效果图发你」
🎣 这次加微钩子为什么成立（对照 2.4 的"故意不要"）
时机对了：她已给数量（7 樘）、主动问价——不再是 L1 试水，抢加微不会吓跑。
钩子够硬：不是空要微信，是"设计师把 7 樘门+全屋柜体的准价单 + 效果图一次发你"，具体可交付物。
踩中她的痛点：她两次说"没时间看/没空跑"，加微被包装成"你不用动、在家等着看" = 帮她省事，不是推销。
顺带抬客单：把"只买 7 樘门（1.06 万）"往"门+全屋柜体"引，客单价天花板打开。

模块 5 · 价格分析 胡桃色 1512/樘 · 7 樘 ≈ 1.06 万

1512 一樘 → 7 樘 1.06 万：报价给得干脆，还顺势变成加微钩子

前两轮她在"调研料和色"，opener（#1）和第一条跟进（#3）刻意不报价——没面积没数量，硬报总价＝随口乱报。但当她 #6 直接问"胡桃色多少钱一个"，我方不绕、干脆报单价：#7「1512 一樘」；等她 #8 给出"7 个房门"，再 #9 核出总价「≈1.06 万」。报价节奏是"调研期不报 → 问价时给单价 → 有数量核总价"的三段递进。

报价口径
胡桃色门 1512 / 樘
单价直给，不含糊；7 樘 = 1512×7 ≈ 1.06 万（仅门）
作用范围
门单买 → 门+全屋柜体

为什么这个报价节奏对路
调研期不报 → 问价干脆给单价 → 有数量核总价，每一步都踩点：#3 阶段没数量硬报会乱报；#7 她直接问价，这时候绕开单价只谈加微反而像藏价、掉信任，所以干脆给 1512；#9 她给了 7 樘，立刻兑现"核总价"1.06 万——先兑现承诺再要微信，钩子才立得住。更妙的是把"准价单"做成加微的交付物，报价不再是终点、而是"加我给你出全套"的理由。
风险 · 单价一旦裸奔，容易被拉进纯比价
「1512 一樘」是个可被直接比价的裸单价——她完全可能拿这个数字去别家问"你家胡桃色多少"。护栏是紧跟的"门+全屋柜体一起更划算"，但目前全屋柜体的总价锚点还没给（只给了门的 1.06 万），客单天花板还没真正打开。建议：她加微后，设计师第一时间给"7 樘门 + 全屋柜体"的打包区间，把比价焦点从"单樘 1512"挪到"整套省多少"。
模块 6 · 信息内部流转路径 云电脑通道 · 回复回写现状

这条 DM 怎么发出去、客户回复怎么进的库

"评论入库 → 评分 → 起草 → 发送"在 DB 里是几行行变化，物理上对应发送设备 + 人工节奏 + 回写。本案由一筑账号经无影云电脑触达；本节也点出这条链路当前的一个真实缺口：客户回复没自动进库。

7.1 当前 · 云电脑通道

7.2 真实缺口 · 无人值守的捕获腿

本案暴露的真实缺口不在"没通道"，而在通道会静默停摆没人知道。opener 走了正规 claim → 库通道（评论、评分、破冰都有 DB 记录）；但 #2–#9 全落在 07-03→07-07 那段「DOM 捕获腿挂了」的窗口——首触 opener 照发、二触照跑，唯独"读客户回复"这条腿死了、还不告警，靠人"数据群怎么没推了"才发现。已按重启流程拉起隐形 Edge + poll agent，捕获恢复（web capture[DOM] COMMIT 写回 循环），后续回复自动进 messages。

复盘 · 各模块做到位 / 不足

这个项目哪里做得好，哪里还能拧紧

给上面 6 个分析模块各打一个评价：做到位的当 SOP 沉淀；不足的当下一周 punch list。good = 已达可复用标准；mid = 能用但有压缩空间；bad = 是这条链路的明显短板。

模块 1

时效性 · 4m 38s

GOOD
✓ 做到位
  • 极速首触达：评论后 4m38s 打回，客户还停在评论区、记忆最鲜，是链路里最快的一档。
  • 两段都有显式数据：3m 入库 / 1m38s 触达，全程可追可分段。
✗ 不足
  • 快 ≠ 成交：客户仍隔 2 天多才回，说明"抢窗口"只是入场券，转化靠后续跟进节奏。
  • 回复段无自动感知：她 7-06 就回了，系统靠人工 7-07 才补录（见模块 6）。
模块 2

内容 · 破冰接住 + 全程对档升级

GOOD
✓ 做到位
  • 破冰正面答"能做"：接住她"有没有人做"的原议题，没有问 A 答 B。
