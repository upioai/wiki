他要的是预算，我们给的是微信 — 但他还是给了

他在贵州。凌晨 00:52，在「佳姐装修日记」的装修全流程视频底下留了六个字：「来一份 主播大爱」。

模块 2 · 内容分析 触发评论 · LLM 评分 · 破冰 + 一轮跟进

共情那半句写得很好，答非所问那半句写得很险

跟进这条消息（#3）是一半一半：前半句「老丈人家翻新更得上心」是本批共情写得最准的一句；后半句直接跳到要微信，把客户明确问出口的「预算大概多少」晾在了一边。客户最后还是给了微信，但这更像是他脾气好，而不是话术接得对。

2.1 触发评论 · 六个字里只有一个动作

「来一份 主播大爱[感谢][感谢][感谢]感谢」— 这条评论的实质内容只有三个字：「来一份」。其余全是客套和表情。①他要东西，但没说要什么规格的东西；②他很客气，一条评论里道了两次谢，这类人后续沟通阻力通常较小；③他没暴露任何房屋信息 — 户型、面积、预算、新旧，一个都没有。换句话说：意图明确、信息为零。所有的房屋事实，都是靠后面那一轮对话换来的。

「你家几室几厅」是一个默认「这是你自己的新房」的问题。而客户的实际情况是：老丈人家的旧房子、他自己动手装。所以他没有回答户型，而是把整个背景重讲了一遍。这不算失败 — 客户主动纠正问题、并给出更完整的背景，反而是好事；但它说明破冰的反问可以更开放一点。
可复用的改法：把「你家几室几厅」换成「你家现在什么情况，新房还是翻新？」— 同样是一句话就能答，但它不预设房子是谁的、也不预设是新是旧，能一次性收到更准的画像。

2.4 跟进 · 一句极好的共情，和一个被无视的提问

客户在 #2 里给了三条硬信息 — 老丈人家的旧房子（房子不是他的）、自己装修（自装，非全包）、看哈预算大概多少（明确的价格提问）。跟进（#3）只接住了第一条。

✓「老丈人家翻新更得上心」— 本批共情写得最准的一句
这句话之所以好，是因为它没有停在复述，而是往前推了一层。客户说的是事实（老丈人家的旧房子），AI 说的是这个事实背后的心理压力：给老丈人装房子，做砸了不只是钱的事。一句话就把「我懂你的处境」传达到位，成本只有 11 个字。
对照本批那些「理解～」「明白啦」开头的空共情，这句是有具体所指的。可复用的写法：客户交代的每一个身份细节（老丈人家 / 婚房 / 出租房 / 父母养老房），背后都对应一种特定的顾虑，接话时说出那个顾虑，而不是复述那个身份。
✗ 他问「预算大概多少」，回答里一个数字都没有
客户明明白白提了一个问题：「看哈预算大概多少」。#3 的回应是「清单我拉出来了，层板和抽屉单价都列了……你报个 vx 号给我」。翻译成人话就是：你问的东西在表格里，先给微信才能看。
这是一次典型的用「资料」置换「提问」：客户想要一个数量级，我们给的是一个门槛。它有风险 — 客户完全可以回一句「那大概多少你直接说下呗」然后卡在原地，本批已经出现过被这样顶回来的案例。
本周建议：客户直接问价时，先给一个带条件的数量级，再要联系方式。比如「旧房翻新自己装的话，柜子这块常见落在 X–Y 万，看你做几个柜子和板材等级；具体的我做成表格发你，报个 vx 号」。先答再要，比只要不答的通过率高，而且不会给人「问什么都不说」的印象。
✗ 「自己装修」这个关键信号被完全忽略了
客户说的是「自己装修」 — 这四个字意味着他大概率没有请全包公司，是自己找工人、自己买材料的路子。这类客户对全屋定制的需求通常是「单点采购柜子」，而不是我们默认的整装方案；他关心的是柜子单价和板材，不是「免费出方案、全包多少一平」。
而跟进给他的是「同户型整套参考清单」+「让设计师直接发你」 — 这是标准全包客户的话术模板，与他的实际身份错位。好在他没有计较。本周建议：把「自装 / 全包 / 半包」识别成一个显式信号，命中「自己装」「自己弄」「自己找工人」时切到单品报价口径，别再推整装方案包。

模块 4 · 地区分析 三层地区信号 · 省 / 市 / 号源市

全屋定制的每一项关键成本都绑在施工地上：能不能派设计师上门量房、走哪个仓发货、安装队怎么排、运费算多少。本案的施工地是老丈人家，而老丈人家在哪，对话里一个字都没提。他人在贵州，房子可能在贵州的另一个市，也可能在隔壁省的老家。
本周建议：把「房子归属」识别成一个和户型同等重要的字段。听到「老丈人家 / 父母家 / 老家的房子 / 给孩子准备的房」时，紧跟一句「房子在哪个市？我按当地的仓和安装队给你算」 — 这句话既拿到了关键信息，又显得是在替他省钱，不会像查户口。
号源侧：业主日记类目本来就打不了同城牌
「佳姐装修日记」的 category 是业主日记，不是本地号 — 这类账号的观众天然来自全国，is_same_city 恒为空并不是数据缺失，而是这个号源的性质决定的。因此本案不应该、也不需要打「同城本地仓 / 本地安装队」这张牌；话术里也确实一个地名都没提，这是对的。真正要补的是客户侧的施工地，而不是号源侧的城市字段。

「答案在表格里，先给微信」是一个能用但很险的打法
它的逻辑是把客户的问题变成加微信的理由 — 本案确实跑通了，客户一分钟就给了号。但它建立在客户脾气好、且不较真的前提上。同批已经出现过客户被这样顶回来、直接卡死在原地的情况；一旦客户回一句「你先说个大概呗」，就只能硬着头皮报，反而更被动。
更实际的风险是预期落差：他现在心里对「预算大概多少」是完全没有概念的。销售加上微信后报出的第一个数字，无论多少，都可能和他脑子里那个凭空想象的数字对不上，而这个落差本来可以在 DM 阶段就用一个区间提前熨平。
怎么改：先给一个带条件的数量级，再要联系方式
客户已经把限定条件全给出来了 — 旧房翻新 + 自己装修，这足以支撑一个粗区间。可以改成：「旧房翻新自己装的话，柜子这块常见落在 X–Y 万，主要看做几个柜子和板材等级。具体到你家户型我做成表格，层板和抽屉单价都列清楚，抖音发不了文件，报个 vx 号我让设计师发你。」
先答再要，多花的只是一句话，换来的是：①他觉得问题被认真对待了；②有了心理锚点，销售第一版报价不会显得突兀；③要微信的动作从「设门槛」变成「给更细的东西」。这是本案最值得复用的一条改法。

7.2 回写事故 · 一漏一错

聊天页里客户实际发了 3 条（一段自述 + 微信号 + 两次道谢），DB 只落了 1 条自述，微信号和道谢都没进来；与此同时，messages 表里多出一条 role = customer 的记录，内容是抖音的火花提示文案。也就是说，这一轮回读既漏掉了整条链路上最有价值的一条信息，又把界面广告当成客户说的话存了进去。

为什么这条事故比「少存一条消息」严重得多
① 业务上，微信号是这条链路的唯一产出。前面所有的采集、评分、起草、发送、共情，最终就是为了拿到 GO_Tiger86 这十个字符 — 而它没有进系统。如果运营没有随手截这张图，这条 lead 就等于白做了。
② 系统状态因此彻底失真：stage 停在 ice_break、handed_off_at = null，在派单逻辑眼里他是一个「聊过没结果」的待跟进对象。一旦自动跟进或二次触达命中他，他会在已经给了微信、还连说两次谢谢之后，再收到一条催他给微信的消息。
③ 误捕的那条噪音会污染下游：「再连续互聊 2 天可点亮火花」被当成客户发言，会进入对话历史、被当作上下文喂给下一轮 LLM，让模型以为客户在聊「养精灵」。
本周建议（三条，按优先级）：
① 联系方式识别 + 落库 — 客户消息命中微信号 / 手机号 / QQ 号 / 二维码图片时，写进会话的联系方式字段，并立刻把 stage 标成 pending_handoff、停掉所有自动跟进；
② 系统提示过滤白名单 — 「可点亮火花」「合养精灵」「对方已确认聊天」「点关注，方便以后找到她」这类抖音 UI 文案建一份黑名单，捕获时直接丢弃，别写进 messages；
③ 连发短消息的捕获补漏 — 客户在一分钟内连发多条（号码 + 表情 + 道谢）时明显漏抓，需要复核轮询频率与去重逻辑。

复盘 · 各模块做到位 / 不足

这条链路哪里做得好，哪里还能拧紧

给上面 6 个分析模块各打一个评价。good = 已达可复用标准；mid = 能用但有压缩空间；bad = 是这条链路的明显短板。本案拿到了微信号，是一条成功的 lead；但成功之下藏着两个坑 — 客户问价没答，以及最重要的那条消息根本没进系统。

模块 1

时效性 · 4 分 53 秒送达，跨夜「不追」追对了

GOOD
✓ 做到位
  • 评论 → 破冰 4 分 53 秒：00:52:40 评论，00:57:33 送达，凌晨时段无衰减。
  • 8 小时 30 分沉默期零催促：没有半夜或清晨补发"在吗"，客户醒来自己回来了，还带来了一段信息量很足的自述。
  • 客户开口后 90 秒接住：09:27:40 → 09:29:10，没让他的早间注意力溜走。
✗ 不足
  • 客户给完微信后再无响应：他连说两次「谢谢」，收到的是沉默 — 交出联系方式那一刻本该有一句确认。
  • 本周建议：把"客户给出联系方式"当成需要秒回的事件处理，而不是一条普通消息。
模块 2

内容 · 共情写得最好，问价答得最差

MID
✓ 做到位
  • 「老丈人家翻新更得上心」是本批最准的一句共情：没有复述身份，而是说出了这个身份背后的心理压力，11 个字见效。
  • 「抖音发不了文件、发图也会压糊」摩擦解释到位：把要微信的动机从"我想加你"换成"平台限制"，客户一分钟就给了号。
  • 破冰结构完整：称呼 + 场景 + 承诺 + 单一反问，四段齐全。
✗ 不足
  • 客户明确问「预算大概多少」，两条 AI 消息零个数字：把问题转成了"资料在表格里，先给微信"，本案客户脾气好才没被顶回来。
  • 「自己装修」这个关键身份被忽略：自装客户要的是柜子单品和板材，收到的却是全包整装话术（免费出方案、整套清单），口径错位。
  • 破冰锚点偏泛：「装修超全流程的视频」放在任何一条装修视频下都成立，不如同批那条引用「13w 四房两厅现代风」的具体。

MID
✓ 做到位

模块 4

地区 · 人在贵州，房子在哪没人问

MID
✓ 做到位
  • 话术里一个地名都没提：号源是业主日记类目（全国流量），本来就打不了同城牌，不提地区是对的，避开了"对贵州客户说别省经验"那类翻车。
  • 号源类目判断清晰：is_same_city = null 在这里是号源性质决定的，不是数据缺失。
✗ 不足
  • 「老丈人家的房子」= 施工地未知，却没人追问：报价、量房、发货仓、安装队全绑在施工地上，而 IP 属地贵州推不出房子在贵州。
  • 市级两端全缺：客户市未公开、号源无城市 → 无法做任何本地化判断。
  • 本周建议：把"房子归属"做成显式信号，听到"老丈人家 / 父母家 / 老家的房子"就跟一句"房子在哪个市？我按当地的仓和安装队算"— 既拿信息又像在替他省钱。

价格 · 客户张嘴问了，我们一个数字没给

BAD
✓ 做到位

  • 本周建议：先给带条件的数量级再要联系方式，多一句话，换来"问题被认真对待"+"有心理锚点"+"要微信变成给更细的东西"三重收益。
