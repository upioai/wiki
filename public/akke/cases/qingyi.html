模块 2 · 内容分析 触发评论 · LLM 评分 · 破冰 + 一轮跟进

一条消息里塞了三个我们并不知道的事实

客户全程只提供了一个信息单位：「翻新」。而跟进（#3）在这两个字的基础上，一口气说出了「翻完了」「柜体最晚这周得定」「同户型那份清单我已备好」三个具体断言。这三句都不是从他那两个字里推得出来的。更早的破冰（#1）里还有第四个 — 把号源发的视频说成了「你家的视频」。

3.1 触发评论 · 六个字，只有索取动作

「能不能发一份」— ①意图明确：他要视频里提到的那份资料；②语气客气：用的是问句而不是命令，通常意味着沟通阻力小；③信息为零：户型、面积、城市、预算、新旧、进度，一个都没有。与本批「跪求」「来一份」是同一类：意图满格、画像空白。

3.2 系统给他打了 78 分

评分理由（intent_reason = 「问购·一般·在调研」，comment_type_reason = 「索取资料是购买信号」）：产品型 · 中等 specificity · active。
78 分，与本批「跪求」「来一份」完全一致 — 系统对「极简索取型」评论有稳定的判法。问题不在评分，而在评分之后：这个分数只说明"他想要东西"，完全没有说明"他家是什么情况"。而本案的跟进话术把 78 分当成了"可以直接推进"的通行证，跳过了补画像这一步。建议在派单卡片上给「极简索取型」加一条硬提示：画像为空，首轮只能问、不能断言。

3.3 破冰文案 · 结构对，但主语错了

首条 AI DM 在 transcript（#1）。称呼、场景锚点、反问三段都在，反问「新房还是翻新」也是本批最好答的一种问法（客户 3 分钟内就点了快捷回复）。但场景锚点这一段把视频的归属搞错了。

① 称呼
直呼昵称
「你好，青衣」
② 场景锚点
把号源的视频说成客户自己的
「刷到你家四房两厅的黑白灰风格视频」
③ 兑现承诺
缺失 — 没接他「发一份」的诉求
（本条破冰未提任何承诺物）
④ 单一反问
开放好答，两个字能回
「想问下你家是新房还是翻新？」
✗ 「你家四房两厅的黑白灰风格视频」— 那不是他家，是号源的视频
客户青衣是评论者，不是视频作者。这条视频属于号源账号「苏等等的家」（source_accounts 与客户 sec_uid 是两个不同的人）。「四房两厅」「黑白灰风格」描述的是视频里那套房子，跟客户自己家没有任何已知关系。
为什么它没有当场翻车：客户在深夜刷视频，看到一句像模像样的开场，大概率没有逐字核对。但这个错误会在下一步埋雷 — 跟进里「同户型那份带图表格清单我已备好」正是建立在"他家是四房两厅"这个错误前提上的。一个假设错了不致命，致命的是后面所有话术都拿它当真。
7-22 追查更正：这里原先写的建议是「破冰模板要区分作者与评论者」，这个归因不准确 — 规则早就有。事后拉了 Langfuse 上线上真正在跑的那版 prompt（dm.ice_break.system production v54，本条 opener 由它在 17:48:48 生成、38 秒后发出），里面白纸黑字写着：「评论里的『你 / 你家 / 你老公 / 你们』= 视频博主，不是你要私信的这位客户」「只描述【视频内容】，绝不把评论里的『你 X』当成客户的 X」，还配了两个线上翻车反例。所以这不是缺规则，是规则没生效。
✗ 真正的原因：同一份 prompt 里，示例句式和禁令自相矛盾
规则写在 prompt 第 13-20 行，而第 53 行有一个用来演示「省级 IP 不要提省名」的「负向正样板」，句式是：「你好，{称呼}，刷到你 116 平奶油风视频 想问下你家是新房还是翻新」。
对照本案实际产出：「你好，青衣，刷到你家四房两厅的黑白灰风格视频 想问下你家是新房还是翻新？」 — 结构和句式几乎逐字复刻了那个样板，只是「你」升级成了「你家」。
这是团队踩过的同一类坑：LLM 跟示例走，不跟禁令走（此前反向评论那次，DB 里 3 条以「您」开头的范文，直接盖掉了 system 里「用中性称呼」的硬规则）。示例的示范力量强于禁令，两者一旦矛盾，改禁令没用。
修复进展：已按「先验证再上线」的口径，把该样板句式改成与同 prompt 第 18 行正确示范一致的「刷到这条 116 平奶油风视频」，创建为 v55 并只挂 staging；production 仍是 v54 未动，离线回归确认无副作用后再决定是否挂正式。
✗ 他问的「能不能发一份」，破冰里一个字都没回应
客户的诉求写得清清楚楚：发一份。而破冰只做了两件事 — 提了一句视频、问了一句新房还是翻新，完全没有说"可以发""我这有"。
对照本批那条 14 分钟拿到微信的案例，它的破冰第三段明确写了「可以发你一份我们整理的避坑清单」，先兑现、再提问。本案的顺序是只提问、不兑现，客户虽然回了，但那是在没有得到任何回报的情况下先付出了一次配合。这会让后面的每一次索取（要微信）都显得更贵。
本周建议：破冰四段中「兑现承诺」不可省。客户明说要资料时，破冰必须出现"可以发"三个字，哪怕只有半句。

3.4 跟进 · 84 秒接住，但四张牌一次打光

跟进（#3）在一条消息里叠了四层：状态误读 → 硬造紧迫 → 无依据的定制承诺 → 低价暗示 → 要微信。逐句看，问题都不大；叠在一起，对一个只说了两个字的陌生人来说密度过高。

① 状态误读
把「要翻新」读成「已翻完」
「翻完了正好」
② 硬造紧迫
我们不知道他家水电进度
「柜体最晚这周得定，不然水电管线没法预留」
③ 定制承诺
建立在错误的户型前提上
「同户型那份带图表格清单我已备好」
④ 低价暗示
无锚点，直接把话题拽向比价
「工厂直供比门店低」
✗ 「翻完了正好」— 他说的是「翻新」，不是「翻完了」
破冰问的是「新房还是翻新」，客户点选了「翻新」。这两个字表达的是房屋类型（旧房改造，相对于新房），不是施工进度。而跟进开口就是「翻完了正好」，把它读成了"翻修工程已经结束"。
如果他其实还没动工（这是"翻新"最常见的语境），这句话就是对不上号的寒暄 — 客户会有一瞬间的困惑："我说要翻新，你说我翻完了？"而困惑是转化最大的敌人之一：它不产生反驳，只产生沉默。
本周建议：把"翻新"这类类型词与"翻完了/装好了/正在装"这类进度词在话术模板里显式区分开。客户答了类型，下一句该问进度（「现在拆改到哪一步了？」），而不是替他假定一个进度。
✗ 「柜体最晚这周得定」— 硬造的时间期限，随时可能被证伪
我们不知道他家水电走到哪一步、不知道他有没有开工、甚至不知道他是不是今年装。「最晚这周」是一个凭空钉下的期限，只要客户的实际进度和它对不上（早了或晚了），这句话立刻暴露为套路。
对照本批那条成功案例，同样是制造"现在就该聊"的理由，它说的是「新开工最要紧是预留位，水电前定柜体能省后期改管钱」 — 那是一条普适的工艺顺序常识，对任何未开工的房子都成立，不需要知道进度，也不会被证伪。一个靠吓，一个靠讲道理，效果和风险差得很远。
本周建议：紧迫感优先从工艺顺序里找（水电前定柜体、瓦工前定门槛石、木工前定吊柜），禁止在不知道客户进度时使用"最晚 X 天/这周/本月"这类时间期限句式。
✗ 「同户型那份清单我已备好」— 户型这个前提是从破冰的错误里继承来的
「同户型」暗示我们知道他家户型（并且已经按这个户型准备好了资料）。而这个"户型"来自破冰里那句把号源视频说成"你家"的描述 — 也就是说，错误被继承了一层，还被当成了确定事实来兑现承诺。
这类承诺在 DM 阶段几乎不会当场穿帮，但它会在加微后的第一次交付时集中爆掉：客户拿到一份跟自己家对不上的清单，前面所有的"已备好""都标清了"会同时失信。
本周建议：承诺物的定语只能写我们真的知道的部分。已知只有"翻新"，那就写「翻新户常用的那份清单」；要说"同户型"，必须先问出户型 —「你家几室几厅？我按你家那版标一份给你」，一句话既拿信息又让承诺成真。
✗ 「工厂直供比门店低」— 唯一的价格表述，却是最不该出现的那种
这是整段对话里唯一一句涉及价格的话，而它既没有数字、也没有计价口径，只有一个方向性的"更便宜"。它的实际作用是把客户的注意力从"这份清单有没有用"拽到"到底便宜多少"上去 — 而后面那个问题我们并没有准备好回答。
同批案例已经验证过更稳的做法：报计价结构（按投影面积 / 按柜体延米 / 板材分档）而不报总价，或者干脆把价值定在省钱侧（「水电前定柜体能省后期改管钱」）。这两种都比"比门店低"这句空话有说服力，而且不会引出比价。
本周建议：在没有任何户型/面积信息时，禁用"比门店低/厂家直供更便宜"这类无锚点低价暗示；要提价格优势，必须绑在一个可解释的结构上。

模块 4 · 地区分析 三层地区信号 · 省 / 市 / 号源市

号源明明是本地号，同城这张牌却打不出来

Akke 的地区信号分三层：客户 IP 属地（省）、自报现居（市）、号源服务市。本案客户只有省级 — 山东。但这条案例和本批其他几条有一处关键差别：号源「苏等等的家」的类目是本地号，本来是最有条件打同城牌的一类号源，偏偏它的服务市字段是空的。

✗ 本地号的服务市没入库，等于白白丢掉一张牌
本地号的价值就在于它的观众高度集中在某一个城市 — 这类号源理论上是"同城判定"最容易命中的场景：如果「苏等等的家」的服务市已入库、且与客户所在市一致，破冰就可以直接说「我们在本地有仓和安装队，量房上门快」，这是全屋定制最硬的一张信任牌。
本案两端都缺：号源侧 city 为空，客户侧只有省级，is_same_city 只能是 null，同城话术完全用不上。话术里也确实没提任何地名 — 这在数据缺失的前提下是对的处理，但代价是本该有的优势没发挥。
本周建议（可执行且一次性）：把类目为「本地号」的号源做一次 city 字段补录专项 — 这类号源数量有限、城市可从主页简介直接读出，补完之后同城判定的命中率会立刻提升。这是号源侧的一次性投入，收益覆盖该号源之后的所有 lead。
客户侧的城市，本可以顺手问出来
客户回复速度很快（2 分 51 秒），配合度是够的。跟进那 84 秒里如果问的是「你家在哪个市？我按当地做法给你标一份」，大概率能拿到城市 — 既是画像补全，又是一次自然的价值展示。
实际发生的是：那条跟进用四层话术直奔要微信，一个问句都没有。整段对话里，我们向客户提出的问题总数是 1 个（新房还是翻新），断言的数量是 4 条。
模块 5 · 价格分析 客户未问价 · AI 主动抛出低价暗示

客户没问价，我们主动把话题引到了便宜上

客户全程没有提过价格。而跟进里主动出现了一句「工厂直供比门店低」 — 这是整段对话唯一的价格表述，也是这条案例价格处理上最值得改的一处：它既没有数字、也没有计价口径，只有一个方向性的"更便宜"。

"比门店低"是一句会反噬的话
三个问题：①它把竞争维度设成了价格 — 而我们在客户心里还没建立任何专业形象，一上来比价，就是在自己最不占优势的维度开战；②它引出的下一个问题我们答不了 — "低多少？"这个问题在不知道户型面积的情况下无法回答；③它和同一条消息里的"已备好清单""最晚这周得定"叠在一起，整体观感更像促销而非咨询。
客户此后没有再回复。我们无法断言是这句话导致的 — 但这是整条消息里最像广告的一句。
怎么改：把价格优势绑在结构上，或者定在省钱侧
同一账号同一天的另一条对话给出了更好的样本：「新开工最要紧是预留位，水电前定柜体能省后期改管钱」 — 一个数字都没有，却把我们的价值定在了帮你少花钱这一侧，而且靠工艺常识建立了专业感。
如果一定要谈价格优势，报计价结构比报方向更可信：「柜子按投影面积算，板材分几档，同样的配置工厂出的价和门店差在中间环节」 — 这句话给了客户一个可理解的机制，而不是一个无法验证的形容词。本周建议：在户型/面积未知时，禁用"比门店低"这类表述。
模块 6 · 信息内部流转路径 云电脑通道 · 消息全落库 · 会话字段全空

技术侧这次挑不出毛病，问题全在话术层

"评论入库 → 评分 → 起草 → 发送"在 DB 里是几行行变化，物理世界对应的是一台阿里无影云电脑上常驻的抖音客户端。本案发送侧与回读侧都正常：channel_pref = cloud_pc、队列零报错、客户的「翻新」也准确落库。这条案例失败在内容，不在管道。

这条案例暴露的是"话术生成拿不到已知事实"这个结构性问题
本页前面列出的四处失实（视频归属 / 翻完了 / 同户型 / 最晚这周），本质上是同一个问题的四种表现：生成话术时，模型手里没有一份"关于这个客户我们确切知道什么"的清单，于是它自己补了。
而 DB 侧恰恰有条件提供这份清单：comments 知道视频属于哪个号源、评论人是谁；messages 知道客户答了"翻新"；customer_profile 本该记录已确认的画像事实 — 但它现在是空的 {}，客户明确答过的"翻新"都没有沉淀进去。
本周建议（按优先级）：
① 给话术生成注入"已知事实 + 未知事实"两张清单，并明确要求：未知项只能问、不能断言；
② 把客户答过的每一个二选一（新房/翻新、自装/全包）写进 customer_profile，让后续每一轮都能读到，而不是每次重新猜；
③ 破冰模板区分"视频作者"与"评论者"，这是模板级修复，改一次全批受益。
当前状态 stage = ice_break · 跟进后零回复

他愿意搭话，只是没等到值得回的第二句

对话技术状态：DB stage = ice_break，3 条消息（AI 2 / 客户 1）全部入库；handed_off_at、next_followup_at、customer_profile 均为空。客户未提供任何联系方式。
业务实质：这是一条"接通了但没接住"的 lead — 客户 2 分 51 秒就回了话，配合度明显高于平均，但在收到一条含四处未验证断言的跟进后停止回复。他没有拉黑、没有反驳，只是不再回。
下一步：①不要原话重发 — 重复同一套话术只会坐实"在套模板"的印象；②如果再触达，换成纯问句、先认领错误，例如「上次没问清楚，你家是准备开始翻新还是已经在施工了？我按你的进度给你标那份清单」，把之前四条断言里最要命的进度误读主动摆平；③把"翻新"写进画像，别让下一轮又从零开始猜；④号源「苏等等的家」补 city 字段，本地号打不了同城牌是本案最可惜的一处结构性损失。

复盘 · 各模块做到位 / 不足

这条链路哪里做得好，哪里还能拧紧

给上面 6 个分析模块各打一个评价。good = 已达可复用标准；mid = 能用但有压缩空间；bad = 是这条链路的明显短板。本案的技术侧几乎无可挑剔 — 触达快、首响快、消息全落库；短板高度集中在内容层：一条跟进消息里出现了四处我们并不知道的"事实"。

模块 2

内容 · 一条跟进里四处失实，是本案的病灶

BAD
✓ 做到位
  • 反问设计好答：「新房还是翻新」两个字能答完，客户 3 分钟内点了快捷回复。
  • 摩擦解释到位：「抖音发不了文件，发图也容易压糊」把要微信的动机归因于平台限制。
  • 承诺物描述具体：「吊柜层板和五金数量都标清了」比空泛的"资料"更有价值感。
✗ 不足
  • 破冰把号源的视频说成「你家的视频」：客户是评论者不是作者，「四房两厅黑白灰」是号源视频里的房子 — 而这个错误还被跟进继承成了「同户型」。
  • 「翻完了正好」误读客户答案：他答的「翻新」是房屋类型，不是施工进度；这类错位不产生反驳，只产生沉默。
  • 「柜体最晚这周得定」是硬造的时间期限：我们不知道他家水电进度，随时可能被证伪。
  • 破冰没有兑现「能不能发一份」：客户明说要资料，破冰一个"可以发"都没出现，让后面的要微信显得更贵。
  • 本周建议：发送前自查——话术里每一个关于客户的事实是否有数据支撑，没来源的一律降级成问句；紧迫感只能从工艺顺序里找，禁用"最晚这周"。

  • 本周建议：先做"事实有无来源"的发送前自查，比补主页截图见效更快、成本更低。
