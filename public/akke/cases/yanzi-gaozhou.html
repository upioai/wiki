模块 2 · 内容分析 触发评论 · LLM 评分 · 抖音破冰 + 企微培育

四个字的评论，被养成了带面积/户型/风格/预算的完整画像

内容侧的看点是信息密度的暴涨：抖音评论只有「求一份」三个字加一个可怜表情，什么参数都没有；进企微 79 分钟后，系统手里已经有了茂名 · 174 平 · 五房三卫 · 全屋 · 原木侘寂 · 还没交房——外加五条硬性需求。这套挖掘链是有效的。但同一段对话里也躺着本案两个最明显的失误：吞掉客户的产品提问、面积变了不重报价。

2.1 触发评论 · 「求一份[可怜]」

在旭东聊装修（全国性装修知识号）的《装修应该提前准备什么？》底下——这条视频 1.2 万赞、936 条评论、1.3 万收藏，是条典型的高流量干货视频——燕子只留了「求一份[可怜]」。
四个字里其实藏着三件事：①她要的是那份"准备清单"，指向明确，不是随手划过 ②用了"可怜"表情，是伸手要东西的姿态，说明她愿意跟博主/评论区互动，接私信的心理门槛低 ③但零参数——没说面积、没说进度、没说预算，所以这是"想了解"而非"要下单"。事后印证得很准：她在企微里亲口说了"还没交房的……提前了解一下"。

模块 5 · 价格分析 企微 50 秒给锚价 3.9 万 · 但面积口径已过期

报价给得又快又稳，只是报的是一套已经作废的面积

客户刚加上微信、只丢了一句「C户型 约138.23㎡」，50 秒后就拿到了一个具体数字：柜体约 3.9 万，还附了"按投影面积算的大概数、准数还得量房后定"的免责口径和一张配置清单图。这一手很漂亮。问题是 50 分钟后她说自己是 174 平五房三卫，而那个 3.9 万再也没被算过第二遍。

报价策略 · 快、有数、留了口子
三点都做对了：①快——加微 50 秒内给数字，客户不用等、也不用反复问价，是建立"这家透明"印象的最佳窗口。②有具体数字——不含糊其辞说"看情况"，3.9 万是个能让客户拿去跟别家比的锚。③留了口子——"按投影面积算的大概数、准数还得量房后定"这句是硬闸写死的，不过模型，正因如此它每次都在，客户日后不会拿这个数当承诺价来对质。这套口径本身是健康的。
风险 · 报价锚在作废的面积上 + 柜体价答了整装问
[面积过期] 3.9 万是按 138.23㎡ 算的。50 分钟后客户说「174平，五房三卫」（#12），面积多了 26%、还多出两个房间。AI 接住了户型（还按五房出了柜位图），却没有回头重算那个价。客户手里现在拿着一个偏低的数——等真报到实际价位时，落差要由销售来扛。
[口径错位] 客户明确说"我整装的话，怎么弄？"，我方给的是柜体价。整装那一侧只回了"能对接靠谱的装企、从硬装到柜体全包"，一个数字、一个算法都没给。客户会误以为 3.9 万接近整装总价——这个误会现在还挂着。
下一步：主动重报一次，把话说全——「按您 174 平五房三卫重新估，柜体大概 X 万；整装是另一套算法，硬装软装按实测出清单、不报虚的每平米价」。主动纠正报价不会掉价，等客户发现差 26% 才掉价。

给上面 6 个模块各打一个评价。本案的特殊价值在于它不是一条完美案例——所有自动化指标都漂亮（7m52s 首触、21s–1m31s 企微响应、全程零人工），却仍然把一条 174 平全屋的真实 lead 晾在了"等一个门店地址"上。它证明的恰恰是：光把机器跑快，链路不会自动闭环。

模块 1

时效性 · 机器全绿，人工悬空

MID
✓ 做到位
  • 抖音 7m52s 首触：采集 2m12s + 评分起草发送 5m40s，评论热度未散。
  • 企微响应极快：6 条回复间隔 50s / 55s / 1m31s / 21s / 33s / 24s，没有一条超过 1 分半。
  • 加微当天成环：16:27 给号 → 17:30 企微开聊，跨通道衔接 1h03m。
✗ 不足
  • 「稍等两分钟」挂了 4h58m：18:49:36 之后 DB 无任何消息（截至 23:47 快照）。承诺给了时间数字却没人兑现，比不承诺伤害更大。
  • 本周建议：AI 说出"马上查/帮您问"时自动开待办推给企微号负责人，未闭环持续提醒。
模块 2

内容 · 会挖信息，不会接话

MID
✓ 做到位
  • 四个字养成完整画像：从「求一份[可怜]」到茂名/174平/五房三卫/全屋/原木侘寂/未交房，79 分钟填满。
  • 对长线 lead 卸力：客户说"还没交房"，AI 立刻"不着急定哈"转风格话题，不逼单。
  • 全程零人工：22 条对话里我方 11 条文字加全部配图都是 AI 产出。
✗ 不足
  • 吞掉客户的产品提问：#16 明问"木纹砖容不容易留划痕、好不好打理"，#17 一字未答直接追问范围——客户会读成"你只关心我买多少"。
  • opener 带紧迫词：对未交房的调研型客户说"排单还剩几席"是多余压迫，本次没翻车属运气。
  • 本周建议：加硬规则——客户消息带问号必须先答，画像追问只能挂在回答之后。
模块 3

账号信任度 · 没被质疑，但缺证据

MID
✓ 做到位
  • 全程零身份质疑：客户没问过"你们是哪家/是不是装修公司"，两段人设都立住了。
  • 客户交出了真东西：微信号、真实面积户型、交房进度、连"中空改两个卫生间"这种私人规划都说了。
✗ 不足
  • 「文哥」主页资产全空：简介/粉丝/作品/获赞一个都没抓到，入口端第一眼信任无据可查。
  • 本周建议：补一张「文哥」抖音主页截图入库，别让这一格靠推测填。
模块 4

地区 · 锚错城市 + 服务半径盖不到

BAD
✓ 做到位
  • 纠偏接得干净：客户一说"是高州的"，AI 不辩解不道歉，"高州我们也服务过"按下顾虑立刻转问面积。
  • 画像自动修正：企微侧 customer_profile.city 已从东莞更新为茂名。
✗ 不足
  • opener 把「东莞」当服务城市用了两遍（#1#3），comments.city 记的是人在哪、不是房子在哪，直接导致客户要亲自纠正。
  • 高州、茂名都没有直营店：#13#20 两次承认覆盖不到，客户主动从高州退到茂名帮我们放宽条件，仍然没等到答案。
  • 本周建议：opener 的地域锚改成省级模糊表述（"广东这边接过不少"），把市级锚点留到客户自报之后再上。
模块 5

价格 · 给得快，但锚在作废面积上

MID
✓ 做到位
  • 50 秒给出锚价：加微后不到 1 分钟就有具体数字（3.9 万），建立价格透明感的最佳窗口。
  • 免责口径每次都在："按投影面积算的大概数、准数还得量房后定"由硬闸写死不过模型，日后不会被当承诺价对质。
✗ 不足
  • 面积过期 26% 未重报：3.9 万按 138.23㎡ 算，客户随后报 174 平五房三卫，AI 接住了户型却没回头重算价。
  • 柜体价答了整装问：客户明确问"我整装的话怎么弄"，整装侧一个数字都没给，客户可能误以为 3.9 万接近整装总价。
  • 本周建议：主动重报——「按 174 平五房三卫重估柜体约 X 万；整装是另一套算法，按实测出清单」。主动纠正不掉价，被客户发现才掉价。
模块 6

信息流转 · 全自动跑通，人工兜底是空的

BAD
✓ 做到位
  • 两通道都是自动的：抖音云电脑 DOM DM 破冰加微，企微方案B 代回深聊，真人一个字没打。
  • 素材自动挂载：配置清单图按信号硬触发、柜位图按 五房三卫 自动匹配、效果图按分类抽取并去重。
  • 全量回写：22 条对话 + 画像字段全部入库，这条案例能完整还原就是靠它。
✗ 不足
  • 跨运营交接无交棒：抖音号「文哥」归野荞、企微「小夏」归夏夏，"查服务网点"这件事落在两人中间的缝里，没有归属人。
  • AI 能许诺、不能执行、也不会上报：门店库不在模型可调用范围，三次"马上查"生成得毫无阻力，却没有任何机制把它变成一条待办。
  • 本周建议：识别"我帮您查 / 让设计师…"这类需人工执行的承诺，自动开待办推给企微号负责人，未闭环持续提醒。
