2.1 触发评论 · 明确购买信号「可以发个清单吗」

在一条 120 平软装搭配视频底下（号源名「Ly__」、类目「本地号」），她写了 「可以发个清单吗」。这句话姿态很明确：①主动索取 —— 求清单是伸手要东西，不是旁观；②指向具体交付物 —— 「清单」= 软装/定制方案的物料清单，是真实的购买调研动作（comment_type_reason = 求清单为购买信号）；③阶段信号 —— 出现在软装搭配内容下，说明她大概率正在给某套房做规划。这本该是一条被优先触达的中意向 lead。

同行闸误伤 · 这条本该被过滤却推进成了真客户
系统判 0 分 · 无关，若严格按分数过滤，这条 lead 就直接被丢了。但它实际被触达、且推进到我方伸手要微信 —— 说明触达决策没被 0 分卡死（被人工或其它放行规则放过），结果证明放行是对的。这反过来暴露同行判据太糙：只凭「定制」二字 + 带行业词的昵称就判同行，会把跨行业消费者一并误杀。建议同行判据加白名单/二次确认（如区分「装修同行」与「其它行业带定制字样的消费者」）。

2.4 跟进文案 · 认新房 + 本地信任 + 拆项 + 借平台限制要 vx

跟进 DM 在 transcript（#3）。客户回「新房」后，AI 两分钟内把加微钩子递了出去，一句话做四件事：①认房况「新房正好规划全屋」顺着她的回复往下推；②本地信任「郑州这边我们有师傅覆盖，上门量尺出方案都能安排」把本地服务坐实；③拆项标注建专业「见光板和封边这两项很多家是单收的，清单里我把它们拆开标了」；④借平台限制要微信「抖音发不了文件、发图也会压糊，你报个vx号给我」。

「东西已备好 + 平台发不了」是标准加微钩
跟进没有继续追问规格（那会拖慢节奏），而是直接抛出一个只差一个微信号就能兑现的价值物（带图拆项清单）。「抖音发不了文件」是真实的平台限制，用它当要微信的理由既自然又不像索取。这是把客户往加微推进的标准打法 —— 只是本案客户暂未回复微信号，钩子递出去了，鱼还没上。

复盘 · 各模块做到位 / 不足

这个项目哪里做得好，哪里还能拧紧

给上面 6 个分析模块各打一个评价。good = 已达可复用标准；mid = 能用但有压缩空间；bad = 是这条链路的明显短板。

模块 1

时效性 · 4 分钟触达

GOOD
✓ 做到位
  • 新鲜评论走实时通道：评论 03:33、破冰 03:37，系统侧几乎零延迟。
  • 收到回复 2 分钟就跟进：客户 07:06 回「新房」、07:08 清单钩子就到。
✗ 不足
  • 首响 3h29m 属客户作息：清晨留言、睡醒才回，系统不可控。
  • 要守住这条链路：本案证明系统能秒级响应，别让评论在采集回扫里变老。
模块 2

内容 / 评分 · 同行闸误伤真客户

BAD
✓ 做到位
  • 破冰借视频主题 + 郑州本地：接住她刚看的 120平软装、立本地服务感。
  • 反问门槛设对了："新房还是翻新"一个词能答，她确实回了「新房」。
  • 加微钩子标准：认新房 + 本地信任 + 拆项透明 + 借平台限制要 vx。
✗ 不足
  • 评分误伤：同行闸凭「定制」字样把跨行业真客户判 0 分·无关，严格过滤就丢了这条 lead。
  • 判据太糙：只看带行业词的昵称/签名，区分不了"装修同行"与"其它行业消费者"。
  • 本周建议：同行判据加白名单/二次确认；钩子已递未上鱼，二次跟进补价格锚。
模块 3

账号信任度 · 小星账号资产盲区

BAD
✓ 做到位
  • 账号命名对路："小星·全屋定制"是装修号该有的名字。
✗ 不足
  • 主页资产一项都没抓：简介、头像、粉丝、作品、点赞全空，无法评级。
  • "暂未给微信"疑点排不掉：账号可信度不足可能是卡点之一。
  • 本周建议：补小星账号主页截图，先把这个盲区填上。
模块 4

地区 · 省+市在手且用上郑州

GOOD
✓ 做到位
  • 省+市两级在手：河南 + 郑州，comments.city 有值。
  • opener 两次用上郑州："本月活动期排单""这边有师傅覆盖上门量尺"，本地信任被话术锚定。
✗ 不足
  • 同城徽章未触发：号源市缺位（is_same_city=null），本地信任只靠话术、没系统背书。
  • 建议：回填号源市，让同城这层从"话术声称"升级成"系统证明"。
模块 5

价格 · 拆项透明、零数字

MID
✓ 做到位
  • 拆项标注建专业："见光板 / 封边很多家单收"点破隐藏收费、显得懂行。
  • 价格数字后置：不在调研阶段抛价，避免被单价吓退或陷入比价。
✗ 不足
  • 全程零数字有悬念：客户可能想先摸个价再决定给不给微信。
  • 破冰带紧迫词："本月活动期排单还剩几席"对刚聊两句的客户略显催促。
  • 本周建议：二次跟进补无压力价格锚（同户型大致区间）、弱化催单语气。
模块 6

信息流转 · writeback 完整、子通道未标

GOOD
✓ 做到位
  • 3 条消息全落库：opener + 客户回复 + 跟进都在，去重与 stage 准确。
  • sender 按 DB 判定：非启发式推断，reconcile 负担为零。

  • 子通道未入库：ADB / WDA / 网页版无 error_message 佐证，需手动判定。
  • 云电脑仍是规划态：5 步迁移已画，未跑通。
