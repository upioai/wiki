ACT 01 · 起点 2026-05-24　10:45 CST

她把诉求切得很窄 ——「只 X 可以不」

在深度空间装饰王工（号源池里的一个桂林本地装饰公司号源，category_v2 = peer_decoration，属同行号源）发的那条工地实拍视频底下，她打了 14 个字加一朵 🌹（原评论）。其他「求联系」类案例（空间向量「我房子准备装修怎么联系你」、刚子道场「能联系下你吗」）开口都不限定服务范围；这条主动加了一个约束 ——「只设计软装」。3 件事同时暴露：①「只 X」= 她已经在筛供应商、分项目预算、不再处于"广撒网"阶段（用排除性副词的客户已经过了"什么都问问"那一段）；②「怎么联系」+「🌹」= 礼貌的直接，软度很高（柔性买家信号）；③ 跨省（安徽 IP / 桂林号源） = 不在意工厂在哪，关心能不能做。

视频信号与评论信号的明显错位：视频是工地实拍 + 靠谱工长方向（硬装 / 施工管理），看这种通常是装修中后期、要监工或验房的人。但她问的是软装（家具 / 灯具 / 窗帘 / 软饰）。这说明她不是顺着视频内容找匹配服务，而是顺着「桂林装修 / 装修公司」hashtag 大词刷下来，看到这家公司在做装修就直接问她真正想问的（软装）。视频内容是引流入口，不是需求匹配 — 软装是一个独立诉求，她需要的是有人能只接软装单。原评论的「只」字是关键 — 假设没有这个字，破冰话术会落入泛泛的「能做装修」回答；有了「只」，AI 立刻知道不要谈柜体 / 不要谈硬装，必须先在第一句话里把「软装我们能做」明确说清楚。

主页画像 inference · 重复商业型评论 · 同一 sec_uid 在 2026-05-19 还问过另一条视频：「火锅店正在找装修公司，能设计吗🌹」（intent_score 33 / 低意向，触线-餐饮商铺装修）。两条评论的句式高度相似（「X 可以不 / 能 X 吗」+「怎么联系」+ 🌹），看起来是同一个人在不同场景下的标准问询模板。

3 种可能解读：① 她确实有多重身份（自家住宅软装 + 商铺装修都在筹备）；② 她是装修中介 / 经纪人，帮不同需求方挂网询价；③ 她是设计师，找硬装承包方搭软装方案。本案不下定论 — 但 ACT 04 加微后第一句话应当探一下身份（"是您自家还是有其他项目？"），customer_profile 可以留 multi_inquiry_signal = true 标记。

6 个可复用的话术原则

1
客户切了范围，AI 的第一句话必须先回答「能不能做」。其他案例的破冰首段都先复述视频内容再绕回业务；本案视频方向不匹配（工地实拍 vs 软装诉求），AI 复述视频会显得答非所问。客户用「只 X 可以不」这种排除性副词时，她已经在筛供应商、分项目预算了，第一句话必须先确认「软装我们能做」+ 拆细（"全案搭配、灯具窗帘家具都包"），让她知道这家公司是真做软装、不是挂个名。「只 X」是高决策度信号，破冰要镜像式收窄。
2
省级 micro-context 要跟业务子方向匹配，不能套模板。空间向量案例是「广东回南天 → 柜体选耐潮板材」（接硬装）；本案是「梅雨季安徽湿气重 → 布艺窗帘别选密织」（接软装）。同一个"南方梅雨季"现象，对应到柜体是板材防潮、对应到软装是布艺透气。气候 micro-context 必须穿过业务子方向折射出去 — 不要拿"广东客户多"这种泛泛话凑数。判断标准：客户读到能想到自家装修的具体场景（南方人都体验过梅雨季窗帘闷味）。
3
触达延迟 4h 内 = 求联系类评论的回复率分水岭。本案完整链路 3h 49m（评论→DM），客户次日回了；空间向量链路 2 天 5h，5 天后仍无回应。同样是求联系类高意向评论，触达延迟跟回复率强负相关。原因：评论新鲜时客户对承接方仍开放，2 天后基本被别家先联系了。后续工程：①「联系/怎么联系/电话/微信/v/wx」关键词命中评论加 cron 加速通道（写入即评分）；②标 priority=urgent 优先消费。本案的 3h 49m 应当成为分析 cron 的 SLA 基线，不是上限。
4
「加微信」必须被 sanitize 替换成「加 v」 — v20 prompt 还有漏网。本案 opener 第 ③ 段写的是「加微信发你具体方案」，违反 feedback_dm_use_v_not_weixin 规则（2026 抖音风控对"加微信"高敏感）。Langfuse v20 prompt 在 examples 里很可能残留旧文案，prompt 改造没穿透到所有 branch。后续工程：① grep Langfuse v20 prompt 的所有 examples，统一替换"微信"→"v"；②在 sanitizeReply 加 string-replace 兜底层，作为最后一道保险。本案客户回复了 — 但若被抖音 IM 风控扫到敏感词，发送 / 投递率会受影响，不能依赖运气。
5
5 人本地流程发完必须立刻 mark-contacted，不然去重失效。5 人本地流程（饭粒/野荞/夏夏/阳阳/Gus）发 DM 不走 message_queue，发完必须立即调 scripts/mark-contacted.ts：标 lead_claim consumed + UPSERT conversation + INSERT message + 反写 comments.status=contacted。不调的话 4h 后该 sec_uid 会被其他同事重新 claim 重发（lead_claim 过期 + 无 conversation 阻挡）— 客户当天可能收到两条同样的破冰，体验差 + 触发风控双倍风险。本案客户已经给微了，重发会非常尴尬。这是5 人本地流程的最大单点漏洞，应该把 mark-contacted 嵌入 send-one.py 的成功回调里，让运营不需要记得手动调。
6
客户给自己的 v + 不寒暄 = 决策权集中型的标准收尾形态。本案、七七笑嘻嘻、草莓圣戴三条共享一个回复模板：「加 v / v 号 / 加微」 + 一串字母数字，没寒暄、没问价、没验证。三条的共同特征：①评论里就已经主动框定 scope（「只设计软装」/「我需要装修怎么联系」/ 直接报需求）；②决策权完全在客户手上、不需要分工对接（对比空间向量「给老公 v」的分工型决策）。识别信号：评论用排除性副词（「只」「直接」「具体」「就要」）+ 求联系动词（「怎么联系」「联系下」「电话」）= 决策权集中型大概率。话术 SOP：①破冰要短、显式给加 v 入口；②加 v 后第一句话不重复破冰、直接进具体方案；③customer_profile 标 decision_type = sole，与 decision_split 区分。
