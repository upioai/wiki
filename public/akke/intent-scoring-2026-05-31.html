Akke 项目 · 截至 2026-05-31 · 「意向」= 一条评论背后这个人有多想找装修服务

SECTION 01意向四档标准

每条评论由大模型打一个 0–100 分，再按阈值（注：分界线）落到四档。档位决定我们要不要去私信这个人：

高意向
≥ 80
明确想做/问联系/问价 → 优先私信
中意向
≥ 60
有兴趣在了解 → 池子枯竭时补用
低意向
≥ 30
弱相关 → 一般不碰
无关
< 30
凑热闹/同行/玩梗 → 丢弃
两层架构：分数不是单靠大模型——是「大模型给基础分」+「代码层兜底纠偏」两层叠出来的（下一节展开）。这样既用上模型的语义理解，又不让它的抖动漏掉明显的买家。
SECTION 02一条评论怎么算出分
评论内容→ 大模型判
类型 × 具体程度→ 基础分→ 代码层兜底→ 最终四档

第一层 · 大模型基础分：按「评论类型（咨询产品 / 知识提问 / 闲聊）× 具体程度（高 / 中 / 无）」给基础分。例：产品咨询 + 高具体 = 高分。

第二层 · 代码层兜底（两个方向）：

规则触发动作
强买家信号 → 强制升高意向命中「怎么联系 / 加微信 / 在哪买 / 怎么买 / 能做吗 / 店在哪 / 我要一套 / 预约出方案」等强信号 且 是装修话题不管模型打多少，直接拉到高意向
同行 → 判无关识别出是同行装修号 / 房产博主（聊房·说房·看房 等后缀）直接标无关，不进池子
为什么要第二层：抽样发现大模型的「具体程度」判断会把「多少钱 / 怎么联系 / 能做吗」这类压成低/中——但这些恰恰是漏斗最深处的买家信号。60%+ 的真高意向曾被误压到中意向，所以加代码层强行救回来。
SECTION 03从上周一(5/25)到现在的演变
5/26 上午
意向 prompt v3.2 + 配方系统
目的：把"评分配方"（各档阈值）做成可切换的几套，方便快速试不同高意向池大小；同步改版 /leads 筛选页。效果：从此能一键换阈值做实验。
5/26 上午
v3.3 — 修 3 类误判
prompt 层修正 3 类典型判错。效果：减少明显误标。
5/26–27
阈值实验
原版高意向 ≥80；试过降到 ≥70（想把高意向池做到 1,500–2,000）；又试把"产品类"基础分 60→62 微调（刚好把 product+中具体 推过 80）；目前回到 80 / 60 / 30。效果：找池子大小与质量的平衡点。
5/26 起
代码层「强买家信号强制升高意向」
根因：模型把"怎么联系/在哪买"压低了。措施：加确定性规则强行救回。效果：找回被误压的 60%+ 真高意向。
5/26 起 持续
同行过滤持续补后缀
不断补「聊房/说房/看房」等房产/同行博主特征 → 判无关。效果：减少同行污染高意向池。
SECTION 04当前效果 · 下一步

当前阈值：高 ≥80 / 中 ≥60 / 低 ≥30 / 其余无关；高意向再叠代码层强买家信号兜底 + 同行过滤。

⚠️ 诚实标注：上述每步的「效果」多为设计意图 / 抽样观察，尚缺每次改动严格的 before/after 量化对比。要给硬数字，需对同一批评论跑新旧配方做 A/B 回测（Langfuse Datasets 已有 harness）。
优先级动作为什么
高对意向配方做严格 A/B 回测现在"效果"多是定性，需量化每次阈值/规则改动的精确率与池子大小变化
中持续扩充强买家信号词 + 同行后缀这两层是兜底，词越全漏判/误判越少
中意向打分与号源打分联动高意向集中在少数号 → 反哺号源 A/B/C 分级
