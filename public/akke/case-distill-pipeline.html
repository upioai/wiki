转化对话背后的逻辑

一位客户在抖音或企业微信发来一句话，到 AI 决定回什么、发什么、把人往哪儿引导之间，背后是一整套系统在做判断。这份说明把它拆开讲清楚：AI 的话术本事从哪来、一条消息进来怎么一步步处理、凭什么保证"不该说的话"发不出去、又怎么盯着"把客户约到店"这个目标往前推。

① 案例驱动

话术来自你们的金牌销售，不是网上通用客服模板——传一张聊天截图，系统自动学到里面的产品信息、说话口吻、决策招式。

② 确定性护栏

是不是图片、是不是回声、有没有乱报价——判断题全归代码确定性把关；AI 只负责把话说得像真人。

③ 会说也会发图

文字之外还能随手发效果图、户型布局图、配置清单、官方海报，承接体感更像一位真人顾问。

④ 记得住 · 引到店

跨多轮记住客户的城市/面积/预算，话术盯着"约到店"推进，每天自动量一遍转化漏斗。

一句话总览

把金牌销售的本事复制给 AI，让它 7×24 接待每一个客户。系统自动从案例里学话术、逐条判断该怎么回、该发图时发图、记得住每个客户，还盯着把人引导到店。全程一排确定性护栏兜底，涉钱 / 存疑的内容留给运营把关——没过关的，碰不到客户。

02

一条消息进来，AI 怎么决定回什么

这是整套系统的核心。一条真实客户消息进来，到发出一句回复之间，系统一步步在判断。贯穿始终一句话：凡是代码能确定判定的，绝不交给 AI 自觉——"该不该回、能不能发"都有确定性护栏兜着，AI 只负责把话说得像人。

先认个底：每通对话都有「阶段」

系统给每通对话记一个阶段，决定这一轮用什么口吻、走哪套规则。

破冰 · 首次开场 → 培育 · 多轮接话 → 临门 · 谈价 / 约到店

两条硬规矩：① 回复客户时永远走培育口吻，绝不拿"开场白模式"去接客户的话；② 临门谈判阶段默认转人工（怕一句拍错就丢单），只有纯价格问答放行自动发。

第一步：还没惊动 AI，先过一排「确定性护栏」

很多场景根本不用麻烦 AI——代码一眼能判、直接确定性处置，又快又不会说错。这排护栏决定这条消息要不要回、用什么方式回。

拦 客户发的是 [图片] / [视频] / [语音]

系统读不到里面的内容，不硬着头皮瞎回，直接转人工——运营看了再回。

↓

拦 这条"回复"其实不是客户说的

可能是我方自己发的话被系统抓回来了，或是视频文案被误当成客户消息。认出来 → 不回，避免"自己跟自己聊"。

↓

确定性接 客户把微信号发过来了

不靠 AI 自觉——写死一句"添加您啦"确定性回过去（还提醒去微信服务号点通过），把人稳稳接到微信侧。

↓

确定性接 加微已完成，客户还在抖音说话

纯确认（"好的""嗯嗯"）→ 静默不回（阵地已转微信）；有实质新问题 → 受限收尾并引导去微信，不再没完没了地培育。

为什么先堆这么多护栏这些都是高频又容易翻车的场景。判断题交给代码，"一眼假"的错误就永远不会发出去；AI 只在"真得开口好好聊"时才上场。这是"AI 会不会说错话"这个担心最主要的答案——大半被前置护栏挡在了发送之前。

第二步：真要"开口聊"，AI 也照一套「骨架」来说

到这一步才调 AI。但 AI 不是自由发挥——有一套明确的骨架框着它，保证每一轮都走"先答再推进、简短、像真人"的路子。

每轮开口第一件事 · 三步决策

1判客户意愿先看客户是抵触、试水、配合、还是已经想加微信
2按意愿选打法给干货 / 只问一个细节 / 抛钩子要微信 / 直接给号
3先正面答原问题"问 A 答 B" 是信任流失第一杀手，必须先答再推进

再叠三层骨架，把话说得像真人

骨架管什么举例
节奏 一回合只发一条、简短、不像机器人分条列点、他多短你回多短 真人金牌销售平均一个回合才 38 字
场景速查 十几条"读到 X 信号 → 走 Y 话术"，常见问题有现成好答句 问板材：直接给"三档怎么选 + 你最在意哪个"
发之前自检 发出去前逐条自查，任一不过就删了重写 有没有反问、超没超长、有没有乱给号、有没有瞎编经历

碰到特定客户，还会盖一层更硬的分场景骨架。最典型的一支——索取型客户（上来就要清单 / 手册 / 资料 / 案例）：

分场景骨架 · 索取型客户

这类人全程走「资料交付四步」，而且全程禁反问

① 证明有货（点两个具体的坑）→ ② 完整版还在我手上（整份带图，先给一小块）→ ③ 说清为什么得加微信（抖音发不了文件、发图会压糊）→ ④ 收尾是加微信的引子，绝不甩个问题回去。

为什么死磕"禁反问"：这类客户你回他一个问题，等于又给他派了个活，他要的是"现在就给"——越问越容易流失。所以给个加微信的引子，赶紧把人接到微信侧。

聊得越久越关键：AI 记得住客户

长对话最怕"失忆"——聊到几十轮，把客户前面说的城市、面积、预算忘了，又重复问一遍，体感立刻掉。系统专门做了记忆能力来兜这件事。

✓ 记得住关键事实

确定性画像

  • 客户说过的城市 / 面积 / 预算 / 房型等，系统确定性地抓下来记住
  • 不靠 AI 自愿记——确定性抽取，该记的一定记得住
✓ 撑得住长对话

滚动摘要

  • 把前面聊过的老对话压成一段摘要随身带着，聊到几十轮也不丢上下文
  • 记忆在回复之后后台异步更新，不拖慢发送速度

第三步：AI 写完不直接发，两层护栏先把关

AI 会犯的错就那么几种固定形状，代码逐条兜——能修的当场修好再发（不静默丢单），修不动的才转人工。

哪一层拦什么怎么处置
自查修复 生成崩（空 / 乱码 / 错语言）、索取型里冒出反问、超长、自曝私人生活 修好再发 先重生成，仍不行就确定性修——砍掉反问、压回长度、删掉穿帮句，不丢单
置信度门 疑似回声、长度异常、索取型仍带反问、命中负面 / 投诉、临门谈判阶段、把热客户晾凉的客套话 转人工 任一命中 = 不自动发，落库等人接手

最后：两个出口

过闸

自动发

  • 草稿标为通过，运营端接手后就地发出
  • 价格问答全放开：具体报价也直接发，不再卡等审批
没过

转人工

  • 躺库里、不自动发一句可能翻车的话
  • 滞留超 30 分钟 / 4 小时 / 24 小时 自动推提醒催人接手

03

不只发文字：该发图时发图

承接客户光靠文字不够。系统现在能在回复里随手发图——效果图、户型布局图、配置清单、官方海报，客户体感更像一位真人顾问。发不发、发哪张，同样是代码确定性判的：怕乱发被当成群发素材，反而伤信任。

能发的六类图

背后是一整个素材库（效果图上万张、装修干货图与原创资料若干），系统按客户当下在问什么，挑对的那一类。

类别是什么什么时候发
效果图 上万张实拍案例图，按「风格 × 空间」分好（现代简约 × 卫生间…） 客户提到风格 / 空间，或泛泛要图；同类里随机抽，避免每人收到同一批
知识图集 装修干货长图（避坑清单 / 流程图…），带我方水印 客户问"有没有清单 / 参考图"，按主题精准命中
装修资料 原创的硬装 / 预算 / 验收 / 主材资料长图 硬装类问题分流到这里
户型布局图 按几室几厅出的柜体位置示意图 客户报了户型、或发来户型图（见下）
配置清单 柜体配置 + 价格口径长图 客户明确要"配置单 / 报价单"
官方海报 品牌海报（价格表 / 环保承诺…），一张只发一次 客户话里命中相关话题时

怎么挑那一张：AI 先出文字，发图在文字之后按优先级"一轮只发一类"地兜——避免又刷屏又拖慢发送：

客户发来图 → 只发户型布局图 否则→ 硬装问题 → 发资料长图 → 要配置单 → 清单图 → 问干货 → 知识图集 → 泛泛要图 → 效果图

官方海报是另一条独立线，客户话里命中相关话题就挂上。这些判定全是确定性规则，没有一步问 AI——所以"该不该发图"稳定可复现，不会今天发、明天不发。

户型图识别 · 唯一用到视觉能力的地方

客户把自家户型图拍来 → AI 视觉读出「几室几厅」→ 选对应的标准布局示意图

这是发图链路里唯一让 AI 看图的一步：读出户型有几个卧室、几个客厅，发那套户型对应的现成布局图。它不自己画图、也绝不猜承重墙——读不准就老实说不知道、或退回按已知情况选，宁可不发也不瞎给（跟全篇"一眼假的错误不发出去"一个脾气）。

企业微信（能发图）
图和文字一起到，客户在聊天里直接看到效果图 / 布局图 / 清单。
抖音私信（发不了图）
平台限制：抖音发不了文件、发图会压糊。所以抖音这条不发图、只备料，等客户转到企业微信再发。

现状与下一步企业微信侧"文字 + 发图"的承接闭环已经跑通；对客户主动发来的图片，识别能力正在持续接入、覆盖面继续扩大。

04

把客户引导到店：从"催"到"数"的闭环

企业微信通道的业务目标就是把客户引导到店。系统不只在话术上往这个方向推，还把"约成到店"变成一个能数出来的指标——让每一次话术优化都看得见效果，而不是凭感觉。

推 到了临门阶段，每条回复顺一个到店钩子

但"用哪套话术"是动态判的——客户说一句"我再看看"，信号过去了就降温回培育口吻，绝不变成一条条催的机器人。既往前推，又不硬催。

↓

数 确定性判断客户是不是真"约成了"

必须有确定时间（明天 / 周六 / 下午三点）或明确应约（"好，那我过去"）才算数；"哪天过去方便"这种反问不算——那还没约成。判据刻意收紧，宁可少记，也不让"到店转化率"这个指标从第一天起就不可信。约成后记入档案、并绿卡提醒对应运营。

↓每天定时汇总

✅ 每天推一张「五档漏斗」到工作群

每一档都带"占上一档的比例"，哪一级在漏一目了然。

新建会话 → ① 客户开过口 → ② 聊起来了 ≥3 句 → ③ 聊得深 / 到临门 → ④ 约成到店

量出来，优化才有靶子把每一级都量出来后，卡在哪一环一眼就能看到，话术资源就能投到最该攻的那一级。日报还会自动挑出"客户说了话、我方还没回"的会话提醒运营，避免漏接——这比埋头改话术更该先做。

Langfuse 的真实角色 —— 不是它在"调用案例"

案例的检索、排序、拼装全在代码里做（读数据库表）。Langfuse 只干两件事，都不碰案例数据。

✗ 它不做

不负责检索案例、不负责编排调用。模板里只有一个"放示例的空位"，填什么由代码从数据库算好塞进去。

✓ 它只做

模板托管（存话术骨架，PM 后台改、30 秒生效）+ 事后观测（记录喂了哪几条案例、花了多少钱）。Langfuse 挂了也不影响话术生成（有兜底）。
