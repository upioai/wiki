01

案例入到哪里：一份案例，散在三层表

案例的原料是企微 / 微信的聊天截图。别以为它只进一张表——同一批案例其实分三层存，各管各的用途。这是最容易搞混的地方。

📱 原料：聊天截图

两条口进来：① 人工整理成结构化文件；② 销售自助上传截图，系统用视觉模型（qwen2.5-vl）自动 OCR 识别文字。

↓入库
第一层 · 原始底座

整段对话原样存 enterprise_sales_cases

把整段对话一字不落地存起来当"仓库底座"。注意：它本身不直接上线，AI 话术不会直接读它，必须先蒸馏成下面两层才管用。

↓蒸馏后进入
第二层 · 上线示例

金牌「客户问 → 销售答」问答对 conversation_examples

让 AI 学口吻——照着金牌销售当时怎么回答，模仿着说话。这层是真正喂给线上话术的。

↓再蒸馏出
第三层 · 决策规则

金牌决策原则 decision_rules

让 AI 学招式——"遇到 X 情况，该做 Y、别做 Z"。这层杠杆最高，比堆示例更能改变话术风格。

02

怎么蒸馏：4 步手动脚本 + 2 道人工闸

从底座提炼成能上线的示例和规则，是一条手动流水线——每步都是运营敲命令跑的脚本，没有定时自动跑。用的是便宜的分析模型 deepseek。

脚本① 抽「金牌回合」

从整段对话里，让 AI 挑出最见功力的"客户问 → 销售妙答"回合，顺手把微信号等隐私脱敏，输出成一份草稿文件。

↓
🔍 人工闸 ①：人眼审草稿——重点看说话人有没有标反（OCR 靠左右气泡猜谁是销售，会猜错），脱敏干净没。这步绝不能跳。
↓

脚本② 灌进示例库

把审过的草稿写进 conversation_examples。

↓

脚本③ 蒸馏成决策规则

把高分示例 + 成单/流单的对话喂给 AI，提炼出"什么场景该怎么做"的原则。

↓
🔍 人工闸 ②：先空跑（dry-run）看一遍规则合不合理，确认了再正式写进 decision_rules。
↓写库完成，线上自动生效

✅ 线上话术下次生成时自动读取，无需重新部署

灌完库就生效，不用发版、不用重启。

04

话术是怎么"调"出来的？想改话术，该动哪一块？

企微 / 抖音是不是自动注入案例、Langfuse 到底管什么、话术 prompt 由哪几层拼成、想改一句话该动哪一层——五个问题一节答完。

① 生成话术时，案例是自动注入的 —— 是

企微好友代回
身份壳用中性"销售"、用"您" · 走 /api/wecom/chat/reply
抖音私信 / 评论
身份壳"小艳"、用"你" · 走 generateOpener / dm-auto-reply
两条通道共用同一个 chatReply 函数
每次生成话术都会自动把三层表拉出来，挑最相关的 3 条示例 + 4 条决策原则 拼进去。运营发话术时不用手动挂案例，灌一次库两条通道都生效。

② Langfuse 的真实角色 —— 不是它在"调用案例"

这里要纠正一个常见误解：案例的检索、排序、拼装全在代码里做（读数据库表）。Langfuse 只干两件事，都不碰案例数据。

✗ 它不做

不负责检索案例、不负责编排调用。你在 Langfuse 里看到的模板，只有一个"放示例的空位"，空位里填什么，是代码从数据库算好塞进去的。

✓ 它只做

模板托管：存话术模板的骨架，PM 能在后台改、30 秒生效。事后观测：记录这次喂了哪几条案例、花了多少钱。Langfuse 挂了也不影响话术生成（有兜底）。

③ 那真正的调用路径长什么样（全在代码里）

代码 chatReply() → getClient() OpenAI 兼容客户端 → OpenRouter chat completions API → 出话术
Langfuse 只旁挂两件：① getPrompt 出模板骨架 ② observeLLM 收 trace / 成本

拼 prompt、挑案例、算相关度、发请求——全在代码里完成；Langfuse 不碰案例数据、不发请求、挂了也不影响出话术。

④ 话术 prompt 由这几层拼成（叠进一个 system prompt）

1人设 PERSONA小艳 / 身份 · 口吻底子
2语气 STYLE用「你 / 您」· 长度 · 一次一问
3客户记忆 MEMORYcustomer_profile 跨会话
4称呼 + 客户画像这通对话已知的
5品牌档案brand_profile 品牌 / 卖点
6产品知识 knowledge_documents案例来的
7决策原则 decision_rules案例来的
8few-shot 示例 conversation_examples案例来的
9Langfuse 模板骨架4 步结构 + 规则 + 自检 + {{examples}} 占位

案例在哪一块？案例不是单独一层——蒸馏后分散注入到第 6、7、8 这三层：产品事实 → 知识、招式 → 决策原则、金牌问答 → few-shot 示例。所以「喂案例」能影响话术，靠的就是这三层里的案例料；其余几层是人设 / 语气 / 记忆 / 品牌骨架，跟具体案例无关。

⑤ 每次改话术，改的到底是哪一块？

「改话术」不是一件事，是四件事——落在不同地方、生效速度完全不同。先想清楚你要改的是哪一类，再去动对应的那块，别一上来就找代码。

一句话记住能不改代码就别改代码——「AI 说得不对」十有八九是案例喂得不够（灌库解决）或模板规则没写清（Langfuse 后台解决），这两条当天就能改完看效果。只有人设、语气底线、硬拦截这三类才必须动代码，那就得走 PR + 部署，快不了。
