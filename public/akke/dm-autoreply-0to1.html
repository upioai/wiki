原则怎么落地

04 · 下一步待做的优化

从"能跑"到"跑好、跑稳、跑量"

🟡
根治短回复崩兜底（解锁 both 的前置）重点
客户回 ≤5 字时 chatReply self-check 把草稿全削成"网络卡了"兜底——这是 both 现在不敢开的根因。先治 self-check，再谈全自动。当前热 lead 靠人工改写 draft 手动发兜。
🟡
抖音号反查覆盖率 + 发送号搜索健康重点
两面卡铺量：①无缓存号回退昵称搜=撞名风险，提高 enrich 命中率(预热缓存)、无号宁可不发；②发送号连日高频搜+发会被风控降权(搜空→wrong_user)，需冷却降频/换号轮换护住搜索健康。
🟡
全自动(MODE=both)小范围灰度重点
暂缓——前置是上面两项(短回复兜底 + 号反查/搜索健康)。治好后再单账号开 both 跑几天，盯 webhook 回执看话术质量+发对率，再多账号铺开。
🟡
chatReply 根治"重复开场白"重点
回复别再照搬开场白开头(你好…哈哈这条挺多人催)；调 prompt / 跟进态去问候化，让回复像真人接话。直接影响客户观感。
○
inbound 回写自动化
目前靠 capture 扫列表；check-replies 补云电脑通道，减少对"窗口停在私信列表"的依赖。
○
长回复取全文
列表预览截断 ~60 字；长回复点进会话 dump 全文再喂 LLM，避免上下文缺失。
○
捕获端过滤状态行/时间戳
扩黑名单 + 正则前置过滤「在线 / 关闭会话 / 时间戳」，状态行一律不写库，止住白烧 LLM 的噪声草稿（铺量后最高频的脏数据来源）。
○
列表翻页捕获
capture 当前只读可见会话行；加滚动/翻页，避免回复多时漏掉靠下的。
○
各机校准两坐标 + 转化漏斗
每台云电脑量AKKE_C_DM_INBOX(私信图标)+AKKE_C_DM_FIRST(第一个会话，撑开列表)；部署照 部署指南。铺量后补回复率/加微率统计，量化双向闭环价值。

05 · 2026-06-23 更新 — both 全链路打通

🎉 整条 both 链路打通 — 三通道同机串行齐活

06-21 还卡在「both 暂缓 · 半自动」，06-23 把根因补齐后 both 全自动真打通：客户回私信 → 自动捕获 → 生成（带护栏口径）→ 在收件箱就地点开 TA 发（不搜号） → 回写。同机 DM 首触 + DM 自动回复 + route-B 三条按窗口锁串行、自动回复最优先。

全部齐活清单（小文 / 野荞 云电脑实测）

通道 / 配置状态
DM 首触（派单发私信）跑 · claim=2 · 窗口锁 on
DM 自动回复 both（本报告这条）mode=both · 每 1min · capture 13 行
route-B 潜在触达起 · watch+consume 两窗口
RC 反评关（同窗口跑 route-B 必须关 RC，否则抢窗口）

both 护栏口径客户没问不提价、问了原样发（PR #484）

三通道分配：同号同窗口、分时抢占

一台无影只有一个抖音前台窗口，三条都靠它驱动 → AKKE_WINDOW_LOCK=1 串行。同一 lead 任一时刻只在漏斗一段，不在「人」上撞、只在「窗口」上抢；客户一回复就出二触池、进自动回复，天然不重碰。优先级按时间敏感度：

优先级通道为什么
① 最高DM 自动回复（both）客户正在对话里等，回复延迟直接砸转化；接窗口锁置 .dm-want、route-B 让位、轮内排在首触前（PR4）
② 次DM 一触（首触）新增高意向 lead，走量主力
③ 垫底route-B 二触捞已 ghost 的人，窗口空 + 鲜视频才跑；自动回复 / 首触一来就让位，最坏等一个在飞单位

就地回复 替代 搜号发：绕开 wrong_user / 风控降权

06-21 的「按抖音号搜人 + 号核身发」撞上 发送号搜索被风控降权（怎么搜都搜空 → wrong_user，见 §3）。06-23 自动回复改走 在私信收件箱直接点开 TA 就地发——对方已在你收件箱、刚回过你，压根不用搜号，结构性绕开撞名与搜索降权。

今日两个卡点（实机暴露 → 当场修）

卡点根因修复
capture 只读 1 行 / 就地回复 no_row：收件箱明明 10+ 会话，脚本只认出 1 行，要发的人全「找不到会话」 会话行靠「名字 + 时间 + 预览」三连识别，时间正则 _TIME_RE 认「昨天 / 天前」却漏「前天」；收件箱里发了 2 天没回的会话时间全是「前天」→ 全军覆没 补「前天」+ 日期格式（PR #495 + gist 已分发）
私信列表撑不开：点完私信图标后，再点「第一会话」撑开列表那一下点空了 AKKE_C_DM_FIRST 归一化坐标量偏（879 落到屏幕偏右、点空），左侧会话列表没渲染 重量坐标 879→717（实测第一会话头像位）→ capture 1 行→13 行
capture 时效太松 / 占窗口：旧 12h 节流远非「回了就回」 红点门控扫描零 LLM 成本，旧 12h 大节流没必要 默认 12h→3min，小文实测压到 1min（AKKE_DM_AUTOREPLY_INTERVAL=60）
坐标 + _TIME_RE 两个根因都补上后，小文云电脑 capture[红点门控] 从 1 行 变 13 行，both 抓回复 + 就地发链路全通。下一步真实验证：等真有客户回私信，盯日志出 未读 M>0 + [inbound] + [reply] sent（不再 no_row）。
