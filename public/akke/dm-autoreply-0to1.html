关键设计原则

原则怎么落地
大脑在云端无影只读屏+发送，话术/护栏/判断全在 Vercel chatReply，无影不跑 LLM
复用现成、不造轮子捕获复用反评的列表读取脚本；发送复用首触的"搜人+号核身+发"链；新增仅一个编排脚本
独立车道、零干扰独立表 + 独立 RPC，串行窗口锁排队，不抢首触/反评/二次触达的账号与窗口
开关分层云端总开关 + 无影支线开关 + capture/both 模式，可逐级灰度，一键全停

04 · 下一步待做的优化

从"能跑"到"跑好、跑稳、跑量"

🟡
chatReply 根治"重复开场白"重点
回复别再照搬开场白开头(你好…哈哈这条挺多人催)；调 prompt / 跟进态去问候化，让回复像真人接话。直接影响客户观感。
🟡
抖音号反查覆盖率重点
无缓存号时回退昵称搜=撞名风险。提高 enrich 命中率(预热缓存)，无号宁可不发也不昵称硬搜。决定能否安全铺量。
🟡
全自动(MODE=both)小范围灰度重点
先单账号开 both 跑几天，盯 webhook 回执看话术质量+发对率，再多账号铺开。从"半验证"到"敢全自动"的关键一步。
○
inbound 回写自动化
目前靠 capture 扫列表；check-replies 补云电脑通道，减少对"窗口停在私信列表"的依赖。
○
长回复取全文
列表预览截断 ~60 字；长回复点进会话 dump 全文再喂 LLM，避免上下文缺失。
○
列表翻页捕获
capture 当前只读可见会话行；加滚动/翻页，避免回复多时漏掉靠下的。
○
各机校准两坐标 + 转化漏斗
每台云电脑量AKKE_C_DM_INBOX(私信图标)+AKKE_C_DM_FIRST(第一个会话，撑开列表)；部署照 部署指南。铺量后补回复率/加微率统计，量化双向闭环价值。
🟡 = 本周重点（直接卡"能不能安全铺量"）；○ = 增量优化。
