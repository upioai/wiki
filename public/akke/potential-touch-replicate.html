潜在触达「路B」复刻教程

给同事 · 事无巨细 + 雷点 ｜ 最后更新 2026-06-17 ｜ 源文件 docs/runbooks/potential-touch-route-b-replicate.md
当前在跑的路B：无影云电脑一台机常驻「实时监控 + GUI 三连」——对你账号已 DM/RC 过、≥1 天没回的高/中意向 lead，一发新视频就自动点赞 + 评论1(评视频) + 评论2(搬DM)。老的派单二触 cron 已停，别再用。

0 · 先搞懂架构（不懂这个，排障全是瞎猜）

两个 Python 进程，同机各开一个窗口常驻：

进程干什么靠什么脆不脆
监控 watch
_realtime_touch_watch_wuying.py		调抖音网络接口盯关注流，逮 lead 新视频→写本地队列网络 API，不碰屏幕稳
消费 consume
_realtime_touch_consume_wuying.py		tail 队列→查话术表→调 GUI 执行器在抖音 PC 上点赞+评论鼠标键盘+屏幕+焦点脆

GUI 执行器 = douyin_comment_grounded.py，像真人一样移鼠标/打字/点按钮/截屏验证（点赞评论抖音没接口，只能扮真人）。它脆就脆在屏幕/焦点/坐标一变就出错。
回写：本地表模式下触达写本地 comment_log_YYYYMMDD.csv，需摆渡回 mac 跑 mark-second-touch.ts 入库（端点直连回写还没做，见雷点④+roadmap）。

1 · 前置 · 机器与账号

  • 无影云电脑（个人版即可），抖音 PC 客户端已登录你的 messaging 账号（跟你 AKKE_ACCOUNT_ID 绑定那个）。
  • 分辨率锁 2560×1600（坐标按这个标定，换分辨率全点歪）。
  • 输入法切英文（中文输入法会把评论打成拼音/吞字）。
  • 关 OS 休眠 = 让 Windows 别自动睡觉（默认闲置会自动睡眠/关屏/停盘→脚本全停）。下面 4 条把「多久后自动睡/关屏/停盘/休眠」全设成 0=永不（PowerShell 跑一次，幂等）。注意：只管 Windows 系统层，无影平台层深夜挂起 powercfg 管不到（雷点⑨）。
powercfg /change standby-timeout-ac 0
powercfg /change monitor-timeout-ac 0
powercfg /change disk-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
  • 账号参数（找 PM 一次性下发）：AKKE_ACCOUNT_ID（你的 messaging 账号 UUID）+ AKKE_ORG_ID。
    例 · 野荞：AKKE_ACCOUNT_ID=81cc9678-9b53-413b-9f40-7964341f4af1（小文（野荞）·cloud_pc）｜ AKKE_ORG_ID=00000000-0000-0000-0000-000000000001

1.5 · 🔴 头号前置 · 关注覆盖（不做这个，监控逮不到任何人）

监控盯的是你账号的「关注流」——只有你账号关注了的人，他发新视频才会出现、才被逮到。 池子里的人如果你没关注，他发一百条你也逮不到。
  • 关注哪些人 = 你池子里的人 = 已 DM/RC 触达过 · 对方没回复 · 且主页有内容（有视频可监控/可评论）的高/中意向 lead。主页空的（不发视频）= 监控逮不到、也没视频可触达 → 排除。
  • 复刻第一步 = 把这批人用你的账号一次性关注掉（一个一次性的初始化任务，关一遍就好）。
  • 关注【写】动作被抖音反爬挡死：raw API 吃 403、Playwright 喂空白页——别试。唯一通路 = 无影 GUI 原生点关注：_follow_grounded.py（搜人→OCR 身份门→点关注→校验）。GUI 点关注有日限 ~30/批防风控，池子大就分几批跑完，但只做这一次（followed.json 跨天去重、连 5 失败早停）。
  • 覆盖率别用 account_follows 表测（只收脚本点的关注，手动/自然关的永不进表 → 报 0% 是假的）。
  • 老号（500+ 关注）大概率够、不用盲关；但同事新号关注覆盖往往不足，必须先补关，否则监控空转。

2 · mac 端的料 · 你自己账号的池子（每人一套，不通用）

潜在触达对象 = 你自己账号 DM/RC 触达过、≥1 天没回、高/中意向的人。所以池子、话术表、关注 全是你账号下的、跟别人不通用——同事 A 的池子对同事 B 没用。

生成涉及 second-touch-worklist.ts（按你的 AKKE_ACCOUNT_ID 出名单）+ _gen-realtime-touch-table.py + 转换，目前由 fanny/PM 用你的账号跑、生成好给你摆渡。你拿到 3 份你账号专属文件：

文件内容
special-follow.json监控池（你账号 DM/RC 过·≥1天没回·高/中意向 sec_uid 名单）
realtime-touch-table.json评论2话术表（每个 sec_uid → 搬你当初发 ta 的 DM 原文）
dy_cookie.txt你抖音账号的 cookie（监控调接口用）

⚠️ 换池必须同步重生成话术表（雷点⑪）。只换池子不换话术表 → 评论2 退空。

3 · 无影端文件清单 全放 C:\akke-wuying\wuying-dm\

脚本 4 个（gitignore，走摆渡）：_realtime_touch_watch_wuying.py · _realtime_touch_consume_wuying.py（必须带 300s 超时版，雷点③）· douyin_comment_grounded.py（必须认 douyin 标题版，雷点①）· douyin_dm_grounded.py
数据 3 个（§2 摆渡来）：special-follow.json · realtime-touch-table.json · dy_cookie.txt
配置：.env（见 §4）

4 · .env 必备项（无影本机）

SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...

AKKE_C_LIKE=... AKKE_C_BACK=... # 坐标按 2560×1600 本机实测，换机重测（雷点⑫）

5 · 启动 · 两个窗口（PowerShell）

监控窗口：

cd C:\akke-wuying\wuying-dm
python _realtime_touch_watch_wuying.py --max-age-min 20 --pool special-follow.json
  • ⚠️ --pool 必须显式带（默认找中文名 special-follow-饭粒.json，你的叫 special-follow.json，不带就报「lead 池不存在」，雷点②）。
  • ✅ banner 应是 … lead池 NNN … 触达闸 发布<=20min，NNN 两三百。

消费窗口（另开一个）：

cd C:\akke-wuying\wuying-dm
python _realtime_touch_consume_wuying.py
  • ✅ banner 应是 … 本地表模式(无DB) … 自动发。
  • ❌ 不要加 --api-base（端点模式连不上 Vercel，雷点④）。

摆位：抖音 PC 前台最大化，两个 PowerShell 窗口拖副屏/最小化、别盖在抖音上（雷点⑦）。

6 · 验真发（消费日志/返回0 都不可信）

  1. comment_log_YYYYMMDD.csv 的 status 列 = sent 才真发；send_unverified/focus_fail/wrong_user/no_msg2 都不算。
  2. executor-runs.log（执行器分阶段落盘）= 看到「♥ 已点赞」+「✅ 评论已验证」才对；一堆「重夺焦点 3 次仍非抖音」= focus_fail（雷点①）。
  3. 铁证（人工）：你账号看抖音「喜欢」列表有没有那条视频 + 另一个号/无痕看评论区有没有你的气泡。
  4. 入库：comment_log 摆渡回 mac，跑 pnpm tsx scripts/mark-second-touch.ts --from-comment-log（一份只跑一次，非幂等）。

7 · 🔴 雷点清单（全是踩出来的血泪）

① 窗口标题 douyin vs 抖音 → 整条 focus_fail
抖音 PC 标题重启后可能从中文「抖音」变英文「douyin」。执行器只认 '抖音' 会判「前台不是抖音」→ 全跳过。用认两个的版本。验：findstr /C:"douyin' in t" douyin_comment_grounded.py。

② 监控池文件名不匹配 → 「lead 池不存在」
watch 默认找 special-follow-饭粒.json，你的叫 special-follow.json → 启动必须 --pool special-follow.json。dir special-follow* 看实际名。

③ 执行器无超时 → 一条卡死冻全天
旧版调执行器没超时，一次 GUI 卡住无限等（实测冻 10 小时、全天 0 真发）。用带 AKKE_EXEC_TIMEOUT_SEC（300s）的版本：超时自动 kill+跳过+落盘 executor-runs.log。

④ 端点模式 --api-base 不能用（机房连不上 Vercel）
无影到 akke.vercel.app 不通（HTTP 000）。开了不但拉池子每轮失败、领号也失败→把触达全跳过（比本地表模式更糟）。只用本地表模式。

⑤ PowerShell 粘贴长命令/长 URL 会被换行截断
长行常被塞换行 → curl: (2) no URL specified。对策：一行一行单独贴；下大文件用 paste.rs 短链。

⑥ 摆渡铁律
一律 curl.exe（带 .exe）写原始字节；别用 iwr/裸 curl（= Invoke-WebRequest，UTF-8 中文会转码弄坏）。下行用 gist raw 直链或 paste.rs 短链；上行 curl.exe -s --data-binary "@文件" https://paste.rs。每次核字节数；paste.rs ~384KB 截断、偶尔 500（重试）。

⑦ 抖音必须真前台 + 触达期间别碰无影桌面
执行器全程控鼠标键盘，你一动就抢前台→点歪/漏字/focus_fail。

⑧ wrong_user：无昵称的「未知客户」搜不到
客户没真昵称（显示「未知客户」）时拿它当搜索词搜不到→落「(非主页)」。只能用抖音号搜（身份门 #342），目前会跳过。

⑨ 平台层深夜挂起 powercfg 管不到
powercfg 只关 Windows 层；无影平台层在你断开远程桌面后挂起整台 VM（个人版无解）。深夜发布仅 1.8%，接受白天档，保傍晚 17–21 高峰（占全天 45%）。

⑩ VL 验证双向误判：开 LENIENT，别开 TRUST_SEND
VL 既有假阴也有假阳。AKKE_COMMENT_VERIFY_LENIENT=1 仍真验证、减假阴——开它。AKKE_COMMENT_TRUST_SEND=1 点了就算、会把真失败刷成功——绝不开。

⑪ 换监控池 = 必须重生成话术表
监控池和话术表是两个文件；只换池子不重生成 → 评论2 退空（no_msg2）。看话术表 LastWriteTime 是否晚于最近换池。

⑫ 坐标按本机分辨率实测，换机重测
AKKE_C_* 是 2560×1600 标定的，换机/换分辨率用 _capture_pos.py 重测。
