02操作手册

A · 抖音号精准搜索（已上线，运营这样用）

第一次装一次（每台 Mac，约 1–2 分钟）：

cd ~/Akke && git pull
bash worker/scripts/wuying-dm/setup-enrich.sh   # 看到 ✅ 装好了 就成

以后：照常导出名单（或跟 Claude 说「云电脑发 N 条」），CSV 自动带抖音号，不用再敲别的命令。导出末尾会打印：

✓ 名字 → 抖音号 xxx      # 拿到了，精准搜
· 名字 查不到 → 回退昵称   # 跟以前一样，不丢人
范围（会查谁）：只查你每次导出要发的那批人（高+中意向 leads），发到谁查谁，不全库批量。查过的进共享库，三人复用、不重查。
查不到约 1/3，正常：绝大多数是用户自己没设过抖音号（接口查成功了但没号）→ 无解，回退昵称，忽略即可；少数是临时限流 → 可救，放量再加固。都不影响发送。

B · 无影按状态分方案（决定每个人现在能用到多少）

无影状态现在怎么做
已跑通吃满全部能力：① git pull + 跑 setup-enrich.sh，导出自动带抖音号；② 正常发 DM；③ 多次触达建好第一批就能用；④ 当标杆帮没跑通的人远程调通。
没跑通两条路并行：
• 路1·修无影（治本）：让跑通的人远程帮修——显示设置关分辨率自适应 + 全屏不缩放 + 锁 2560×1600；锁不到就锁能锁的最大固定分辨率，再跑 --capture + measure_nav.py 重采坐标；锁完别再缩放窗口。
• 路2·手机兜底（不停工）：修无影期间改用手机 ADB/WDA 发，不依赖无影；手机走 sec_uid 直达，连抖音号都不需要。产量不停。
03多次触达 · 规则（已定稿）
是什么：给「昨天 DM 过、到今天仍没回」的高+中意向用户，自动在 ta 视频下点赞 + 公开评论，把人勾回来看私信。用抖音号精准定位。
维度定下来的规则
目标昨天 DM、今天没回的高+中意向用户
动作脚本全自动点赞 + 公开评论
话术公开评论只走「轻钩子+勾私信」（回应视频内容 + 暗示私信过 + 软钩子）；报价/正经话术留私信，不公开晒；生产模型 qwen3+Langfuse 现起
评哪条视频近 3 天有新动态→评新视频；无→评最新历史视频 + 引用原始评论（不放弃）；完全无视频→退回补 DM/挂观察
时机每天定时跑 1–2 次（v1）；优先「发新动态后」，否则按当初抓到评论的高峰时段
节奏规则阶梯（不打分）：没回→触达1→隔 3–5 天触达2（换视频/角度）→转低频养着（1–2 周/次，不删）；回复/回访/点赞→升级；拒绝/删评/拉黑→停
账号各运营自己的号（发过 DM 那个）触达，不设专号；盯每日动作额度
送达门v1 不卡（视频评论是独立通道，DM 没送达照样通知到）
04三个独立判断（背后的考量）

① 「没回」不该减分 —— 它是噪音，不是意向信号

把「没回」当意向降级依据，有三重陷阱：

  • 长决策：全屋定制是几周到几个月的大决策，真高意向也可能现在不回（比价、等交房、跟家人商量）。减分淘汰=把「只是还没到点的真买家」在犹豫期扔了。
  • 测量脏：抖音陌生人私信大量没被看到（进请求箱 / 被静默限流）。「没回」很多时候在量送达失败，不是意向——拿它减分=给自己的发送失败打分。
  • 代价不对称：误杀一个真买家=丢一单大几万；减分省下的只是一次触达额度。宁可坚持也别轻易丢。

「没回」该驱动的是节奏（放慢、设次数上限防刷屏），不是意向降级。真正该减分/停手的是硬信号：拒绝、删评、拉黑、明说不需要、同行号。

② 公开评论不晒报价 —— 内容跟着渠道可见性走

视频下的评论是公开的。把私信那套报价搬上去：像广告（易被判垃圾删评、连累账号）、同行全看见（报价/打法泄露）、对方尴尬（视频又不是讲装修的）。公开评论的目的不是再推销一遍，只是「重新进视线 + 勾去看私信」。所以：公开场合只做轻钩子，实质（报价/谈单）留私域。

③ 不上打分引擎，用规则阶梯 —— 别要假精确

打分意味着给每个信号配权重，而配对权重需要数据（哪个信号真预测成交）——现在没有。硬上打分=假精确：一个看着科学、系数全靠拍脑袋的数字，反而会被过度信任、调错旋钮。规则阶梯简单、透明、好改。顺序是：先用阶梯攒「触达→结果」数据，够了再升级成校准过的打分。数据在前，打分在后。

05什么做 / 什么不做 · 为什么

做（✓）

做什么为什么
抖音号精准搜索根治无影搜名字撞名/搜错人，还能救回改了名的用户
共享缓存（查一次三人复用）抖音号是用户固有属性，查一次存库，零重复打接口、避风控
导出自动补（焊进脚本）运营不用记/敲命令，没装环境也柔性跳过不挡发送
视频点赞+评论做二次触达独立于私信的新触点，DM 没送达照样通知到对方
各运营用自己的号触达身份连贯（发过 DM 的人再点赞=强化关系）+ 触达量摊到 3 个号降风控

不做（✗）

不做什么为什么
不在公开评论晒报价像广告、同行可见、对方尴尬；实质留私信
不「没回就减分」没回是噪音信号（没看到≠没意向），长决策行业易误杀真买家
不上打分引擎（用阶梯）没数据校准权重，过早打分=假精确；先攒数据再说
不批量预热全库抖音号一天才发 ~20，全库 95% 用不到 + 压风控；懒填（发到谁查谁）够用
不设专「采集号」做触达陌生身份跟 DM 对不上 + 风险集中在一个号
不做分钟级实时监控新动态常驻轮询重、有风控；v1 每天定时跑 1–2 次够用
反查不放云端（Fly/Vercel）cron该接口在服务器机房 IP 被抖音封，只能本机/无影跑
06卡点 & 待办
前置·卡点
无影 GUI 修通。多次触达要全自动点赞评论，依赖无影；没跑通的人先按 02-B 修或走手机兜底。
待开建
多次触达功能（需求 PR #93 已定稿）。监控新动态 → 抖音号定位 → 点赞+评论 → 话术生成。等无影通了开建。
待解决
「没回」的测量：抖音无已读回执，「今天没回」可能是 DM 没送达。v1 不卡（视频触点独立），但影响以后「判断要不要放弃」。理想是只对「送达确认 status_code==0」的 DM 做——但当前无影/手机发都不解码 status_code，需后续补。
放量加固
临时失败别当「无号」缓存：当前限流/cookie 失败会被存成「查过无果」、下次不重查。量小没事，放量时改成只缓存真无号、失败不缓存 + 多账号摊 + 错峰。
