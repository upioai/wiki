② 核心转折 · 「破冰报全套价」→「破冰不报价，按问句类型拆分支按需注入」

v38 → v41 回滚最大的变化不是"少说一句话"，而是整个报价节奏被拆成两段：

阶段v38 时期 · 一锅端v41 + 后期 · 节奏分两段
破冰阶段 4 个价格锚点同时砸 · 4 数字 + 品牌串 + 限量一套 不报具体价格；按客户问句类型挂 1 个钩子 + 反问
客户首次接收 868 / 568 / 品牌 / 限量 4 件事同时进入 → 防御性强 1 个钩子 + 1 个反问 → 顺手回一句的门槛低
nurture 阶段 破冰已亮底牌，nurture 没料 客户问价时 dm.nurture.system 的 buildPricingPrompt 自动注入 4 段价格铺垫：① 品质背书 ② 零售 868 锚点 ③ 装企供货价对比 ④ 限时活动价 568 + 截止 + 名额
价格四要素 破冰强制全套（缺一 false retry） 留给 nurture · 客户主动问价时自动注入无需再改代码
结论：v41 回滚的本质是"价格信息的发送时机"被往后挪。破冰只负责把客户钩进对话，价格信息的具体落地放给 nurture——这也是为什么 v41 起需要拆出价格的 6 个子分支，按客户问句类型决定破冰阶段要不要碰价格、碰到什么程度。

③ 当前 v43 价格 6 分支拆解

⑥ v43 R 兜底 fix 详解 · commit 7652e071 改了什么

6.1 改动 1 · 后置硬拦单价泄漏 hasRBranchPriceLeak

在 src/lib/llm/signals.ts 新增函数 hasRBranchPriceLeak(opener, comment)：

// (R) 分支抢路兜底 — 评论命中 isDataRequestComment 但 LLM 跨段被 (RE)/(H)/(A4) 抢走
// 抛了"284 一平 / 5 万起"硬价格。(R) 段硬规明文禁报价、但 hasUnauthorizedTotalPrice
// 只拦总价、单价不在其管辖范围。
const HARD_PRICE_REGEX = /\d+(\.\d+)?\s*(一平|元?\/?㎡|元一平)|\d+\s*[-~–至]\s*\d+\s*万|\d+(\.\d+)?\s*万(起|元)?/;

export function hasRBranchPriceLeak(opener: string, commentContent: string): boolean {
  if (!isDataRequestComment(commentContent)) return false;
  return HARD_PRICE_REGEX.test(opener);
}

在 generateColdOpener retry loop 中调用（src/lib/llm.ts 第 2522-2532 行附近）：opener 命中 → 标 self_check_failed 强制 retry。

实测数据：v43 上线后审计 28 条 A 类「该走 R 没走」opener 里 4 条 (14.3%) 真抛硬价。此闸闭合后该 14.3% 直接归零。

6.2 改动 2 · 补「材料包」regex

v43 实跑审计发现 9 条「(一键三连，)求材料包」evaluator 自报走 (R) 但代码层 regex 没命中。_DATA_REQUEST_REGEX 新增 材料包：

const _DATA_REQUEST_REGEX =
  /888|来一份|发一份|给我一份|发我一份|给我发|发我|给我|来个|要一份|要个|发一下|发个|发份|清单|手册|攻略|链接|资料|材料包|效果图|图纸|案例|参考一下|参考下/;

修后 isDataReq + LLM 自报一致，B 类「不该走 R 走了」9/9 全是材料包的根源消除。

6.3 同期 (R) 三模板权重调整 · 2:2:1 → 3:1:1

2026-06-23 运营反馈 B 模板骨架太死，同一视频下高频露脸 → 客户秒辨机器人。pickRTemplateVariant 槽位分配从 [A,A,B,B,C] 改为 [A,A,A,B,C]。同 seed 仍稳定（决定性 hash），但 B 命中概率从 40% → 20%。
