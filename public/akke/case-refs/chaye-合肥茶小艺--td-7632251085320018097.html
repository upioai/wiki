结论

这一条能确认的只有三件事：它讲的是「实体店」，它卖的是安吉白茶，它的评论区几乎全是想买的人。封面是四行绿底大字「实体茶店 / 用口感赢得认可 / 一杯好茶 / 自有说服力」，背景是店里的茶架和拆开的纸箱，角上有 Osmo Action 的角标，底部字幕「安吉白是吧」，像是店主或店员在跟到店顾客对话。入库判定命中的是「本行业主营内容」和「商家经营日志 / 到店接待」，没有命中发货记录，类型「服务过程」是按行业默认推定的。

评论区 21 条里 17 条有购买意向，占比 81%，三条里最高。和意向第二那条（上海闵行）比，这一条的意向结构偏「到店」：问店在哪的 5 条（「合肥哪，我也去买点」「实体店在哪？」「位置在哪」），多于问怎么买的 4 条；那条问店在哪的只有 3 条、问价占七成。标题和封面把「实体店」放在最前面，评论就跟着问地址。点赞 115，大约是同号前 48 条中位数（39）的 3 倍，在三条里最低，说明它不是靠流量带来的意向，而是看的人里想买的比例高。

为什么是这一条

可复制的结构（从封面、标题、评论能确认的）

  • 把「实体店」写进封面第一行。「实体茶店 / 用口感赢得认可」，和意向第二那条片中「实体店买茶不踩雷」是同一个立场，这里直接做成了封面。评论里问地址的比例明显更高。
  • 只讲一款茶。标题、话题都只有安吉白茶，评论里的问价「这个多少？」「这茶多少一斤？」不用再分是哪一款。
  • 对话片的痕迹。封面字幕「安吉白是吧」是口语，可能来自到店顾客的现场对话，和点赞第一那条「老熟客又来了」同属对话片；需要看原片确认。

不可复制的运气 / 还说不清的

  • 样本小。平台显示 33 条评论，判过 21 条。17 条意向里多条是两三个字的「价格」「位置？」「多少钱」，几条点赞都是 2，有可能是同一批人，占比 81% 不宜当成稳定的转化率。
  • 安吉白茶的上市季。约 4 月下旬发布，正是当季新茶在卖的时候，有人问「为什么实体店的安吉白茶要比网上的大」，季节关注带来的问价不是每个月都有。
  • 画面里有什么说不了。没有看原片，爆点到底在对话、在价格还是在冲泡，没法归因。

和上一版相比改了什么

  • 转写上云。本地 CPU 跑 Whisper 处理 2.5 小时素材要两个多小时，换成 Paraformer 接口后只要几分钟，费用 0.7 元，每月前 10 小时还免费。
  • 不再让人看素材。最耗时的「3 小时素材里找 9 分钟」交给模型出剪辑清单，人只审故事线。
  • 剪辑结果落成剪映草稿。不追求全自动成片，而是生成一个已经剪好的剪映工程，人在熟悉的软件里精修。剪映的人像特效、字幕样式、导出都能接着用。
  • 换脸分期。先用剪映特效保证效果，自建方案验证通过后再替换，避免一开始就卡在 GPU 环境上。
  • 人工集中到三个检查点：审故事线、审片、发布。中间步骤之间用一个 JSON 清单传数据，每步读上一步的输出文件。
  • 调用方式只用命令行和 API。这些工具都在本机或云端接口上，skill 直接调用，不必再包一层 MCP。MCP 只在跨系统时用：比如把每集的数据写进飞书多维表格，或把复盘页发布成 Artifact。

表外的前提

  • 主理人在镜头里要会说话。这条视频一半的价值在洋子的对白，不能外包，也不能 AI 生成。
  • 服务时长会变长。边做边讲、每步确认，单次服务估计多出 10–20% 时间。
  • 顾客授权。换卡通脸降低了顾客的顾虑，但肖像授权仍要签。
  • 预期按中位数定。新号要做到几十集才可能有存量观众。按同账号前 48 条点赞中位数 9.2 万定预期，不要按 116 万定。

这一集的特殊处理

  • 标语封面可以模板化。「实体茶店 / 用口感赢得认可 / 一杯好茶 / 自有说服力」这类四行标语，Claude 按品名和店的立场一次出 10 组（约 ¥0.2，估），封面那一步从里面挑，套同一个绿底白字样式。
  • 立场片要配地址。讲「实体店」的片子带来的是问地址的人，发布时挂门店 POI，评论置顶写店名和大致位置，复盘那一步把问地址的评论优先挑出来回。
  • 重采素材。这一条要按 README 用 collect.sh 7632251085320018097 重采一次（目录里现有文件是错的，重采前要清掉），再补关键帧、时间线和制作参数。
