§1 用户建模三要素：先立框架

"给用户建模"听着抽象，拆开就是三个能问出口的问题。这是对话式销售的通用骨架，不是 Akke 专属。

对话式销售 AI 要把一个陌生评论者养成到店客户，绕不开三件事：知道他走到哪一步、记得他说过什么、给得出他要看的东西。行业综述把这三者作为同一套系统的支柱——意图/阶段追踪、对话记忆、动态个性化ZoomInfo / MarketsandMarkets 2026。其中"记忆"这条被反复点名：反复追问同一信息的机器人，会在真正对话开始前就把信任耗光ZoomInfo Pipeline 2026——这正是 Akke 用户最常抱怨的"一看就是机器人"。

图1 · 用户建模三要素与彼此关系
WHO / WHEN
① 阶段评估
他在买家旅程哪一步？决定该用什么语气、推什么钩子
WHAT-SAID
② 跨会话记忆
他之前说过什么？避免二次触达重问面积/预算，守住信任
WHAT-GIVE
③ 专属物料
给他看什么针对性内容？以阶段+记忆为检索键挑物料
三者串联：①阶段 决定"现在该干嘛"，②记忆 提供"他是谁"，③物料 是"递出去的东西"。①②是检索键，③是被检索的内容——所以物料必须建在阶段+记忆下游。来源：行业综述 + Akke 现状映射。

每态由 Langfuse 可编辑的独立 system prompt 承载（PM 改 dm.<stage>.system）；流转判定目前由 LLM 分类驱动（classifyDecorationStage / decision_signal）。来源：src/lib/llm.ts:824–931 switch(stage) 分支核验。

关键设计：阶段不只换措辞，还换整套行为——破冰期反问要号、决策期才外发号，是写死在 stage 分支里的硬约束，不靠 LLM 自觉。

§4 跨会话记忆怎么跑（已落地 ~75%）

同一个抖音用户冷掉后被二次触达时，怎么"还记得他"——这是守信任的核心机制。

它解决什么：二次触达时重问"您家多大面积 / 预算多少 / 哪个城市"，是用户投诉最响的"一看就是机器人"信号——行业综述同样把"反复追问同一信息"列为信任头号杀手ZoomInfo Pipeline 2026。这条记忆机制就是堵这个洞。

§5 决策：复用现有 vs 另起炉灶

三块能力的数据载体都已就位且在生产跑，从零搭一套用户模型没有理由。

✓ 复用并扩展现有栈

  • 数据载体已就位：conversations.customer_profile / conversations.stage / conversation_examples 三张表都在生产里跑。
  • 已接生产主路径：阶段机 + 记忆已进 chatReply 主链路，每条回复都在用，不是旁路 demo。
  • RLS 隔离已踩过坑：memory.ts 已处理"null org 不能 fall-through 跨租户读"，隔离边界经生产验证。
  • 缺口是窄增量：挂现有地基下游即可，不动主链路。

✗ 另起炉灶搭新用户模型

  • 重复劳动：阶段/记忆/示例三张表要重造一遍。
  • 重做多租户隔离：RLS + org-scoping 的坑要再趟一次，memory.ts 趟过的全白趟。
  • 再踩一轮坑：token 爆炸、跨上下文串味这些已被现有设计规避的问题要重新发现。
  • 收益不抵成本：换来的"更全模型"边际价值低于重写代价一个量级。
判断：地基（阶段 + 跨会话记忆 + org 隔离）已浇好且经生产验证。在它之上加增量，比另搭一套"更全的用户模型"成本低一个量级，且不用重蹈隔离覆辙。

§6 缺口清单矩阵（增量补，不推倒）

承认缺口，但每个都是窄增量，挂现有地基下游，不需推倒重来。

图5 · 缺口 × 优先级 × 补法矩阵
缺口优先级补法
① 记忆浅合并、无字段级溯源 低优 memory.ts 注释自陈"which key came from which conv 需 schema change"。等到必须解释"这条物料为什么推给他"时再补 provenance，现在不补。
② 记忆不回放历史原文 别改 这是刻意取舍——防 token 爆炸 + 跨上下文串味。别为"更全记忆"去回放原文，那是退步不是进步。
③ 专属物料库（WBS 主题5） 真缺口 唯一真正的空白。但应建成阶段机下游，用已有 stage + customer_profile 当检索键，不另造一套用户模型。
④ 阶段流转靠 LLM 分类、无确定性转移规则 可下沉 有确定性信号的部分下沉到代码：已留微信 → decision、已邀约到店 → store_invite。省 token、更稳、可测。
四条缺口中只有 ③ 是真空白，其余是"低优可缓 / 刻意不改 / 工程优化"。无一需要推倒现有用户模型。来源：memory.ts 注释 + llm.ts stage 分支 + WBS 主题5 待建项。

§7 一句话收口

收口：用户建模的地基（阶段 + 跨会话记忆 + org 隔离）已浇好且在生产跑；任务4 是在地基上加房间（专属物料匹配 + 阶段确定性流转），不是重新打地基。复用扩展，别另起炉灶。
