装修场景该用哪套框架

上一页（① 框架横评）把 LangGraph / Dify / n8n / CrewAI 这些主流编排框架横着比了一遍。这一页只回答一件事：全屋定制 / 装修这个具体场景，到底该不该引入新框架？这是要拍板的一页——不是泛泛对比，是落到 Akke 自己的代码栈和真实瓶颈上做取舍。

结论
不引新框架。Akke 现有代码栈够用且更优；装修场景真正的瓶颈是微信通路选型（个微 vs 企微）和报价数据源，框架一行都帮不上忙。把选框架的精力，全投到主题4 通路 PoC 和主题3 报价数据上。

决策：不该引，三条理由

装修场景的需求实质，是把已经在抖音侧跑通的「评论 → 打分 → 起草 → 人审 → 触达」闭环，克隆到微信通路。这件事现有栈已经做到了，引框架不是加分项，而是先要拆掉一套已验证逻辑、再用更弱的抽象重搭——净亏。

理由 ① 编排环已全闭环
装修场景 = 把抖音侧 DM-reply 流水线移植到微信。五大战略 WBS 主题4 明写走 gate.ts / adjust.ts / chatReply 三件套移植——引框架反而要先把这套已验证的确定性逻辑拆开重接。
理由 ② 真瓶颈不在编排
WBS 的 0 号闸是「微信通路 个微 vs 企微 选型 PoC」，卡的是通道接入与合规，不是流程怎么连。框架解决不了一行通道问题——它假设你已经能发消息了。
理由 ③ 护城河会被冲掉
60+ 确定性硬绑信号、价格护栏 clamp、needs_human 闸门、多租户 RLS、单测覆盖——这些是现有栈的护城河。塞进通用可视化框架的节点抽象里，等于自废武功。

一句话：框架擅长的是「从零搭一条没人写过的流程」；Akke 的装修场景是「复制一条已经在生产跑稳的流程」。前者是框架主场，后者引框架只会增加迁移成本和回归风险。

何时才值得重评

「现在不引」不等于「永远不引」。下面三条触发线，任一长期成立，再把这个决策拿出来重评。当前三者均不成立。

触发线成立时该上的框架当前状态
运营 / PM 需自己改 workflow 拓扑，且频率 ≥ 每周 可视化编排（Dify / n8n）才有 ROI——把改流程的权交给非工程 不成立 拓扑由工程维护，改动月级、走 PR
分支爆炸到代码 if/else 难维护（>20 并行阶段 / 动态 DAG） LangGraph 图抽象才划算——显式状态图比手写状态机清晰 不成立 三阶段状态机（ice_break / nurture / decision）线性可控
要把「编排能力」本身作为产品，交付给租户自定义 需要可视化 builder 当产品功能（主题2 商户联盟走到这步） 不成立 当前编排是内部能力，非对外交付物

复评纪律：这三条都是「长期成立」才触发——偶发一次的复杂需求不算，别为一个边缘 case 提前背上框架迁移债。

不引框架，缺的几环用什么补

框架不是凭空火的，它打包了一组真实能力：可视化、回放、节点测试、人审、调度。逐条对照——Akke 现有栈这几环已经各有承接，且多数更细。

框架卖点Akke 现有补法引证
可视化编排 暂不需要——拓扑稳定、改动走工程。用 WBS / runbook 文档 + cron 清单描述流程足够 vercel.json cron 清单
回放 / 调试 Langfuse trace 已全覆盖且更细——手动注入 OpenRouter cost + runBy 指纹，能查到是谁、花了多少 src/lib/observability.ts
节点测试 现有 vitest 回归——闸门、派单原语、LLM 纯函数都有单测，改动即跑 gate.test.ts · dispatch/shared.test.ts · llm.test.ts
人审队列 needs_human 闸门 + dashboard 审批 + claim-leads RPC，已在生产跑（运营 5 人通道） claim_leads_batch / mark_lead_contacted RPC
调度 / 重试 Vercel Cron + worker poller 的 attempts / QUEUE_MAX_ATTEMPTS + 双指标心跳（存活 + 业务 delta） worker/services/queue.py

结论很直白：框架打包卖的五样能力，Akke 已经自有五样的对应实现，且 Langfuse 的 cost/runBy 指纹、确定性信号硬绑这类细节，是通用框架给不了的。引框架是「用更粗的抽象换走更细的已有能力」。

一句话给 Gus

别在「选框架」上耗精力。把这份力气直接投到主题4 的微信通路 PoC（个微 vs 企微，先把「能不能合规地发出去」这道 0 号闸打通）和主题3 的报价数据源——那才是装修场景真正卡住的地方。框架是流程稳定后的锦上添花，现在添的不是花，是迁移债。
