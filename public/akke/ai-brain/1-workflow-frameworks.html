类似工作流方案的框架

市面上做「线索触达 / 客服自动化」agentic workflow 的产品和开源框架都用什么？把主流框架摆上台横评——但在比框架之前，先把 Akke 自己已经有的编排能力盘清楚。先问缺不缺，再问选哪套。

结论
Akke 的「workflow 编排」本质已经是一条 代码驱动的状态机流水线，agentic workflow 的五个环节全覆盖。LangGraph / Dify / Coze / n8n 解决的是「快速搭 demo」，没有一套能装下 Akke 的多租户 + 人审闸门 + 反封号 + grounding 现有栈约束——引入任何一套都是负收益重构。

先刹一脚：这页要回答 WHETHER，不是 HOW

WHETHER 刹车。 今天已经有一批 agent 在调研同一题，但全都直接收敛到了 HOW——「我比较了 LangGraph / Dify / n8n 三套框架，建议用 X」。没有一个人先问：Akke 到底缺不缺一个新框架？ 这页的任务不是替换掉那个对比，而是补上它跳过的前置判断：先把现有栈摊开看清楚，再决定要不要往里塞框架。如果现有栈已经把五个环节都做了，那「选哪套」就是一道伪命题。

框架横评：四套主流方案，逐一对位 Akke

把市面上最常被拿来对比的四套摆上台，每张卡一句结论——它们到底能替 Akke 解决什么、又会撞上什么：

LangGraph · 负收益
不引入 代码内 agent 编排库。Akke 已经用 if/else 手搓出图了，引它=把现有分支改写成 graph DSL——纯重构、零新增能力，还要重接 Langfuse / Supabase。

Dify · 丢可测性
不引入 可视化 LLM 平台，适合从零的团队。把 60+ 确定性硬绑 / 价格护栏 / 阶段机塞进可视化节点，会丢掉现有的 vitest 回归能力——拿可测性换拖拽。

Coze（字节）· 合规红线
不引入 面向 bot 快搭、深绑字节生态、数据出境。容不下 Akke 的多租户 RLS + 反爬 / 封号治理 + 合规红线，业务约束直接撞墙。
n8n · 倒退一步
不引入 能替代的只有 Cron 触发层，但要重做 CRON_SECRET 校验 / trace / 双指标心跳，等于倒退，还多一个要运维的常驻组件。

关键判断：难点根本不在编排

四套全部解决的是同一件事——「快速搭一个 demo workflow」。可 Akke 的瓶颈从来不在编排这一层。真正的难点是 话术质量 / 护栏 / 封号治理 / 合规——
  • 话术质量：阶段感知 persona、称呼派生、grounding 真实评论，靠的是 prompt 工程 + vitest 回归，不是画布连线。
  • 护栏：60+ 确定性硬绑 + 价格护栏 + tool-call 泄漏清洗，是逐条沉淀的领域规则。
  • 封号治理：status_code 静默丢弃检测、stranger-DM 限流、Cookie 时效——抖音平台对抗，没有框架懂。
  • 合规：多租户 RLS 隔离 + 数据不出境，是法律边界，不是编排功能。
这四样，没有任何一套框架能代劳。换框架解决不了 Akke 的问题，只会在已经稳定的编排层上多压一个抽象、多一笔运维债。结论很干脆：保留现有代码驱动状态机，把精力继续投在话术 / 护栏 / 反封号上。
