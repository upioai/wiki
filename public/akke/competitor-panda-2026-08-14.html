00

一分钟看懂这是个什么东西

熊猫智汇是一套 to-B 的销售智能体平台：AI 替销售打第一轮电话，线索来自它自带的企业大数据库。它不控制任何设备、不碰任何社交平台。把它放进这份竞品序列里，最大的价值不是拆它，而是用它来校准我们对「智能外呼」这条赛道的判断。

本次拆解最重要的三条

  1. 21 页官方材料里，没有任何一页出现抖音、短视频、评论区、私信。它的技术底座是 ASR 语音识别 + 意图识别 + 对话管理 + TTS 语音合成 + 知识检索 + 智能质检，三根柱子里有一根是 WebRTC——这是一套语音通话引擎，不是社交自动化引擎。
  2. 它自带的 12 类大数据里，没有一类是 C 端消费者。企业 / 商标 / 政策 / 工厂 / 店铺 / 专利 / 招标 / 展会 / 产业 / 楼宇 / 海关 / 城市宏观——全是工商与产业侧。这直接决定了它能找到的是公司，找不到要装修的业主。
  3. 它把 08-10 那条结论修正得更准确了。08-10 写「智能外呼整条赛道零家跑通」——熊猫智汇推翻了字面意思（它有算法备案、3,000+ 客户、完整链路）。但结论方向没变，反而更清楚：外呼是一条成熟但不属于我们的赛道。
01

六段收口

前几家的六段都能拆得很细，因为它们都在解决「怎么把一台设备变成获客机器」。熊猫智汇的 ①–④ 会很短——不是材料不够，是这些问题对它不成立，而这件事本身就是结论。

①

用什么设备

口径电脑端（第三批调研文档里对它只有这一句：「熊猫智汇：电脑端」）。

推断0.7从产品形态看是 SaaS Web 控制台——平台总览页把「SaaS 架构能力」列为三根技术柱之一，B2B Agent 页的配图也是一个 Web 版「AI 外呼系统」工作台。不涉及任何被控手机或被托管的社交账号。

②

怎么控制 / 运行

实证技术底座是「超级熊猫 AI 对话引擎」，基于自研 1B RAG 引擎 + 大模型；环绕六个能力：ASR 语音识别 · 意图识别 · 对话管理 · TTS 语音合成 · 知识检索 · 智能质检。

实证三根柱子：自然语言处理 · SaaS 架构能力 · WebRTC（「基于 WebRTC 技术，实现优质真人与客户互动」）。这套组合说明了一切：它是一套语音通话引擎。0.9

执行动作＝打电话。封号风险这一项不适用——它不碰任何平台账号。

③

是否依赖电脑 / 插件 / 脚本

依赖被控设备 / 客户端 / 插件 / 脚本：全都不依赖。SaaS 形态。

真正依赖的是两样别的：① 外呼线路（合规的呼叫资源）② 号码数据（它自带，但对家装是 B 端号）。

④

实际操作流程

一条外呼流水线：线索数据云按行业/来源/优先级调度外呼任务 → 销售 Agent 打第一轮电话（ASR 听 + 大模型理解 + TTS 说）→ 意向分层 → 未接/待回访交给触达 Agent 排提醒 → 分析 Agent 汇总接通率、意向率、拒绝原因 → 数据看板按「老板 / 销售负责人 / 销售团队」三种视角订阅。

它还有一条 B2C 线，但拆开看仍然是：智能客服 · SCRM · 外呼触达（批量线索触达、活动邀约、老客唤醒）· 数据看板。「获客」在它这里等于「把已有号码打一遍」。

⑤

发送时间机制

与前几家不是同一类东西。它的调度语义是外呼任务调度：「按行业、来源、优先级和销售规则调度外呼与跟进任务」。材料里没有出现任何频率、间隔、时间窗的具体参数——这在电话外呼里其实是更受管的（有外部法规约束），但材料没提，合规细节是空白。

⑥

实测数据

21 页材料里没有任何价格。主体成立于 2024.01；自称 3,000+ 服务企业、30+ 渠道伙伴；有算法备案（九家里唯一）。详见 第 04 节。

03

线索数据云：它真正的壁垒，也是它的边界

12 类大数据里，没有一类是 C 端消费者

  • 企业 · 商标 · 政策 · 工厂 · 店铺 · 专利 · 招标 · 展会 · 产业 · 楼宇 · 海关 · 城市宏观——全部是工商与产业侧数据。
  • 唯一沾边的是「楼宇大数据」和「店铺大数据」——理论上能拿到新交付楼盘和门店信息，对家装是间接有用（找新交付小区、找建材商），但这是 B 端线索，不是 C 端业主。0.7

但有一条产品设计值得我们借用

  • 线索数据云里有一句：「真实业务对话和客户反馈可反向优化话术和分层策略」——把通话结果回流去改话术和分层规则，形成闭环。
  • 我们的对应位置是「检查机器人与客户的聊天示例」和「像带新人一样给机器人回答打分」，但目前是人看、人打分，没有把结果自动回流去调整意向分层的阈值。熊猫智汇把这件事写成了数据底座的四分之一，值得作为一个方向记下来。

05

对我们意味着什么：一条旧结论的修正

08-10 那条「不做外呼是对的」要加一句限定0.7

  • 原来的说法：「智能外呼：百应未发布、亿销云自认开发中——整条赛道零家跑通。」
  • 熊猫智汇推翻了这句话的字面意思：它把外呼做成了主体业务，有算法备案、有 3,000+ 客户、有从 ASR 到质检的完整链路。
  • 但结论方向没有变，反而更清楚了：能把外呼做起来的公司，客户是微众银行、平安、贝壳、万科这种有大量存量号码、按接通率算账的大 B。而有大有小是本地门店、靠公域捞陌生业主——连号码都没有，外呼无从谈起。
  • 准确的说法应该改成：「外呼是一条成熟但不属于我们的赛道；我们不做是对的，理由不是它做不起来，而是它的前提（有号码池）我们不具备。」这个说法在甲方面前比原来那句更站得住。

零假设：如果这条不成立，熊猫智汇的客户墙上应该出现本地生活 / 家装 / 门店类客户，或者它的 12 类数据里应该有 C 端消费者数据源。两样都没有。

所以它在比价名单里的位置

  • 大概率不进候选。七家做过机制拆解的里，真正和我们正面竞争的只有四家（水流 / 今立 / 知了 / 极域），尘锋是互补关系，熊猫智汇是不同赛道。
  • 这条对报价有直接含义：真正要对标的价格区间是那四家（2,980 – 290,000），不是九家全部。
06

还没问清的（优先级低——它大概率不进候选）

对熊猫智汇的 3 问

  1. 价格与计费单位？（21 页材料零价格）
  2. 12 类大数据里的「楼宇大数据」和「店铺大数据」，能不能拿到新交付小区的信息？——这是它唯一可能对家装有用的口子。
  3. 外呼的频率限制与合规资质怎么做？（材料完全没提，而这是外呼最受管的地方）

本页的证据分级：实证＝官方 PPT 页面上直接读到的；口径＝调研文档转述；推断＝组合判断，带置信度。局限：本页没有任何一屏真实后台——全部来自厂商自己的 21 页宣传 PPT，没有演示、没有沟通记录（第三批调研文档里对它只有「熊猫智汇：电脑端」这一句）。所以本页对它的产品能力判断证据强度低，但对它的赛道归属判断证据强度高（21 页里零抖音、12 类数据零 C 端，这两条是硬的）。
