01

结论先行：一个真问题 + 一个测不准

「通过率低」这句话里，其实混了两件性质不同的事。把它们分开，才知道各自该找谁解决。每个论断我都标了来源：实测 查库确凿 · 推测 系统备注里的猜测、未证实 · 未知 当前数据答不了。

● 真问题：请求发不出去 实测

已经动手加的 338 条里，230 条（68%）加不上，其中 216 条是「搜不到人」——在企业微信里按名单信息根本找不到这个人，请求连发都发不出去。这是漏斗最顶端、也是唯一板上钉钉的大流失，是当前最该攻的点。

● 测不准：通过率算不出来 未知

发出去的 103 条请求，系统里 0 条标成「已通过」。但系统检测「对方是否通过」的自动复查在 07-01 因为多次误判被改成了「保守不动」（见 §5）——所以这个 0 很可能是没检测出来，而不是真的没人通过。真实通过率现在无法从数据算出，需要人工核对企微好友列表才能知道。

🎯 一句话

能不能把请求发出去（真问题，68% 发不出去，需甲方一起想办法）和发出去后通过率到底多少（测不准，先得把统计补上）是两回事。在把「已通过」的统计补齐之前，任何「通过率 = X%」都不可信，包括这个 0%。别拿 0% 去评估效果。

🔑 为什么「搜不到人」这么多？一个已证实的事实 + 一个待验证的推测

已证实 实测：加企业微信好友主要靠「按手机号搜人」。而 401 条名单里只有 11 条（2.7%）带微信号，其余 388 条只有手机号可搜。触达完全押在手机号搜索这一条通道上。

待验证 推测：这 216 条失败在系统里的备注文案是「搜不到（可能没开手机号搜索）」。但要说明——这句「可能没开手机号搜索」是脚本预先写死的默认文案（wecom_add_agent.py），只要搜不到人就统一贴这句，并没有逐个去核实客户到底是不是关了手机号搜索。所以「客户没开手机号搜索」是一个合理但尚未证实的假设，不是确诊结论。其他可能：手机号本身是错号/空号、客户已注销、搜索被风控限频等，也都会表现为「搜不到」。

2.7% 实测

名单里带微信号的比例（11 / 401）。带微信号可以直接加，绕开手机号搜索这道坎。

标签≠诊断

失败原因是脚本自动打的标签，「没开手机号搜索」是其中预置的猜测。要坐实真因，需抽样人工核验一批。

话术非当前瓶颈

在 94% 都「搜不到人」的前提下，请求根本没发到对方面前——换验证话术对通过率影响有限，先解决「搜得到」。

05

为什么「已通过」是 0

这是最容易被误读的一块，单独讲清楚——0 不等于「真的没人通过」。

系统怎么算通过率的

系统定义：通过率 = 已通过 ÷ (已发请求 + 已通过)。现在 已通过 = 0、已发请求 = 103，算出来就是 0%。

但「已通过」这个状态要靠一个自动复查去回填：客户点了「接受」往往是几小时后的事，系统需要事后重新去看这个人是不是已经成了好友，再把状态改成「已通过」。

复查为什么没把 0 顶起来

代码里确实有这条自动复查支线（每轮回头复查发出超过 N 小时的「已发请求」）。但——07-01 它出过误判：把 2 个还不是好友的人错判成「已通过」、还误推进了战报群。

出于止损，复查被调成了「拿不准就不动」的保守模式。代价就是：真通过了的人，现在也很可能没被标上「已通过」。所以 0 更像是「没测出来」，而非「真的为 0」。

⚠️ 诚实结论

真实通过率目前无法从系统数据得出——可能远高于 0，也可能确实很低，两种都有可能，现有数据不足以区分。要拿到真数，只能人工核对一遍企微好友列表（数发出去的 103 条里实际加上了几个），或把自动复查修准。在那之前，请把「通过率」这一栏当作「暂缺」，而不是 0%。

06

下一步建议 · 待双方讨论

按「谁能推动」分两栏。甲方侧 是「有大有小」对自己客户有话语权、能改善的；我方侧 是 Akke 工程 / 运营要补的。

甲方侧 有大有小

  • 名单尽量补微信号：现在 97% 只有手机号（仅 11/401 带微信号）。有微信号可直接加，绕开手机号搜索这道坎——这是提升「发得出去」的最直接一招。
  • 在客户触点引导「加我们」：下单 / 售后 / 客服环节，让客户主动扫码加，或引导客户打开「允许通过手机号搜索」。客户主动加的通过率天然接近 100%。
  • 提前告知客户会有企微添加：客户预期到「厂家会加企微跟进」时，接受率更高，也更少被当骚扰。
  • 一起核名单质量：07-02 加不上率飙到 85%，需一起看这批名单的来源和有效性（是否有错号/空号）。

我方侧 Akke

  • 先把「通过率」测准 —— 当前最优先。人工核对一遍已发出的 103 条实际加上几个，同时把自动复查修准（在不误判的前提下恢复回填）。不测准，后面所有优化都没有基准。
  • 抽样核实「搜不到」的真因：随机抽一批失败号，人工验证到底是「客户关了手机号搜索」还是「错号/空号/限频」，再决定对策。
  • 「搜不到」自动降级：手机号搜不到时，改走「引导客户主动加」（发二维码 / 短信），而不是反复硬搜。
  • 做成实时看板：让双方随时看到最新漏斗，不靠人工拉数。
🧭 讨论顺序建议

① 先对齐「0% 是测不准、不是定论」这个前提；② 聚焦真问题——怎么让请求发得出去（补微信号 + 客户侧引导，甲方主导）；③ 我方并行把通过率测准，下一轮复盘拿真实数据再谈优化。
