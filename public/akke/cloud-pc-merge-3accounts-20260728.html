2三个阻断项 · 未解决不要开工

ACDP 调试端口 9222 写死在代码里，没有 env 开关

三个号必须各开一个独立 Edge（各登一个抖音号），端口只能错开成 9222 / 9223 / 9224。但现在这几处全是硬编码常量：

文件行现在的值
douyin_dm_web_send_dom.py43CDP = "http://127.0.0.1:9222"
douyin_dm_web_capture_dom.py39CDP = "http://127.0.0.1:9222"
douyin_touch_web_dom.py45CDP = "http://127.0.0.1:9222"
start-edge-debug.bat22-23set PORT=9222 / set PROFILE=C:\akke-edge-debug
watchdog-dm-routeb.ps142-43, 101profile 与 9222 均写死
不改的后果不是报错，是静默发错号。三个 poll agent 各读各的 .env（account_id 是对的、领的单也是对的）， 但发送时全部连到 127.0.0.1:9222 这一个浏览器 —— 也就是三个号领的单，全部从同一个抖音账号发出去。 DB 里会记成三个号各自发了，实际只有一个号在发。这是最坏的一类故障：日志全绿、数据全假。

改法（三个 .py 各一行，.bat / .ps1 收参数）：

# 三个 .py 统一改成读 env、默认仍是 9222（老机器零行为变化）
CDP = "http://127.0.0.1:" + os.environ.get("AKKE_CDP_PORT", "9222")

# start-edge-debug.bat 收 env，未设时退回原值
if "%AKKE_CDP_PORT%"=="" (set PORT=9222) else (set PORT=%AKKE_CDP_PORT%)
if "%AKKE_EDGE_PROFILE%"=="" (set PROFILE=C:\akke-edge-debug) else (set PROFILE=%AKKE_EDGE_PROFILE%)
改动落在 worker/scripts/wuying-dm/，不在高危路径清单里，但建议走 PR（这条链上任何一处漏改都会导致上面那个静默发错号）。 合 main 后由 sync-wuying-scripts.yml 同步到公共镜像，云电脑才拉得到。 只推镜像不合 main 是无效的 —— 下次任何 wuying 改动合 main 会拿旧版把镜像覆盖回去，修复静默还原。

Bpoll agent 固定读「自己所在目录」的 .env，三个号不能共用一个目录

# wuying_poll_agent.py:47,57
WORK_DIR = Path(__file__).resolve().parent
load_dotenv(WORK_DIR / '.env')

脚本从自己所在目录读 .env，AKKE_ACCOUNT_ID 是 1:1 绑死的。 所以一机三号 = 三份完整独立的部署目录，不能共用一个 C:\akke-wuying\wuying-dm。 目录规划见第 ③ 节。

连带影响：sent_log_YYYYMMDD.csv、agent.log、templates\ 也都是按目录走的，三套各自独立， 不要为了省事做符号链接指到同一份 —— sent_log 一旦被三个进程同时 append， 会触发「无表头 → csv.DictReader 把首行数据当表头 → 全标 failed 但其实真发了」那个老坑。

C抖音风控：一机三号 = 设备聚集 × 搜人量三倍叠加

这一条没有代码能绕开，只能靠调节奏压住。两次实证：

  • 2026-06-23：小文 / 文哥 / 小胡三台是同一镜像克隆出来的，抖音客户端设备指纹（%APPDATA%\douyin、 %LOCALAPPDATA%\douyin、注册表 HKCU\Software\ByteDance）被一起复制 → 抖音判定「同一台设备挂 3 个号、从 3 个 IP 活动」→ 三台搜人集体软封（搜索结果为空，但联想下拉有结果、浏览器能搜）。
  • 2026-06-26 修正：饭粒同款克隆机、同样跑了关注脚本却没软封 → 说明克隆指纹只是放大器，扣扳机的是当天「搜人」动作的累积总量。 小文 / 文哥把关注 + DM（日限拉到 20）+ route-B 评论多个搜人通道堆在同一天，搜人量爆表过线。
三号合一机是同时踩中放大器和扳机：真·同一台设备（比克隆更彻底）、同一个出口 IP、 而且三个号的搜人动作（DM 搜人 + route-B 搜人 + 关注）全部堆到同一台机器上，日搜人量直接 ×3。 另有一层更重的风险：三个号「出现在同一台设备」会形成账号关联，某个号违规有连坐封号可能（比搜索软封重得多）。

缓解措施（合并当天就要做，不是出事再做）：

  • 三个号的 accounts.daily_limit 从 各 30 下调到各 15，先跑一周看，别一上来就 90/天堆一台机。
  • 三个号的 route-B / 关注不要排在同一时段，错开跑（搜人量按天累积，同日堆叠才是过线主因）。
  • 出现「搜抖音号和昵称都返回空、但浏览器能搜」= 软封信号，立刻停掉所有搜人动作养 24-48h。 06-28 零星那次就是纯停发冷却 ~2 天自愈的。但「等等就好」不是通用解：封得深或反复触线时未必自愈， 该跑 reset-douyin-fingerprint.ps1 还得跑。
  • 止血用 accounts.dispatch_paused_until（见第 ⑤ 节，这个字段一改就同时停派单和静音心跳告警）。 换机器对「搜人量过载」无效，别把停发误当成机器问题去重装。

顺带一个要现场压测的：12G 内存够不够

合并后这台机要同时跑：3 × 调试版 Edge（各带独立 user-data-dir，实测每个约 0.8–1.5G） ＋ 3 × poll agent ＋ route-B 的 watch / consume 进程。6 核 12G 是原本按单号配的。

每个目录一份 akke-start.ps1，内容就是原来那套（kill 残留 → 拉 Edge → 轮询等 CDP 通 → 暖机 → 起 poll agent）， 只是把端口 / profile / 目录换成本号的。注册成三个登录触发任务，错开延时避免同时抢资源：

任务名延时拉起
AkkeDomDmStart（野荞，已有）30swuying-dm\akke-start.ps1
AkkeDomDmStart-Yizhu90swuying-dm-yizhu\akke-start.ps1

暖机那 15 秒别省。poll agent 一等到 CDP 端口通就起，但抖音私信面板 JS 还没渲染完 → 首轮捕获报 conversation-item=0（面板没开/DOM变了）。 判别：by_name N>0 但 conversation-item=0 ＝ 面板没加载好（时序问题），不是登录过期 （真过期是连 by_name 都读不到）。无害但污染日志，Start-Sleep 15 + 先跑一次 capture 暖机即可。
akke-start.ps1 里那段自更新（起 poll agent 前先从镜像拉最新 wuying_poll_agent.py，带 >20KB 体积校验防截断） 要三份都保留。少了它，机器会永远跑缓存的旧版 —— 症状是「改动明明合了 main 和镜像，云电脑行为却不变」。 另外：给云电脑加任何自动化前，先跑诊断确认真实启动入口 （列启动文件夹 + Get-ScheduledTask *akke* + 看 akke-start.ps1 内容）， 别默认是 start.bat —— 07-26 就把自更新焊进了 start.bat，而 DOM 机开机根本不过它，白干一轮。

3交叉验证：agent 的号 ＝ 它那个 Edge 里登的号 逐台把 banner 里的 account 和对应 Edge 窗口里抖音登录的账号肉眼对一遍 三对三一致
这是 wrong-account 事故唯一测得出来的地方
4捕获腿真的活着 各目录跑 py douyin_dm_web_capture_dom.py 出 web capture[DOM] ＋ conversation-item N>0 ＋ COMMIT 写回，无报错
5DB 侧心跳 查三个号的 accounts.last_poll_at 三个都在 5 分钟内刷新（超过就判离线、零派单）
6肉眼核私信气泡 三个号各发一条真单后，人工翻抖音私信列表 对方会话里真有气泡
第 6 项不能省，也不能用日志代替。云电脑 GUI / DOM 这条链的 sent 只代表「点了发送」， 抖音的陌生人私信限流（status_code 7911，约 24h 冷却）是静默丢弃的 —— HTTP 200、success:true、 日志一片绿，消息根本没送到。迁移后的第一批必须人工核气泡。
「捕获腿挂了但 DM 照常发」是这套架构的固有盲区（两条腿在同一个 poll agent 进程里但互不影响）。 所以判「捕获活着」只认第 4 项那三个字样，别拿「DM 在发」当捕获正常的证据。

6回滚预案

  • 两台旧机至少留 7 天不要释放实例。迁移失败时，回滚 = 清空两个号的 dispatch_paused_until ＋ 在旧机上重新拉起 agent，即刻回到原状（旧机的部署目录和 .env 原封没动）。
  • 合并机上出问题、但还不想整体回滚：把出问题那个号的 dispatch_paused_until 设未来， 单独停它一个（另外两个不受影响），同时心跳告警自动静音。
  • 看到「从某时刻起连续 dm_panel_failed、之前全 sent」＝ Edge 窗口卡死，不是号出问题。 判别依据：dm_panel_failed 不罚账号，所以账号仍 active、consecutive_failures=0、无 ban/cooling —— 看到失败但账号计数没涨，八成就是窗口卡死。修法 = 重跑该号的 akke-start.ps1。 别在卡死的 Edge 里手动点私信或导航离开抖音（是常见诱因）。
  • 确认某台旧机关着时，卡在 claimed 的行必然没发出去，可以直接 REST PATCH 回 status=pending, claimed_at=null 让新机重领，不会重复骚扰。
