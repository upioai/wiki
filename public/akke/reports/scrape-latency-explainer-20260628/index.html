🔗一条评论要在 10 分钟内进系统，要闯 5 关——现在各关什么状态

第 1 关 · 账号在池

发视频的抖音号得先被我们收编监控。状态：持续供血中（每天新收编约 20 个）。副作用：新号的历史评论天生超时，压天花板 ~7 个点——结构性，不修。

第 2 关 · 视频被发现 🔴 真根因在这里：我们根本看不到新视频

号发了新视频，靠「巡号」发现它。7-22 深夜实测（近 7 天新入库 3044 条有发布时间的视频）：
发布→我们入库的滞后，p10 = 6.4 天、中位 8.3 天、<2 天的 0 条（一条都没有）。
这不是「巡号慢」，是抖音那个接口本身就有 6-7 天的「发布→可见」延迟——团队 2026-06-15 就已双向实测锁死过这个根因：该延迟是全局的（国内 IP 拉同一接口也照样只到 6 天前），唯一能看到当天视频的路径是国内 IP 的网页渲染；而 Fly 东京两条路都看不到（当时给东京 worker 开过 DOM 兜底，实测新入库 99 条里新鲜的 = 0，已回滚）。
所以：巡号提速最多把 8.3 天压回 6.4 天（那 2 天的差是排队排出来的），剩下的 6.4 天是墙，在东京怎么调都过不去。这才是 7/19 那刀让巡号翻倍、KPI 却纹丝不动的真正原因——不是「量级不够」，是这个方向本身就顶在墙上。
后果：一条视频我们平均在它发布 8 天后才收编，它发布初期的评论高峰我们从来没在场。这就是下面那张表里「该视频第一条 lead」只有 14% 能 10 分钟内抓到的来源（其中还有 16% 是评论早就存在、我们后来才发现这条视频，那批命中率是 0%）。

第 3 关 · 排上队被盯 ✅ 已修复

视频进池后要排进扫描队列。7/8-7/9 拆掉三颗雷（排队毒丸 / 优先级挤占 / 幽灵票堵死），这一关已满分——跳变主力。

第 4 关 · 增量扫描抓到 ✅ 满分 / 伤口已缝合大半

被盯视频的新评论 100% 在 10 分钟内抓到（7/9 起逐日归因验证）。伤口：抖音压了 10-44 分钟才放出的客户评论会被水位线误判成老评论永久丢弃（实测 11.5%）——第一版修复开错阀门没起效（11.4%，纹丝不动）；修正版 7/15 上线（每视频每小时 1 次带回看的扫描）。7/19 对账验收合格：永久丢失率 11.4% → 5.2%，砍掉一半还多；而且丢的「质量」同步降——丢失评论里含「求链接 / 求材料包 / 多少钱」这类购买意图的浓度从 44% 降到 14%。剩下的 5.2% 集中在 6 个视频（占 88%），怀疑是抖音延迟超过 60 分钟回看窗、或每视频 1 小时节流的空档，尚未实锤，不下结论。

第 5 关 · 抖音审核放行 ⚠️ 不可控天花板

「求链接 / 多少钱」这类客户评论被抖音压 10-44 分钟才对外可见——在它可见前谁都抓不到。这部分是真天花板，谁来都一样。

三句话读懂：
① 在热集合里的 lead 占 69%、抓到率 63.3%；掉出去的占 31%、抓到率只有 17.4%。热集合这条腿贡献了全部「10 分钟内抓到」成绩的 89%。
② 所以整体 ~50% ≈ 「69% × 好成绩 + 31% × 差成绩」的加权结果。要往上走，只能去救那 31%——而那 31% 全卡在「视频还没被发现」，也就是第 2 关。
③ 而第 2 关已确认加不动（见上）。这就是 ~53% 那条天花板线的来历。
⚠️ 这张表不是新发现，是给一个 6/29 就下过的结论补上了数字。「高/中意向在产视频豁免空跑退避」是 2026-06-29 主动做的时延权衡（`HOT_FAST_LANE_HIGH_INTENT_BACKOFF=0`），当时的实测就是「退避会把正在出客户的视频踢出快车道，下一条 lead 来时扫不到、拖到 5-30 分钟，占慢尾大头」，团队记录里这一档一直标着「高危反伤 lead 视频，别动」。
7-22 下午我们没先翻这条记录，从「91% 空扫来自这条车道」出发又提了一次「收窗口」，晚上这张表把它按住了——并且第一次把代价量化出来：2-3 小时、3-6 小时两组共 493 条 lead、抓到率 91%，收窗口会让它们掉进 17-22% 的池子，KPI 大约掉 8 个点（49% → 41%）。
正确的读法：那 7.1% 的产出率不是浪费，是保险费。为了接住那 91% 的命中率，多扫的那些空趟是值得的——评论什么时候来没人能预知，只能一直守着。

口径：近 7 天、`comment_time` 在窗内的高/中意向评论 4206 条（剔除时延为负或 >30 天的脏数据）。「距上条 lead」按入库时刻算，与快车道判热集合的口径一致。已知瑕疵：「距上条 0-1 小时」那组（2041 条、抓到率 52.8%）混进了批量回填——一批老评论同时入库、间隔≈0 但时延很大，所以那组数偏低、未列入上表主论证；真实「热视频正常冒评论」的水平以 1-6 小时三组的 84-91% 为准。

① 把「发现」搬到国内 IP
唯一能翻过天花板的路
已有在办项目，不用新立		这不是新提案，是 2026-06-15 就已定方向、至今没推进的那件事。视频发现从 Fly 东京搬到国内出口（国内常驻服务器 / 复用国内出口的机器），让我们能在视频发布当天就收编它，而不是第 8 天。
下一步是已经写好的一步：先别建系统，在目标国内机器上跑单号验证（已知有新视频的那个 sec_uid），带登录 cookie 渲染主页，看能否拿到 <2 天的视频且不弹滑块		命门（动手前必须先过）：国内机房 IP ≠ 住宅 IP。当初的成功验证跑在住宅 IP 上，抖音对机房 IP 风控更严——机房 IP 到底能不能看到新鲜视频，至今没验过。
过了 → 按反爬纪律（cookie 轮换 + jitter + 低并发 + 按号冷却，不能裸批量，会触发滑块）建发现作业；不过 → 加国内住宅代理
② 加真产能加机器 / 加并发⚠️ 先验证再花钱：7/10 并发 3→4 的实验是每活耗时 +39%、总吞吐持平，且两台机 CPU 大量空闲——说明卡的是抖音侧 IO/限频，不是算力。没验证清楚之前加机器大概率是白花钱
③ 改目标承认「10 分钟」只对已经在冒评论的视频成立（那部分我们做到 84-91%），对「一条冷视频的第一条 lead」另立一个诚实的 SLA不是认输，是别拿一个物理上做不到的数字长期考核自己。真要一个数：热集合内 84-91% 才是这套系统当前的真实能力

同时保持不动的：高意向注入窗口 6 小时（保险费，别省）、A 杠杆封顶 240 分钟（省下来的产能没坏处，只是不够）。原则照旧：一次只放一个变量，放完等满 24 小时再看账。

🧮每个数怎么算的（分子 ÷ 分母）

共同基础——"目标评论"的定义：`comments` 表里 `intent_label ∈ {高意向, 中意向}`、`comment_time` 非空、`video_id` 非空的评论。T1 = `created_at`(入库时刻) − `comment_time`(评论发布)。主线用的 ≤10min 口径与下表 ≤5min 完全同法，只是阈值不同。

⚠️ 最重要的一句（关于分母）：所有百分比的分母 = "我们已抓到入库的评论"，不是"抖音上实际存在的评论"。没抓到的评论不在 `comments` 表里 → 不进任何分母、我们也看不见。所以这些 % 读作"在我们捞到的评论中，多少是 ≤5min 的"。对最新一天还有额外乐观偏差：当天发的、还没抓到的慢评论暂不在分母 → 拉高比例，满日后才稳。
指标分子分母
≤5min%（目标表）T1 ≤ 5min 的目标评论数近 7 天按入库时间(`created_at`≥7d前)的目标评论数
≤5min%（by-day 每天）当天 T1 ≤ 5min 的目标评论数按发布日(`comment_time` 北京)分桶后、当天的目标评论数
物理上限 / 天花板（预测器命中率）"评论到达前 H 小时内、该视频有过对应信号(高/中 或 任意评论 的入库)"的目标评论数 = 理论上可提前预测到的近 7 天目标评论数
在热视频里 ≤5min（高42%/中20%）在注入集内 且 T1 ≤ 5min 的条数在注入集内的目标评论数（注入集 = 评论到达前 6h 该视频已有高/中入库）
热集合扫描频率（中位 38 次/个）非比例，是中位数：近 6h 产高/中意向的去重视频，各自近 60min 被完成的 `scrape_video`(按 payload.url 匹配)次数，取这组数的中位
leads / 天非比例，是计数：`created_at` 落在该天的目标评论数

两套窗口约定别混：目标表按"入库时间"取近 7d（看整体水位）；by-day按"发布日"分天（看每天趋势、对齐 #643 拐点）。脚本：`_diag-le5-split` / `_diag-le5-byday` / `_diag-predictor-ceiling-5min` / `_diag-hi-vs-mid-why`（均直查生产 `comments` 表）。

③ 其它高频黑话

词意思
产能worker 每分钟能抓多少个视频（抓取吞吐量）。实测 59-130 个/分钟（≈每 5min 扫 300-650 个）。"产能够不够"= 要扫的视频会不会多到 worker 扫不过来。
空跑去扫一个视频、结果没抓到新评论（白扫一趟）。
空跑退避省力机制：一个视频连续 3 次空跑，就判它"安静了"，把它从 3min 快道暂时挂起 6-30min（每多空跑一轮挂更久、封顶 30min），免得反复白扫。副作用：正在"一阵一阵"冒评论的热视频会被误挂 → #643 对热集合关掉它。
慢尾最慢的那一小撮评论（长尾），不是平均、是极端值。
p50 / p90 / p99把所有评论按耗时从快到慢排队，第 50%/90%/99% 那条的耗时。p50=中位（一半比它快）、p90=最慢 10%、p99=最慢 1%。"慢尾 p99 ~20min"=最慢的 1% 要等约 20 分钟。
整号扫 / 单视频快道整号扫=去一个号主页翻一圈、批量抓多条视频（慢，23-211s）；单视频快道=只抓某一条视频的新评论（快，~6.7s）。

📌 跟本次时效的关系：这轮 #643 动的是 pri=0 高/中意向快道那一档——不改它的优先级，只是不再让它被空跑退避临时踢出快道，让"正在出客户"的视频稳定每 3min 被扫到。tier 分级、aging、其它 pri 档全没动。
