GLOBAL ORDER

三个模块的前后顺序

STEP 01 · FIRST TOUCH

首触先建立对话

识别完整服务群标题，确认没有发过，聚焦输入框后发送第一句话并建立安全画像。

STEP 02 · AUTO REPLY

客户回复后实时承接

读屏识别新消息，结合当前会话、画像和销售身份生成回复，经护栏后发送并回执。

STEP 03 · RECALL

客户沉默后进入召回

首触至少24小时仍未回复才进入；按七次固定内容继续触达，回复即自动停止。

进群 / 加企微 首触 实时承接 沉默召回 / 停止
互斥原则

客户有新回复时由自动回复接管，召回立即失去候选资格；召回不会和实时回复同时向同一客户发消息。

01

FIRST TOUCH

首触：让第一句话发对群、只发一次

优化前

  • 可能按昵称或不完整标题识别，历史重复会话容易被当成两个客户。
  • 点击后直接输入，焦点若落错位置可能错输或错发。
  • 发送结果缺少完整回执，卡住时不容易被发现。
  • 首触后没有统一安全画像，后续承接缺少城市、活动档位和待补信息。
→

优化后

  • 按完整群标题去重，目标精确到“批次 + 品类 + 城市 + 服务群”。
  • 发送前做输入框焦点预检，不满足条件则不发。
  • 飞书记录收发回执，流程卡住自动 @野荞。
  • 15条安全初始画像落库；测试号、内部号不写入。

工作流逻辑

01 发现服务群云电脑扫描企微会话列表，读取完整群标题。
→
02 身份与去重按完整群标题查历史；已首触则跳过。
→
03 焦点预检确认目标群与输入框可用，失败即停止本轮。
→
04 发送首触使用夏伟身份，单气泡发送，避免刷屏。
→
05 留痕画像记录城市、活动档位、群标题、状态和缺失字段。
→
06 飞书回执发送成功/失败可见，卡住主动告警。
成功出口

首触时间与历史截止点写入画像，后续同群不会重复首触。

失败出口

标题不完整、目标不确定、焦点不正确时 fail-closed：宁可不发，也不冒险错发。

02

AUTO REPLY

自动回复：读懂客户，再以夏伟身份承接

优化前

  • 云电脑进程可能静默卡住，运营只看到“客户没回复”。
  • 发送前缺少输入焦点确认，存在把内容输入错误区域的风险。
  • 收发链路缺少统一飞书回执，无法快速区分“没生成、没发送、没读到”。
  • 客户画像较薄时，容易重复询问或从错误话题开始。
→

优化后

  • 云电脑运行脚本 MD5 77bbe550…，DRY_RUN=False。
  • 发送前输入框焦点预检；身份、目标、输入区不确定即跳过。
  • 飞书收发回执上线，卡住时自动 @野荞。
  • 实时读取安全画像；首触和回复均使用对应销售身份，不串人设。

工作流逻辑

01 截屏读消息GUI loop 截取当前会话，视觉模型识别最新客户内容。
→
02 去重与归属确认是客户新消息、属于夏伟会话、不是历史回声。
→
03 调回复大脑经 Fly 中转请求 wecom-chat，读取历史、画像、销售身份和知识库。
→
04 生成与护栏LLM生成单气泡回复；校验称呼、价格、长度、敏感承诺和资料。
→
05 GUI发送再次确认目标和焦点，打字发送；不满足条件则不发。
→
06 落库与通知消息、画像、成本和配置指纹落库；飞书记录结果。
记忆原则

当前企微画像优先；跨渠道只合并结构化事实，不搬原话和抖音话术，避免串味。

自愈原则

loop持续心跳；脚本版本可自愈拉取，链路异常由监控与飞书提示。

03

SEVEN-TOUCH RECALL

召回：沉默后七次有节制地继续提供价值

优化前

  • 新客户只有画像，没有正式召回状态，明天不会自动发送。
  • 动态阶段选题可能偏离运营指定的七个主题。
  • TING 与异常名称会话并存，直接全量启用可能同群双发。
  • 蓉蓉已互动，但冷启动模板无法承接她对配置的明确关注。
→

优化后

  • 14位真实客户已写入 fixed_7_v1 生产计划。
  • 七条主题与顺序冻结，不再被动态阶段选题覆盖。
  • TING只启用干净会话，历史重复记录暂留但不会参与召回。
  • 蓉蓉首条专门承接“柜体柜门、五金、环保”的已知兴趣。
第1天关注点三选一
第2天补一个需求
第3天价格与配置
第5天比较清单
第7天低门槛预估
第9天装修节点
第11天低压力收口

工作流逻辑

01 到达可召回时间首触至少24小时，且 next_eligible_at 已到。
→
02 停止条件检查客户已回复、退群、删除、计划完成均不再派单。
→
03 取当天固定话术按 touch_count 读取第1至第7条，结合城市档位与画像缺口。
→
04 入派发队列一人最多一条在途，backlog与频率门控制节奏。
→
05 精确搜索服务群云电脑按完整群标题搜索，做身份门和焦点预检。
→
06 成功后推进成功才 touch_count+1；前三次每日，之后隔日；满7次停止。
时间安全门

“明天开始”不是强行固定上午10点。每位客户必须距首触满24小时，预计从明天下午起陆续进入队列。

回复即停

最后一条消息变为客户回复后，该客户自然退出候选；实时自动回复接管，不再继续召回。
