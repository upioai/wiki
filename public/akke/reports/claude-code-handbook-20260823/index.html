↑ 和 ↓ 分别代表什么

在 claude 二进制的符号常量表里，这两个箭头是这么定义的：

Jre = "↑"   // ↑
AZ  = "↓"   // ↓

它们在整个 Claude Code 里只有两类用途：

出现位置↓ 的意思↑ 的意思
状态行（你最常看到的）本轮生成的 token 数——数据下行到终端—（状态行只有 ↓，不会出现 ↑）
Memory 多仓同步日志pull ↓12/−3 拉下来 12 条push ↑5/−1 推上去 5 条
键盘输入方向键「下」方向键「上」（翻历史输入）
为什么确定 ↓ 是 output 而不是输入总量： 实测同一轮里 1h47m → ↓16.2k、2h06m → ↓27.0k，19 分钟涨了 10.8k ≈ 570 tok/分钟——这是生成速率的量级。 而同期实测单次请求的输入上下文是 50 万~99 万 token，差了 40 倍。所以状态行显示的绝不可能是输入。
最重要的一条：别拿状态行估你的额度消耗。 实测某一天状态行分轮加起来是 89.9 万 output token，但那天真实流过的总量是 3.85 亿—— 差 428 倍。差在 cache_read（上下文重放）占了 97%，而状态行一个字都不显示这块。

02左边那些符号：是层级关系，也是状态

你在屏幕最左侧看到的竖线和折角，确实是层级关系——Claude Code 用的是一套标准的「树形绘制字符」， 和 tree 命令、Git 日志图是同一套东西。二进制里这套常量原样长这样：

Kx = { topLeft:"╭", topRight:"╮", bottomLeft:"╰", bottomRight:"╯" }

右下角那个符号 = 当前权限模式

这个符号最值得认，因为它决定我会不会先问你再动手：

符号模式行为
⏸Manual / Plan暂停符。每个动作都停下来问你，或只做规划不动手
⏵⏵Accept edits快进符。改文件不再逐个问
⏵⏵Bypass Permissions（红色）快进符 + 红色。全部放行，删文件也不问
⏵⏵Auto自动判断该不该问
⏵⏵ 是红色的时候要格外注意。 实测某台机器 14 天里 95.8% 的时间处在 Bypass 模式（2,534 次 vs auto 110 次）—— 意味着几乎所有命令都是直接执行的，没有弹窗兜底。这也是为什么删文件建议走 ~/.Trash 而不是 rm。

切模式：按 shift+tab 循环。

03怎么判断它是真在跑，还是已经死了

这是最常见的焦虑：转了一个多小时，不知道该等还是该重来。 好消息是——状态行本身就区分了三种状态，认出来就不用猜了。

① 正常在跑

✳ Julienning… (1h 47m 28s · ↓ 16.2k tokens)

判据：转圈词会变、计时在走、↓ token 数在涨。 三个里最硬的是 token 数——只要它还在涨，模型就在生成。 计时器和转圈动画是本地渲染的，断网了它们照样会动，别拿它们当活着的证据。

② 卡在等 API（红字）

Waiting for API response · next try in 3s · attempt 2 · esc to interrupt

屏幕上会直接出现红色的 Waiting for API response。 这说明请求发出去了但没回音——网络或服务端的问题，不是你的问题。 Claude Code 内部有专门的「卡顿探测」（tengu_spinner_stalled_ui）， 超过阈值就会把状态行从转圈词切成这行红字。

③ 报错在重试

✳ API error · Retrying in 0s · attempt 1/10

格式是 Retrying in {等待} · attempt {第几次}/{总共几次}。 它会自己退避重试到上限，这期间你什么都不用做。 只有当它打出 Maximum retries reached 才算真的失败了。

一个容易误判的情况：token 数长时间不涨，但没报错。 这多半是正在跑一个长命令（比如 pnpm build、大文件 git push）， 模型在等 Bash 返回，自然没有新 token 生成。 按 ctrl+o 展开就能看到 running tool for 3m 20s 这类行——那就是它在等什么。

三种状态速查

屏幕上是实际状态你该做什么
转圈词 + token 在涨正常生成等着，别碰
转圈词 + token 不涨 + 展开有 running tool在等某个命令跑完等着；超过 10 分钟可以按 esc 问它在干嘛
红字 Waiting for API response网络/服务端无响应等 1-2 分钟；不恢复就走 §04
API error · Retrying in ... attempt N/10自动重试中让它重试完；到 10/10 还挂就走 §04
什么都不动、计时器也停了进程可能真挂了直接走 §04 的「新开会话」

04网络卡顿 / 中断了怎么恢复

你现在在用的三种姿势，各自的代价其实差很多。按推荐顺序排：

姿势 A · 直接输「继续」

适用：上一轮明显做到一半被打断，上下文还在。
代价：最低。整个会话上下文不动，缓存命中率保持。
风险：如果它其实已经做完了只是没显示，「继续」会让它重做一遍，可能产生重复动作（重复提交、重复发消息）。

更稳的说法：别说「继续」，说「你刚才做到哪了？先复述状态再继续」。 这一句能把「重做」的风险按掉——它会先报状态，你确认后再往下走。多花 200 个 token，省掉一次重复操作。

姿势 B · esc 打断，再重输一遍

适用：它跑偏了，或者卡在一个你不想等的动作上。
代价：中等。被打断的那一轮已经烧掉的 token 不退，但上下文保留。
注意：esc 是打断当前轮，不是清空。打断后屏幕会显示 Interrupted · What should Claude do instead?，直接接着说就行。

连按 esc 打断多次、每次都重发同一条指令，是最差的做法。 实测有一段记录里连着 4 次 /wrap-up 全被 Interrupted，第 5 次才发现是 API 在报错—— 如果状态行已经在 Retrying in ... attempt N/10，打断再重发只会重新排队，不会更快。 这种时候正确做法是停手等它退避重试完。

姿势 C · 新开会话，重发上一轮的信息

适用：会话真的卡死了、或者上下文已经太长（接近 1M）。
代价：最高。新会话要把项目上下文重新读一遍，第一轮就得烧掉几万 token 重建缓存。
但有个更省的做法——见下。

姿势 D（推荐）· claude --continue / /resume

这两个是专门为「断了接着干」设计的，比手工新开会话省得多，因为它把原会话的上下文整个接回来：

命令作用什么时候用
claude --continue
claude -c		接上这个目录里最近活动的那个（不一定是你刚关的）终端崩了 / 关掉了 / 断网重连后
claude --resume
claude -r		列出历史会话让你挑一个接上；可带搜索词或 session-id同目录有多个会话时必须用这个
/resume会话内切换到另一个历史会话已经在 Claude Code 里了
claude --fork-session从某个会话分叉出新的一条想在不污染原会话的前提下试个方向
最容易搞错的一点：claude --continue 是在「终端」里敲的命令，不是在 Claude 的输入框里说的话。 屏幕上其实有两层，混在一起就懵了：
┌─ 终端（zsh / bash）──────────────────────┐
│ ~/Akke $ claude ← 这一层敲的是「命令」 │
│ ┌─ Claude Code 会话 ────────────────┐ │
│ │ › 帮我改这个页面 ← 这一层说的是「人话」 │ │
│ │ ⏺ 好的，我先看一下… │ │
│ └──────────────────────────────────┘ │
└─────────────────────────────────────────┘

完整操作：A 会话卡住了，一步步该怎么做

第 1 步 · 在 A 会话里：什么都不用说。
直接按两下 ctrl+c 退出，或者干脆关掉终端窗口。 不需要留言、不需要告别、不用等它跑完—— 所有对话记录都实时写在磁盘上（~/.claude/projects/），关掉不会丢。

第 2 步 · 回到终端，cd 到同一个目录，敲命令：

cd ~/Akke          # ← 必须是 A 会话当时所在的目录
claude --continue
目录错了就接不到。--continue 找的是「这个目录下最近的那个会话」， 不是全局最近的那个。

第 3 步 · 接回来之后，第一句话说什么。
它接回来的是完整的 A 会话——不是新会话，是同一条。前面所有内容它都还记得， 你不用重述任何东西。推荐第一句直接说：

「你刚才做到哪了？先把状态复述一遍：做完了什么、验证了什么、还剩什么，然后再继续。」
为什么不直接说「继续」——因为你不知道它卡住前是不是已经做完了。 直接说「继续」有可能让它把同一件事再干一遍（重复提交、重复发消息）。 多花两百个 token 让它先报状态，省掉一次返工。

对照表：你以为 vs 实际

你以为要做的实际要做的
在 A 会话里说点什么保存进度什么都不用说，直接退出
新会话怎么开claude 然后手动重述上一轮claude --continue（在同一目录）

它记得多少什么都不记得，要重新讲全都记得，A 会话的完整上下文都在
⚠️ 多会话陷阱：--continue 接的是「最近活动的那个」，不是「你刚关的那个」。
二进制里的原文定义是 Continue the most recent conversation in the current directory—— 判据是最后活动时间。如果同一个目录下你开了好几个会话，另一个窗口活动更晚，它会接错人。

同目录有多个会话时，改用 claude --resume：弹出交互式选择器让你挑，还能带搜索词： 
claude --resume              # 列出来挑
claude --resume 企业大脑      # 带搜索词过滤
claude --resume <session-id>  # 知道 id 就直接点名

「关掉」到底怎么关

下面这些全都等价，随便用哪个（二进制里的退出别名原文）：

exit    quit    :q    :q!    :wq    :wq!

加上按两下 ctrl+c、直接关终端窗口——也都行。

为什么怎么关都不会丢：对话转写是实时逐行落盘的， 每条消息即时写进 ~/.claude/projects/<项目>/<session-id>.jsonl。 不存在「没保存」这回事，进程被 kill 也一样。
还有个不用退出终端的办法：在会话里直接敲 /resume（别名 /continue）， 参数同样是 [conversation id or search term]，可以原地切到另一条会话。
--continue 不是「新开一个会话」，是「把原来那个会话重新打开」。 这就是它比手动重开省的地方——省的不是打字，是它不用重新读一遍你的项目 （这部分实测要烧几万到几十万 token）。

什么时候才真的需要新开会话重述？只有当 A 会话的上下文已经逼近 1M 上限 （实测有会话到过 88.0 万 / 82.0 万），接回来也活不了多久，那才值得开新的。 判断方法：接回来后跑 /context 看余量。

05暂停与继续

「暂停」在 Claude Code 里其实有四种不同的意思，用错了会白等或丢东西。先对号入座：

停下这一轮
它跑偏了 / 不想等了		esc直接接着打字。屏幕会显示 Interrupted · What should Claude do instead?
让它在后台继续跑
我要腾出终端做别的		ctrl+b
（tmux 里要按两下 ctrl+b ctrl+b，因为 tmux 自己吃掉第一下）		在任务列表里按 f 调回前台（foreground）

退出时的一个细节：按 ctrl+c 时屏幕会提示 Press Ctrl-C again to exit，如果当时有子任务在跑，它还会补一句 · N agent(s) will keep running——意思是那些后台任务不会被你的退出杀掉。

「暂停」还有一个完全不同的含义：暂停记忆

如果你说的「暂停」是指不想让它往长期记忆里写东西（比如在处理敏感内容），那是另一个开关：

/pause-memory        # 暂停自动记忆
/pause-memory        # 再运行一次 = 恢复

暂停期间屏幕会显示 Memory is paused. Run /pause-memory to resume automemory.

推荐的收工姿势

不要靠「关掉终端 + 下次凭记忆重述」。 正确顺序是：① 让它把当前产物落盘（写成文件 / commit），② 直接关， ③ 下次 claude --continue。
这样即使会话真的丢了，盘上的东西还在，不用靠聊天记录接活。

06172 个转圈词全表

先说结论，这条最重要：

转圈词是纯装饰，跟当前在做什么毫无关系。 二进制的数据段里是一张按字母序平铺的 172 词表，从 Accomplishing 到 Zigzagging， 每轮随机抽一个。表里混着 Clauding、Gitifying、Whatchamacalliting 这种根本无法对应任何真实动作的自造词，而真正表达状态的是另一套字段： requesting / thinking / tool-use / running tool for。
判据：如果词跟动作有关，二进制里应能找到 word→动作 的映射表；实际只有一串扁平常量，且同一个词收了两遍（Channeling / Channelling 美式英式各一份）。置信度 0.9。

那「在终端里的含义」是什么？

答案是：172 个词的终端含义完全一样——「我还活着，在忙」。
这不是偷懒的回答，是设计如此。既然是随机抽词，就不可能有「Sketching 表示在起草、Julienning 表示在切分任务」这种对应关系。

那这份表还有什么用？两件事：
① 认出它是装饰——看到 Transmuting… 别以为它在做什么高深转换，那只是随机词；真正判断死活看 ↓token 数涨不涨（见 §03）。
② 这些词本身的英语差别是真的。下面每一家我都补了「语义梯度」——同一家族里的词在英语里其实有轻重、先后、褒贬之分，那部分不是随机的。

⑧ 程序员内部梗10 个 · 外人完全看不懂的一家

这条链是整份表的自我说明书：从「勉强算个词」一路滑到「我承认我在瞎写」。 Reticulating 是终点——一个 1994 年游戏里公开承认的假读条文案，被原样搬进了 2026 年的 AI 终端。
词梗的出处
Reticulating整张表里最尖锐的自嘲。《模拟城市 2000》(1994) 的读条画面写着「Reticulating splines」（织网样条）。开发者 Will Wright 后来承认这句话毫无意义，纯粹是编出来忽悠玩家的假读条文案。它明摆着在告诉你：这行字没有信息量。
Clauding生造词，「Claude 化」——自指
Gitifying生造词，「git 化」——自指
Bootstrapping源自「pull yourself up by your bootstraps」（拽自己鞋带把自己提起来，物理上不可能）→ 计算机的「自举 / 引导」
Newspapering生造词，「报纸化」
Actioning名词 action 硬转动词（企业黑话，被语言洁癖者痛恨）：We'll action that in Q3.
Crunchingcrunch numbers 算数据；游戏业 crunch = 血汗加班
