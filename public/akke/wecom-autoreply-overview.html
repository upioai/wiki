0→1 逻辑原理图（一条消息的往返）

① 客户发消息
企业微信好友单聊里，业主发来一条消息
▼
② 云电脑 · 读（wecom_reply_loop.py）
双通道扫未读（①轮询当前打开会话 + ②遍历左侧红点）→ 截屏 → Qwen-VL 逐条列出消息 → 代码取最底一条 + 确定性归属判定
▼ 云电脑国内 IP 连不上 vercel.app
③ Fly Tokyo 中转（wecom_relay.py）
纯透传：云电脑 → akke-worker-prod.fly.dev/wecom/chat/reply → Vercel（Fly→Vercel 必通），不持密钥
▼
④ Vercel 大脑（/api/wecom/chat/reply）
chatReply 出小艳人设回复（按 stage：首触/nurture/decision）+ 确定性海报匹配 + 客户画像回写 + Langfuse 追踪 + 成本记账
⑤ Supabase
conversations / messages 落库；指纹幂等去重
▲ 回 reply ┃ ▼ 发送
⑥ 云电脑 · 发
拟人延迟 → 点输入框 → SendInput 逐字打字 → Enter 发送（换行切段封顶 3 条）
⑦ confirm 落库
GUI 真发出后才回调落 AI 消息（显式失败：没发成不记账）
蓝 = 云电脑（只做 GUI I/O） · 紫 = Vercel（大脑/DB/成本全在这） · 黄 = Supabase。 核心分工：Python 端不碰任何企微 API、不做任何判断——读靠 VL、发靠模拟输入，大脑与账本全在服务器。这也是它绕开方案A 那道 ICP 墙的原因（云电脑→Vercel 是普通入站请求，不调企微接口）。

03 / Badcases & Fixes

踩过的各类 Badcase · 优化方式 · 进展

GUI 自动化把「位置/布局/发送方判断」这类任务交给了 VL 与隐式机制 → 一旦看歪就静默丢单或发错。以下按层归类，均可追溯到具体修复 PR。

A读取层 —— 读错 / 漏读客户消息

现象根因优化方式进展
漏读最底部最新客户消息长会话滚不到底、被上方大气泡带偏；只信 VL 判「哪条最新」打开先滚到底 → read_latest_bottom() 裁底部 58~88% 专读最后一条 → 改「按序列出全部→代码取最后」+ 确定性归属判定，不信 VL 左右根治 #705/707/708/709
VL 把客户消息误判成 self → 卡死跳过发送方归属 100% 靠单次 VL 看图，非确定性不再信 VL 的 customer/self，改：读最底一条，只要非我方近发文案/非会话名/本会话没回过就当客户新消息已修
名字系统性读空会话列表分隔条被拖宽 → 裁剪切进标题读空改整屏兜底只问标题；裁剪比例提为 env AKKE_WECOM_CROP_RATIO 可调已修
消息被截半句 → 去重失效重复回裁剪比例 0.15 切进最左气泡裁剪比例降到 0.12；底部窄带二读复核紧贴我方回复下的小气泡已修

B防自回 / 防重复 —— 发错对象 / 发重复

现象根因优化方式进展
自问自答（回复自己）VL 把我方气泡误判成客户消息护栏① 我方近发文案模糊匹配拦截（读串一两字也拦）已修 #695/703
把自家黑窗日志当客户消息回出去截图圈进了 loop 自己的控制台读取侧前台校验 + 黑窗日志误读检测已修
同一条消息回两遍VL 漏读右侧我方气泡时 burst 混入已答旧行护栏③ 每会话回复台账，去重降到逐行已修 #704
好友验证系统样板被当客户开口回「我通过了你的验证/现在可以聊天了」被 VL 读成左气泡两个变体（有/无"我们"）双侧正则过滤，剔空则跳过已修

C发送层 —— 发送形态不像真人

现象根因优化方式进展
一条回复被切成多条气泡（无上限）回复里的 \n 被企微当 Enter=发送发送前按 \n 切段、封顶 3 条、超出用空格连不丢内容已修
首触被拆条 / 固定连发 3 条太机械换行发送副作用 + 固定条数首触 single_bubble 钉死单条；代回气泡数随机 1-3 条已修 #692/714
抢窗口不稳 → 坐标落偏点空无影上 activate/maximize 常没真铺满屏focus_wecom 硬置前 + 最大化 + 铺满屏校验，没铺满就跳过本轮已修 #694

D身份 / 会话 —— 串台 / 碎记忆

现象根因优化方式进展
同一客户裂成多条会话、称呼念成「橘枳@微信」VL 读显示名当身份，后缀/空格差一字撞不上唯一键normalizeCustomerName 剥「@微信」后缀 + 空格归一过渡已修
跨销售号同名客户"通灵"（说出没对本号讲过的城市）身份只用裸显示名，跨号共享历史身份键改 persona:客户名，按销售号隔离已修
同号同名仍会串（无稳定 userid）GUI 拿不到官方 external_userid，架构级天花板确定性根治只剩官方付费「会话存档 API」P2 · 已拍板搁置

E话术 / 人设 —— 回复质量

现象根因优化方式进展
给已加微客户发「发个微信号我让设计师加你」ice_break 会话代回落了抖音冷开场模板route 把 ice_break stage 强转 nurture + wecomOpener 企微专属覆盖（禁要微信号/禁逼单）已修
把海报记账标记 [图片:config-568] 当文字打给客户LLM 学舌历史里的去重记账标记喂历史前 + 回复后 + confirm 落库三道剥离已修

企微号署名冒出抖音「小艳」few-shot 署名未按渠道隔离署名 persona 感知；few-shot fallback 按渠道隔离已修 #758

会话聚焦时客户秒回不弹红点 → 漏触发触发只靠左侧红点双通道：①轮询当前打开会话 + ②遍历红点会话已修
改了 loop 但云电脑没生效，排查半天wecom-chat 不在自动同步范围，靠人工传文件纳入 sync-wuying-scripts.yml 镜像 + update-wecom.bat token-free 自取PR #760 待合

05 / Deployment Guide

云电脑部署指南

在一台无影云电脑（Windows）上把这套跑起来。后端（大脑端点 / Fly 中转 / 服务器密钥）PM 已一次性就绪，新机只做「读屏 + 打字」。完整逐步版见 upio.ai/akke/cloud-pc-wecom-autoreply-deploy。

前置物料（开工前找 PM 要齐）

  • 一台无影云电脑（Windows，Python 3.x）+ 一个已加了客户好友的企业微信主号
  • OpenRouter key（sk-or-v1-…，给 VL 读消息用）
  • WECOM_CHAT_SECRET（大脑端点密钥，所有云电脑同一个值）——真密钥不写在公开页，向团队内部 Lark 私聊取

一次性配置（9 步）

装企业微信 + 登录一次
登录加了客户好友的主号；窗口保持打开、别最小化到托盘（最小化截不到屏）。重启一次确认登录是否保持。
确认 Python 3.x
python --version。没有就 winget install -e --id Python.Python.3.12 --scope machine，新开窗口再验。
拉脚本到 C:\akke-wecom
从公开镜像 raw.githubusercontent.com/upioai/wiki/main/public/akke/wecom-chat/ 下载 wecom_reply_loop.py / start-wecom-reply.bat / update-wecom.bat（合并 #760 后 token-free 可用）。
bootstrap 装依赖
.\bootstrap-wecom.bat 自动装 pyautogui 等 + 从模板生成 .env。
量坐标（最易错·必做）
python measure_wecom_coords.py，按 6 秒倒计时把鼠标停在「输入框 / 发送按钮 / 会话列表第一行」，得到 AKKE_WECOM_C_INPUT/C_SEND/C_SESSION1——每台机分辨率不同，必须量自己的。
填 .env
填 OpenRouter key、WECOM_CHAT_SECRET（内部取）、上一步坐标；WECOM_CHAT_ENDPOINT=https://akke-worker-prod.fly.dev/wecom/chat/reply（固定别改）；设 AKKE_WECOM_PERSONA（xiaoxia/xiaofan/xiaowen，本机绑哪个销售号）。
空跑验证（DRY_RUN=1）
默认 AKKE_WECOM_DRY_RUN=1：只读+生成+打印，不真发。看它能否正确读出客户消息、生成合理回复、坐标点得准。
发送测试
python test_send_wecom.py 往一个测试会话真发一条，确认打字/发送键正常（企微设置若是 Ctrl+Enter 就把 AKKE_WECOM_SEND_KEY=ctrl+enter）。
开真发
改 AKKE_WECOM_DRY_RUN=0，双击 start-wecom-reply.bat 启动（崩溃自重启、遇 STOP 锁住）。启动行会打印 VERSION，核对是最新版。

日常运维

  • 每天/重启后拉起：走 /cloudpc-wecom-autoreply-restart skill，念黑窗日志 + 看 wecom_reply_status.json 心跳验活。
  • 一键停发：在 C:\akke-wecom 建 wecom_reply_STOP 文件即停；删掉才会重启恢复。连续 3 次异常 loop 自己写 STOP 停发。
  • 更新版本：双击 update-wecom.bat 从公开镜像自取最新 loop（自动备份 *.bak）→ 重启。
  • 登录过期 / 坐标偏：重登企微；换了远程桌面分辨率要重量坐标（loop 检测到分辨率变化会跳过本轮防点偏）。
  • 存活告警（#761 合并后）：工作时段心跳停 >30min 会自动推 Lark 云电脑监控群，不用盯屏。
安全纪律：本页公开，不含任何密钥值。WECOM_CHAT_SECRET / OpenRouter key 一律走团队内部 Lark 取，别写进任何公开文档或截图。主号无隔离 → 日限/时限从严，别擅自调高。
