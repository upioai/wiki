案例账号拆解 Skill

十分钟装好，然后直接说需求就能用。支持抖音、小红书、订阅号文章。

给第一次用的人

这个 skill 是干什么的

给它一个账号或一条链接，它把那个号的内容扫一遍，挑出真正的案例内容，产出一页可对外的分析，并归入对应行业的样板库。

我们跟客户讲「案例内容怎么做获客」时，最有说服力的从来不是我们说，而是同行已经在怎么做。过去回答这个问题要人工翻账号、一条条看、凭印象总结，翻一个号半天，结论还不可复查。现在它是可复跑、可校准的流程：抓取自动，判定靠明文规则，规则由人工标注校准，每条判定都标着得分和理由。

成果在 upio.ai/akke/case-refs。

装：三步，大约十分钟

1. 装 skill 本体

git clone https://github.com/Akke-AI/akke-skills.git
cd akke-skills && ./install.sh

装完重启你的工具。 以后更新就 git pull && ./install.sh。

Claude Code 和 Codex 都能用：脚本把真实文件放在跨运行时目录 ~/.agents/skills/，再从各家自己的目录建符号链接过去。只有一份文件，更新一次全部生效。

2. 克隆代码仓库

git clone https://github.com/Akke-AI/akke-official-site.git

规则、数据、脚本都在这边的 case-refs/ 里。skill 正文里不写具体规则——规则每轮标注都会变，抄一份在文档里迟早会漂。正文只写「为什么这么定」和「踩过什么坑」。

3. 本机依赖

要什么干什么用
python3判定、建页、发布
node + npm i playwright-core驱动浏览器抓取
ffmpeg合成封面海报、视频抽帧
gh CLI（已登录）发布到站点
Google Chrome抖音和小红书必须真实浏览器，普通 HTTP 抓不到

用：直接说需求，不用记命令

工具会自己识别并调用，也可以显式写 /analyzing-case-accounts。照下面这么说就行：

你想做什么这么说
看一个具体账号帮我看看这个号 douyin.com/user/MS4wLj… 的案例内容怎么做的
收录一条案例把这条加进参考案例集（后面贴链接）
调研一个新品类我们在谈一个做植发的客户，调研一下这个品类
拆解最好的几条把这个号点赞前 3 条拆一下，看能不能用同一个工作流做

只有一张主页截图也能开始——把图发给它，它会从截图读出账号名，再去定位。

支持哪些平台

平台收录单条整品类调研要登录吗
抖音✅✅不用（视频搜索要）
小红书✅✅必须
订阅号文章✅—（但能按合集整本收）不用

小红书这条最容易踩坑：没登录拿到的是降级数据，不是被反爬。实测同一个账号主页，未登录只给 12 条、笔记 id 全是空字符串，登录后给 117 条、id 全齐。遇到「字段都在、唯独 id 是空的」，先想登录状态。

视频号不支持：它没有公开的网页地址空间，内容在微信内，channels.weixin.qq.com 是创作者后台不是内容页。

它怎么判断什么算案例

一句话：画面是不是自家做出来的活，而且指向一次真实的交易或交付。不要求点名客户，也不要求写地址。

这句话是被两轮人工标注分别从两个方向纠正出来的——第一轮 80 条跑出 49%（收太紧），放宽后第二轮 67 条跑出 58%（放太松）。当前 128 条标注：是否判定 98%。

最该知道的一条是：同一条规则对不同行业是反的。

形态行业画面里是什么要额外证据吗
作品展示型门窗 / 窗帘 / 保洁 / 宠物美容 / 美甲 / 婚纱 / 装修那扇窗、那只狗、那个家本身就是交付物不要
商品交易型茶叶 / 大黄鱼是商品不是交付物——一罐茶谁都能拍要：发货 / 复购 / 评价 / 订制
服务结果型植发 / 考公考研 / 数字游民不然就是知识讲解或培训课要：具体的人 + 结果

还有一条不写在规则里、但每次收号都要人过一遍的：商业环节看谁在发。商家号发的个人案例要收，即便内容完全不提商业环节——发布这个动作本身就是商业环节；个人号发的、没有商业的，不算案例。

完整口径随时跑 python3 scrape/digest.py 看，它从规则文件直接渲染，永远是最新的。

闲时工人：让机器在你不用电脑时干活

有两类活很慢但不烧 Claude 额度：品类调研（被抖音风控逼的，5 个品类要 56 分钟）和 top3 拆解的素材采集（一个账号约 50 分钟）。它们交给一个后台工人。

装完会在屏幕顶上的菜单栏出现一个圈：

图标含义
○关着。电脑空闲 10 分钟会自动打开
◎开着，待命
◉正在干活

点开能看还剩几个账号没分析、一键开关、看日志，还能直接粘链接或写调研方向提交给它。

两种打开方式行为不同，这是故意的：你手动打开＝你就是要它现在跑，人在用电脑也继续；空闲自动打开＝趁没人用，你一回来它就收手并把开关关回去，不跟你抢机器。

命令行也行：akke on / akke off / akke（看状态）/ akke log。

三条纪律

一、自动化永远不发布线上。 工人的产出堆在候选池，入库和发布都要人过一遍。这条是吃过亏定的：上一次整夜自动入库，把三个不该收的号直接挂到了线上，事后用校准过的规则重算才发现，那时页面已经对外挂了一段时间。

二、改完规则必须做两件事。 跑回归（scrape/regress.py，准确率掉了就是改坏了），然后重算全库（scrape/recompute.py）。第二件最容易漏——只改规则不重算，线上页面展示的还是旧结论，等于页面在撒谎。上一轮改完规则，24 个号里 22 个的命中率变了，最多的从 99% 掉到 0%。

三、账号级的判断必须人看。 有三条规则抓不到的检查：这个号是不是用户自己的号、是不是这个品类的商家本身、内容是不是自家交付。工具每次都会把清单打出来提醒你。

遇到问题

现象多半是
抓抖音返回空的用了普通 HTTP。必须真实浏览器 + CDP
小红书字段都在、id 是空的没登录。在那个浏览器里扫码登录即可
只拿到首屏几十条作品滚错容器了。抖音用户页真正滚的是 div.route-scroll-container，不是 window
规则改了页面没变没跑 recompute.py
判定结果和文档说的不一致以 scrape/digest.py 的输出为准，文档可能比规则旧
两个仓库分工：Akke-AI/akke-skills 放 skill 本体与安装脚本；Akke-AI/akke-official-site 放代码、规则、数据、标注集（都在 case-refs/）。
想看方法论——规则是怎么被标注一轮轮纠正出来的、踩过哪些坑——看 这一篇。
