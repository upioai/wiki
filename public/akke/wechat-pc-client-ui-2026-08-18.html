00 · 路线总表

「个微 + Windows 客户端自动化」其实只有两家真在做；另外三家各给了一种不同的答案

把「个微自动化」按微信登录在哪、谁在操作它、人从哪个界面控制三个问题拆开，五家分成四条路线。白格 = 有界面实证；灰字 = 口径/推断；待问 = 今晚（08-18）约访要问的。

家个微登录在哪谁在操作微信人的控制界面界面证据强度
水流 Windows 电脑，自研「微信聚合壳」多号聚合 本地客户端软/硬双模 RPA（跑起来顶部红字「模拟操作中，请暂停操作键盘鼠标」） 本地客户端：RPA 助手九宫格 + 聚合会话窗 + 6 节点客群 SOP 面板 + AI 标签表 强——9 张实拍 + 演示视频
鲲炬 Windows 电脑，直接登在官方微信 PC 客户端上 桌面 RPA 接管整台电脑（字幕「鲲炬AI员工 接管电脑工作中」，光标自己动） 对话框：打字/语音下自然语言指令 → AI 拆任务清单 → 确认后自跑；手机端看工作报告。没有专门的微信管理面板（微信界面本身就是它的操作对象） 中——演示录屏（投屏），无软件截图
亿销云 不在电脑上——刷机工作手机（Redmi） 手机端系统级 App；PC 不装控制客户端 Web 后台（浏览器）：聚合聊天 + AI 回复侧栏 + 语音/视频转文字 + 微信全量归档 + 128 项权限开关 强——4 支演示录屏 + 83 页 PDF
亿量 待问（六环节流程图里有「微信/企微跟进 + AI聊天记录质检」，但载体没讲） 待问——已知它刻意不做自动发圈（封号风险，自认退出获客自动化） 待问（约 08-18 晚） 弱——只有海报与流程图
零一万物 公开产品线（万智 · 企业级 Agent「超级员工/超级销售」）未见任何个微自动化产品；本专题暂列待调研 无材料

真正「装 Windows 客户端控制个微」的只有水流和鲲炬，而且两家界面哲学相反：水流把微信包进自己的壳里（你看到的是它的聚合界面，微信被藏在后面），鲲炬不做任何壳（你看到的就是微信官方客户端，AI 像个隐形人在你眼前点它）。亿销云绕开了 PC 个微这条路（手机侧接管 + Web 后台），亿量做过而退出。对我们：这两种界面哲学正对应「重界面研发」和「零界面研发」两个极端，各自的演示说服力和风控暴露面完全不同。0.75

01 · 水流

聚合壳路线——微信被包进它自研的界面里，人只看它的面板

个微全托管是水流投入最重的板块。形态：本地 Windows 客户端里一块自研微信聚合壳——多个微信号聚合到一个会话面板，右侧挂 AI 标签表（意向程度/价格接受度自动填充），下挂 6 节点客群链路（新客开场白 → 痛点 → 激活需求 → 产品介绍 → 营销 → 成交）。RPA 分软/硬两模，硬件模式跑起来屏幕顶部常驻红字「模拟操作中，请暂停操作键盘鼠标」（浮层写 Ctrl+Alt+Del 解除锁定）——这行红字本身就是「界面」的一部分：它明确告诉你这台电脑此刻不是你的。

完整机制拆解见 手册 · 水流档案 与 水流单页；官方演示视频（03:16）在档案内。

02 · 鲲炬

零界面路线——不做壳，AI 直接在官方微信 PC 客户端上点

鲲炬对个微没有任何专属管理界面：微信官方 PC 客户端登录在这台电脑上，桌面 RPA 像隐形人一样操作它——演示里「光标一直在动」「点开了我的对话框」，屏幕常驻字幕「鲲炬AI员工 接管电脑工作中……」。人的交互只有两个入口：①对话框下自然语言指令（打字或语音，AI 自己拆成任务清单、回「确认」就跑）；②手机端看当日工作报告。配置一次后「电脑不关不断网，一年不管也行」。

逐字稿证据（08-18 入库）：微信侧动作包括千人千面群发（按备注改称呼、按历史聊天生成文案，演示实拍「王景老师好」+配图）、朋友圈自动点赞/按内容生成评论/自动发圈、自动加好友与通过验证、私信接管。微信首次绑定不需要验证码（平台账号首绑需要）。没讲的：一台电脑能登几个微信、多号怎么切、封号责任归属——已进待问。完整档案见 手册 · 鲲炬档案。

03 · 亿销云

反面参照——个微不上电脑：手机端接管 + Web 后台，PC 不装客户端

亿销云对「个微 + Windows 客户端」这个命题给出的答案是不这么做：个微登录在厂商刷机的工作手机上（系统级权限），电脑上只开浏览器——所有交互都在 Web 后台完成。它的合规 PDF 正是把「协议 / 模拟器方案」（即水流那类聚合壳路线）列为高封号风险。看它的价值在于：这是「同一个需求、界面做在另一端」的完整样本，而且是九家里界面完成度最高的。

04 · 亿量

材料最薄的一家——流程图里有「微信跟进」，载体是什么今晚要问出来

亿量的已知立场：做过抖音获客自动化又因封号风险整条退出，且明确「不能自动发朋友圈，可准备素材让销售自己发」。但它的销售保 AICRM 流程图里第 ③ 环是「微信/企微跟进，进行客户答疑」，解决方案列了「AI 谈单思路/话术 · AI 聊天记录质检 · AI 客户数据统计 · AI 客户心态分析」——要拿到微信聊天记录做质检，就必须有一个采集载体（工作手机？PC 客户端？接口？），这正是今晚（08-18）约访的核心问题。

已知界面素材仅两张海报（13 条痛点 · 输单分析）+ 宣传片，无一张后台实拍。完整档案见 手册 · 亿量档案。今晚待问清单见第 07 节。

05 · 零一万物

待调研——公开产品线里没有个微自动化

零一万物（01.AI，李开复 2023 年创立）当前主线是企业级 Agent 平台「万智」：「超级员工」序列里的「超级销售」做的是 ToB 销售协作——线索分析、商机质量判断、售前方案与报价跟进，面向销售团队内部流程，不是个微触达自动化。公开材料未见任何「控制个人微信」的产品或功能（检索于 2026-08-18；ToC 端「万知」只是问答助手）。0.7

本专题对它的处理

列入待调研：若接触渠道拿到的是「万智超级销售」，那与我们的对位在销售过程协作层（类亿量），与个微 PC 自动化无关；若对方声称有个微能力，先要一张后台实拍再谈。参考：零一万物·企业级 Agent 发布稿 · 万智平台介绍（第三方）。

这通电话值得拆的三点

① 打错了对象仍然成交了「加微」：客户两次否定（不是做财税的 / 电话不多），AI 两次把话术上抬一层（财税专用 → 任何要筛客户的 → 人手不够的），第三次成功——这就是它宣称的「大模型实时对话，不是固定脚本」的实证，但也说明它的线索名单打得很糙（财税名单里混着非财税公司）。② 每一轮回复都以「加微信」收尾——CTA 密度拉满，全程没报价格。③ 终点是微信：外呼的产出物不是成交，是「推送到销售微信上由人工转化」——外呼赛道最终也汇入个微/企微私域，和本专题主线是同一条河。0.85

③ 销售 QA 增补（第四批文档笔记）

  • 回拨：客户回拨也由 AI 接，有上下文记忆（缓存管理承载，自称无上限）。
  • 实时对话：自称大模型实时交互而非固定脚本，客户跑题/反问可实时应答——通话案例部分印证，但后台截图显示存在「主线流程 + 知识库关键词」的剧本层，更准确的说法是「剧本为骨、大模型为肉」。0.7
  • 拒绝处理：明确拒绝 → 礼貌收尾、标记拒绝意向、停止二次拨打、拒绝原因写入线索标签。
  • 线索分层：通话后自动分 高意向/一般/无意向/无效号码，并把客户原话、顾虑点、需求附在线索后（销售看摘要不用复听）。
  • 持续调优：上线初期按每日真实录音调话术与提示词；服务分工=业务对接人 + 后端技术调优。

07 · 今晚（08-18）约访待问清单

亿量、鲲炬两场；问题按「答案能改变判断」排序
对象必问为什么
亿量 ① 微信跟进的采集载体是什么——工作手机 / PC 客户端 / 接口授权？要求看一屏后台实拍；② 外呼模块的形态与合规口径；③ 定位（销售外勤定位是哪种技术）；④ 知识库怎么建、有没有冲突处理；⑤ 报价口径（正文 5,000≈900 小时 与全景表 1,500/账号/年 两口径对不上） ③环「AI 聊天记录质检」必须有载体才成立；它是「风险退出者」，它现在敢用什么载体碰微信，本身就是行业风险水位的读数
鲲炬 ① 一台电脑能登几个微信、多号怎么切换；② 微信操作时人能不能同时用这台电脑（对照水流红字浮层）；③ 千人千面群发的频控参数（间隔/日上限）在哪配、给看一屏；④ 封号了算谁的；⑤ 算力单价（2,980 含 5,000 万算力，剪一条视频/发一条私信各耗多少） 它是「零界面」路线，频控和多号能力全在黑箱里；答不出③的话，「真人能做的都能做」就要按无频控理解
