根因归类:七条问题其实只有三类病根

01早班:「后续一些画面没有声音了突然」

#1
「后续一些画面没有声音了突然」
早班 · 审片时发现
现象
成片播到某一段,画面还在、人声没了。自动检查一路绿灯没拦住。
根因
自检只比总时长——而音轨是一格一格拼的,哑掉的那一格照样贡献了正确的秒数,总长对得上,就漏过去了。至于那一格为什么哑有两种,代价差一个量级:①音频本身没生成(主播格得重付口型钱)②音频好好的、合成时没拼进去(重拼不花钱)。
状态
已修上线
解决
① 审片词表加「这段没声音」一档(此前只能勾「其他」→ 不自动处理 → 永远落人工);② 修法 broll_only:素材格作废重切(不花钱),主播格只报不删——在坐实是「没生成」还是「没拼进去」之前,不对付费产物做不可逆动作;③ 自检从「只查时长」升级到同时查时长和帧数。
改在
PR #525 express/revise.py review-feedback.ts
留一手 「没声音」是词表里唯一一个修法取决于那一格是什么的档:素材格重切音轨不花钱,主播格的音轨是付费口型产物的一部分。所以它不自动作废主播格,报出来让人先判断怎么回事。

02销售(第二次):「有一小段描述的内容跟画面不一样」

这条是今天的重头。它「修过又犯」,不是一个 bug,是四件事叠在一起。

#2
「还是一样会有一小段描述的内容跟画面不一样」
销售 · 第二轮反馈
现象
口播在讲「板材封边」,画面放的是「安装灯槽周边的吊顶板」。真库实测:匹配分满分 1.00。
根因
打分量的是「字被覆盖了多少」,不是「画面在做什么」。素材标注是一大袋名词(物件+部位+动作+场景),名词越多的段越容易满分。再叠加:词表把「板材/封边」放进了木工档,而木工那 756 段几乎全是吊顶——一说板材封边,吊顶素材全进候选池。
状态
在修 · PR #537 待合
解决
A 检索收紧(PR #537):① 词表归位——板材/封边/打孔/开孔 挪到柜类档;② 动作闸——查询的动作词必须真的出现在候选的动作描述里,不是命中一大袋名词。真库验证:非柜类工序 10/10 零误伤,柜类最恶劣错配挡下。
改在
PR #537 express/broll.py
#3
找不到是哪一句、分数多少 —— 只能靠猜
复盘 · 排查这条问题时暴露
现象
销售说「有一小段」对不上,但说不清是哪一段,产线这边也查不到当时凭什么配上去的。
根因
产线每条片子都算过一张逐句对照表(这句说什么、想看什么、实际放了什么、凭什么算匹配),但它只留在工厂机上,从没传出来。
状态
已修上线
解决
对照表回写进 video_jobs.alignment 列 → 审片页可展开,每行一个「这句不对」:点了就跳到那一句、打点、预选好问题类型。销售再报「有一段对不上」,直接查是哪句、分多少。
改在
PR #529 审片页 + alignment 列
#4
修过一轮,为什么还犯 —— 返修那版根本没走修好的线
复盘 · 「修过又犯」的真相
现象
08-19 明明修过检索,销售还是报同样的问题。
根因
修好的判据只在快车道里,而返修单定位不到时会整单退回老线——老线的画面选择是另一套实现,那三条修复一条都不生效。链路:首版快车道→报问题→返修走老线→原样复发。
状态
已修上线
解决
返修不再退回老线,留在快车道整条重做;逃生开关保留。同一条线、同一套判据,修一次就真修掉。
改在
PR #529 daemon.uses_express
#5
发现问题的人,没有能准确表达它的格子
复盘 · 审片词表缺档
现象
审片词表里最接近的一项是「画面不自然、一眼看出是 AI」——可「画面对不上」和「画面假」是两件事。
根因
勾错的代价不是标签难看,是修法方向反了:「画面不自然」的动作是掏钱重做底片;而「说的和画面对不上」正确的修法是换那一格素材、或退回主播镜,都不花钱。
状态
已修上线
解决
审片词表新增「画面和说的对不上」一档,修法=换素材/退主播镜。主播格物理上不可能对不上(人在说话,就是他在说那句话)。
改在
PR #529 review-feedback.ts

03销售的两条建议,其实指向两个更深的问题

销售不只报问题,还提了两条办法。它们不是拍脑袋,恰好点到产线的两个软肋。

#6
「设置一个场景一个人物一直口播讲完会自然点」
销售 · 建议一 → 全程口播
解读
这不是审美偏好,是这个库撑不起分镜的必然结果:柜类素材只占 3%,严格要求对题,画面自然就逼近全程口播。他的直觉是对的。
状态
决定不做(全程口播开关)
为什么
原以为「加个开关技术很小」,细看不成立:工厂机是多店共享的,全局开关会把那段时间所有店的片子都变成全主播镜,不是「某个重要客户单独用」。要 per-job 得穿透 提单UI→DB列→job-book→runner 四层,是个真功能。A 已把错配本身修掉,B 只是兜底,不值得为它仓促铺四层、还可能误伤别的店。
替代
A 的动作闸已经在做「配不对题就退回主播镜」——等于按需、自动地做了他要的事,只是不需要人去勾开关。要正经做 per-job 开关的话,留了可接手的 spec。
#7
「需要的脚本去找差不多类似的素材去抓取生成」
销售 · 建议二 → 补素材(收割机)
解读
正是根因③的解药:库里没有对题的柜类画面,那就去抓。这条方向完全对。
状态
阻塞 · 缺前置
卡在哪
之前有个 B-roll 收割机,但它08-10 就停了(宿主机随人离职消失),而且它这辈子只自动收了 52 段,库的主体是一次性人工建的。它默认收的是复刻账号的施工视频,跟现有库同源,补不了柜类。08-20 尝试上云,4 次部署全失败卡在「同步 secrets」。
要重启
三件事缺一不可:① 修好上云的 secrets;② 有人先攒一份定制柜账号的授权清单(核心,没它重启也是空转);③ 标定一轮成本。这是中长期项目,不是「点一下重启」。

末仍需人做的两件事(代码解决不了的)

  • 开格级复用开关:fly secrets set EXPRESS_LOCAL_REVISION=1 -a akke-video-worker。开了返修才只重做点到的那几格;不开也已经修好了,只是整条重做、更贵。(本机 flyctl 没登录,得在有权限的机器上敲。)
  • 攒定制柜账号的授权清单:这是补柜类素材(根因③)的唯一前置。收割机重启、A 的对题率天花板,都卡在这一步。需要号主授权,不是技术活。
一句话收口 今天用户能感知的两条问题(无声音 / 画面对不上)都已经有修复上线或在途。剩下真正难的是根因③:库不对口——A 保证「不再配错」,但「又对题又有画面」的天花板,只有补柜类素材才能抬高。而那件事的瓶颈不是机器,是先得有一份授权过的定制柜账号清单。
