云电脑克隆镜像操作手册

把 饭粒（一筑） 和 夏夏（小星／零星） 现在这两台无影云电脑， 通过自定义镜像各克隆一份，开成 2 台新云电脑，环境原样搬过去、不用重新部署一遍。
版本 无影个人版 EDSP 操作入口 支付宝／微信「无影云电脑」小程序 整理日期 2026-07-28
一句话流程：每台各自 关机 → 小程序里「管理 → 镜像 → 新建镜像」→ 拿到镜像 → 开新云电脑时选这个自定义镜像 → 新机起来核对 .env 里的账号 ID 并验活 → 旧机关机保留 7 天。两台完全独立做两遍，互不相干。

1开工前必须知道的三件事

① 镜像入口在小程序里，不在网页控制台

个人版（EDSP）的镜像管理只能在支付宝或微信的「无影云电脑」小程序里操作， 网页端和软件客户端都没有这个入口。做镜像前先把小程序找出来。

② 一个镜像只能有一台在跑

绝对不要拿同一个镜像开出两台、然后同时开着跑。 2026-06-23 就是这么出事的：小文 / 文哥 / 小胡三台从同一个镜像克隆， 抖音客户端的设备指纹（%APPDATA%\douyin、%LOCALAPPDATA%\douyin、 注册表 HKCU\Software\ByteDance）被一起复制过去 → 抖音判定「同一台设备挂 3 个号、从 3 个 IP 同时活动」→ 三台搜人集体软封 （搜索结果为空、但联想下拉有结果、浏览器能搜）。 更重的一层是：多个号「出现在同一台设备」会形成账号关联，某个号违规有连坐封号风险。
但我们这次是搬家，不是复制 —— 只要旧机停掉，这个坑就不存在。 风控看的是「同一个指纹的多台机器同时活跃」。 饭粒的镜像只开饭粒那一台、夏夏的只开夏夏那一台，旧机克隆完就关掉， 任何时刻同一份指纹都只有一台在线 —— 不构成设备聚集。 所以这次不需要清指纹、不需要重登抖音，登录态可以直接跟着镜像搬过去。

③「镜像码」这个说法要对齐一下

翻了阿里云个人版官方文档，镜像相关的能力只写了一条： 「通过镜像管理创建自定义镜像备份数据，然后在新云电脑中使用该镜像恢复」。 文档里没有「镜像码 / 分享码」这种跨账号分享镜像的机制。
  • 如果 2 台新云电脑开在同一个阿里云账号下（最常见）：不需要任何码， 新建云电脑选镜像时，在自定义镜像列表里直接按名字选就行 —— 这也是本手册默认的路径。
  • 如果要开到别人的阿里云账号下：官方文档没写支持，需要先找阿里云客服确认，别默认能行。
做镜像时填的镜像名称就是之后认它的唯一凭据，所以名字必须起得能一眼分清是谁的（见 Step 2）。

2操作步骤

📱 小程序 = 支付宝／微信「无影云电脑」小程序  ·  🖥️ 云电脑 = 新云电脑里的 PowerShell  ·  🗄️ DB = 让 Claude 改数据库字段
饭粒和夏夏各自把 Step 1–6 完整走一遍，两台互不影响。

1先暂停派单，避免克隆到一半还在发单🗄️ DB

克隆期间机器要关机，派单系统看不到心跳会以为出故障。开工前找 Claude 把这台号的 dispatch_paused_until 设成一个未来时刻（比如今天 23:00）。

这个字段一改管两件事：① 派单直接跳过这个号，不会白派； ② 心跳告警也一并静音，不会在群里报「无影 agent 没在轮询」。所以不用另外去关告警。 迁完一定要让 Claude 清空它，否则新机器起来了也一条不派 —— 之前栽过两次， 一次野荞被自己静音一整天，一次把人为静音误当成「风控自愈冷却」查了半天。

2做镜像📱 小程序

  1. 支付宝或微信里搜「无影云电脑」小程序，打开。
  2. 进 云资源 页签，找到自己那台云电脑，先关机。
  3. 点云电脑卡片上的 管理。
  4. 切到 镜像 页签 → 新建镜像。
  5. 填镜像名称和描述。名字按下表起，别用「备份1」这种：
谁的机器镜像名称建议描述里写
饭粒（一筑）akke-yizhu-20260728饭粒 一筑全屋定制 DM+二触 环境克隆
夏夏（小星／零星）akke-xiaoxing-20260728夏夏 零星 DM+二触 环境克隆
  1. 选磁盘范围：系统盘必须选上（部署目录 C:\akke-wuying\wuying-dm 在 C 盘）。有数据盘就一起选。
  2. 「协助清理个人数据」开关 —— 这次保持关闭。
  3. 点确认关机并创建，等镜像创建完成。
第 7 步为什么关掉：这个开关是给「把镜像分享给别人」用的，会清掉登录态和个人数据。 我们是同一个人的机器搬家，关掉才能把抖音登录态、Cookie、坐标模板一起带走， 新机开出来基本能直接跑。开了的话新机要重新登抖音、重新配一遍。 （反过来说：万一将来要把环境给别的同事用，那个开关必须打开。）

3用镜像开新云电脑📱 小程序

  • 小程序里新建 / 购买云电脑，在镜像那一步选 自定义镜像 → 选 Step 2 起的那个名字。
  • 新云电脑的数据盘容量不能小于旧云电脑的数据盘容量（官方硬性约束，选小了创建会失败）。
  • 配置尽量和旧机保持一致，尤其分辨率。
分辨率变了，二次触达会全跑偏。二触脚本用的是归一化坐标（AKKE_C_*）， 按旧机分辨率标定的。新机分辨率对不上又没重测 → 退回默认坐标 → 二触全部 wrong_user（点到别人主页去了）。 新机分辨率和旧机不一致时，必须在新机上跑一遍 measure_nav.py 重新量坐标。

4新机第一次开机：核对账号 ID🖥️ 新云电脑

镜像是整机克隆，.env 会原样跟过来，理论上不用改。但必须核一遍， 这是唯一能拦住「按 A 号领单、却在 B 号前台发」那类事故的地方：

cd C:\akke-wuying\wuying-dm
Select-String .\.env -Pattern AKKE_ACCOUNT_ID
这台机是谁的AKKE_ACCOUNT_ID 必须是
饭粒（一筑·全屋定制）c5d236e1-fd80-4cff-b349-506dfd09699b
夏夏（小星／零星）8af08f10-6db5-4d83-8942-b908349efbda
夏夏这条尤其要看清。数据库里叫「零星」的账号有两条， 云电脑这条永远是 8af08f10，另一条 d7ac1384 是早就停用的手发号。 对不上就是搬错了，别自己改，先找 Claude 确认。

5更新脚本（这一步最容易假装做完）🖥️ 新云电脑

cd C:\akke-wuying\wuying-dm

# ① 必须先单独拉一次 update.bat 本身，再跑它
curl.exe -fsSL -o update.bat "https://raw.githubusercontent.com/upioai/wiki/main/public/akke/wuying-dm/update.bat"
.\update.bat
验收看 OK 行数，不看它说没说「成功」。 update.bat 的下载列表里不包含它自己，所以机器上那份会永远停在被摆渡下来那天的版本， 之后仓库里新加的文件永远拉不到 —— 而它照样会打印「all downloaded」。
跑完 [2/3] 段应该打出 12 行 OK； 只打 1-2 行 = 机器上是远古版更新器，按上面第 ① 条重拉一次再跑。
07-19 饭粒机就栽在这：douyin_dm_grounded.py 是几个月前的截断版， 把整条捕获链炸掉了很久没人发现 —— 因为 DM 发送腿照常在发，看着一切正常。
update.bat 不覆盖浏览器 DOM 通道的脚本（它只下 6 个抖音 PC 客户端脚本）。 饭粒和夏夏两台都是 DOM 版，所以 douyin_dm_web_*.py 这几个要单独补拉： 
curl.exe -fS "https://raw.githubusercontent.com/upioai/wiki/main/public/akke/wuying-dm/<文件名>.py" -o <文件名>.py
确认本机在跑哪个发送脚本：Select-String .\.env -Pattern AKKE_DM_SCRIPT

6起来 + 验活🖥️ 新云电脑

powershell -ExecutionPolicy Bypass -File C:\akke-wuying\wuying-dm\akke-start.ps1

然后逐项对：

#检查项合格标准
1调试版 Edge 通了浏览器开 http://127.0.0.1:9222/json/version 返回版本 JSON
2agent banner 绑对号account= 与 Step 4 表格一致，second_touch / rc 开关和旧机一样
3抖音登的是本人号Edge 里抖音登录的账号，和 banner 里的 account 是同一个人
4回复捕获腿活着py douyin_dm_web_capture_dom.py 出 web capture[DOM] ＋ conversation-item N>0 ＋ COMMIT 写回
5开机自启还在Get-ScheduledTask *akke* 能看到 AkkeDomDmStart 等任务是 Ready
6DB 侧心跳让 Claude 查 last_poll_at，5 分钟内有刷新
7肉眼核私信气泡发出第一批后人工翻抖音私信，对方会话里真有气泡
第 7 项不能用日志代替。日志里的 sent 只代表「点了发送」。 抖音对陌生人私信有静默限流（约 24 小时冷却），命中时日志一片绿、消息根本没送到。 新机第一批必须人工核气泡。
第 4 项报 conversation-item=0 时先别慌：如果 by_name 有数字、只有 conversation-item 是 0， 那是私信面板还没加载完的时序问题，不是登录过期（真过期连 by_name 都读不到），下一轮会自愈。

7收尾🗄️ DB

  • 让 Claude 清空 dispatch_paused_until，恢复派单。这步忘了 = 新机器一条都不发。
  • 观察第一批实发，核气泡。

3旧机怎么处理 · 推荐做法和理由

推荐：新机验活通过后，旧机立刻关机，但保留 7 天不释放，7 天后再退

三条理由，按重要性排：

  1. 新旧同时开着跑，就把「搬家」变成了「克隆多开」。 同一个抖音号、同一份克隆出来的设备指纹，两台机器同时在线活动 —— 这正是 06-23 那次三台集体搜索软封的触发条件。旧机一关，同一时刻只有一台在线，这个风险直接归零。
  2. 两台机器会抢同一批派单。新旧两台的 .env 里是同一个 AKKE_ACCOUNT_ID， 两个 poll agent 会同时去领同一个号的派单队列，结果是抢单、重复发给同一个客户、 本地发送记录互相打架。这不是风控问题，是当场就会出的数据问题。
  3. 关机但不释放 = 留一个能立刻回滚的兵。新机万一有问题（脚本没拉全、坐标不对、登录态没带过来）， 把旧机开回来 + 清掉暂停字段就恢复原状了。多留几天的机器钱，比出问题时无处可退便宜得多。
验活没全绿之前，两台都别跑。正确的顺序是：旧机关机 → 做镜像 → 开新机 → 新机验活 → 确认没问题后才清 dispatch_paused_until 让新机开始接单。 全程不存在两台同时在跑的时刻。
