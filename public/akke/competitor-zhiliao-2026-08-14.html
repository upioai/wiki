00

一分钟看懂这是个什么东西

买一个「指挥官」，你得到的是一套 Web 控制台 + 一台被它托管的普通安卓手机。任务在电脑上配，动作由手机在真实抖音 App 里做——点关注、发私信、在私信列表里逐条打字。手机不用插电脑，只要有网就能被指挥；但跑起来这台手机就归它了。

本次拆解最重要的三条

  1. 「电脑下达指令、手机操作」被画面坐实了。控制台旁边常驻一块手机实时画面，手机在真实抖音里刷视频、进对标账号主页点「已关注 / 发私信」、在私信列表弹键盘打字。字幕正好是「电脑端和手机端同时运行」。
  2. 它是六家里唯一「不挑机型、不用刷机、不插线」的。安卓不限型号，PC 端 Windows 和 macOS 都支持。销售还专门用一段话点了同行的名：「同行对设备是有依赖的，必须要固定机型」——这几乎是指着水流（锁摩托罗拉 S50）和亿销云（定制 ROM）说的。
  3. 销售主动承认自己大部分功能是半自动的。原话：「前面这些功能都属于半自动，下面这个 AI 自动驾驶就是真正的全自动」。九家里难得有厂商自己划这条线，这句话可以直接拿去问其余各家。
01

六段收口

按 08-14 机制页的固定六段填。知了是六家里私信频控做得最显式的一家。

①

用什么设备

口径1 个「指挥官」= 1 台电脑 + 1 台手机；账号绑定不限数量，指抖音 / 快手 / 小红书 / 视频号这几个平台号。

口径手机：安卓，不限型号，不需要刷机。

实证电脑：Windows 和 macOS 都支持——「获客PC端」顶部并排两个 tab：电脑AI数字员工（Windows系统） / 电脑AI数字员工（mac系统）。这一点六家里只有它做到。

②

怎么控制 / 运行

实证大脑是 Web 控制台「知了指挥官」，一级菜单：工作台 · AI项目中心 · AI视频中心 · 移动端获客 · PC端矩阵获客 · GEO优化 · 我的AI员工 · 全域获客工具 · 设备管理。

口径手机怎么连：不用插电脑，只要有网就能用；下载安装运行即可，不用再做别的准备。

实证手机上跑什么：在真实抖音里执行真实动作——刷视频、进评论区、进对标账号主页点「已关注」「发私信」、在私信列表里逐条打字回复。

口径电脑上跑什么：独立的「获客PC端」，任务与手机端几乎一一对应。销售原话：「无非只是执行的设备不同」。

③

是否依赖电脑 / 插件 / 脚本

手机必须连电脑：不必须——这是它和水流（电脑给手机发指令）最本质的区别。

要不要刷机 / 挑机型：都不要。要不要写脚本装插件：不要。

口径运行时电脑可以做别的事情，手机不能；电脑软件和手机还可以分别做不同的任务。

推断0.55纯手机端任务时电脑是否必须开着，本轮未确认，已进待问。

④

实际操作流程

在获客中心选执行设备（手机 / 电脑，同一排 tab 切）→ 勾执行平台（抖音 / 快手 / 小红书 / 视频号）→ 逐个打开任务开关（关键词获客 · 同城评论 · 行业获客 · 白名单获客 · 互动执行 · 养号管理 · 内容发布）→ 每个任务点进去配参数 → 设全天时段与循环天数 → 手机 / 电脑在真实 App 里执行 → 留资自动推送到指定的微信群。

另有一条省力路径：在小程序或电脑端「AI助手」里用一句话（甚至语音）下指令 → AI 拆成方案 → 点「确定」→ 直接派给设备。

⑤

发送时间机制

五层：全天时段 + 循环天数 + 私信轮询间隔 / 每次上限 / 每天上限 + 仿真行为概率 + 互动执行秒回。详见 第 04 节。

⑥

实测数据

累计执行 72,531 次；算力余额 109,670；仿真行为策略拦截概率 23% / 61% / 62%；同城范围档 1–100km；上下文「翻上面五六条」。详见 第 06 节。

这是本页最该看的一组图——左边控制台配置、右边手机实时画面，动作过程从头到尾可见。

这条路线对 20 家门店的真实成本含义

  • 好处：不挑机型、不刷机、不插线，装完就能跑；电脑还能照常干活。
  • 代价：每台设备要占一部安卓机，且跑起来店员不能用。20 家店就是 20 部手机的采购与占用成本——这笔账比功能清单更能决定甲方选谁。

四种拓客入口 + 一个「全自动」开关

入口怎么找人销售原话要点
关键词获客按行业关键词全网找热门视频 → 在评论区自动找意向高的客户 → 发私信引流到微信—
同城获客 / 同城评论设周边 3 / 5 / 10 公里内的视频，在这些同城视频下打广告、做曝光建立互动「看到你评论的人基本上都是在你服务半径之内的客户」

AI 自动驾驶告诉系统要什么客户、要多少，分析 / 执行 / 优化 / 复盘全交给 AI「前面这些功能都属于半自动，下面这个才是真正的全自动」
04

时间机制与频控：六家里最显式的一套

水流强在跟进节奏模板，知了强在频控与拟真的概率参数——两家补的是不同的洞。

层控件粒度
① 时间窗「全天时段 00:00–23:59」（可改）整个获客中心一个营业时间
② 周期「循环天数」+ 日期区间（演示为 2026-04-18 → 05-18，循环 30 天）任务跑多少天
③ 频控私信自动回复的「轮询间隔 · 每次上限 · 每天上限（人/天）」六家里唯一把私信频控做成显式数字的
④ 拟真每个任务独立的「仿真行为策略」：拦截概率 · 顺序执行概率用概率打散行为，避免机械规律
⑤ 即时互动执行是秒回（事件触发）不排队

「仿真行为策略」这两个百分比值得单独记

  • 三个任务的实测读数：拦截概率 23%（关键词）/ 61%（行业）/ 62%（同城）；顺序执行概率 19% / 16% / 15%。
  • 把行为按概率打散，是「装你电脑上模拟人操作」这条路线上成熟度的分水岭——能不能跑起来大家都能，节流做得细不细才是差距。这两个参数的确切语义材料里没解释，已进待问。
05

语音指挥：一句话出方案，但有个「确定」按钮

一个反向发现，对我们是旁证

  • 「一句话就自动干活」这个叙事，实际形态是「一句话出方案 + 人点确认」。
  • 这和我们「AI 起草 + 店长确认 + 审核台放行」是同一路。可以引用为旁证：连主打全自动叙事的厂商，真正落到执行前也放了一道人工闸。

对我们意味着什么

维度知了我们判断
执行面手机在真实 App 里点，不插线、不挑机型云电脑 GUI 串发 + iPhone WDA它的装机门槛更低；我们的云电脑不占店员设备
硬件成本每台设备占一部安卓机，跑起来店员不能用云电脑，本机可关我们领先，这是 20 门店场景下的实质差别
频控轮询间隔 / 每次上限 / 每天上限 + 仿真概率，全部可见可调有配额与串行节奏，但界面上看不见它领先——不是能力问题，是呈现问题
公域打分命中回复话术，上下文翻五六条LLM 语义打分 + 装修阶段分类我们领先
线索去向留资直接推到指定微信群推 Lark，门店店长侧无等价物它的做法更轻、更贴近人已经在看的地方
人工闸AI助手出方案后要点「确定」AI 起草 + 店长确认 + 审核台同一路，可引为旁证

三条可以直接用的动作

  1. 把频控参数搬到界面上。甲方问「你们一天最多加多少人、间隔多久」时，我们目前答不出一个可以指着看的数字——而这不是能力缺失，是没做成界面。
  2. 把「留资推送到微信群」这条路径抄过来。不做通知中心，直接推到店长已经在看的地方。
  3. 把「半自动 vs 全自动」这句话拿去问其余各家。知了自己划了这条线，其他家没有——这是一个很好用的追问。
08

还没问清的（下次沟通照着念）

对知了的 5 问

  1. 手机跑起来就不能自用了——门店店员那台手机怎么办？是要单独配一台，还是有办法后台跑？（这是它落到 20 家门店时最现实的成本）
  2. 手机是怎么收指令的——云端下发还是要和电脑在同一个网？手机端任务跑的时候，电脑必须开着吗？
  3. 「仿真行为策略」里的拦截概率 / 顺序执行概率具体是什么意思？调高调低分别影响什么？
  4. 「AI 自动驾驶」和前面那些半自动功能，效果差多少？有没有跑过对比数据？
  5. AI 聊天「翻上面五六条」是产品固定值还是可调？（对比：水流是 0–50 滑杆可调）

本页的证据分级：实证＝演示画面上直接读到的；口径＝销售在片中或问答里说的；推断＝组合判断，带置信度。一处必须说明的局限：全部画面来自厂商官方剪辑过的演示视频，不是现场实操——剪辑意味着失败与卡顿的片段可能被剪掉了，这一点与水流那种腾讯会议实时共享屏幕不同，证据强度低一档。
