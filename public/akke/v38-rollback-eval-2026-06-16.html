结论：不建议回滚 v38

④ 信号缺口与长期监测建议

为什么 DB 数据这么少？根因清单

  1. 抖音平台层无 DM 回复 API — 平台基因约束，所有第三方工具同样问题
  2. 三条发 DM 通道，回复收集只为 message_queue 通道做过：
    • A. message_queue + Fly worker → 有 /api/cron/check-replies 但 6/05 前后已下线
    • B. ADB / WDA → scan-dm-replies.py 工具存在但没人在跑（data 目录零文件）
    • C. 阿里无影云电脑 → 完全没有扫盘工具
  3. handed_off_at 加微转化全靠人工标 — 没有写入口，没人填
  4. 抖音收件箱滚动天花板 — 即使扫盘也只能看到列表能滚到的范围

长期监测机制建议（按优先级）

  1. 🔥 云电脑扫盘工具 MVP（1 天）— 收口到云电脑后唯一可行的回复收集通道
  2. 🔥 加微回写口子（半天）— mark-handed-off.ts 一行命令 / Lark 飞书表单
  3. ⚙️ 回灌自动化（半天）— GHA cron 每晚自动跑 sync-inbound-replies.ts
  4. ⚙️ prompt 切换自动评估（半天）— 切版本写 prompt_version_changes，7d 后自动出对比卡
  5. 📊 常驻看板（1 天）— upio.ai/akke/prompt-eval 按 prompt × account 切片
