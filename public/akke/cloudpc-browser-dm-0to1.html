1 为什么是「浏览器 + 视觉定位」

三条路里选 C。关键判断：手工浏览器能发 DM ⇒ web 私信入口存在 ⇒ 自动化可行；视觉定位绕开 Playwright 反检测。
路线做法工作量结论
A · PC 客户端 grounded装抖音 PC 客户端 + 现成 wuying_poll_agent.py零写已投产，但要放弃浏览器
B · 浏览器 PlaywrightDOM 驱动 web 私信大（+反检测调试）弃 navigator.webdriver/指纹易被拦
C · 浏览器视觉定位 ✅截图→Qwen VL 找元素→真鼠标点中（搬骨架+重标坐标）选定 保住浏览器 + 绕反检测 + 复用机器
复用 PC 版（douyin_dm_grounded.py）： Qwen VL 调用 / 截图 / SendInput 中文键入 / 主页身份 OCR / 气泡核对 / CSV 契约。 重写三段： ① 导航（地址栏直达 douyin.com/user/<sec_uid>，省搜索+双因子撞名）② 视觉点「私信」灰按钮 ③ 面板身份门（OCR 浮层顶昵称，防全局私信箱没切干净发错人）。

3 遇到的卡点（按出现顺序）

7 个，全部已解。头号是 IME 吞 URL；最隐蔽是 dotenvx 横幅污染 JSON。
#现象根因修法
1云电脑 pnpm 不存在这台只有浏览器+python，无 node 工具链claim/mark 留 mac，云电脑只发（且避免 service key 下放）
2.env 搜不到 ANTHROPIC_API_KEY实为 OPENROUTER_API_KEY脚本两者都认 + 默认 OpenRouter base/Qwen VL，无需补
3claim JSON 解析报 Unexpected token ◇隐蔽 dotenvx ◇ injected env 横幅打到 stdout，且含 [www.dotenvx.com] 骗过「首个 [」按行首是 [ 的那行定位真数组
4claim 出 0 条带 opener这俩 lead 无云端预生成话术生产 generateOpener 补；1/2 self_check_failed 空话术 → 跳过不发
5URL 跳成「搜狗搜索」发不出头号 中文 IME 拦/吞 typewrite 的 URL → 残缺串被当搜索词SendInput unicode 注入 URL 绕开 IME（PC 版打中文同款机制）+ 非主页自动重导航 ×3
6私信面板首次 verify 假阴性面板还在渲染就核对 → 误判没开改「先多等 2.5s + 复核，真没开才再点」——面板已开时再点私信部分主页会 toggle 关掉
7125% 缩放坐标/截图风险DPI 混合像素易错位、截图降采样糊SetProcessDpiAwareness → 截图清晰 + 坐标同物理像素自洽（读到满血 2560×1600）
