一句话：在你的云电脑上挂个常驻程序，它自己去库里拉客户线索、自动加微信、自动回写进度，你不用守着。

③ 线索怎么分给每个人（不会重复加 · 重点）

一句话：所有人共用一个线索池；每台云电脑每轮去池子里「捞还没人领的几条」，捞到就盖上自己的名字章，别人再也捞不到这几条。
举个例子（池子里现有 300 条「待加」，三台同时跑）：
  1. 夏夏的 agent 这一轮捞 5 条没人领的 → 盖上「夏夏」章 → 这 5 条变成夏夏的，别人看不到了。
  2. 同一时刻 饭粒的 agent 也在捞，但它只会捞到另外 5 条（夏夏盖过章的它直接跳过）→ 你俩永远不会加到同一个客户。
  3. 野荞同理，再捞另外 5 条。三个人各干各的，池子越捞越少。
  4. 你名下加完的（已发请求/加不上）就结了；没加完的（比如崩了、或这轮搜不到先跳过的）下一轮你自己的 agent 优先重新捞回来，不会丢、也不会被别人抢。

所以你要做的只有一件事：在 .env 里 AKKE_WECOM_OPERATOR 填你自己的名字、而且和同事都不一样（饭粒 / 夏夏 / 野荞…）——这就是"盖章"用的名字。重名了系统就分不清谁是谁、统计也会串。其余系统自动分，你不用手动划分谁加哪些。

技术上：claim_enterprise_leads 用 FOR UPDATE SKIP LOCKED 原子认领，"捞 + 盖章"是一步到位、并发也不会两台领到同一条。

⑤ 开跑（3 步搞定，第 4 步可选）

1
拿两个脚本，放到云电脑 worker/scripts/wuying-dm/ 下（找 PM 要 paste.rs 链接 / 共享盘）： 
# 两个都要，缺一不可
wecom_add_agent.py            # 无人值守大脑
wecom_add_contact_grounded.py # 真正在企微里点点点加好友的
2
配 .env（跟脚本同目录，没有就新建）： 
SUPABASE_URL=https://nytlptpfqfnrpqemrtpr.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<你自己的 eyJ… key>
AKKE_WECOM_OPERATOR=<你的名字，如 夏夏>
OPENROUTER_API_KEY=<sk-or…，一般已有>
AKKE_WECOM_DAILY_LIMIT=20
AKKE_WECOM_CLAIM_LIMIT=1   # 第一天先填 1，盯一条端到端；稳了再调 5
3
起 agent（企业微信前台最大化、输入法切英文、分辨率锁死）： 
python -u wecom_add_agent.py
它会每 5 分钟自己跑一轮，今天配额发满就自动待机。关机 = 暂停，再开机重新起一下就接着跑。

✅ 不用先采坐标——脚本靠看屏幕（VL）自己定位（饭粒云电脑实测：不采也能准确找到搜索框/按钮）。直接起就行。

盯通第一条后，把 .env 里 AKKE_WECOM_CLAIM_LIMIT 改成 5、Ctrl+C 停掉重新起 = 一轮领 5 条。

4
（可选，一般不用）真定位点歪了再采坐标：万一看到它点错地方/老搜不到，先手动搜个能加的人、把「发送添加申请」弹框开出来，再跑 python wecom_add_contact_grounded.py --capture 按提示采一遍。没问题就跳过这步。

⑥ 盯第一轮，看这 4 样对不对

  1. 开头打印 org=… operator=你的名字 … = 连上数据库了。
  2. 出现 新认领 1 条 + 话术X = 拉到线索、AI 选好话术了。
  3. 企业微信里真的在动：搜索框打号 → 点「网络查找」→ 弹人物卡 → 点「添加」→ 验证框里是选好的话术（不是默认占位语）→ 点发送。
  4. 去数据库看那条线索，状态从 待加 变成 已发请求 = 闭环成立。

这几样都对，就把 AKKE_WECOM_CLAIM_LIMIT 改成 5、重启，放手让它自己跑。看到 加不上/搜不到 别慌——很多号没开手机号搜索，正常，不占配额、会自动跳下一条。

⑦ 节奏怎么调（配额 / 频率 / 一轮几条）

三个旋钮都在 .env 里，改完 Ctrl+C 停掉、重新 python -u wecom_add_agent.py 才生效。
想调什么改这行说明
一天最多发几条（配额）AKKE_WECOM_DAILY_LIMIT=20一天最多发几条好友请求，发满当天自动待机到明天。加好友敏感，别贪多，先 20 看几天封不封再往上加。加不上/搜不到 不占这个数。
一轮领几条（批量）AKKE_WECOM_CLAIM_LIMIT=5每轮去池子捞几条来处理。第一天先 1 盯着，稳了改 5。

实际速度 ≈ 一轮领 N 条、一条一条发（每条间隔 40–120 秒）、发完歇 5 分钟再来。想发快点：调大 CLAIM_LIMIT 比缩短轮询有用，但都别太猛。

⑧ 怎么查进度 · 通过率（已自动标，不用你管）

✅ agent 现在会自动检测谁通过了：发出去 24 小时后，它每轮顺带把那条号再搜一次，看到"已经是好友"就自动把 已发请求 标成 已通过——你不用手动标。

几个要知道的：

  1. 刚上线头一两天通过率还是低 / 为 0，正常——对方本来就要隔天才点通过，复查也得等请求满 24h 才查。攒几天就会自己涨。
  2. 复查很保守：只在明确"已是好友"才标 已通过，拿不准一律不动（宁可少算、不乱算）。所以个别真通过了但没被标到的，可让 PM 手动补：scripts/writeback-enterprise-lead.ts --source-id=… --status=已通过。
  3. 统计：PM 跑 scripts/wecom-acceptance-by-template.ts 出「每条话术 已发 / 已通过 / 通过率」，看哪条话术更易过。
  4. 复查跟发请求共用一个窗口、排在发请求后面，不会抢节奏；不想要可让 PM 关（AKKE_WECOM_RECHECK=0）。

查自己今天发了几条：数据库看 enterprise_leads 里 claimed_by=你的名字 + add_status=已发请求 当天条数；或问 PM。
⚠️ 复查这块刚上线、还没在云电脑实跑验证过——头几天留意下日志里有没有 [recheck] 行、标的对不对。

⑨ 最容易踩的坑（出问题先看这里）

逐条对照：
  1. 名字别跟同事重名（AKKE_WECOM_OPERATOR）。重名会让「谁领了哪条、重试、统计」串台。
  2. 两个 key 别填错：Supabase 的是 eyJ…（连数据库），OpenRouter 的是 sk-or…（AI）。两个都要、各填各的位置。
  3. Supabase key 要能写。只读 key 会出现「能加、但状态一直回写不上、卡在同几条上反复」。
  4. 分辨率锁死、别开自适应缩放。变了之前标的坐标全废，要重 --capture。
  5. 输入法切英文。中文输入法会抢走搜索词的第一个字 → 搜错人/搜不到。
  6. 企业微信前台、最大化。缩到后台，点击会落到别的窗口。
  7. 一般不用 --capture 采坐标——VL 看屏幕自己定位（饭粒实测可行）。只有真看到它点歪了再采。
  8. 话术想改文案，找 PM 改源头（统一的 3 条），别在云电脑本地脚本里改 —— 下次更新会被覆盖。
  9. 「搜不到」很多是正常的：不少人没开「允许手机号搜到我」→ 记成 加不上，不是 bug。
  10. 起步慢：先 20/天看几天封不封，再决定要不要放量。
