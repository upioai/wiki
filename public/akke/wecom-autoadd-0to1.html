企业微信「无人值守自动加好友」· 同事上手教程

兔宝宝全屋定制 · 客户线索（手机号/微信号）→ 云电脑企业微信自动加好友 → 自动查通过 · 一台云电脑挂上就自己跑 · 2026-07-01

一句话：在你的云电脑上挂个常驻程序，它自己去库里拉客户线索、自动加微信、自动查对方通过没，全程你不用守着。

跟手动版（自己拉单→传文件→点着发）比，这版全自动：起一次，它每几分钟自己干一轮。多个同事一起跑也不会重复加同一个人。

它到底在自动做什么？四件事，循环干：

① 拉单——去数据库领一批"待加"的客户线索（有手机号/微信号）；② 选话术——按客户备注自动挑一条加好友话术；③ 加好友——在企微里搜人→网络查找→添加→填话术→发送；④ 查通过——发出一天后再搜那个号，看对方通过没、自动标"已通过"。一台云电脑 = 一个企业微信号 = 一个你。

③ 批量化：从 1 台到全员一起跑

不会重复加：所有人共用一个线索池，每台云电脑只领"还没人领"的，领到就锁在自己名下——数据库原子锁，物理上不可能两个人领到同一条。
举例（池子 300 条，三台同跑）：
  1. 夏夏的 agent 捞 5 条盖「夏夏」章 → 这 5 条别人看不到了。
  2. 饭粒同时捞，只会捞到另外 5 条 → 你俩永远不加同一个客户。
  3. 没加完的（崩了/搜不到先跳过的）下轮你自己的 agent 优先重捞，不丢不重。

你只需做一件事：.env 里 AKKE_WECOM_OPERATOR 填你自己、跟同事不重名的名字。重名会让"谁领了哪条 / 统计"串台。

④ 它怎么自动查"好友通过没"（免手动标）

核心一招：拿当初发请求那个号，在企微里再搜一次，看它变成"好友"了没——不发消息、不打扰对方、只搜一下看状态。

为什么用"再搜一次"：搜的号跟当初发请求的一模一样 → 天然知道是哪条线索，不用扫"我的客户"名单、不用靠昵称猜（昵称常≠真名、还重名）。

再搜后卡片显示判断动作
「发消息」/已是好友/已添加对方通过了标 已通过
「等待验证」/重新发送还没通过不动，下次再看
又能「添加」/搜不到没通过（拒了/删了/没开搜）保守不动

多久查一次：请求发出满 24 小时才开始查（对方总得有时间点通过）；之后每个号约每 12 小时被复搜一次，轮着来覆盖所有待验证的号，不反复搜同一个（防风控）。每轮顺带查 3 条，排在发新请求后面、共用同一窗口。

保守优先：只在明确"已是好友"才标已通过，拿不准一律不动（宁少算不乱算）。所以通过率会自己慢慢涨；个别真通过没标到的，PM 可手动补 writeback-enterprise-lead.ts --status=已通过。不想要复查设 AKKE_WECOM_RECHECK=0 关。

⑤ 群里会自动通知你什么（「企微数据值班监控 Agents」群）

你不用一直盯着云电脑——该看的时候机器人会主动把卡片推到「企微数据值班监控 Agents」群。一共三种：
什么情况触发推什么卡多久你该做什么
有客户通过了好友申请（复查检出真通过） 🎉 绿卡 列出谁通过了 · 谁加的 · 话术几号 · 地区/联系方式 每 15 分钟扫 看到就去 1v1 跟进这个客户
某个号当天成功发满 20 个请求（到日上限） 📊 蓝卡·当日战报 该号今天 ✅通过 / ⏳等通过 / 🔍搜不到 / 🚫无效 各多少 每 30 分钟查 了解每个号今天战况；没满 20 不推
某个号连续 10 条搜不到（账号被搜索风控） 🚨 红牌·熔断告警 @对应运营 + 写清怎么办 一触发立刻 agent 已自动停手；歇账号 24h+ 再验证恢复（见下）

熔断为什么重要：日上限 20 卡的是"成功发出"，搜不到不算数。所以账号一旦被风控（搜啥都"找不到"），agent 会一直凑不满 20 而闷头狂搜——既空烧号池、又往死里锤账号（实测一天搜 119 次只成 2 条）。熔断就是防这个：连续 10 条搜不到就自动停手，落一个 _breaker_tripped.flag 文件，重启也会直接退，必须人工确认账号恢复、删掉这个文件才继续。

🩺 账号被风控了，怎么"人工确认恢复"
  1. 先让账号歇满 24 小时，期间别开——硬搜会加剧风控甚至封号。
  2. 之后在企微里手动搜一个你确定能搜到的手机号（同事的、或你知道肯定在微信上的号）：
    · 能弹出人物卡片、有"添加" = 恢复了 → 删掉 _breaker_tripped.flag → 重启 agent；
    · 还是"无法找到该用户" = 还在被限 → 继续等，别开。
  3. 拿不准就问 PM，别赌。

怎么判断是被风控、不是号池差：同一个池子比失败率——正常号搜不到率 <30%，被风控的号会飙到 90%+；别人正常就你惨=你账号被限。想让熔断也@你本人+推群，在 .env 加 AKKE_WECOM_ALERT_WEBHOOK + AKKE_WECOM_ALERT_AT_OPENID（值找 PM 要）；不加也会自动停手，只是不推群。

⑥ Good case / Bad case（心里有数）

👍 Good case
  1. 备注有真实装修线索（毛坯新房/想了解价格）→ AI 选对话术 → 搜得到 → 已发请求 → 隔天通过 → 复查自动 已通过。这是最理想的一条。
  2. 备注写「手机号是微信号」→ 脚本自动用微信号搜（微信号优先），照样加得上。
  3. 多台同跑各领各的，池子越捞越少，谁也不撞谁。
👎 Bad case（多半不是 bug）
  1. 搜不到 → 加不上：很多号没开"手机号搜到我"，该用户不存在。正常，不占配额、自动跳下一条。
  2. 死号（备注空号/无效且无微信号）→ 直接跳过标"无效"，不浪费。
  3. 同行 / 已装修 / 明确拒绝 → 加了也没用，属预期损耗。
  4. 真 bug 型：搜错人/搜不到全部→多半是输入法没切英文（IME 抢首字）；点歪→分辨率没锁；连不上库→key 填错/填成 sk-or；卡在同几条反复→key 没写权限。

⑦ 下一步

  2. 攒数据看通过率：跑几天有 已通过 后，PM 跑 wecom-acceptance-by-template.ts 出「每条话术 已发/已通过/通过率」，看哪条话术更易过、据此调配比。
  3. 放量决策：先每天 20 看几天封不封，稳了再往上调 DAILY_LIMIT。
  4. 可能的增强（还没做）：超 14 天还没通过的自动标"未通过"，让通过率分母更干净。

⑧ 其他要知道的

  1. 关机 = 暂停：云电脑关了 agent 就停，再开机重新 python -u wecom_add_agent.py 起一下就接着跑，不会重复加。
  2. 脚本更新：PM 发新 paste.rs 链接时，Ctrl+C 停 → curl 覆盖三个 .py → 重起。.env 不动。
  3. 话术别在本地改：改文案找 PM 改源头，本地改会被下次更新覆盖。
  4. PII 安全：手机号/微信号/备注只在数据库 + 云电脑本地，名单 CSV / 日志全 gitignore 不进代码库；别把 key、别把名单外发或截图给外人。
