①两端结论：浏览器走 DOM，PC 维持原状

同一个目标（自动读私信判客户回没回），两个界面，结论完全不同——这是整件事最重要的战略判断。

🌐 浏览器端（Edge 网页版）

标准 Chromium · CDP 可挂
  • Playwright connect_over_cdp 接管已登录的调试版 Edge
  • 私信有整套语义锚点 data-e2e：conversation-item / msg-input / msg-item-content
  • 无 canvas、无 shadow DOM
  • navigator.webdriver=false（接管现成 Edge，不翻自动化旗）
✅ DOM 自动化（本方案）· 已上线

🖥️ PC 客户端（douyin.exe）

CEF 套壳 · 有反调试守护
  • 是 CEF（Chromium 内嵌），但 release 版调试口默认关
  • 有专门的 douyin_guard.exe 反调试守护进程盯着
  • 全端口空扫无 CDP；带 flag 重启也大概率被掐
  • imSaasContainerId 是 UIA AutomationId，证明不了 CDP 可挂
⛔ DOM 判死 · 维持 UIA 读 + 像素发
关键判断：不追求"两端统一一套核心"——那是幻想。浏览器端拿确定收益，PC 端不押宝。

⑤Badcase 分类 · 根因 · 优化方式 · 进展

A. 判回复准确性（最关键——错了就把我方话写成客户回复 / 漏真回复）

Badcase根因优化方式进展
我方多发的第二条话术被当客户回复（小艳子🍭）we_sent_last 只比对库里一条 opener，对不上就误判红点闸：无未读红点=非新回复，直接跳过，不靠预览猜已根治

B. DOM 稳定性

Badcase根因优化方式进展

"私信列表要点用户头像才出来"（运营观察）那是肉眼视觉渲染；点头像=进具体会话=标已读Playwright 读 DOM 不是读画面——点「私信」后 conversation-item 已在 DOM 里，不需点头像澄清·非问题

⑦时效压缩方案 · 回复→自动回复压到 ~15–40s（规划中）

目标：把「客户回复 → 自动回复发出」的端到端时延从当前 ~3–7min 压到 ~15–40s。硬 15s 不能当承诺——下面三条是物理墙，方案是逼近下限、不是消灭它。

为什么硬 15s 做不到（先认清物理墙）

物理墙约束对策
Vercel cron 最小粒度 1min起草挂在 /api/cron/dm-auto-reply */5 上，光提频也到不了 15s起草改事件触发（搬出 cron，见改动①）
单 Edge 窗口串行AKKE_WINDOW_LOCK：首触/二触/RC 与自动回复共用一个抖音窗口，有批在发(每条20–45s)时回复排队autoreply 轮内最高优先级；有 pending 回复时让首触让位
每轮 DOM 读 + chatReply 各几秒单轮闭环物理下限 ~8–12s无法消除——决定了 15s 是地板不是天花板

改动清单（捕获→起草→发送 收敛成单轮闭环）

  • 核心
    ① 起草改事件触发（去掉 0–5min cron 等待）
    新建 POST /api/dm-reply/draft-one（入参单个 conversation_id，内部复用 ensureInboundVerdict → generateDraftForConversation → gateDraft，即 processAwaitingReplies 抽单条版，逻辑零新增）。捕获脚本 douyin_dm_web_capture_dom.py 命中真回复、record_dm_inbound 写完后同步 POST 它（~2–5s 拿到 approved）。高危路径，走 PR。
  • P1
    ② 同轮发送（不等下一轮）
    both 模式本就在同一 pass 扫 approved 发出；改动①已在本 pass 前段把 approved 写好 → 同轮直接发，省掉一整轮 60s。把「内联起草」排在「扫 approved 发送」之前即可。
  • P1
    ③ 捕获真按 15s 跑
    云电脑 .env 加 AKKE_POLL_INTERVAL=15 + AKKE_DM_AUTOREPLY_INTERVAL=15，改完重启 poll agent。只设后者无效——捕获嵌在 poll 主循环里，每轮末 sleep(POLL_INTERVAL)，有效节奏 = max(两者)，缺 AKKE_POLL_INTERVAL 时 15s 被默认 60s 压死。
  • 兜底
    ④ 保留 */5 cron 做降级网
    inline POST 网络抖动/失败时，cron/dm-auto-reply 仍每 5min 兜底补起草。别删——删了内联失败就成单点漏回。

改完后的时间账（空窗 = 窗口没在跑首触批）

子步骤改前改后
捕获读到 inbound~60s~15s（改动③）
起草调度等待0–5min~0（改动① 事件触发）
chatReply 起草 + gate几秒几秒
发出等下一轮 ~60s同轮（改动②）
合计~3–7min~15–40s
两个必须接受的权衡
① 抢窗口：要回复稳定 15–40s，得在「有 pending 回复」时暂停首触派单（autoreply 抢不了进行中的发送，只能让下一批让位）。有首触批占窗时回复退化到分钟级。
② 风控：每条 15s 内秒回、节奏机械 → 像 bot。建议留 5–15s 随机抖动，别真做到 0 延迟。

（落地顺序：改动① 收益最大先做；改动③ 改云电脑 .env 即可；改动②④ 随①一起。本节为规划，未上线。）

⑧第一个落地案例 · 首触派单 + DOM 捕获回复（已上线）

这是本方案第一个真实跑起来的案例：野荞机（admin / account 9535e31c）整条私信链于 2026-06-29 切到 DOM——给新 lead 发招呼（首触派单） 和 读客户回复+自动起草（DOM 捕获回复） 都在隐形 Edge 里跑。下面是这个案例端到端怎么搭起来的，黄色 = 关键操作 / 关键设置。后续推广到饭粒/夏夏/零星等机就是复制这套。

（本案例对应的：逻辑原理图见 ②；批量统计 + Badcase + 优化进展见 ④⑤；下一步优化见 ⑥。）

一、云电脑关机 / 重启后 · 恢复（每次开机必做）

云电脑一关机，隐形 Edge 和 poll agent 都没了 —— 不手动拉起就既不发也不捕获。重启后按顺序跑这两条：

1先拉起隐形 Edge（读和发都靠它，后台无窗口） 
Start-Process "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" -ArgumentList '--headless=new','--remote-debugging-port=9222','--user-data-dir=C:\akke-edge-debug','https://www.douyin.com'
2再起 poll agent（首触派单 + 捕获回复都在它里面） 
cd C:\akke-wuying\wuying-dm
py wuying_poll_agent.py
登录过期兜底：若起 Edge 后捕获一直 conversation-item 0 / 报没登录，说明 cookie 过期了 → 关掉 headless Edge，用可见窗口起（命令去掉 --headless=new），重新登录抖音 + 点开一次私信，再切回 headless。Cookie 一般撑 15-30 天。

二、首触派单（给新 lead 自动发招呼 · 走 DOM）

poll agent claim 新 lead→ 写 contacts.csv→ douyin_dm_web_send_dom.py→ sec_uid 进主页点「私信」→ 打字+点发送键→ 写 sent_log

靠这一行 env 切换（poll agent 派单/回读/状态映射全不用改）：

.env 设置 
AKKE_DM_SCRIPT=douyin_dm_web_send_dom.py   # 从 grounded 改成 DOM 发送器

跑起来日志会出现（看到就是首触在 DOM 发）：

=== DOM 批量发送: N 条 (间隔 20-45s) ===
  [sent] 张三: 你好，张三。全屋定制按建筑面积…

注：DOM 首触只发 DM、不做关注/点赞（关注是软封最大的雷，少做更安全）；按 sec_uid 直达天生不撞名，省了 OCR 身份门。

三、DOM 捕获自动化回复（读客户回复 + 自动起草 · 走 DOM）

每轮 capture→ 读 conversation-item→ 红点闸 + 判回复链→ record_dm_inbound 写回→ 起草回复
.env 设置（3 个） 
AKKE_DM_AUTOREPLY_CAPTURE=1   # 开捕获腿(没有=根本不跑捕获)
AKKE_WEB_DM_USE_DOM=1         # 捕获走 DOM 版(不设=走旧 VL)
AKKE_WEB_DM_DOM_COMMIT=1      # 真写库(不设=只打印不写)

日志会出现（看到 [DOM] = 捕获走 DOM；有真回复会出 [inbound]）：

=== web capture[DOM]  (COMMIT 写回) ===
  conversation-item 11 个 / 有红点 1 个 / 命中客户回复 0 条

注：DOM 捕获全程不点会话、永不标已读，不污染未读信号；红点是权威闸，无红点不当回复。

四、.env 全清单（首触 + 捕获一起开）

C:\akke-wuying\wuying-dm\.env 
AKKE_DM_SCRIPT=douyin_dm_web_send_dom.py   # 首触派单走 DOM(含 web → 路由对)
AKKE_WEB_DM_USE_DOM=1                     # 捕获走 DOM
AKKE_WEB_DM_DOM_COMMIT=1                  # 捕获真写库
AKKE_DM_AUTOREPLY_CAPTURE=1               # 开捕获腿
AKKE_DM_MIN/MAX_INTERVAL=20/45                # (可选)首触发送间隔抖动

改完 .env 必须重启 poll agent 才生效（python-dotenv 只在启动读）。

五、回退（出问题一键回旧版）

改 2 处 + 重启即回 VL/像素老路

# 删掉 / 改 0:  AKKE_WEB_DM_USE_DOM            # 捕获回 VL 版
