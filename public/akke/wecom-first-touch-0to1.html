01 / 第一个案例

首触 + 代回，真实链路产物

这些都是真实链路跑出来的原样话术（云电脑 GUI 读发 / 端点直调），不是示意。首触面对的是已经加了企微好友、但我方还没开口的人；代回面对的是已加好友、回了消息的人——两边都不再向客户要微信号。

① 首触 — 新好友刚通过，我方主动打第一句

你好呀，我是小文，做全屋定制好几年了。咱们家房子是新房还是翻新呢？
小文（云电脑真发实测）· 中性招呼(无哥/姐) · 不要微信 · 不提视频 · 只问一个 · 钉死一条

② 代回 — 客户问价（有大有小柜体口径，非抖音整装）

你们做衣柜吗？多少钱
您家大概哪个城市呀？咱们家是全国连锁，各地都有门店，能就近安排对接。 衣柜当然做，全屋柜体定制都是 568 元/投影㎡，江浙沪京深另加 100 元/㎡。 您要是方便说下面积和户型，我帮您大概算个数，比干聊价格更准哈。
小文 · 568/投影 口径 · 问面积城市 · 引导就近门店

③ 代回 — 客户问「怎么加你们微信」（关键：已是好友，不再抛号）

怎么加你们微信
您这不已经加上了吗～咱们现在就是在企业微信上聊呢 您是想了解哪方面呀？我让设计师直接对接也一样的 您家房子是在哪个城市呀？咱们就近安排门店看看
小文 · 正确识别「已经加上了」，不再抛 Homedz3791 / 备注抖音名 — badcase #7 修复后效果
02 / 0→1 逻辑原理

GUI I/O 在云电脑，大脑 / DB / 成本全在云端

云电脑 Python 只做看屏幕 + 点鼠标打字；认人、生成话术、落库、算成本全在 TS 端点。云电脑（国内 IP）连不上 Vercel，走 Fly 中转纯透传。

① 风控门
工作时间 9-21 · 日限 20 · 时限 8 · 每客户连发 ≤6 · 随机间隔 25-70s
→
② 抢窗口
ctypes 硬置前 + 最大化；没铺满屏就跳过本轮（不往错位窗口瞎点）
→
③ VL 读屏
截图 → 看有无未读 → 点开最上会话 → 读会话状态（新好友? 客户消息? 发送方?）
↓ 分流
④A 新好友待首触
会话只有「已添加/可以开始聊天了」系统提示、无真人对话 → action:opener
④B 客户回了消息
最新一条是客户发的 → 过两道护栏 → action:generate
↓ Fly 中转（纯透传，绕 Vercel 大陆不可达）
⑤ TS 端点 · chatReply
按 persona（销售身份壳）认人 → 首触走企微专属 opener prompt（早退，不套抖音 ice_break）/ 代回走有大有小 nurture/decision 规则 → 幂等去重 → Langfuse 计费
↓ 回话术
⑥ GUI 发送
点输入框 → 逐字 Unicode 打字（绕 IME）→ Enter。首触钉死单条；代回按换行最多 3 段
→
⑦ confirm 落库
只在真发出后才记 AI 消息（显式失败）+ 记入「我方近发文案」缓冲（供护栏①）
蓝=云电脑 GUI · 紫=云端大脑 · 绿=发送落库。首触与代回同一个 loop、同一套发送/风控，只在第③步分流。

三道确定性护栏（不靠 LLM / VL 自觉）

护栏① 防自问自答
读到的「客户消息」若 == 我方近发文案 → 判 VL 发送方误判，跳过（否则会回复自己、连发）
护栏② 防误读联系人
读到的「消息」若 == 会话名 → VL 把联系人标题/空会话当消息了，跳过
护栏③ 窗口校验
企微没铺满屏（抢窗口失败）→ 本轮不动作，避免坐标落偏点空
