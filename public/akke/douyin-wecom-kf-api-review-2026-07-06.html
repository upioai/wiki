评审：《抖音商业获客到企业微信对话方案》可行性

评审日期 2026-07-06 · 来源：外部提供的 12 步实操指南 docx · 评审人 Claude（受 fanny 委托）
⚠️ 一句话结论：这条路 Akke 早在 2026-06-10 就走过了。
文档描述的核心架构「微信客服 kf API + 自建回调 + 私有化 AI 回复」在 Akke 里已经全部写完并部署（PR #268），但撞上了文档完全没提的一堵硬墙——ICP 备案主体校验，被迫冻结，团队已转向「方案B：企微 PC 客户端 GUI 自动化」并在生产运行。所以本文档的价值不是「要不要做」，而是给外部方一份现实纠偏：官方接口路线有个致命的备案前置条件，不解决它，在企微后台连回调 URL 都存不进去。

1. 方案在说什么

一条付费广告 inbound 漏斗，跟 Akke 现在「抓评论→主动私信」（免费 outbound 冷启）完全不同：

抖音效果图内容 / 巨量信息流广告
      ↓
巨量橙子建站落地页（户型渲染 + 测算表单）
      ↓  DeepLink 唤起微信
企微「获客助手」加人
      ↓
微信客服 API（kf/sync_msg 拉 + kf/send_msg 回）
      ↓
私有化大模型知识库自动多轮回复 + 下发 PDF 报价单

2. Akke 现状：这套架构我们已经建完 + 已冻结（最重要一节）

依据：memory project_akke_wecom_kf_integration.md（2026-06-10 深度调研 20 来源定稿）+ 代码实测。

2.1 已建成的东西（PR #268 全部上线）

  • src/lib/wecom/crypto.ts：官方 wxcrypt 协议验签 + AES 加解密，零依赖，单测 7/7 通过（本次复跑确认）。
  • src/lib/wecom/client.ts：gettoken / kf/sync_msg（cursor 分页）/ kf/send_msg，含 token 过期重试。
  • src/lib/wecom/process.ts：收消息→复用现有 chatReply（小艳人设/知识库/few-shot 全现成）→ 拟人化延迟发回；含 48h/5 条窗口防御、wecom_msgid 幂等去重、纯媒体轮兜底话术。
  • src/app/api/wecom/kf/callback/route.ts：GET echostr 握手 + POST 5s 内 ack + after() 异步处理。
  • WECOM_KF_MODE env 开关：echo（固定回声验通道）/ ai（chatReply 全 AI）。
  • 连文档没提的坑都解决了：企微「企业可信 IP」约束（Vercel 出口 IP 不固定，直连必报 60020）→ 独立 Fly 固定出口代理 akke-wecom-proxy，static egress IP 209.71.88.154。

换句话说：文档问「你们技术团队要不要 AES 报文解密/知识库匹配的技术支持」——这些我们半个月前就写完了。

2.2 为什么冻结：ICP 备案主体校验（文档完全没提的硬墙）

企微「接收消息服务器配置」保存回调 URL 时，会校验该域名的 ICP 备案主体必须与企业主体（杭州辰焰科技）一致或关联：

  • akke.vercel.app → 拒：「Domain entity verification failed」
  • 裸 IP http://209.71.88.154/... → 同样拒（IP 无备案主体）
  • 所有境外免备案域名（vercel.app / fly.dev / upio.ai）→ 全部不可用
  • 且配置依赖链被锁死：可信 IP、绑应用都排在「回调 URL 存进去」之后，域名一卡，整条链断。
这是整套官方 API 方案的真正阻塞点。文档号称「完全规避风控」，却漏了这个最现实的前置。

2.3 团队实际在跑的：方案B（企微 GUI 自动化）

因 ICP 卡死，2026-06-11 转向 Windows 企微 PC 客户端 GUI 自动化（云电脑上跑）：VL 读消息 + SendInput 逐字输入发字 + 内联发官方海报，已上线在用（PR #645/#706/#760-762）。大脑同样复用 chatReply，只是把「官方 API 管道」换成「GUI 模拟点」——代价是回到有一定封号风险的 GUI 路线，这正是官方 API 路线本该消灭、却因 ICP 备案没能落地的东西。

2.4 当前机器状态

akke-wecom-proxy 两台机器自 2026-06-16 起停机省钱（auto_start_machines=false），static IP 209.71.88.154 仍绑着未丢。公司一旦拿到备案域名 CNAME 到 Vercel，方案A 代码零改动即可复活。

3. 文档本身的技术准确性核对

✅ 真实存在、能落地的部分

文档说法判断
企微认证年费 300 元✅
微信客服 API：kf/sync_msg + kf/send_msg✅ 官方接口（我们已实现）
Webhook echostr 握手 + AES 解密回调✅ 已实现，单测过
media/upload→media_id→发 file 卡片✅ 真实接口
微信客服 48h/5 条会话窗口✅ 真实规则（已做窗口防御）
巨量橙子建站 + 信息流 + DeepLink✅ 真实产品

⚠️ 文档的技术硬伤：获客助手 ≠ 微信客服

文档说「获客助手绑定客服号池、拉出加好友名片、然后 kf/send_msg 自动回复」——把两个不同产品缝在一起：

  • 获客助手 → 加成销售/设计师的外部联系人（好友）。给外部联系人 1:1 自动发消息，企微 API 严格限制，没有干净的官方接口（这正是方案B 要靠 GUI 模拟点的根因）。
  • 微信客服 → 用户进客服会话，才有 kf/send_msg 的 48h 自由回复权。

想要全自动 AI 回复，入口必须是微信客服链接/二维码，不是获客助手加好友名片。

⚠️ 文档漏掉的最大前置：ICP 备案（见 §2.2）

文档号称「完全规避风控封号风险」，却完全没提回调域名 ICP 备案主体校验这个把整套架构卡死的前置条件。这是它作为「实操指南」最严重的遗漏。

⚠️ 不能当事实用的数字

  • 获客助手「1 元/有效好友」：按成功获客扣费属实，但单价随行业/地区/竞价浮动，1 元是文档拍的，报预算前要实测。
  • 整条 ROI 漏斗（CTR 3.8% / 唤起 22% / 加粉 68% / 开口 75% / 意向 28% → CPL 4.57、量房 23.27 元/条）：全是文档拍的「行业平均」，无出处。装修信息流实际 CPL 常见几十到上百，23 元/条量房偏乐观，不可写进任何对外承诺。

⚠️ 合规「假合规」隐患

落地页「伪造互动测算表单」、欢迎语谎称「文件 120MB 过大回复 1 才下发」——接口官方，但话术诱导，照样会因用户投诉「诱导/骚扰」被限流降权。官方接口只保你不因技术手段被封，保不了因内容被投诉。

4. 操作建议（更正版：不是搭 demo，是解备案）

原先「阶段0搭回调 demo 验证」的建议已作废——demo 早已建好且验签单测通过，真正卡住的是业务前置。按现实，动作是：

步骤谁动作卡点/产出
S1 解 ICP 备案域名（关键路径）fanny + 公司/法务拿一个备案主体=杭州辰焰科技（或关联）的域名，子域 CNAME 到 Vercel；或个人备案变更为企业主体（5-10 工作日）；或新域名企业备案（1-3 周）有它=方案A 全链路解冻；没有=官方 API 路线走不了，只能继续方案B GUI
S2 复活 proxy技术fly machine start 两台（IP 不变，无需重配可信 IP）代理恢复
S3 按依赖链配企微后台管理员回调 URL（备案子域）→ 可信 IP 209.71.88.154 → 绑「可调用接口的应用」→ 接待方式切 APIkf 发「测试123」收到 echo 回声 = 通道通
S4 切 AI 模式验收技术Vercel 补 WECOM_KF_APP_SECRET + WECOM_KF_MODE=ai真实客户消息小艳自动回
S5（可选）接前端流量运营先用抖音主页/视频挂客服链接免费导流验漏斗，算得过账再上巨量付费投放真实 CPL 替换文档假数字

不要做的事：① 不重搭已存在的回调代码；② 不照文档搞「获客助手加好友 + kf API」（收不到消息）；③ 落地页/欢迎语不用诱导话术；④ 拿到备案域名前，官方 API 路线无法验收——它不是代码问题。

5. 我能怎么验证 / 验证不了什么（诚实交代）

  • 能验（已验）：crypto.test.ts 7/7 通过（本次复跑确认签名+AES 加解密正确）；回调路由/收发逻辑代码路径可读、tsc 通过；echo/ai 双模式逻辑齐全。
  • 验不了（被业务前置卡住，非能力问题）：端到端活体验证（扫码→发消息→AI 回）做不了——因为①企微后台没有备案域名连回调 URL 都存不进去（ICP 墙）；②proxy 机器当前停机；③需要真实 WECOM_KF_APP_SECRET。这三件全是 PM/公司层面动作，不是写代码能解的。
  • 一句话：这套的正确性瓶颈从来不在代码（代码半个月前就绿了），在一个备案域名。
