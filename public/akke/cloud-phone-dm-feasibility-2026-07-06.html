云手机跑抖音 DM 自动回复 · 可行性评估

目标：在云端 Android（云手机）上无人值守跑抖音私信自动回复（1-3 号试水）

评估日 2026-07-06 · 数据源：团队 2026-05 云手机 PoC 记录 + 本次阿里无影云手机实测复验
✕ 结论 · 不建议

阿里无影云手机跑抖音 DM 自动回复 = 死路

卡点是抖音风控，不是代码——两道墙叠加：①虚拟设备指纹（DYLoginActivity 强制只读）；②活检人脸 + 摄像头无法注入（阿里摄像头仅宿主透传，喂不进抖音活检）。这两条团队 2026-05 已实测判死，本次装好抖音后又撞在活检墙上复验。建议改用已在 production 跑的无影云电脑网页版 DM 通道；若坚持云手机，唯一未验死的候选是华为云 CPH 定制镜像，但须先跑风控 PoC、不可直接部署。

01 · 背景为什么会想到云手机

抖音 DM 自动回复目前跑在无影云电脑网页版 / iPhone WDA / 本机真机 ADB 三条通道。云手机（云端 Android via ADB）看似能"无人值守 + 不占本机"，所以被提出评估。但这条路团队 2026-05 已做完整 PoC 并判死，本次是用户"就是想要"实际再试一把 —— 装好抖音后撞上活检墙，触发本次复评。

02 · 核心结论两道过不去的风控墙

下面两条是根因，任一条都足以让自动回复跑不起来，且都不是脚本能绕的。

墙 ①

虚拟设备指纹 → 强制只读

抖音识别到云手机是容器/虚拟指纹，把老号判成陌生设备，任何主动操作（私信/点赞/关注）都被 DYLoginActivity 登录遮罩挡死。诊断：dumpsys window | grep mCurrentFocus 返回 DYLoginActivity。

墙 ②

活检人脸 + 摄像头喂不进

装好抖音后触发人脸活检。阿里/华为/腾讯的"摄像头"是宿主透传给远程办公，不是抖音活检读的 Camera2 前置摄像头 —— 电脑摄像头/预录视频注入不进去。能注入的 MP4→Camera2 只有星界云等群控厂商有，阿里没有。

厂商形态 / 价格突破 IDC IP突破虚拟指纹
阿里无影云手机云端 ARM 容器✕✕ redroid 自爆

结论：最接近的是 VMOS Edge（硬件盒子），但群部署设备型号相同 = 群控特征。公有云云手机无一过关。

活检的额外铁律：1 张身份证只实名 1 个号、1 张脸只过该号活检、不可跨号复用；主动式活检（眨眼/转头/张嘴）预录视频必败。即便解决指纹，活检这关对号池规模化也是硬天花板。

03 · 架构如果墙解决了，能复用多少

好消息：大脑和后端与前端无关，直接可复用；只有落地到抖音界面的"手"要在 Android 上重写。这说明墙一旦被突破，工程量并不大 —— 问题纯粹卡在风控。

✓ 可复用（前端无关）

  • 派单 agent 骨架：wuying_poll_agent 的 RPC + subprocess 模式
  • 整条服务端生成 / 审批链：record_dm_inbound / claim_dm_replies / dm_reply_drafts + DB 触发器 + 置信度门
  • Android 出站积木：local_android_agent 导航栈（deeplink→私信→ChatRoom）+ rid 表 + set_text 中文注入

⚠ 必须新建（即便墙解决）

  • Android 收件箱捕获闭环：扫消息 tab 找未读 → 读 inbound → 写 record_dm_inbound
  • 现状 Android 上一行都没有（收发自动回复只在 iPhone WDA / 无影云电脑有）
  • 有现成范式可移植：dm_ios_wda_inbox_poll（iOS）+ 无影 wuying-dm/*（红点门控 / 去重）

04 · 方案如果坚持云手机 · 分阶段带硬闸

核心原则：先花最小成本复验风控墙，验通了再建闭环。团队上次正是卡在墙前停的；跳过复验直接建 Android 闭环，墙没破的话代码全废。

0
硬闸

Phase 0 · 风控复验 PoC（go / no-go · ~1 天 · ¥几十）

选华为云 CPH（2026 定制镜像 + 开放 ADB，唯一未验死的公有云候选）。别再碰阿里无影云手机 / 星界云 —— 已实测死。下方 5 条标准任一红即 STOP，不进 Phase 1。

  • ADB + u2 通：adb connect + ping
  • 登录不掉（墙②）：换全新小号登录后 mCurrentFocus ≠ DYLoginActivity，且维持 ≥2h
  • 指纹不自爆：Build.FINGERPRINT / ro.product.device 不含 cloudphone/redroid/userdebug
  • 能读 inbound（墙①）：进消息 tab 不卡骨架态，能 dump 出会话列表
  • 真送达：发一条回复后 blackboxprotobuf 解出 status_code==0（200+success 不算，防静默丢）
1
仅全绿

Phase 1 · capture 闭环

新建 Android 收件箱轮询 → 捕获 inbound → 写 record_dm_inbound。移植 iOS / 无影范式；服务端生成链零改动。

2

Phase 2 · reply 回写发送

claim_dm_replies 拉 approved 草稿 → 复用 local_android_agent 导航栈就地回 → complete_dm_reply 回写。

3

Phase 3 · 常驻自驱

复用 wuying_poll_agent 骨架，subprocess 换成 Android 驱动脚本；节流 / 已读状态机。

🔧 Phase 0 工具已就绪

  • worker/cloud_phone_dm.py 本次补齐 --health-check（IP ASN + 指纹自爆检测）+ --login-check（登号后验 DYLoginActivity 登录墙）
  • 华为云 CPH 一开通，adb connect 上去按 5 条标准一路验，当天出 go / no-go
  • 开通 / 定制镜像那步需走华为云商务或工单（评估方代不了）

05 · 建议三条路，怎么选

✕ 阿里无影云手机 · 别耗

同时撞在指纹墙 + 摄像头无注入两条上，不是配置问题、是产品能力缺失。团队原话结论：云手机 / 云电脑 / 模拟器 = 负优化。

✓ 推荐 · 无影云电脑网页版 DM（已在 production）

目标（1-3 号 DM 自动回复）已有在跑的通道 —— 有大有小 shawsnk 就在用（douyin_dm_web_capture_dom.py + send_dom.py）。抖音网页版不吃 App 的活检 / 指纹这套，零风控墙、零新建。

◑ 唯一还能试的云手机候选 · 华为云 CPH（需先 PoC）

2026 新能力：自定义镜像 + 开放 ADB。是公有云唯一未被验死的候选，但五道锁是否全破需真实 PoC，不可信营销号、不可直接部署。走 Phase 0 硬闸，一天见分晓。
