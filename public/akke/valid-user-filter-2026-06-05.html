01做什么 · 口径

号源筛出来的触达候选要更精准——尽可能排除同行（全屋定制 / 装修 / 装饰），以及卖设计、卖灯具、卖瓷砖的商家号，不把 DM 配额浪费在无效用户上。

为什么现在拦不住？实战案例：B嗯嗯（广东）
评论「我需要装修，怎么联系你？」→ 意向 85 分 + 标「强买家信号·联系方式」→ 做成案例页准备交销售加微 → 后发现她做灯具。昵称干净 + 满分买家话术，两道文本过滤全漏；身份只暴露在主页里。

引流号（主动塞微信）、跨行业 B2B 不在本期口径内（PM 已拍板收窄）。

02现状诊断 · 过滤链路 3 层，洞在「主页画像」
层现状能不能拦「卖灯具的」
1. 文本 gate
peer-filter.ts		扫昵称（已含「灯具店」「建材」等 ~60 词）+ 评论内容套话，analyze 投 LLM 前生效部分 只拦昵称暴露身份的
2. LLM 意向分打的是评论文本拦不住 同行会写满分买家话术
3. 发送前人工看主页写在拉单流程 step 2，纯靠人自觉最可靠但不自动 无沉淀、会漏
核心洞：身份藏在「主页简介（signature）/ 主页视频」里，而现有文本 gate 只扫昵称+评论，不扫 signature。评论入库时也没存 signature——「免费扫」不存在，必须补拉主页，区别只在拉多少。
03方案 · 拉单时自动查主页（A）+ 顺手扩词表（C）
方案成本能拦多少性价比
A. 拉单时查主页 ✅每天 ~30-60 次主页请求（只查要触达的候选）；worker 接口现成、零改动拦住「昵称干净、身份在简介里」的伪装者最高 请求量是全量的 1/100，100% 花在真要发 DM 的人身上
B. analyze 全量查主页每天几千次请求，反爬风险高同 A低 99% 的请求查的是永远不会触达的低意向评论
C. 扩词表 ✅（顺手）零请求「卖设计/灯具/瓷砖」昵称词已基本在表里，增量小白捡 但治不了本

04验收 · 基线 → 回测 → 复测（带数字，不说「更准」）

05边界 case 与风险 ⚠️ 待 PM 确认
情况处理
signature 为空（大量用户不写简介）放行，不误伤；日志记数
主页接口失败 / 超时放行 + 拉单报告显式列出「N 条未完成主页校验」，不静默跳过也不断拉单
signature 含「设计」但属生活语境（如「热爱生活设计」）词表用「室内设计 / 设计师 / 全案设计」等带限定词形态，不收单字
被 discard 的候选 claim 锁沉淀标「无关」后 4h 锁自然过期，不需主动释放

风险：① worker 主页接口走 sec_user_id 路径，5/19 实测拉回过 signature，但未大批量验证海外出口反爬表现——上线先小批量观察，失败率高退回本机拉取兜底；② 某天池子同行密度高时 1.5× 超额仍可能拉不满 N，报告如实报「拉到 M/N」。

历史数据：不回填、不清理已触达历史（低影响又烧钱）；只对改造后新拉单生效，基线抽样仅作统计。
