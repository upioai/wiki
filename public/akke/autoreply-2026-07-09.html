一、这套是什么（背景）

企业微信好友单聊的 AI 自动代回。不走官方 API（官方客服 API 被 ICP / 可信 IP 卡住）， 而是在云电脑上跑一个常驻 Python loop，用「截屏 → 视觉模型认字读消息 → 固定坐标点击打字发送」的 GUI 方式代回。

数据链：云电脑 loop → Fly 中转 → Vercel /api/wecom/chat/reply → chatReply（小艳，模型 glm-4.6）→ 回传 → GUI 打字发出

先天特性：GUI 方式没有"送达回执"，靠截图认字，天生比 API 脆——本次优化就是尽量把这些脆点补硬。

二、本次优化了什么（10 项，均已上线 + 有测试）

项治什么问题状态
A 连发防抖客户连发多条时，读到半截就回、剩下的下轮又回一次（拆成多条）。改：读到待回消息后先确认聊天区 2.5s 不再变化（发完）才回。已上线
B 读取上限每次最多读 6 条 → 连发 >6 条漏前面。改为 10 条。已上线
C 红点不饿死某会话红点卡住不消时独占 3 个处理槽，饿死其他客户。改：本轮已点过的行跳过。已上线
系统消息过滤"XX撤回了一条消息""工作台统计（总客户N位/收款N元）"被当客户消息回。改：正则拦截，从源头跳过。已上线
F 红点检测修正截图含最左导航栏 → "消息"图标红角标被当成 y≈58 的假未读，一直点顶部死区、点不开真新好友（野乔通过没首触）。改：裁掉导航栏 + 顶部死区过滤。已上线
G 发送前重抢前台"读→生成"隔数秒，其间焦点被抢 → 发送中止 / 打字中途丢焦。改：发前主动把企微顶到最前+最大化。已上线
VL 断连重试视觉模型（OpenRouter）偶发掐连接 → 整轮读取作废。改：失败重试 3 次 + 退避。已上线
★ 发送后回读确认治"假成功"——按发送键就记成功，但字没落进输入框/坐标偏/被窗口挡，聊天里根本没有（野乔首触两次假成功、还被锁成"已招呼"）。改：发完截图回读，确认文案真出现在右侧才记成功；没确认到 → 不记已发、不锁已招呼、下轮重试。已上线
★ 定期全量扫会话客户在【无红点、又非当前打开】的会话里回消息，两条腿都够不着（野乔发"新房"漏读）。改：每 5 轮把前 6 个会话逐个点开读一遍补漏。已上线
★ @微信 硬门全量扫 + 历史假成功把系统通知/内部群（客户联系/服务总结/行业资讯/企业微信团队/内部全员群）也回了、还写进台账污染去重。改：只代回标题带「@微信」的外部客户，系统/群/同事一律不碰。已上线
配套动作（运维）：清掉云电脑本地被污染的台账文件 wecom_replied_ledger.json / wecom_sent_texts.json，重置历史脏去重状态。

四、优化点 / 下一步

  • 🔑 路线3 · 官方 API（根治，唯一能"稳定不出问题"）：重新评估企微客服 API 的 ICP 备案 / 可信 IP 白名单能否解开。通了就是 100% 可靠——真消息 ID、送达回执、不用截图认字。需业务/合规投入，目前搁置。
  • 坐标重标：若干净环境下真客户仍发不出，跑 measure_wecom_coords.py 在当前窗口重新标定输入框/发送坐标。
  • 环境固化：给云电脑一个专用干净桌面——企微常驻最大化、日志黑窗最小化别盖上来、关掉悬浮 widget。这是当前 GUI 方案稳定性的最大变量。
  • 人工兜底（路线2）：若坚持不上 API，可退一步用"AI 出草稿 + 真人一键发"，牺牲全自动换可靠。
  • D / E 收尾：补"部分发送也记账防重发"、探索更稳的会话身份。

五、日常运维要点

  • 企微保持最前、黑窗最小化别碰——这是发送能否落地的头号因素。
  • 云电脑重启后：跑重启流程把 loop 拉起（对应 skill：企微自动回复重启）。
  • 出任何异常：在 C:\akke-wecom\ 建空文件 wecom_reply_STOP 即停；排查好删掉再起。
  • 怀疑去重出错（真客户被误跳/系统会话被回）：清 wecom_replied_ledger.json + wecom_sent_texts.json 重置。
  • 判断新版是否生效：看启动字节数（本版 63999），别看黑窗里写死的版本号。
