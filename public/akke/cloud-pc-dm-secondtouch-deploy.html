1 DM + 二触 自动发送的逻辑

同一台机上两条通道不是两个程序同时跑 —— 是一个 agent 进程、一个循环、两条 lane 严格串行。

为什么必须串行?

抖音 PC 是 GUI 自动化(模拟鼠标点屏幕坐标、抢窗口焦点)。同一时刻只能有一个程序操作抖音窗口 —— 两个一起点必然抢焦点、点错位、双双崩溃。所以 agent 用阻塞式调用,DM 那批发完才轮到二触,时间上完全错开。

wuying_poll_agent.py   # 全机唯一进程,start.bat 只拉它一个
  while True:
     # 路线 A —— DM 私信
     claim_dispatch(≤3)        → douyin_dm_grounded.py       # 阻塞到这批发完
     # 路线 B —— 二次触达评论(开关开了才跑)
     claim_second_touch(≤3)    → douyin_comment_grounded.py  # A 完了才开始,阻塞
     sleep(60)                 # 两条都跑完 → 歇 60s → 下一轮
路线 A

DM · 自动私信

给高/中意向新评论的人发开场白私信(LLM 现起文案)。

  • 队列:dispatch_queue
  • 每轮领 ≤3(AKKE_CLAIM_LIMIT)
  • 批内逐条间隔 30–90s
  • 派单节奏:距上次实发 ≥ min_send_interval_seconds(默认 60s,抖动后约 1–2 分钟/条)
  • 当日上限:accounts.daily_limit
  • 滚动 1h 上限:CLOUD_PC_HOURLY_CAP(默认 10)
路线 B

二触 · 自动评论唤回

对发过 DM、≥3 天没回的高/中意向用户,去 ta 视频下发一条评论唤回(复用最后一条 DM 原文)。

  • 队列:second_touch_dispatch_queue
  • 每轮领 ≤3(AKKE_SECOND_TOUCH_CLAIM_LIMIT)
  • 批内逐条间隔 固定 60s
  • 进入门槛:距最后 DM ≥ SECOND_TOUCH_MIN_DAYS(3 天)
  • 当日上限:SECOND_TOUCH_DAILY_CAP(20)
  • 合并 1h 门:DM + 评论 ≤ SECOND_TOUCH_COMBINED_HOURLY_CAP(6)
📌 两通道不会叠加超量:DM 日限和二触日限是两张表分开计数,但「单号每小时总动作」用合并 1h 门锁住(近 1h 的 DM 实发 + 评论之和 ≥6 就停派二触)。日预算还跨通道合并 —— 同账号人工(手机/WDA)发的也占额度,当天人工发多了云电脑当天就少发。只数真成功,被拒/跳过不占。

2 镜像部署方案(推荐)

已有一台配好的(野荞这台)→ 烤成自定义镜像 → 新机克隆。零重装、零装依赖、同分辨率零校准,每台只改几处。

✅ 推荐

A · 镜像克隆

镜像里已含 Python + 依赖 + 全部脚本(DM + 二触)+ 模板 + 开机自启。新机克隆出来只改账号 + 开开关。

备用

B · 手动从零

无镜像时:装 Python → 传脚本 → 装依赖 → 配 .env → 设自启 →(分辨率不同才)校准。见 wuying-selfdrive-deploy.html 方式 B。

  1. 把配好的那台烤成自定义镜像(PM 做一次)
    阿里无影控制台 → 选中实例 → 创建自定义镜像。镜像内含:Python 3.12 + 依赖、C:\akke-wuying\wuying-dm\(脚本 wuying_poll_agent.py / douyin_dm_grounded.py / douyin_comment_grounded.py + templates/)、开机自启 akke_wuying_agent.bat。
    🔑 烤好后 PM 记下镜像 ID(形如 m-xxxxxxxxxxxx)发给团队。务必确认源机已装 douyin_comment_grounded.py 且二触坐标校准过,否则克隆机只能发 DM。
  2. 新机用这个镜像开 / 重装
    先找 PM 要镜像 ID;新建无影实例时「镜像」处选「自定义镜像」→ 填这个 ID → 克隆出来零重装、零装依赖。
    ⚠️ 分辨率必须和源机一致(本套 2560×1600)。一致 → 模板/坐标直接复用、零校准。不一致 → DM 走 douyin_dm_grounded.py --capture、二触走 _measure-comment.py 各重采一次。建议在无影客户端锁死分辨率。
  3. 每台改这几处(因为是不同抖音账号)
    ① 抖音登录:打开抖音 PC → 扫码登录这台要绑的账号 → 窗口最大化 → 输入法切英文(Win+空格)。
    ② 改 .env:把 AKKE_ACCOUNT_ID 换成这台账号的 id(PM 下发);要开二触就加 AKKE_SECOND_TOUCH_ENABLED=1(见下方 .env 模板)。
    ③ 开 DB 开关(PM 做):该账号 accounts.channel_pref=cloud_pc + 设节奏/上限。
  4. PM 在 Vercel 开二触真发开关(全 org 一次性)
    二触默认是干跑(dry-run)只算不发。要真发,在 Vercel 环境变量设 SECOND_TOUCH_AUTOSEND_ENABLED=true。两个开关都开才真发二触:Vercel 的 SECOND_TOUCH_AUTOSEND_ENABLED(派单侧)+ 无影 .env 的 AKKE_SECOND_TOUCH_ENABLED(执行侧)。
  5. 重启一次 → 完成
    重启无影 → 登录后开机自启 agent 自动跑。验证(在 PowerShell 里跑,详见第 3 章):Get-Content C:\akke-wuying\wuying-dm\agent.log -Tail 8,看到 === wuying_poll_agent account=… every 60s second_touch=on … 即两条通道都在。

2.1 .env 怎么配(先看你是哪种部署)

镜像克隆(方式 A)

.env 已在镜像里 · 只改 1 行

源机的 .env 跟着镜像一起克隆过来了,不用整份重配。只改两处:
① AKKE_ACCOUNT_ID 换成这台绑的账号(不同抖音号,见下表怎么拿);
② 这台要发二触就确认有 AKKE_SECOND_TOUCH_ENABLED=1。
其余(URL/key 等)全队一样、照搬不动 → 下面整份照抄可跳过。

从零 / 无镜像(方式 B)

整份自己配 · 从本机 .env.local 照抄

没有镜像、新机上没有 .env 时,才需要照下面 3 步整份配。值几乎全在你本机 Mac 的 .env.local 里,照抄即可、不必等谁下发。

镜像克隆改那 1 行:无影上 cd C:\akke-wuying\wuying-dm → notepad .env → 把 AKKE_ACCOUNT_ID= 那行换成你的账号 id → 存盘 → 重启 agent。改完不重启 agent 不读新值。

↓ 以下是「从零整份配」(方式 B)用的;镜像克隆只看上面那 1 行就行。

  1. 本机 Mac:读出你 .env.local 里的值
    # 本机 Mac,在 Akke 仓库目录里跑
cat .env.local
    里面已有 NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY / SUPABASE_SERVICE_ROLE_KEY / OPENROUTER_API_KEY / AKKE_ACCOUNT_ID —— 正好就是无影 .env 要的那几个。
  2. 无影:新建 .env,按下面模板把值填进去
    # 无影 PowerShell / cmd
cd C:\akke-wuying\wuying-dm
notepad .env
    在 notepad 里手填(.env 含密钥,别走 paste.rs / 别截图发群;CSV 能走 paste.rs,.env 不行)。
  3. 存盘 → 重启 agent 读新值
    改完 .env 必须重启 agent 才生效:关掉 agent 黑窗口 → 双击 start.bat 重开(见第 3 章)。

每个值从哪拿 ↓

无影 .env 变量从哪拿
SUPABASE_URL + NEXT_PUBLIC_SUPABASE_URL本机 .env.local 的 NEXT_PUBLIC_SUPABASE_URL,两行填同一个值
NEXT_PUBLIC_SUPABASE_ANON_KEY本机 .env.local 同名,直接抄
SUPABASE_SERVICE_ROLE_KEY本机 .env.local 同名,直接抄(连库鉴权,自助最省事的路)
OPENROUTER_API_KEY本机 .env.local 同名,务必是后台设了额度封顶的 key
AKKE_ACCOUNT_ID本机 .env.local 的 AKKE_ACCOUNT_ID = 你这台绑的账号。一机一号,别和别人填重(没配过 → 这是一人一号的绑定,找 PM 要一次)
AKKE_POLL_INTERVAL / AKKE_CLAIM_LIMIT / AKKE_SECOND_TOUCH_*固定值,照下面模板填即可
 
# —— Supabase(本机 .env.local 照抄)——
SUPABASE_URL=https://<项目>.supabase.co
NEXT_PUBLIC_SUPABASE_URL=https://<项目>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
SUPABASE_SERVICE_ROLE_KEY=<service_role key>        # 连库鉴权(自助最省事)
# 这台绑的账号(本机 .env.local 的 AKKE_ACCOUNT_ID,一机一号)
AKKE_ACCOUNT_ID=<accounts.id>
# 视觉定位 —— 务必用设了额度封顶的 key
OPENROUTER_API_KEY=<sk-or-... 封顶 key>
# 固定值,照填即可
AKKE_POLL_INTERVAL=60
AKKE_CLAIM_LIMIT=3
# ↓ 开二次触达评论通道(不加=只发 DM)
AKKE_SECOND_TOUCH_ENABLED=1
AKKE_SECOND_TOUCH_CLAIM_LIMIT=3
🔒 安全(共享云桌面更要注意): service_role 权限很大。更稳的做法是用受控 JWT(role=wuying_worker,只能领单/回写)替代它 —— .env 里删掉 SUPABASE_SERVICE_ROLE_KEY、改填 SUPABASE_SCOPED_JWT(配合 anon key),agent 自动识别。这把 JWT 要用 JWT 密钥签出来、cat 不出来,问 PM 要一次(全队共用一把)。OpenRouter key 也务必后台设 Credit limit($30 等),烧超即停、不碰生产额度。

3 云电脑关了 · 重开之后怎么操作

关机:直接关,没事

agent 停 → cron 顶多在队列留 1 条 pending(背压门挡着,不会堆)→ 不丢单、不重发。发到一半被关的那条会被 15 分钟死锁回收、下次重领。不挑关机时机,下班随手关。

重开:4 步,30 秒

开机后队列里攒着的单会自动续发。你只要确认抖音和输入法状态对,agent 是开机自启的,不用手动开。

开机后照这个清单过一遍 ↓
  • 抖音 PC 开着 + 登录本账号 + 窗口最大化 + 在最前台(别被黑窗口或浏览器挡住)
  • 输入法切英文(Win+空格)—— 中文输入法会抢走搜索词第一个字、搜错人
  • 等约 30 秒 —— 开机自启 akke_wuying_agent.bat 会延迟 30s 自动拉起 agent(等抖音先起来)。它在后台一个黑窗口里跑,但日志被写进了 agent.log、窗口里看着是空的(正常),所以光看桌面判断不了,得按下一步读日志。
  • 验证 agent 在跑:开始菜单(按 Win 键)→ 输 powershell → 回车,打开蓝底的 Windows PowerShell 窗口,把下面这条粘进去回车(只有 PowerShell 认这个命令):
Get-Content C:\akke-wuying\wuying-dm\agent.log -Tail 8
# 输出里看到这行 = 两条通道都在(second_touch=on):
=== wuying_poll_agent  account=81cc9678…  every 60s  claim=3  second_touch=on  rc=off ===
没看到那行 / 报「找不到文件」= agent 没起来,手动拉一下(二选一):
① 最省事:双击 start.bat —— 文件管理器进 C:\akke-wuying\wuying-dm 文件夹,双击 start.bat。会弹出一个能实时看到日志滚动的黑窗口,出现 account=… 那行就成了。
② 或在刚才那个 PowerShell 窗口里逐行敲: 
cd C:\akke-wuying\wuying-dm
py wuying_poll_agent.py
⚠️ 不管哪种,拉起后那个窗口一直开着别关(关掉 = 停发);要停就关窗口或按 Ctrl+C。
想确认它到底在不在发、还能发几条、几点自动续 —— 在本机 Claude Code 里问「云电脑在发吗 / 还能发几条」会跑状态脚本从 DB 反推(scripts/cloudpc-status.ts),不用进无影看。

4 想立马就发 · 怎么手动触发

自动通道有节奏门(DM 约 1–2 分钟/条、二触每小时派一轮)。要现在就推一批出去,不等 cron,有两条路。

路 1 · 仍走队列(快)

立刻派一批进队列

本机 PM 跑 CLI 直接入队,无影 agent ≤60 秒内领走开发。绕开 cron 的等待,但仍走 GUI 自动发。

路 2 · 绕队列(全手动)

本机备料 → 无影直接跑 CSV

完全不靠 cron/agent:本机 claim+出文案+投递,无影下载 CSV 直接 py douyin_dm_grounded.py contacts.csv 一把发完。适合临时冲量。

路 1 · 立刻派一批(本机 PM,DM)
# 给指定账号立刻派 N 条进 dispatch_queue(不带 --pace = 不等 1-2min 节奏门)
pnpm tsx scripts/dispatch-leads.ts --account=<accounts.id> --per-account=10
# 无影那台的 agent 每 60s 轮询,会在 1 分钟内自动领走开发
想让线上 cron 逻辑立刻跑一次(等同等到下个整点),也可由 PM curl 触发端点: 
# DM 派单
curl -s -H "Authorization: Bearer $CRON_SECRET" https://<生产域名>/api/cron/cloud-pc-dispatch
# 二触派单(需已开 SECOND_TOUCH_AUTOSEND_ENABLED=true)
curl -s -H "Authorization: Bearer $CRON_SECRET" https://<生产域名>/api/cron/second-touch-dispatch
路 2 · 全手动 on-demand(绕队列,DM)
本机最省事:在 Claude Code 里说「云电脑发 N 条」会自动跑 send-cloudpc-dm skill(claim→出文案→+v→投递)。手动版:
# 本机(有 Akke 仓库)
pnpm tsx scripts/export-leads-csv.ts --limit=N --out=data/contacts.csv
pnpm tsx scripts/release-surplus-claims.ts --csv=data/contacts.csv   # 释放多锁
sed -i '' 's/微信/+v/g' data/contacts.csv                            # 避关键词风控
curl -s --data-binary @data/contacts.csv https://paste.rs            # 返回 URL 给无影
# 无影(确认抖音登录+最大化+前台+输入法英文)
Invoke-WebRequest -Uri <本机给的URL> -OutFile C:\akke-wuying\wuying-dm\contacts.csv -UseBasicParsing
del C:\akke-wuying\wuying-dm\sent_log_*.csv
py douyin_dm_grounded.py contacts.csv
⚠️ 路 2 与自动 agent 不能同时操作抖音。手动跑 CSV 前,先关掉自动 agent 的黑窗口(或确认它正在 sleep 不在发),否则两个程序抢抖音窗口必崩。发完手动那批再把 agent 开回来。
二触没有「绕队列」的一把手动脚本;要立刻发二触,用上面路 1 的 curl 触发 second-touch-dispatch 端点即可。

5 日常运维要点

一台机 = 一个进程 = 一个号
绝不在同台机起两个 agent、或一边自动一边手动跑 CSV。二触不是「加一个 agent」,是给那唯一 agent 设 AKKE_SECOND_TOUCH_ENABLED=1。
节奏 / 上限改哪
DM:accounts.daily_limit + min_send_interval_seconds;二触:SECOND_TOUCH_DAILY_CAP / MIN_DAYS / COMBINED_HOURLY_CAP(Vercel env)。由 PM 改。
开 / 关通道
整账号开:channel_pref=cloud_pc;关:改回 manual。单关二触:无影 .env 去掉 AKKE_SECOND_TOUCH_ENABLED 重启。
OpenRouter key 必封顶
vision 每发一条都烧、又在共享机 → 后台给 key 设 Credit limit(如 $30),烧超即停、不碰生产额度。
加机器扩产能
每台一个账号、产能 = 该账号上限;镜像克隆即可线性扩。
不碰本机
整链全云端(Vercel+Supabase+无影),运营本机 Mac 关不关都不影响发送。

6 排错速查

现象原因 / 处理
agent 起来但不发多半当日上限满(含人工通道)→ 等滚动窗口腾槽自动续;或该账号没 channel_pref=cloud_pc
只发 DM、不发二触.env 没加 AKKE_SECOND_TOUCH_ENABLED=1;或 Vercel 没开 SECOND_TOUCH_AUTOSEND_ENABLED=true(还在干跑);或没满足 ≥3 天没回的候选
启动行显示 second_touch=off开关没生效 → 改 .env 后重启 agent(改了不重启不读新值)
搜错人 / 身份门跳过输入法不是英文(抢搜索词首字);或同名撞大号(身份门跳过 = 安全兜底)
文字没进输入框 → 不发分辨率变了坐标偏 → DM 重跑 --capture、二触重跑 _measure-comment.py
agent.log 空自启缺 -u(缓冲);或还在 30s 倒计时
连库报错 401把角色 JWT 当 apikey 了;确认 SUPABASE_SCOPED_JWT + NEXT_PUBLIC_SUPABASE_ANON_KEY 都配了
手动跑 CSV 时界面乱跳自动 agent 没关、两程序抢抖音窗口 → 关掉 agent 黑窗口再跑手动

镜像克隆 → 抖音登对号 → .env 开二触开关 → DB 开 cloud_pc → 重启 → 两条通道自己跑。
