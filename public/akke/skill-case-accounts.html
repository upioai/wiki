案例账号拆解 Skill

给一个抖音账号，把它的全部作品扫一遍，挑出其中真正的「案例内容」，产出一页可对外的分析，并归入对应行业的样板库。

这是什么

给一个抖音账号，它把这个号的全部作品扫一遍，挑出其中真正的「案例内容」，产出一页可对外的分析，并归入对应行业的样板库。

我们给客户讲「案例内容怎么做获客」时，最有说服力的从来不是我们说，而是同行已经在怎么做。过去要回答这个问题，得人工翻账号、一条条看、凭印象总结，翻一个号要半天，结论还不可复查。

这个 skill 把它变成可复跑、可校准的流程：抓取是自动的，判定靠明文规则，规则由人工标注校准，每条判定都标着得分和理由，可以逐条核对。换个行业、换个账号，重跑一遍就行。

它能做什么

输入可以是账号链接、账号名，甚至只是一张主页截图。它会依次做完这些：

  1. 定位账号 —— 从名字或截图找到唯一标识，同名号很多时用抖音号和粉丝数核对
  2. 抓全量作品 —— 滞速滚动加载，实测单个号最多抓过 2819 条
  3. 判定哪些是案例 —— 按全局 + 分行业规则打分，每条给出得分与理由
  4. 下载抖音原始封面 —— 不是截图裁切，是平台原图，无 UI 附加物
  5. 生成分析页 —— 含 4×4 封面海报、案例卡片、判定规则表，每张卡片直链原视频
  6. 归入行业样板库 —— 按品类归档，列表页自动更新并排序

还能成批做：给一个品类（比如「我们在谈一个做茶叶的客户」），它会先检索视频、从内容倒推账号、筛掉不对的账号类型，再逐个跑完上面六步。

所有对抖音的请求都按慢速节奏走（搜索间隔 25–45 秒、账号间隔 60–180 秒、每几步强制长休息），并全程 checkpoint 落盘，中断可续跑。实测连续跑了一整夜，没有触发风控。

怎么装

两条命令，Claude Code 和 Codex 都生效：

git clone https://github.com/Akke-AI/akke-skills.git
cd akke-skills && ./install.sh

装完重启你的工具。更新就 git pull && ./install.sh。

脚本把真实文件放在跨运行时目录，再从各家自己的目录建符号链接指过去：

~/.agents/skills/analyzing-case-accounts/   真实文件
~/.claude/skills/analyzing-case-accounts    → 链接（Claude Code 读这里）
~/.codex/skills/analyzing-case-accounts     → 链接（装了 Codex 才建）

这样只有一份文件，一次 git pull 所有工具同步生效，不会出现某个工具里的版本落后。没装 Codex 的同事不受影响，脚本会自动跳过。

还需要克隆代码仓库（skill 里的脚本和规则在那边，不重复一份是为了避免两边漂移）：

git clone https://github.com/Akke-AI/akke-official-site.git

本机还需要：Node（npm i playwright-core）、Python 3、ffmpeg、gh CLI。

怎么用

不用记命令，直接说需求就行。 工具会自己识别并调用，或者你显式写 /analyzing-case-accounts。

三个典型场景，照这么说就行：

场景原话示例
看一个具体账号帮我看看这个号 douyin.com/user/MS4wLj... 的案例内容怎么做的
把账号加进样板库把这个茶叶号加进参考案例集
调研一个新品类我们在谈一个做植发的客户，调研一下这个品类

只有一张主页截图也能开始 —— 把图发给它，它会从截图读出账号名和抖音号，再去定位。

调研新品类时有一件事值得你插手：关键词怎么选。实测茶叶那轮，搜「茶叶 案例」出来的全是讲运营起号的服务商，而搜「茶叶 回头客」「茶叶打包发货」这类交易动作才找到真正的商户。你比它更懂这个行业客户怎么说话，直接把词告诉它。

它怎么判断什么算案例

定义只有一句：画面是不是自家做出来的活（服务过程、成果、作品）。不要求点名客户，也不要求写地址。

这条是被人工标注纠正过来的。第一版规则要求「指向一次具体的交付」，结果 80 条标注一跑准确率只有 49%，而且漏判 39 条、误判 1 条 —— 方向整个是反的。按标注改完是 100%。

评分制，满 3 分收录：

信号分
命中本行业的主营内容+3
明说案例（含「案列」这类错别字）+3
交付动作：完工 / 安装 / 上门测量 / 验收 / 发货+3
前后对比：改造前 / 翻新 / 变身+3
转述他人作品（「设计师：X」「抄作业」）−9
工具产品种草 / 促销−9
无关生活情绪 / 解压−9
同行向 / 行业吐槽−9

分行业只定义一件事：什么算本行业的主营内容。 精度靠上面四类全局排除项保证。所以新增一个行业很轻：加一个 JSON，写清楚这一行的案例长什么样。

行业案例长什么样
门窗 / 窗帘做完的窗、装好的帘
开荒保洁作业现场、前后对比
宠物美容剪完的狗（狗就是客户）
美甲做好的甲、服务过程
婚纱摄影拍出来的片（样片也算）
茶叶 / 大黄鱼交易记录本身：发货、复购、评价、晒单
植发术后前后对比、具体发友
考公考研学员结果：上岸、提分、录取（不是讲题技巧）

判定不带地域属性。 本地、同城、小区、楼盘都不作为依据 —— 那是装修行业留下的惯性。地域可以写进观察结论，但不进规则。

命中率是账号级指标，不是筛选器。 实测跨度很大：婚纱摄影 100%、宠物美容 98%、开荒保洁 82%，而一个 466 万粉的植发号是 0%。高说明这个号绝大部分内容都在展示自家的活；低就要看原因。

维护纪律

规则是数据，不是代码。 全在 case-refs/rules/ 的 JSON 里，改规则不用动 Python。每条规则带 note 说明它为什么存在，接手的人能看懂依据。

改完必跑回归测试。 这是唯一硬规矩：

cd akke-official-site/case-refs
python3 scrape/regress.py

准确率掉了就是改坏了。当前标注集 79 条、准确率 100%。

但别把 100% 当成可靠。 它是拿标注集校准出来的，有过拟合。真正的检验永远是下一轮新标注。

规则靠标注校准，不靠拍脑袋。 两种取样模式解决不同问题：

python3 scrape/make-labels.py ambiguous 10   # 新增行业 / 改完规则：查规则对不对
python3 scrape/make-labels.py spread 3       # 入库一批后：查分类维度够不够

生成的是本地 HTML，打开就标，localStorage 自动存，可随时关掉续标，标完导出 JSON。标完存进 labels/，它就成为回归测试集的一部分。

取样时别漏掉 0 分那一档。它不是「确定不是案例」，是「规则什么都没看出来」。第一轮正是靠它发现婚纱摄影 434 条全卡在 0 分，说明是召回有问题而不是阈值有问题 —— 这两种病修法完全不同。

仓库装什么
Akke-AI/akke-skillsskill 本体 + 安装脚本
Akke-AI/akke-official-site代码、规则、数据、标注集（都在 case-refs/）

skill 本体很短，它不复述代码，只写踩出来的东西 —— 比如抖音抓取的四个坑（普通 HTTP 请求返回全空、Chrome 136+ 禁止对默认 profile 开调试、滚动容器不是 window 导致只能拿到首屏 55 条、话题标签是噪音）。这些不写下来，每个人都要重踩一遍。

有两件事还得人看，别全交给它：

  • 账号类型 —— 规则判内容准，但判不了「这个号是不是我们要的那类商家」。茶叶那轮 286 个候选号里混进了包装厂、代购、测评号，它们发的确实都是「自家做的事」，规则没判错，错在类型。
  • 观察结论 —— 自动入库的页面写的是数据驱动的自动文案，标着「待复核」。像「这个号 16 格封面里大半是同一套模板」这种洞察，目前还得人看出来。
