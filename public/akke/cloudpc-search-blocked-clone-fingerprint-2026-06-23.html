AKKE · 云电脑运维复盘

三台云电脑抖音搜索集体「搜索结果为空」已修复 ✅

日期 2026-06-23 · 影响机器:小文 / 文哥 / 小胡(均自小文镜像克隆) · 通道:无影云电脑 DM / RC / 二触

1出现的问题

三台云电脑的抖音 PC 客户端搜索用户全部失效:无论搜抖音号还是昵称,结果页都显示「搜索结果为空」,导致 DM / 反评 / 二触三条通道全断(都依赖「搜索 → 进主页 → 操作」这一步)。

输入抖音号/昵称→ 联想下拉有结果→ 点搜索 → 结果页为空 ❌

关键反差:同一台云电脑用浏览器搜,能正常搜到人。只有抖音 PC 客户端搜不到。

2诊断:逐个排除,锁定根因

「搜索为空 + 浏览器能搜」一开始有多个可能,我们逐项排除:

怀疑方向验证结论
Cookie 失效 / 没登录联想下拉有结果、能正常浏览排除
IP 被封同机浏览器同 IP 能搜排除
单账号被风控换一个干净账号登录,搜索仍然为空排除
客户端版本旧 / 安装损坏有可能,但不能解释「三台同时坏」存疑
设备指纹被风控软封三台都是同一镜像克隆 → 命中根因
真正锁死根因的一句话 三台机器(文哥=6/10 克隆、小胡=新克隆)都是从小文那台云电脑克隆的镜像。这才解释了为什么三台会同时、同样地坏。

3根本原因

克隆一台已经装好/登录过抖音的机器做镜像时,抖音客户端的设备指纹(device_id / 安装 GUID)被一起复制了——它缓存在本地数据目录(%APPDATA%\douyin、%LOCALAPPDATA%\douyin + 注册表 HKCU\Software\ByteDance),再加上 Windows 克隆带过来的相同机器 SID。

同镜像克隆 3 台→ 3 台共用同一 device_id→ 抖音判定「一机多号·设备聚集」→ 该指纹下搜索软封

抖音看到「同一台设备挂着 3 个号、从 3 个 IP 同时活动」,命中设备聚集 / 一机多号风控,对该设备指纹下的搜索做软封(降权)——查询能发(所以联想下拉有内容),但结果被压成空。浏览器是另一套 surface,指纹不走客户端那份缓存,所以不受影响。

4遇到的卡点

① 误判:差点归因到「搜索太频繁」

「干净账号也搜不到」一度像是行为风控(我们的 agent 60s 一搜)。但真正的触发源是克隆指纹碰撞,不是搜索频率——所以降频并不是这次的根治点。误判会让人去白白调节奏、甚至重置实例。

② 成本判断:重置实例 ≠ 第一选择

无影重置/重建实例能换机器级身份,但会清空整台机器,要重新部署 C:\akke-wuying\wuying-dm(脚本 + cookie + 坐标全重来)。先用更轻的「只清客户端」方案试,不行才上重置。

③ 路径 & 启动方式更正

部署目录是 C:\akke-wuying\wuying-dm(不是 C:\akke-wuying);这些机器没有「双击 start.bat」这套启动,靠 wuying_poll_agent.py / start-dm-routeb.ps1 拉起。

④ 文件投递:paste.rs 偶发抽风

脚本传无影走 paste.rs 时偶发 SSL/读空,重试一两次即可;下载后必须核对字节数(本地 4202 = 远端 4202)确认完整。

5解决方案

Step 1 · 重置抖音客户端设备指纹(每台各做一遍,~20 分钟,不动部署)

用脚本 reset-douyin-fingerprint.ps1 ——只清抖音客户端及其设备身份缓存,绝不碰 C:\akke-wuying\wuying-dm。

# 脚本在仓库:worker/scripts/wuying-dm/reset-douyin-fingerprint.ps1
# 本机 host 到 paste.rs 得到链接,再在无影下载(把 XXXX 换成本次链接):
cd C:\akke-wuying\wuying-dm
Invoke-WebRequest -Uri https://paste.rs/XXXX -OutFile .\reset-douyin-fingerprint.ps1 -UseBasicParsing
(Get-Item .\reset-douyin-fingerprint.ps1).Length   # 核对字节=4202

# 执行(杀进程+删douyin数据目录+清注册表设备键+校验部署完好)
powershell -ExecutionPolicy Bypass -File .\reset-douyin-fingerprint.ps1

脚本跑完,手动收尾:

  1. 卸载抖音:设置 → 应用 → 卸载「抖音」
  2. 重启:Restart-Computer
  3. 装最新版 + 重登本机对应账号(小文机登小文 / 文哥机登文哥 / 小胡机登小胡,别交叉)
  4. 验证:切英文输入法,搜一个抖音号或昵称 → 能出结果即重生了唯一 device_id ✅
  5. 验证通过后,按平时方式拉起 agent(py wuying_poll_agent.py 或 start-dm-routeb.ps1)
实测结果本次三台按 Step 1 处理后,搜索恢复正常,通道重新跑通。✅

Step 2 · 仍为空才上:无影重置实例

若某台 Step 1 后搜索仍为空,说明被机器级身份(克隆的 SID/MAC)兜住 → 无影重置/重建该实例换机器级身份,再重新部署 wuying-dm。代价更高,只对个别机器单独做。

Step 3 · 防复发(写进部署规范)

永远不要把「已装/已登抖音」的机器做成基础镜像去克隆。 基础镜像只装干净 OS + 依赖 + wuying-dm 脚本;抖音客户端在每台机器克隆好之后单独装、单独登 → 每台从第一次启动就拿到独立设备指纹,根本不会聚集。

补充:60s/条的高频搜虽不是这次根因,但上生产仍建议把陌生潜客发送间隔放回 45–90 分钟(避 status_code 7911 限频),属长期卫生。
