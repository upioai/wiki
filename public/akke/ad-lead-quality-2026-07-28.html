阶段判断：无效及低质量线索占比较高，且存在明显的“广告内容预期错位”。

02 / 无效结构

无效及低质量咨询主要呈现为六种类型。

“无效”不是一个单一标签。不同类型分别反映了人群匹配、内容理解、点击意图或会话承接上的差异。

错投

完全跨业务咨询

相亲、青草、找美女等，和全屋定制没有关系，属于明显的人群或内容错配。

样本表现：高频、直接偏题
误解

内容/视频预期错位

询问短片、视频入口或进入后才问业务，可能把广告理解为泛内容入口。

样本表现：按钮意图不清
玩闹

随意互动与无意义输入

表情、乱码、“我很喜欢你”“你猜”等，通常没有可识别的装修需求。

样本表现：低成本误触
跑题

泛话题讨论

农村人口、麻将等话题与业务无直接关系，即便客服尝试拉回，也未形成需求信息。

样本表现：会话存在、意向缺失
反向营销

异业推销与中介

主动售卖商品、留下联系方式或询问中介合作，占用客服响应资源。

样本表现：非买方线索
待核验

弱意向/信息不足

只问“什么业务”“怎么看视频”，需用城市、房屋面积、装修时间三问快速判定。

样本表现：不可直接判死

04 / 原因链路

问题同时出现在入口识别与后续承接。

大量用户在点击前没有形成清晰的全屋定制预期，导致客服环节承担了额外筛选成本；两个有效线索案例则显示，进入会话后的解释和流程同样影响最终结果。

STEP 01

广告素材/标题

泛内容表达可能带来低成本点击，但业务识别度不足。

STEP 02

定向与版位

人群过宽或版位偏娱乐，放大误触与随意互动。

STEP 03

咨询按钮

按钮未提前说明“咨询全屋定制报价/方案”。

STEP 04

客服承接

统一长文回复过早，尚未先完成需求资格判断。

确认含糊

一句“对的”同时承接两个问题

客户同时问价格和“50㎡有没有”，单句确认无法判断是在确认单价、面积还是服务能力。

计价错位

房屋面积不等于柜体投影面积

应在第一轮用例子说明：50㎡是房屋面积，568 元/㎡按实际柜体投影面积计算，不能直接做 50×568。

身份混淆

品牌、厂家和装修服务边界未先讲清

客户把“有大有小”“兔宝宝”“搞装修”混在一起，说明素材和回复没有快速建立品牌角色与服务范围。

样本口径：这是此前已计入的“价格 + 50㎡咨询”客户后续，不新增样本数量。该线索仍归为“潜在有效”，但最终状态更新为“解释后未继续回复”。
06 / 消息触达

“进入客服消息”属于承接通道问题，不能仅靠修改回复文案解决。

当前用户看到的是微信“客服消息”入口，而非一个普通微信好友会话。是否展示在主会话列表，受账号产品形态与微信客户端规则控制。

结论：运营方无法强制把公众号/微信客服消息变成普通好友会话。

如果目标是长期出现在用户的普通聊天列表中，需将承接链路调整为“添加企业微信客户联系人”，由用户主动完成加企微；若继续采用公众号/微信客服通道，则应接受其入口及折叠机制，并通过用户置顶、服务通知和首轮互动提升可见性。

方案 A｜广告直接加企业微信

优先推荐。将咨询组件或落地页主按钮改为添加企业微信客服，用户添加后形成一对一客户联系，便于持续跟进、打标签和分配销售。

方案 B｜保留客服消息，增加转企微动作

首轮先完成城市/面积筛选；确认有需求后，再引导用户添加对应城市的设计顾问企业微信，减少把无效流量导入销售私域。

方案 C｜服务号置顶提示

对于必须留在服务号的链路，可提示用户将服务号置顶；但这是用户侧操作，不能由品牌后台批量强制完成，也不应作为唯一解决方案。

07 / API 接入

通过 API 连接投放、客服与成交结果。

目前主要依靠人工截图复盘，无法持续还原每条线索来自哪个素材、花费多少、最终是否有效。API 接入可以建立完整的数据关联，以下为企业微信开通流程和准备资料。

接口接入的价值，不只是“看更多数据”，而是让系统知道什么样的广告真正带来装修客户。

当广告来源、对话内容和销售结果能够通过同一线索标识关联，团队才能从“咨询数量”转向“有效线索成本”，并把有效结果持续反馈给投放端。

01 · 广告数据

连接投放来源

获取账户、计划、广告、素材、版位、地域、消耗、点击、咨询等字段，识别无效流量具体来自哪里。

02 · 会话数据

连接客服对话

在脱敏前提下读取会话时间、首句话、响应状态及来源标识，自动识别意图与无效类型。

03 · 业务结果

连接线索状态

回写无效、待培育、有效、加企微、预约量房、到店及成交等结果，形成统一判定口径。

04 · 自动应用

连接优化动作

生成实时看板、素材质量排行与异常预警，为预算调整、素材迭代和客服跟进提供依据。

先确认通道，避免开错接口员工企微添加客户，应开“客户联系 API”；广告进入“客服消息”，应接“微信客服 API”；如果要分析员工与客户的企微好友聊天正文，还需单独购买并合规开通“会话内容存档”。客户联系 API 默认不能读取聊天正文。
推荐第一期

客户联系 API

关联 external_userid、添加渠道、跟进人、标签和线索状态，先完成“来源—客户—业务结果”闭环。

当前客服消息适用

微信客服 API

同步微信客服账号、会话、接待人员和消息，适用于目前用户进入“客服消息”的承接方式。

按需付费开通

会话内容存档

用于员工企微好友聊天正文分析；需要购买、配置授权范围、RSA 密钥并完成员工及客户告知。

企业微信 API 开通操作

管理员确认企业主体

使用超级管理员登录企业微信管理后台，确认企业已注册且可正常使用。准备企业名称、统一社会信用代码、营业执照及管理员身份；若后台要求认证，先完成企业认证。

取得 CorpID

进入“我的企业”，复制企业 ID（CorpID）。CorpID 可交给后端配置；任何 Secret 都不能放在网页、群聊或前端代码中。

创建自建应用

进入“应用管理”→“自建”→“创建应用”，应用可命名为“广告线索数据闭环”；设置可见员工/部门，保存 AgentId 和应用 Secret。

准备服务器与可信 IP

提供正式 HTTPS 域名、有效 SSL 证书、固定出口公网 IP 和后端服务；在应用开发配置中加入可信 IP，由后端用 CorpID + Secret 获取 access_token。

配置事件回调

填写公网 HTTPS 回调 URL，生成 Token 与 EncodingAESKey；服务端完成 URL 验证、签名校验、AES 解密、事件去重、重试幂等。

开通客户联系权限

进入“客户联系”→“权限配置”设置成员范围；在“客户”→“API”查看客户联系 Secret，并把自建应用加入“可调用应用”。

按当前通道接微信客服

进入“应用管理”→“微信客服”，确认客服账号和接待人员；在开发配置/API 中配置应用、回调与 Secret，接入会话和消息同步。

需要聊天正文再开存档

电脑端后台进入“安全与管理/管理工具”→“会话内容存档”，按后台实时报价购买；配置成员范围、确认函/授权、RSA 公钥和存档 Secret。只能获取正式接入后且授权范围内的数据。
