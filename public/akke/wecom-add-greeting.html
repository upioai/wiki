企微加好友的打招呼话术

兔宝宝全屋定制 · 客户线索加微信 · 自动加好友流程的「话术」一环 · 按线索从 3 条话术选最匹配的一条 · 2026-06-30

一句话：3 条话术，拉单时按每个客户的备注，自动挑最匹配的一条。

不用手打。备注里有真实装修线索的（想了解价格 / 新房毛坯 / 想对比品牌…）→ AI 选对应那条；没线索的 → 用通用的话术2。3 条全部压到 50 字内，发出去不会被截。

⏱ 话术什么时候定下来？（最容易问的一点）

第 1 步 · 你本机 · 拉单时
🎯 话术在这一步就选好

敲拉单命令的瞬间，去数据库读每个客户的备注，有线索的让 AI 从 3 条里挑最匹配的一条，一行一条写进名单（CSV）。名单里每个人后面已经跟好一条话术。

→
第 2 步 · 云电脑 · 执行加好友时
📤 不选了，照着名单发

发送脚本不再挑话术，只读名单里那条现成的 → 填进企微验证框 → 发出。这 3 条话术不带自称，云电脑只管照单发。

所以：话术 = 拉单时（本机）按备注选好 → 写进名单 → 云电脑加好友时照着发

不是加好友那一刻才现选。为什么分开？备注在数据库里、只有本机查得到；云电脑只有名单、连不到库，所以「选话术」放本机做，云电脑只管「照单发」。

② 怎么按线索选（逻辑）

每条线索按备注分情况处理
备注情况怎么处理
有真实装修线索
（面积/小区/毛坯/翻新/风格/想了解价格/想对比/闲鱼或装修客服安排…）		AI 选 1 条 读备注，从 3 条里挑最匹配的（价格→话术2、材料品牌→话术3、新房图优惠→话术1）。
没备注 / 垃圾痕迹
（归属地、未接电话、微信未通过…）		默认话术2 没线索可匹配，用最通用的话术2（有「您好」+明确报价+全包+保障）。
死号
（空号 / 无效 且没有微信号）		跳过不加 不导进名单、单独计数，省得白发。

想全员统一发同一条、不按线索选：拉单时加 --no-personalize，所有人都用默认话术2。

③ 话术怎么接进发送流程（给重搭流程的同事）

话术不在发送环节生成 —— 拉单时就按备注选好、写进名单 CSV 了，发送只管照名单发。

同事重搭发送流程时，脚本读名单 CSV，按下面这张表对接（重点是 verify_msg 列）：

名单 CSV 列是什么 / 怎么用
verify_msg这条线索要发的验证话术（已按备注选好整条、≤50字）。填验证语时 优先用它；为空才回退默认 env AKKE_WECOM_VERIFY_MSG。
search_key搜人用：微信号优先，否则手机号
name / note姓名 / 备注（核身份、参考）
_source_id回写状态 / 通过率统计的唯一键

现成的 wecom_add_contact_grounded.py 已经是这么读的——沿用它，话术零改动直接通；换新脚本就照 verify_msg 这条接（别漏，漏了就全发默认话术了）。

怎么生成带话术的名单（本机拉单 · 话术在这步选好） 
# 先预览每条选了哪句话术（不拉单、不占线索）
pnpm tsx scripts/claim-enterprise-leads.ts --limit=5 --by=你的名字 --dry-run
# 没问题就正式拉：导出带 verify_msg 的 CSV，传云电脑给发送脚本吃
pnpm tsx scripts/claim-enterprise-leads.ts --limit=5 --by=你的名字

云电脑端整套设置（登录 / 锁分辨率 / 输入法 / --calibrate 标坐标）属于发送流程那一环，看 runbook docs/runbooks/wecom-add-contact-cloudpc.md。这 3 条话术不带自称，不用设账号名。

想换话术 / 全员统一一句？
  1. 全员统一、不按线索选：拉单时加 --no-personalize，所有人都用默认话术2。
  2. 改这 3 条话术的文案：找 Claude 改 scripts/claim-enterprise-leads.ts 里的 T1 / T2 / T3 三个常量（每条 ≤50 字），推一下即可。

④ 按话术看通过率

哪条话术更容易被通过，一条命令看

每条 lead 拉单时选了哪条话术已记进库。等回写过「已通过」后，跑：

pnpm tsx scripts/wecom-acceptance-by-template.ts --by=你的名字

输出每条话术的 已发 / 已通过 / 通过率，谁高谁低一目了然，据此调话术或调配比。

注：通过率 = 已通过 ÷ 已发请求。加好友是对方隔几小时/几天才点通过，所以得先有人把「对方通过了」回写成 已通过，这数才准。
