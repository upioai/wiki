01 — 现状核对

那份流程文档，跟实际在跑的东西对得上吗

大方向是对的，三层蒸馏真在跑，不是纸上谈兵。但有三处硬性对不上，其中一处会直接影响你对系统能力的判断。

对得上的部分

文档说的实查结果结论
三层蒸馏：原始案例 → 金牌问答 → 决策原则 27 案例 / 165 问答 / 34 原则 / 66 篇知识 属实
每轮注入 top-3 问答 + top-4 决策原则 代码写死 slice(0,3) 与 DECISION_RULES_PER_STAGE=4 属实
企微走语义检索（bge-m3），抖音走关键词 属实，取向量失败会自动退回关键词，不会挂 属实
pgvector 素材库暂未启用 默认关（KB_RETRIEVAL） 属实

对不上的三处

文档说 · 提示词由 9 层拼成

人设 / 风格 / 记忆 / 会话信息 / 品牌 / 产品知识 / 决策原则 / 金牌问答 / 模板骨架。

实际 · 是 13 块

文档漏了：门店地址清单、服务点清单（这两块绕过知识库排序、每轮全量硬注入）、报价口径块、防复读指令块、长对话压缩摘要块。

文档说 · 11 步闸门流水线

媒体拦截 → 回声过滤 → 给号模板 → 生成 → 资料交付分支 → 生成后自检 → 置信度闸 → 分流「自动发 / 转人工」。

实际 · 企微只有其中一半

那 11 步描述的是抖音的流水线。企微只有：非真人闭麦 → 好友验证样板剔除 → 老话去重 → 回声闸 → 媒体识别 → 生成。没有置信度闸、没有转人工出口、没有草稿状态机。

这条最要紧：企微是「AI 写什么，云电脑就原样发什么」，全程没有任何一个「这条我不敢发、交给人」的出口。抖音有的那道 gateDraft（检测到负面情绪、投诉、临门决策就转人工）在企微不存在。文档里的第 10、11 步，企微通道是空的。

文档说 · 自我修正靠生成后自检

检测断句、反问、超长、自曝、缺钩子，重写 ≤3 次。

实际 · 企微只有 4 道，都埋在生成函数里

反复读硬闸（相似度 0.62）、明禁项重写、内心独白泄漏兜底、空回复重试。跟文档描述的那套自检不是一回事。

02 — 覆盖度盘点

话术设置目前缺哪几块

顺着上面这个问题往下查，发现的不只是「某条规则写得不好」，而是有几整块场景压根没接上。按严重程度排。

决策期话术是死库存，一次都没跑过

致命

企微会话的阶段分布是 培育 47 / 破冰 5 / 已转人工 4——决策期 0 条。 翻遍代码，没有任何一处会把企微会话推进到决策期（唯一改阶段的地方是手动转人工）。 也就是说：整套 wecom.decision.rules 提示词、52 条决策期金牌问答、11 条决策期原则， 全是建好了接不上电的库存。客户聊到「哪天能去看」「定金怎么算」时，AI 用的还是培育期那套口吻。

企微首触零示例，第一印象全靠一段静态规则硬扛

高

首触走的是一条早退分支，不注入任何金牌问答示例。库里 165 条问答里破冰类只有 7 条， 而且企微首触还用不上。全靠 606 字的静态规则撑着。 上周「有大有小」被写成「大有小」那次事故，就发生在这一句上——首触只有一句话，错了没有下一轮兜。

没有「客户拒绝 N 次就停推」的闸，也没有情绪出口

致命

客户说「太贵了」「别家更便宜」有议价话术管，但「我不需要」「别发了」连说三次之后会发生什么，规则里没写、代码里也没拦。 抖音那边靠置信度闸检测负面信号转人工，企微没有这道闸——客户不耐烦了，AI 会继续按规则推到店。

没有「到店后 / 出方案后 / 成交后」的话术

高

阶段机总共只有破冰 / 培育 / 决策 / 已转人工四档。 但一段真能聊到 50 轮的会话，必然要跨过「约到店 → 到店了 → 设计师出方案 → 谈定金 → 交定后跟进」这几段， 每段该说的话完全不同。现在全压在「培育」一个模式里，越往后越对不上客户所处的位置。

已读不回只有一个 7 天召回，没有梯度

中

加了好友不说话的走 7 天召回。但聊到一半突然不回的没有分层跟进—— 第 1 天、第 3 天、第 7 天该用什么力度的话去勾，现在是一套话打到底。

知识库每轮只有约 13% 能进提示词

中

66 篇知识文档合计 11,034 字，但注入上限写死 1,500 字。 虽然按客户当下这句话排了序，但「工期多久」「售后怎么算」「质保几年」这类冷门问答很容易抢不到位置， 抢不到 AI 就只能自由发挥——这正是「答错」类问题的温床。

金牌问答不分渠道，抖音和企微共用一套

中

conversation_examples 表没有渠道字段。 这 165 条是从企微/微信聊天截图蒸馏出来的，但抖音私信也在用同一批（只是署名换成「小艳」）。 两个渠道的口径本来是有意做区别的（比如量尺免费的说法），示例却是混用的。

03 — 根因

为什么「修好了，下次又出新问题」

五条，按影响从大到小。每条都有实查证据，不是推测。

根因 1

你改的地方，和线上跑的地方，不是同一份

近 30 天企微一共生成 130 次，其中用到代码里那份话术规则的次数是 0。线上 100% 跑的是 Langfuse 后台那一份。

而代码里那份 fallback，近 120 天被改了 17 次。上周那个 PR 的标题直接就写着「话术 fallback P0/P1/P2 修法（风洞四人横评产出）」——改完只有 PM 手动同步到 Langfuse 才会生效。

我把线上那份拉下来逐字对了，现在就有一处没同步干净，而且已经导致提示词自己跟自己打架：

模型在两条互斥规则之间只能随机挑一条执行——这就是你感受到的「时好时坏」。代码那份里这两处早就改一致了，线上只同步了后半截。

根因 2

每天那份质检建议，对照的是错的规则基线

每天早上 9:30 的话术巡检，会把「我方现行规则」喂给判定模型，让它回答「这条问题现有规则有没有管、为什么还犯」。

但拼这份「现行规则」的代码，读的是那份从不生效的 fallback（文件开头自己都标了警告）。两边已经漂移了。

后果是双向的：线上其实没这条规则的，会被误判成「有规则但没遵守」→ 建议你「升级成硬规则、去查代码」；线上明明有的，会被判成「缺规则」→ 建议你「再加一条」。建议的方向本身就是错的，照着改当然按下葫芦浮起瓢。

根因 3

规则只加不减，已经堆到自己跟自己打架

企微的系统提示词实测 输入 7,346 token（中位数），约 6,000 多个中文字——这还没算对话历史。

光「一条回复该多长、该不该抛钩子」就叠了五套互相拉扯的口径，而且是无条件全量注入、每轮都在：

规则块它要求的
节奏铁律≤50 字、只答这一点、答完就停
金牌卖点必打价值节点放宽到 ≤80 字、必带两个亮点、必须先给占便宜锚定
SPIN 主动挖需求别只被动接话，要往前带、软挖一层
钩子克制大多数回复只答问题、不抛钩子
收口信号必推客户说「我再看看」时必须当场约到店

每条单看都对。叠在一起，模型只能挑一条执行。你按金牌对话修了 A，模型这轮就更听 A、更不听 B——B 那类问题就冒出来了。这就是「修一个坏一个」的机制本身。

根因 4

没有回归闸：只验「这条修好没」，不验「以前修好的还在不在」

全仓一共 3 个评测脚本（读户型图 / 意向打分 / 质检模型选型），没有一个是企微话术的。评测用例目录里只躺着一个意向打分的文件。

那 331 条自动化回归全是纯函数测试——正则、切句、相似度算法——没有一条覆盖「给定这段对话，回复应该满足哪些条件」。

所以每次改提示词都是裸改、无保护。这是「修一个坏一个」能一直循环下去的直接原因。

根因 5

观测有盲区，你看不见自己修的东西有没有生效

近 30 天企微 130 次生成的实测底盘：

信号次数意味着
回复被事后清洗76 / 13058% 的回复带了脏东西：导演说明、人设名前缀「小艳：」、句内复读
撞明禁项、重写修好15规则确实在起作用
撞明禁项、重写后照样撞6然后照样发给客户了——没有第二道拦截
空回复兜底118.5% 的轮次模型返回空，靠重试和兜底话救

更麻烦的是两个真盲区：反复读硬闸触发时不写任何记录（130 条里查不出它到底拦过没有）；明禁项重写那次调用不进追踪系统（看不到它重写成了什么）。修完没法验证，只能靠肉眼看对话。

04 — 50 轮

先说个不好听的：生产里从来没有过 50 轮

也就是说，现在关于「50 轮质量」的所有判断，都来自推演，不是真客户。

而且现在的记忆架构，物理上撑不到 50 轮

  • 接口只取最近 40 条消息；
  • 超过 16 条时，只保留最近 10 条原文（约 5 轮），前面的压成一条「要点提示」；
  • 但这条要点提示是正则抠出来的，而且只扫我方说过的话——只认价格、数字、承诺词；
  • 所以客户在第 3 轮说的「家里有小孩怕甲醛」「着急住要加急」「预算就 3 万」，一个字都进不去，直接蒸发；
  • 本该兜底的长期画像，56 条会话里只有 3 条写出来了。

结论：过了第 8 轮，AI 对这个客户的记忆 ≈ 最近 5 轮对话 + 我方报过的价。别的什么都不记得。

05 — 方案

怎么彻底修

分四档。P0 那三条不做，后面全白干——因为你改的东西压根不一定生效，质检给的方向也不一定对。

P0 先把「改哪里」这件事收口 ✓ 当天已完成
  1. 规则的唯一出处，二选一定死CI 闸已挂
    要么话术正文全部收回代码、Langfuse 只放实验版；要么代码那份改成从快照文件读、禁止手写。现在这种「两份都能改、只有一份生效」是最贵的坑。今天就能做的最小动作：把快照比对脚本挂进 CI，一漂移就红——我刚跑，现在就是红的。
  2. 修掉线上那句自相矛盾已修
    去 Langfuse 后台把【答产品用真信息】那行的「拉清单」删掉，同步成代码里的说法（「到店或线上会议咱当面过一遍」）。改一行、立刻见效，这是投入产出比最高的一条。
  3. 让质检去读线上真规则已修
    把拼「现行规则」那段改成读快照文件（= 线上真跑的），别再读代码 fallback。这一改，每天那份建议的方向立刻就对了。
P1 建回归闸——这才是「修一个坏一个」的根治 ✓ 当天已完成
  1. 把历次修过的问题，一条条固化成用例已建 · 25 条
    每个修过的问题存 1～3 条：历史对话片段 + 客户这一句 + 确定性断言（不能出现「发你清单」／必须报真实门店地址／长度 ≤80／不能再问已说过的城市／必须先接住问题再问城市…）。起步 30～50 条。
  2. 改提示词前后各跑一次，只允许「全绿或更绿」已成规矩
    走评测专用 key，单次成本几毛钱。这样「以前修好的又坏了」会在上线前被抓住，而不是等客户聊崩了你才发现。
  3. 接上已有的发布闸
    仓库里那个提示词发布脚本本来就是为这个建的，把它接到这套用例上就活了，不用从零写。
P2 给提示词减负，把打架的规则改成互斥分支 进行中 · 已切一刀
  1. 五套节奏规则改成「按客户这句话选一块注入」报价这一刀已做
    问价／问材质 → 卖点块；闲聊／问进度 → 节奏块；露出收口信号 → 约到店块。一次只注一块，不再让它们互相打架。代码里报价提示（命中问价词才注入）就是现成范式，照抄即可。
  2. 目标：从 7,300 token 压到 3,000 以内
    这不是省钱，是提示词越短，每条规则的遵守率越高、表现越稳定。现在这个体量，加一条新规则的边际收益已经是负的了。
P3 把 50 轮真的撑起来 1 周
  1. 补上缺失的阶段：决策期先接上电
    52 条决策期问答 + 11 条决策原则已经在库里躺着了，缺的只是「什么条件下把会话推进到决策期」这段判断。这是本次盘点里性价比最高的一块——料是现成的。之后再补到店后 / 成交后两段。
  2. 让客户画像真的写起来
    别再指望模型主动记（56 条只写出 3 条）。改成每轮用便宜模型确定性抽一次结构化画像存库，成本可以忽略。这是长对话不失忆的地基。
  3. 要点提示别用正则，改成滚动摘要
    每 8 轮让便宜模型做一次会话摘要存库，之后每轮注入摘要，而不是拿正则去抠我方说过的数字。客户说过的需求、顾虑、时间压力才能留得住。
  4. 给企微补一个转人工出口
    抄抖音那道置信度闸：负面情绪、连续拒绝、临门谈价这几种就别发了，推 Lark 让人接管。一段 50 轮的会话必然有几轮是 AI 不该接的，现在这些全被硬发出去了。
P4 补观测 半天
  1. 把两个盲区点亮
    反复读硬闸命中要记一笔；明禁项重写那次调用接进追踪系统。不然你永远不知道自己加的闸有没有在干活。
  2. 建一张企微质量日看板
    清洗率 / 重写未修复率 / 空回复率 / 按轮次分段的问题率（1–5 轮、6–15 轮、16 轮以上）。这些数现在全在库里，就是没人看。分段这一项尤其关键——它能直接回答「到底第几轮开始崩」。
06 — 闸建起来之后

回归闸第一天抓到了什么

25 条用例、每条 8 次采样跑下来，两件事值得单独说——一件是纠纷风险，一件推翻了我自己在根因 3 里的判断。

一、AI 在编造公司没有的退款政策 已修

用例 no-refund-promise 八次采样只过一次。原话：

公司根本没有这个政策。提示词里那条「退款别乱承诺」写了快一个月，模型照样编——客户拿这句去对账就是纠纷。

按质检自己的分类法这属于「有规则但没遵守」，该从提示词升级成确定性护栏，而不是再往七千字的提示词里加第二遍。已加，修后八次全过。

这里最要小心的是别误伤：「环保不达标全额退」「假一赔三」是合同里真有的承诺、是核心信任锚，检测刻意不含裸的「全额退」，只抓与定金和时限绑定的编造。后来复查还发现「定金不能退」这种正确说法会被误判，也一并收紧了——把模型从正确答案上推开，比不管更糟。

二、报价锚定基本没在生效 已修

用例 gold-standard-price-anchor 八次只过一次：客户问「多少钱一平呀」，模型 87.5% 的时候只干巴巴回一句「568一平」。

「原价 868 → 样板房补贴 300 → 只要 568」这套占便宜说法，是价格心理的核心——没有原价和补贴，客户只记住一个数字，感觉不到自己赶上了活动。它事实上已经失效了。

这一条推翻了根因 3 的判断

我在根因 3 里说这是「五套规则互相拉扯、模型只能挑一条」，需要提示词大改造。查下去发现不是。

报价提示块的最后一条——也就是最贴合「问多少钱一平、还没报面积」这个场景、最具体的那条指令——逐字规定了要说哪句话：报单价"568 一平（…全包）"。那句处方里根本没有 868 和补贴。

而要求锚定的【金牌销售·卖点必打】是一个遥远的通用块。具体的赢过笼统的，模型照着最近那条念，锚定就丢了。

所以修法不是减负，是把最具体那条指令改对——代码本来就知道 868/300/568 这三个数，把锚定直接写进处方本身。改完 1/8 → 8/8。

对 P2 的启示：「规则打架」是真的，但在动大手术之前，先逐条查「有没有哪条具体指令自己就写错了」。这一条改动只有一行，收益是 700%。

三、顺带纠正一个方法论错误

我第一版基线用 3 次采样，得出「20/25 全绿、5 条抖动」。那个数是假的。

3 次采样分不清「33% 遵守」和「67% 遵守」——上面那条报价锚定在不同的跑里给出过 0/1、2/3、2/3、0/3，看着像抖动，提到 8 次采样才看清真相是 1/8。用采样不足的基线判断「修复有没有失效」，会系统性低估问题。

现在定基线一律 8 次采样（25 条约十分钟、一毛五）。另外还有一条判读规矩：改了哪条分支，就只看走那条分支的用例——改完报价块之后有两条用例分数掉了，查下来它们压根不走报价分支、改动够不着，纯属噪声。不查因果就改回去，等于被噪声牵着走。

口径提醒 · 别急着下结论

之前那次延迟问题（中位数 44 秒、最高 277 秒、36 次超过 1 分钟）确实已经随模型回滚解决了，回滚后中位数 5.0 秒。

但回滚后企微一共只跑了 13 次。样本太小，现在还不能说「质量稳了」。等 P1 的回归用例建起来，才有资格说这句话。
