CASE这次校准从哪来的

客户拿我们之前导出的评论文档，逐条人工标注了 99 条（《客户评论标注-20260606》），给每条打了 0–100 分（半随机抽样 + 半「我们判得跟同类多数不一样」的分歧样本）。这是第一次有客户侧的"标准答案"来校准我们的意向打分——以前都是我们自己定标准。

这一版的所有改动，都是拿客户这 99 条标注当尺子量出来的：先看我们和客户哪里判得不一样、差在哪，再决定改什么。下面 §2 是差异，§3 是发现，§4 是改动。
SECTION 01上一版打分机制（回顾）

每条评论先由大模型（DeepSeek V4 Flash）拆成 3 个维度，代码按固定公式算出 0–100 分，再按阈值落四档。得分 = 基础分（类型）+ 加分（具体程度）+ 加分（时效），上限 100：

① 评论类型基础分② 具体程度加分③ 时效加分
问购（想买/找服务）60具体+25近窗（刚发）+15
问工艺（问知识/做法）40一般+10在调研+8
感慨（闲聊/玩梗）15模糊+0无时间+0

落档：高 ≥80 / 中 ≥60 / 低 ≥30 / 其余无关。举例：

高意向 93 「120平一般装多少钱」
问购 60 + 具体 25 + 在调研 8 = 93
中意向 78 「这套下来多少钱」
问购 60 + 一般 10 + 在调研 8 = 78（够 60 不够 80）
低意向 58 「求份攻略」
问工艺 40 + 一般 10 + 在调研 8 = 58
⚠️ 这一版（06-08）没有改这张表——基础分/加分/阈值全部保持原样。改的是「大模型怎么把评论拆成这 3 个维度」（prompt）和「同档里先碰谁」（排序）。为什么不改表，见 §7。
SECTION 02客户的标准 vs 我们的，差在哪

把客户的 0–100 分也归成四档，跟我们的判定并排比（96 条可比）：

档位我们判了几条客户判了几条差异
高意向2147客户比我们多 26 — 我们把一大半真高意向看走眼
中意向3018我们多 12（大多被客户判成了高）
低意向2323基本一致
无关2611我们多 15 — 我们把客户觉得还能碰的当垃圾扔了
严格同档一致 51%，±1 档内一致 91%——没有离谱乱判，但一档之差是系统性的、有方向的：该捞的高意向没捞上来，不该扔的当无关扔了。

一句话总结客户的"评分观"：

客户的门槛整体比我们松、更看重"人愿意开口具体提问"这件事本身——问价、深度请教、求资料、甚至同行搭话，在他眼里都是值得碰的线索；而我们的模型偏"学术"，按"知识 vs 产品""具体 vs 泛"打分，反而把"具体的技术请教"误当成了无意向。

SECTION 03今天分析出的 5 个关键点
#发现证据 / 例子
1真高意向被压成"中意向"（最大漏召）我们判中意向的 30 条里，客户有 21 条判成高。我们"高"档很准（说高时客户 90% 认同），但太保守——大量该进高的卡在中档（多数卡在 78 分，差 80 线一点点）。
2预算/价格类被系统性低估这类平均比客户低 26 分。「多付钱不」我们 35/低→客户 80；「已经看了好久 10000-1000…」我们 30/低→客户 80。
3知识类判得"一刀切"大批做法/工艺咨询统一给 58/低。但客户把它劈两半：闲好奇（"风水没问题吗"）→ 低；真技术请教（"水泥墙有涂料，预拌砂浆贴要不要铲掉"）→ 100。同一个标签，客户眼里天差地别。
4"无关"下手太狠 + 误杀我们判无关的 22 条里 11 条客户要留。最严重：一条认真技术请教被判 0 分（误判成非装修品类），客户给 100。
5同行/分享类客户当高价值「我这有两户过来给我帖」我们 33/低→客户 100。这位客户（工长/师傅）把同行合作当线索，跟我们默认相反。
SECTION 04更新版打分机制（这次实际上线的 = B + C）

校准走了一个「不爆池」的折中方案（为什么不直接采纳客户的松门槛，见 §7）。两块改动：

B｜把"大模型怎么拆维度"改准（prompt 修 3 处真错，已上线）

修了什么效果
装修工艺/施工请教 + 房子相关，不再误判"非装修品类"（砂浆/涂料/防水/美缝/户型/装修费）"水泥墙涂料请教" 0/无关 → 中意向，不再被当垃圾扔。只有成品家具(沙发/床单买)、家电、数码才判无关→0。
知识类"具体程度"拆开：带自家户型/材料/施工现状的深度请教 → 具体(high)；泛泛闲好奇/抬杠 → 模糊(low)深度技术请教升档；闲好奇（"风水没问题吗"）落低意向，不再都挤中间。
同步补回 3 条客户/PM 既定规则（报面积→问购、报面积→具体、全屋智能→装修）"98平小三室预算多少"→高意向 93、"186平可以设计吗"→高意向 93。

C｜中意向桶内"按分优先"（拉单排序，已上线）

真高意向被压在中档（78 分那批"问价/要清单/求设计"）——这次没硬把它们提进高意向（避免池子失控，见 §7），而是改成：运营拉单时，中意向桶里高分的排在最前面优先碰。等于"暂不提档、但优先处理"。

中意向 78 「这套下来多少钱」「可以发一份装修清单吗」「186平可以设计吗」
仍是中意向，但 C 让它们排在中意向桶最前列 → 运营优先碰，不被 60 分的随口一问稀释
新版举例（实测）：
· 「水泥墙有涂料，预拌砂浆贴要不要铲掉」→ 不再 0 分（深度请教归"具体"，进中意向，C 里优先）
· 「98平小三室预算多少」→ 高意向 93（报面积 = 强购买意图）
· 「这样搞风水没问题吗」→ 低意向（泛泛闲好奇，不再误占中档）

SECTION 07我对"意向分演变"的看法 · 对这一版的看法

关于意向分演变的"基础"——我的三条看法：

① 分数不是目的，"该不该碰这个人"才是意向分只是把"要不要私信"这个动作可排序、可解释。所以演变的尺子永远是业务侧的真值（客户/运营认不认），不是某个内部指标好看。这次有了客户标注，第一次能拿外部真值校准——这比我们自己调参靠谱得多。
② 分类（prompt）和打分（公式表）要分开演变同一个错判，可能是"模型把评论类型/具体度拆错了"（prompt 的事），也可能是"公式阈值划错了"（表的事）。先分清是哪一层再动手——这次大部分问题是 prompt 拆错（技术请教被当非装修），改 prompt 就好，不该动阈值。乱动阈值是最容易出事的。
③ 召回和产能是一对约束，不能只看准"判得跟客户一样准"和"运营 5 人能消化多少"是两件事。把召回拉满、池子翻几倍，但发不出去，等于把真高意向稀释在一堆里——反而更差。意向分的演变必须带着下游产能一起算。

对这一版的看法——为什么是 B+C，不是直接采纳客户：

关键发现（也是这版最重要的判断）：客户认为"问价/要清单/求设计"(中意向 78 分那批) 都该是高意向——这没错。但拿全库 39,471 条实测，只要把这批提进高意向，高意向池子会从 2,896 涨到约 9,500（7.3% → 24%，3.3 倍）。这批是评论里最大的一桶，绕不过去。运营 5 人 + 私信配额扛不住 3.3 倍。

而且客户标注样本里 49% 是"故意挑的分歧 case"，不代表真实评论分布——拿它校准阈值套回真实流，会系统性过度提权。"对齐客户标注最优" ≠ "线上能跑"。

所以这版的取舍是：

✅ 立刻做（B+C）
修真错 + 优先排序
prompt 误杀（技术请教判0）是硬伤，必须修；product/medium 暂不提档但在中意向里优先碰。不爆池、低风险。
⏸ 暂不做（v6）
改阈值 / 提档
会让池子 3.3 倍。配方已备好(env 开关)，等产能上来、且用新一批标注复核后再切。
⚠️ 诚实标注：v6 配方的"严格对齐客户 53%"是拿 99 条 in-sample、且基于旧 prompt 产出的四轴调出来的——是"对着答案考试"的上限值，真实新数据会更低，且 prompt 一改四轴会变、最优阈值会漂。正确顺序是先上 prompt（已做）→ 用一个新标注批次复核 → 再谈要不要切 v6。
