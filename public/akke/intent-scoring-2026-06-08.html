CASE这次校准从哪来的

客户拿我们之前导出的评论文档，逐条人工标注了 99 条（《客户评论标注-20260606》），给每条打了 0–100 分（半随机抽样 + 半「我们判得跟同类多数不一样」的分歧样本）。这是第一次有客户侧的"标准答案"来校准我们的意向打分——以前都是我们自己定标准。

这一版的所有改动，都是拿客户这 99 条标注当尺子量出来的：先看我们和客户哪里判得不一样（§2）、归纳出关键发现（§3）、把问题按"该改哪一层"分类（§4），再分层落地（§5）。
SECTION 01上一版打分机制（回顾）

每条评论先由大模型（DeepSeek V4 Flash）拆成 3 个维度，代码按固定公式算出 0–100 分，再按阈值落四档。得分 = 基础分（类型）+ 加分（具体程度）+ 加分（时效），上限 100：

① 评论类型基础分② 具体程度加分③ 时效加分
问购（想买/找服务）60具体+25近窗（刚发）+15
问工艺（问知识/做法）40一般+10在调研+8
感慨（闲聊/玩梗）15模糊+0无时间+0

落档：高 ≥80 / 中 ≥60 / 低 ≥30 / 其余无关。举例：

高意向 93 「包做好吗我有500平方多少钱一平方」

一句话总结客户的"评分观"：客户的门槛整体比我们松、更看重"人愿意开口具体提问"这件事本身——问价、深度请教、求资料、甚至同行搭话，在他眼里都是值得碰的线索；而我们的模型偏"学术"，按"知识 vs 产品""具体 vs 泛"打分，反而把"具体的技术请教"误当成了无意向。

SECTION 03 · 反向反过来：哪些是我们判高、客户判低

SECTION 04方案总览：问题分两类，修法不同

5 个发现按"该改哪一层"分类——有的改评分公式表能解，有的只能改大模型的 prompt，有的是产品决策：

问题占多少根因修在哪
高意向漏召（中→高 21 条）大头评分表门槛卡太高配方表立竿见影
中段太严（低↔中 错位）中中意向门槛 60 太高配方表
认真技术请教被判 0/无关4 条但最伤大模型把它判成 off_topic / 没吐轴prompt表救不了
明确问价被判无关个别大模型误判 off_topicprompt
同行/share 客户当高价值整类客户行业特殊偏好产品决策
为什么要分层：同一个误判，可能是"大模型把评论的类型/具体度拆错了"（prompt 的事），也可能是"公式阈值划错了"（配方表 的事）。先分清是哪一层再动手——乱动阈值是最容易出事的。

第二层 prompt 层：3 条公式表救不了的硬伤 已上线 Langfuse v11

这 3 个是大模型"拆维度"本身就拆错了，改分数表无济于事，必须改 prompt：

① 认真技术请教被当 off_topic → 0 分
例：「请教一下老师，水泥墙上有涂料，如果用预拌砂浆贴的话需要把涂料铲掉吗？如果用环氧碳基的话，需要把涂料铲掉吗」 客户 100、我们 0
修复：带「请教/求教 + 具体工艺细节 + 自家情况」的长问句，必须判 type=知识、具体度=高，禁止判 off_topic。
② 知识类具体度"一刀切"打 medium
闲好奇「这样搞，风水上没问题吗」 vs 真请教「请教一下老师，水泥墙上有涂料，如果用预拌砂浆贴的话需要把涂料铲掉吗？如果用环氧碳基的话，需要把涂料铲掉吗」——以前全打 medium，分不开
修复：含具体尺寸/型号/自家户型/施工细节 → 具体(high)；纯泛问 → 模糊(low)。高的自然进高意向，低的掉无关，不再都卡中间。
③ 明确问价被判 off_topic
例：「这套沙发的尺寸和价格是多少」 我们判 0
修复（按客户细化）：房子/全屋定制相关的问价/要清单/求联系方式 → 一律 home，禁判 off_topic；但成品家具(沙发/床)、家电、数码这类非定制品的问购，仍判 off_topic→0（沙发是成品家具不是定制，该判 0 是对的）。

第三层 产品决策：同行/share 类 结果：A 普适提权

同行/分享类（「我这有两户过来给我帖」「大庆有推荐的装修公司吗」客户给 80-100，我们给低）——决定普适提权：所有 org 都把 share 类整体提一档（即第一层里 share 底分 15→25），不只针对这一个客户。

但「整体提一档」有个坑要先填——这恰恰是一个能单独上线的小步：
现在代码里 share 是个大杂烩兜底桶——同行搭话（「我这有两户给我帖」= 工长 B2B 线索）、晒家炫成果、点赞、纯表情、@别人，全塞一起、统一底分 15。直接 15→25，会把没价值的「晒家 / 点赞 / 兜底」也一并抬上来。
更稳的做法：先在 第二层 prompt 把「同行」从 share 里拆成单独一类（认出「找施工 / 找同行合作 / 求推荐装修公司」），再由第一层只给「同行」加分、「分享 / 点赞 / 兜底」保持低。
关键点：这是个小桶、不爆池，可以脱离 v6 那套大改、单独上线——它跟「中意向门槛 60→50」那个让池子涨 3.3 倍、要等产能的大动作完全是两件事，别绑一起等。
SECTION 06实际上线的是什么 = B + C（不爆池折中）
关键判断：第一层 v6 配方虽然对齐客户最优，但拿全库 39,471 条实测，只要把「问价/要清单」(中意向 78 分那批) 提进高意向，高意向池子会从 2,896 涨到约 9,500（7.3% → 24%，3.3 倍）。这批是评论里最大的一桶，运营 5 人 + 私信配额扛不住 3.3 倍。而且客户标注 49% 是"故意挑的分歧 case"，不代表真实分布——"对齐客户最优" ≠ "线上能跑"。

所以这版没有全量切 v6，走"修真错 + 不爆池"的折中：

动作是什么状态
B｜prompt 修真错第二层那 3 条（技术请教不再判 0、知识具体度拆分、问价按房子/成品家具区分）。改的是"四轴拆得准不准"，不动阈值表。已上线 v11
C｜中意向内按分优先真高意向（78 分那批）暂不硬提档（避免爆池），改成：运营拉单时，中意向桶里高分的排在最前面优先碰。等于"暂不提档、但优先处理"。已部署生产库
D｜同行/分享拆类 + share 提权第二层 prompt 把「同行」从 share 杂烩桶里拆出来，第一层只给同行加分（share 底分对同行 15→25，分享/点赞/兜底不动）。小桶、不爆池、不依赖产能——跟下面 v6 那套要等产能的大改不是一回事。可独立上线 · 待拆类
第一层 v6 配方（改阈值）会让池子 3.3 倍，暂不默认启用备用 gated

SECTION 08我对"意向分演变"的看法
① 分数不是目的，"该不该碰这个人"才是意向分只是把"要不要私信"这个动作可排序、可解释。演变的尺子永远是业务侧的真值（客户/运营认不认）。这次第一次有客户标注当外部真值，比我们自己调参靠谱得多。
② 分类（prompt）和打分（公式表）要分开演变先分清错在哪一层再动手——这次大部分问题是 prompt 拆错（技术请教被当非装修），改 prompt 就好，不该动阈值。乱动阈值最容易出事。
③ 召回和产能是一对约束，不能只看准"判得跟客户一样准"和"运营能消化多少"是两件事。把召回拉满、池子翻几倍但发不出去，等于把真高意向稀释在一堆里——反而更差。意向分演变必须带着下游产能一起算。这就是为什么这版选 B+C 而不是直接全切 v6。
