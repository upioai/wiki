# 个人微信电脑端 Bug 集：新增记录规范

适用于 `public/akke/personal-wechat-pc-bugs.html` 中 **W-98 起**的新编号；W-01～W-97 是旧台账，不追溯补造画面。新增记录同时维护 HTML 台账和 `personal-wechat-pc-bug-guide.js` 的 `entries`、`highlights`、`scenes`。

每条新 Bug 必须有具体的微信场景还原，直接显示在卡片中，至少包括事发前、触发或事发后两个画面。画出客户消息、我方消息、系统提示或会话列表的相对顺序；每帧写清楚为什么这样还原。完整技术台账仍放在展开区。

- 有运营截图：`kind:'wechat'`，按截图还原微信聊天，说明哪些文字经过脱敏或意译。截图无法证明的时间、顺序和发送结果不要补写成事实。
- 只有日志：`kind:'log'`，以微信聊天或列表的示意卡片还原日志**能证明**的动作和先后，明确写“日志还原”、缺失原帧、无法确认的界面细节；不能冒称一比一截图。
- `source` 写具体证据类型与边界；两帧都要有标题、画面内容和说明。公开仓库不得提交未脱敏截图、客户身份、联系方式或原始私聊。推断与已确认事实分开标记。
- 证据不足以具体还原时，先补取截图或日志，暂不把猜测画面作为新编号发布。需要追踪的问题可以先留在非公开待核实流程，待有证据后再入 Bug 集。

提交前运行 `node tools/check-pc-bug-scenes.mjs --self-test`，PR 中同名检查必须通过。自动检查只验证**是否有结构化场景**，内容是否符合证据、是否脱敏仍需人工逐条复核。
